# 组件通信与插槽总览（componentsBase）

> [!abstract] 一句话
> 这套示例只讲两件事：**数据怎么在父子组件之间流动**（`props` 向下、`emit` 向上），以及**父组件怎么把"一段 UI"塞进子组件的预留位置**（插槽）。==前者传数据，后者传结构；作用域插槽则是"子组件出数据、父组件出结构"的合体==。

---

## 一、知识地图

```text
componentsBase
│
├── ① 组件通信（数据流）
│   ├── Exp1  父 → 子：props
│   │   ├── 基础传值（静态 / 动态绑定）
│   │   └── props 校验（类型 / 必填 / 默认值 / 自定义 validator）
│   └── Exp2  子 → 父：自定义事件 emit
│
└── ② 插槽（结构流）
    ├── Exp3  默认插槽 + 后备内容
    ├── Exp4  具名插槽（多个占位）
    ├── Exp5  条件插槽（v-if + $slots 判断）
    ├── Exp6  动态插槽名（#[name] + v-for）
    ├── Exp7  作用域插槽（子传数据给父的插槽内容）
    │   ├── 默认作用域插槽
    │   └── 显式 #default
    └── Exp8  具名作用域插槽（多个插槽各自传数据）
```

> [!info] 两条主线
> **通信线**：`props` 往下、`emit` 往上；兄弟组件要靠父组件中转（或 Pinia）。
> **插槽线**：默认 → 具名 → 条件 → 动态名 → 作用域 → 具名作用域，逐层叠加，最后一项是前几项的组合。

## 三、一页速查

### 3.1 父子通信

```vue
<!-- 父：传值 -->
<Child :title="greeting" id="001" @minus="handleMinus" />

<!-- 子：接收与校验 -->
const props = defineProps({
  title: { type: String, required: true, default: '默认值' },
  loginMethod: { validator: (v) => ['Tel', 'QQ', 'WeChat'].includes(v) },
})

<!-- 子：发事件 -->
const emit = defineEmits(['minus'])
emit('minus', 2)

<!-- 父：监听 -->
function handleMinus(payload) { /* payload === 2 */ }
```

### 3.2 插槽六连

```vue
<!-- 子组件 -->
<slot>后备内容</slot>                  <!-- 默认 -->
<slot name="header" />                 <!-- 具名 -->
<slot :user="user" />                  <!-- 作用域 -->
<slot :name="section">后备</slot>      <!-- 动态名 + 作用域 -->

<!-- 父组件 -->
<Child>默认内容</Child>
<template #header>标题</template>
<template #default="{ user }">{{ user.name }}</template>
<template #[section]>动态名内容</template>
<template #user="{ user }">具名作用域</template>
<template #header v-if="show">条件插槽</template>
```

### 3.3 三种"判断插槽是否存在"的写法

| 写法 | 位置 | 说明 |
| --- | --- | --- |
| `$slots.header` | 模板 | 父组件是否提供了该插槽（存在即真） |
| `useSlots()` | `<script setup>` | 在 JS 中拿到 slots 对象 |
| `v-if="$slots.header"` | 子组件模板 | 条件渲染包裹层，常用于 header/footer |

## 四、必须记住的 8 个结论

> [!important] 核心结论
> 1. **props 是只读的**，子组件不能直接改；要改就 `emit` 通知父组件改。
> 2. **静态属性传字符串**（`id="001"` → `"001"`），**动态绑定保留类型**（`:id="1"` → `1`）。
> 3. **模板里 prop 用 kebab-case**：`login-method` ↔ `loginMethod`。
> 4. **插槽内容在父组件作用域编译**：父模板里的变量来自父组件，不是子组件。
> 5. **插槽内容不会自动继承子组件的数据**；要拿子组件数据，必须用**作用域插槽**显式传出来。
> 6. **后备内容只在父组件"没提供"该插槽时显示**；提供了空内容也算"提供了"。
> 7. **`v-slot` 只能写在 `<template>` 或组件标签上**，不能写在普通元素上。
> 8. **`#` 是 `v-slot:` 的简写**，`#default` 可省略参数（直接写在组件上即默认插槽）。

## 五、常见混淆对照

| 容易混 | 区别 |
| --- | --- |
| `props` vs 插槽 | props 传**数据**；插槽传**模板结构** |
| 默认插槽 vs 具名插槽 | 一个占位 vs 多个有名字的占位 |
| 具名插槽 vs 作用域插槽 | 前者解决"放哪里"，后者解决"用什么数据渲染" |
| `v-slot="{ user }"` vs `v-slot="slotProps"` | 前者解构，后者拿整个对象（`slotProps.user`） |
| `v-if` 写在哪 | 写在**父组件提供的 `<template #x>`** 上 → 控制插槽是否存在；写在子组件包裹层 → 控制外壳是否渲染 |
| `:name="section"` vs `#[section]` | 子组件端动态命名 vs 父组件端动态匹配 |
| `defineProps` 赋值 vs 不赋值 | 赋值后才能 `props.xxx`；模板中本来就能直接用 `xxx` |

## 六、项目如何运行

```bash
cd componentsBase
npm install
npm run dev
```

`src/App.vue` 默认只挂载了 Exp6：

```vue
<script setup>
import Exp6_DynamicSlotName_Parent from './components/Exp6_DynamicSlotName_Parent.vue'
</script>

<template>
  <Exp6_DynamicSlotName_Parent />
</template>
```

> [!tip] 切换实验
> 把 `App.vue` 里的 import 和标签换成想看的 `ExpN_..._Parent.vue` 即可。每个实验都只依赖同目录下的 `_Parent` 与 `_Child` 两个文件。
