# any

> [!abstract] 一句话定义
> `any` 是**关掉类型检查的逃生舱**：它绕过一切类型约束，==可以赋给任何类型，也可以接受任何类型的赋值==，代价是把 TypeScript 的保护全部丢掉。

---

## 一、基本用法

```ts
let x: any = 1
x = 'hello'          // ✅ 换成字符串没问题
x = { a: 1 }         // ✅ 换成对象也没问题

x.foo.bar.baz        // ✅ 任意属性访问都不报错
x()                  // ✅ 当函数调用也不报错
x++                  // ✅ 算术运算也不检查

const arr: any[] = [1, 'two', { three: 3 }]
```

**显式标注**是"主动放弃检查"；但更需要注意的是**隐式 `any`**：

```ts
function f(param) {        // ⚠️ 没写类型 → 参数隐式 any
  return param
}

// tsconfig 里 "noImplicitAny": true（strict 的一部分）会把隐式 any 直接报错
```

> [!tip] `noImplicitAny` 是拦隐式 `any` 的闸门
> 显式写 `any` 永远合法；但**忘写类型**产生的隐式 `any`，在 `strict` 下会被标红。二者要分清。

---

## 二、常见场景与注意事项

**适合用 `any` 的少数场景**

- 从旧 JavaScript 项目**渐进迁移**，先让代码跑起来。
- 引入**没有类型声明的第三方库**，暂时兜住。
- `JSON.parse`、动态键访问等**类型确实无法静态描述**的地方。

**注意事项**

> [!warning] `any` 会"传染"
> 只要链路上一处是 `any`，后续基于它的推导**全部退化为 `any`**——保护层层失效。这就是 `any` 比 `unknown` 危险的地方：它**不报错、也不提示**。

```ts
const data: any = JSON.parse(json)
const name = data.user.name   // 全程无检查，user 不存在也要运行时才炸
```

> [!tip] 能用 `unknown` 就别用 `any`
> 你若只是想"先接收、再处理"，[[unknown]] 是**类型安全的替代品**：它同样能装下任何值，但**用之前强制你先收窄**。二者对比见下节。

> [!warning] `any` 会破坏函数类型检查
> 把一个 `any` 传进期望具体类型的函数不会报错，错误被推迟到运行时。

## 三、与其他类型的关系

`any` 是**双向通用**的：它与任何类型都可以互相赋值（这也是它"关掉检查"的本质）。

| 关系                | 说明                                 |
| ----------------- | ---------------------------------- |
| `any` → 任意类型      | ✅ 都能赋过去                            |
| 任意类型 → `any`      | ✅ 都能赋进来                            |
| `any` 与 `unknown` | 互相可赋；但 `unknown` 用前必须收窄，`any` 不用   |
| `any` 与 `never`   | 互相可赋                               |
| 出现在联合类型           | `any \| T` 会被**吞并**成 `any`（联合失去意义） |

> [!note] `any` 不是"所有类型的联合"
> 它没有任何成员类型，只是一个**跳过检查的标记**。所以 `any` 上做任何操作都不报错——因为编译器根本没打算检查。

## 四、小结

| 项目 | 内容 |
| --- | --- |
| 所属层级 | 顶层类型（Top Type） |
| 关键字 | `any` |
| 核心特征 | 绕过类型检查，双向可赋值 |
| 危险点 | **传染性**：污染下游所有推导 |
| 更安全的替代 | [[unknown]] |
| 相关开关 | `noImplicitAny`、`strict` |
| 建议 | 只在迁移、无类型库等**不得已**处使用；生产代码尽量让它的范围最小 |
