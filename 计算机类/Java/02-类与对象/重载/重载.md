# Java 重载（Overloading）

> 关联笔记：[[方法]]、[[构造方法]]、[[继承]]、[[static关键字]]、[[this关键字]]、[[Java方法的解释]]

## 一句话解释

==**同一个类里，方法名相同，但参数列表不同。**==

编译器根据调用时传入的实参，在**编译期**自动判断该调用哪个方法。

重载解决的是「同一件事有多种入参形式」的问题：功能不变，入口可以有多个。它和 [[继承]] 里的重写不是一回事。

---

## 一、先理解「方法签名」

重载的所有规则，都建立在「方法签名」这个概念上：

> **方法签名 = 方法名 + 参数类型列表**（泛型按擦除后的类型算）。

下面这些东西**都不属于**方法签名：

| 组成        | 是否属于签名 | 说明                  |
| --------- | ------ | ------------------- |
| 方法名       | ✅ 是    | 必须相同才谈得上重载          |
| 参数类型      | ✅ 是    | 个数、类型、顺序都算          |
| 返回值类型     | ❌ 否    | 所以返回值不同不能区分重载        |
| 参数名       | ❌ 否    | `a` 改成 `b` 没有任何影响    |
| 访问修饰符     | ❌ 否    | `public` / `private` 不参与 |
| `throws`  | ❌ 否    | 声明哪些异常不参与           |
| 泛型实参      | ❌ 否    | 擦除后可能变成同一个签名        |

> [!tip] 记住一句话
> **签名只看「名字 + 参数类型」。** 判断两个方法能不能共存、算不算重载，先看签名是否相同。

---

## 二、三个条件

1. **方法名必须相同**
2. **参数列表不同**（个数、类型、顺序至少有一个不同）
3. **返回类型不能作为区分依据**

前提：这些方法要处在**同一个类**里，或者子类重载从父类**继承来的**方法。两个毫无关系的类里各写一个同名方法，不叫重载。

| 维度     | 是否参与重载判断 |
| ------ | -------- |
| 方法名    | ✅ 必须相同   |
| 参数个数   | ✅ 可以不同   |
| 参数类型   | ✅ 可以不同   |
| 参数顺序   | ✅ 可以不同   |
| 返回值类型  | ❌ 不参与    |
| 参数名    | ❌ 不参与    |
| 访问修饰符  | ❌ 不参与    |
| `throws` | ❌ 不参与    |
| 泛型实参   | ❌ 不参与    |

---

## 三、参数列表「不同」的三种方式

### 1. 参数个数不同

```java
void show() { }
void show(int a) { }
void show(int a, int b) { }
```

### 2. 参数类型不同

```java
void show(int a) { }
void show(double a) { }
void show(String s) { }
void show(int[] arr) { }
```

基本类型和包装类型也算不同类型：

```java
void show(int a) { }
void show(Integer a) { }     // 合法重载，但调用时容易踩坑，见第七节
```

### 3. 参数顺序不同

```java
void show(int a, String s) { }
void show(String s, int a) { }   // 合法重载
```

> [!warning] 顺序重载的陷阱
> 顺序不同虽然合法，但和自动类型转换混在一起时很容易产生二义性：
>
> ```java
> void f(int a, double b) { }
> void f(double a, int b) { }
>
> f(1, 2.0);   // ✅ 第一个
> f(1.0, 2);   // ✅ 第二个
> // f(1, 2);  // ❌ 编译错误：两个方法都能靠拓宽匹配，无法抉择
> ```
>
> 所以顺序重载除非语义非常清楚，否则不建议使用。

## 四、完整示例

```java
class Calculator {
    // 两个 int
    int add(int a, int b) {
        return a + b;
    }

    // 三个 int —— 参数个数不同
    int add(int a, int b, int c) {
        return a + b + c;
    }

    // 两个 double —— 参数类型不同
    double add(double a, double b) {
        return a + b;
    }
}
```

调用：

```java
Calculator c = new Calculator();

c.add(1, 2);        // 走第一个：add(int, int)
c.add(1, 2, 3);     // 走第二个：add(int, int, int)
c.add(1.0, 2.0);    // 走第三个：add(double, double)
```

编译器不是「随便挑一个」，而是根据实参的类型和个数做**精确匹配**。具体规则见第六节。

## 五、什么不算重载

下面这些写法看起来像重载，实际上要么编译报错，要么根本不是重载：

```java
import java.util.List;

class Demo {
    int f(int a) { return a; }
    // double f(int a) { return a * 2; }   // ❌ 只改返回值：签名相同

    void g(int a) { }
    // void g(int b) { }                   // ❌ 只改参数名：签名相同

    public void h() { }
    // private void h() { }                // ❌ 只改访问修饰符

    void k() throws java.io.IOException { }
    // void k() throws java.sql.SQLException { }  // ❌ 只改 throws

    void m(int a) { }
    // static void m(int a) { }            // ❌ 只改 static

    void n(List<String> list) { }
    // void n(List<Integer> list) { }      // ❌ 泛型擦除后都是 List

    void p(int[] arr) { }
    // void p(int... arr) { }              // ❌ 可变参数本质就是数组

    <T> void q(T t) { }
    // void q(Object o) { }                // ❌ 擦除后都是 q(Object)
}
```

逐条记原因：

| 写法                        | 结果     | 原因                    |
| ------------------------- | ------ | --------------------- |
| 只改返回值                     | 编译错误   | 签名不包含返回值              |
| 只改参数名                     | 编译错误   | 签名不包含参数名              |
| 只改访问修饰符                   | 编译错误   | 签名不包含修饰符              |
| 只改 `throws`               | 编译错误   | 签名不包含异常声明             |
| `static` 与实例方法同签名        | 编译错误   | 签名相同，只是归属不同           |
| `List<String>` 与 `List<Integer>` | 编译错误   | 泛型擦除后签名相同             |
| `int[]` 与 `int...`        | 编译错误   | 可变参数在底层就是数组           |
| `<T> void f(T)` 与 `void f(Object)` | 编译错误 | 类型参数擦除后与 `Object` 相同 |

> [!note] 返回值不同但参数也不同，可以共存
> ```java
> int f(int a) { return a; }
> double f(double a) { return a * 2; }
> ```
> 这两个能共存，**不是因为返回值不同，而是因为参数类型不同**。返回值从头到尾都没参与判断。

## 六、编译器如何选择：重载解析

重载是**编译期**完成的。编译器按固定顺序筛选候选方法，一旦在某个阶段找到适用方法，就不再往下走。

### 1. 三个阶段

| 阶段       | 允许的转换                                             | 不允许           |
| -------- | ------------------------------------------------- | ------------- |
| ① 严格调用   | 基本类型拓宽（`int → long → float → double`）、引用类型向上转型、`null` 赋给引用类型 | 装箱 / 拆箱、可变参数  |
| ② 宽松调用   | 阶段 ① 的全部，外加**装箱 / 拆箱**                            | 可变参数          |
| ③ 可变参数调用 | 前两阶段都找不到时，把 `T...` 当成 `T[]` 来匹配                   | —             |

> [!important] 找到即停
> **先在阶段 ① 找；找到就不再考虑阶段 ②。** 这就是为什么 `int` 实参往往选中 `long` 版本，而不是 `Integer` 版本。

### 2. 精确匹配优先

有完全匹配的方法时，永远选完全匹配：

```java
void f(int x)   { System.out.println("int"); }
void f(long x)  { System.out.println("long"); }
void f(double x){ System.out.println("double"); }

f(1);    // int —— 精确匹配
f(1L);   // long —— long 字面量
f(1.0);  // double —— 小数默认是 double
```

### 3. 基本类型拓宽优先于装箱

```java
void f(long x)    { System.out.println("long"); }
void f(Integer x) { System.out.println("Integer"); }

f(1);    // 输出 long
```

`int → long` 属于阶段 ① 的拓宽，`int → Integer` 属于阶段 ② 的装箱。阶段 ① 先命中，所以选 `long`。

反过来，如果只有一个包装类型版本，装箱也能完成调用：

```java
void g(Integer x) { }
g(1);    // ✅ 自动装箱
```

但「基本类型拓宽 + 装箱」不能一步完成：

```java
void h(Long x) { }
// h(1);   // ❌ 编译错误：int 不能先拓宽成 long 再装箱成 Long
h(1L);     // ✅ 直接传 long，再装箱
```

### 4. 引用类型的向上转型也属于阶段 ①

```java
void f(Object o) { System.out.println("Object"); }
void f(long x)   { System.out.println("long"); }

Integer i = 1;
f(i);    // 输出 Object
```

`Integer → Object` 是引用拓宽，阶段 ① 就适用；而 `Integer → long` 要先拆箱，属于阶段 ②。前者优先。

### 5. 最具体原则

同一阶段有多个候选时，选**最具体**的那个：

- 基本类型：能拓宽到对方的更具体。`long` 比 `double` 具体。
- 引用类型：子类比父类具体。`String` 比 `Object` 具体。

```java
void f(long x)   { System.out.println("long"); }
void f(double x) { System.out.println("double"); }

f(1);    // 输出 long —— int 能拓宽到 long，long 又能拓宽到 double
```

```java
void f(Object o) { System.out.println("Object"); }
void f(String s) { System.out.println("String"); }

f(null);    // 输出 String —— String 比 Object 更具体
```

### 6. null 的二义性

如果两个候选类型互不相关，`null` 就无法抉择：

```java
void f(String s)  { }
void f(Integer i) { }

// f(null);   // ❌ 编译错误：对 f 的引用有歧义
```

必须强转才能通过：

```java
f((String) null);    // ✅
f((Integer) null);   // ✅
```

`System.out.println(null)` 也是同样的坑：`println(String)` 和 `println(char[])` 互不相关，编译直接报二义性。

### 7. 可变参数永远最后考虑

```java
void sum(int a, int b) { System.out.println("固定参数"); }
void sum(int... nums)  { System.out.println("可变参数"); }

sum(1, 2);    // 固定参数：阶段 ① 直接命中
sum(1);       // 可变参数：固定版本不匹配
sum();        // 可变参数
```

装箱也优先于可变参数：

```java
void f(Integer x)   { System.out.println("Integer"); }
void f(int... nums) { System.out.println("varargs"); }

f(1);    // 输出 Integer：阶段 ② 的装箱早于阶段 ③
```

> [!note] 一个实用判断法
> 看到重载选择问题时，按顺序问自己：
> 1. 有没有参数完全一致的？
> 2. 有没有靠基本类型拓宽就能匹配的？
> 3. 有没有靠引用类型向上转型就能匹配的？
> 4. 有没有靠装箱 / 拆箱就能匹配的？
> 5. 以上都没有，才轮到可变参数。

## 七、重载 vs 重写

这两个词最容易混。它们唯一的共同点是「方法名相同」。

| 对比项   | **重载（Overload）** | **重写（Override）**    |
| ----- | ---------------- | ------------------- |
| 发生位置  | 同一个类，或父子类之间      | 子类与父类之间             |
| 方法名   | 相同               | 相同                  |
| 参数列表  | ==必须不同==         | ==必须完全相同==          |
| 返回值   | 无所谓              | 相同，或是父类返回值的子类型（协变）  |
| 访问权限  | 无所谓              | 不能比父类更严格            |
| 异常声明  | 无所谓              | 不能抛出更宽的受检异常         |
| 绑定时机  | ==编译期（静态绑定）==    | ==运行期（动态绑定）==       |
| 目的    | 为同一功能提供多种入参形式    | 让子类改造父类的行为          |

```java
class Animal {
    void speak() {
        System.out.println("动物叫");
    }
}

class Dog extends Animal {
    @Override
    void speak() {                   // 重写：名字、参数完全一样
        System.out.println("汪汪");
    }

    void speak(int times) {          // 重载：参数不同，与重写无关
        for (int i = 0; i < times; i++) {
            speak();
        }
    }
}
```

> [!warning] `@Override` 只用于重写
> 把 `@Override` 写在 `speak(int times)` 上会编译报错，因为父类没有这个方法——参数不同是重载，不是重写。

重载的详细对比也可以回看 [[方法]] 里的「重载 vs 重写」一节。

## 八、父子类之间的重载

重载不只发生在同一个类里。子类声明一个与父类同名、但参数不同的方法，就构成对父类方法的重载：

```java
class Parent {
    void show(int x) {
        System.out.println("Parent.show(int)");
    }
}

class Child extends Parent {
    void show(String s) {
        System.out.println("Child.show(String)");
    }
}
```

`Child` 的对象同时拥有两个可调用的 `show`：

```java
Child c = new Child();
c.show(1);       // 调父类继承来的 show(int)
c.show("hi");    // 调子类的 show(String)
```

但注意，**能调用哪些重载版本，取决于变量的编译期类型**：

```java
Parent p = new Child();
p.show(1);          // ✅ Parent 里有 show(int)
// p.show("hi");    // ❌ 编译错误：Parent 类型里没有 show(String)
```

## 九、重载是编译期绑定（静态绑定）

重载在编译期就选定了方法签名，所以它被称为「编译期多态 / 静态多态」。但严格说，这只是**名字解析**；真正的多态是重写带来的运行期动态派发。

```java
class Animal {
    void speak(Object o) {
        System.out.println("Animal.speak(Object)");
    }
}

class Dog extends Animal {
    void speak(String s) {
        System.out.println("Dog.speak(String)");
    }
}

Animal a = new Dog();
a.speak("hello");    // 输出 Animal.speak(Object)
```

为什么不是 `Dog.speak(String)`？因为编译器只看 `a` 的编译期类型 `Animal`，在 `Animal` 的方法表里只能找到 `speak(Object)`，于是选定这个签名。

> [!note] 先选签名，再派发方法体
> 重载解析只负责「选哪个签名」；如果选中的签名恰好被运行期对象重写了，才会继续发生动态派发。
>
> ```java
> class Dog extends Animal {
>     @Override
>     void speak(Object o) { System.out.println("Dog.speak(Object)"); }
> }
> ```
> 此时 `a.speak("hello")` 仍按 `Animal` 选中 `speak(Object)` 签名，但方法体执行的是 `Dog` 的版本。

静态方法与重载的关系：

- 静态方法**可以被重载**，调用时同样按参数选版本。
- 静态方法**不能被重写**；子类写同名同参的静态方法叫「隐藏」（hiding），不是重写。

## 十、构造方法重载

构造方法也遵循重载规则：名字固定等于类名，只能靠参数列表区分。

```java
public class Student {
    private String name;
    private int score;

    public Student() {                        // 无参
        this("匿名", 0);                       // 委托给参数最全的版本
    }

    public Student(String name) {             // 一个参数
        this(name, 0);
    }

    public Student(String name, int score) {  // 两个参数
        this.name = name;
        this.score = score;
    }
}
```

调用：

```java
new Student();                 // 走第一个
new Student("小明");            // 走第二个
new Student("小明", 95);        // 走第三个
```

构造方法重载最常见的写法，就是让参数少的版本通过 `this(...)` 委托给参数最全的版本，避免重复赋值代码。详见 [[构造方法]] 和 [[this关键字]]。

> [!warning] 构造方法不能靠返回值区分
> 构造方法本来就没有返回值类型，所以「返回类型不同」这条路在构造方法上连讨论的意义都没有。

## 十一、实际意义与 JDK 例子

### 1. 不用给功能相近的方法起不同名字

没有重载，就得写成 `addTwoInts`、`addThreeInts`、`addTwoDoubles`，可读性很差。

### 2. 模拟默认参数

Java 没有默认参数语法，通常用重载来替代：

```java
void log(String msg) {
    log(msg, "INFO");        // 调用另一个重载版本
}

void log(String msg, String level) {
    System.out.println("[" + level + "] " + msg);
}
```

调用方只关心消息时写 `log("hello")`，需要指定级别时写 `log("hello", "WARN")`。

### 3. 让 API 更直观

JDK 里到处是重载：

| 方法                        | 重载的作用                                 |
| ------------------------- | ------------------------------------- |
| `System.out.println(...)` | 支持 `int`、`long`、`double`、`char[]`、`String`、`Object` 等 |
| `String.valueOf(...)`     | 把各种类型转成字符串                            |
| `Math.abs(...)`           | `int` / `long` / `float` / `double` 各一版 |
| `String.substring(...)`   | `substring(int)` 与 `substring(int, int)` |
| `StringBuilder.append(...)` | 追加各种类型的数据                            |
| `ArrayList.add(...)`      | `add(E)` 与 `add(int, E)`               |

`System.out.println()` 能打印各种类型，本质就是重载在起作用。

## 十二、常见坑与最佳实践

### 1. 只改返回值

```java
int foo(int a) { return a; }
// double foo(int a) { return a; }   // ❌ 编译错误
```

调用方写 `foo(1);` 时根本不看返回值，编译器无法靠返回值决定调哪个。

### 2. 泛型擦除导致的「假重载」

```java
void f(List<String> list) { }
void f(List<Integer> list) { }   // ❌ same erasure
```

运行时泛型类型被擦除，两个方法的签名都变成 `f(List)`，无法共存。

### 3. `null` 的二义性

```java
void f(String s) { }
void f(Integer i) { }
// f(null);    // ❌ 编译错误
```

### 4. 基本类型与包装类型同时重载

```java
void f(int x)     { System.out.println("int"); }
void f(Integer x) { System.out.println("Integer"); }

f(1);              // int

Integer i = 1;
f(i);              // Integer
```

同样一个字面量，直接传和装进变量再传，可能选中不同方法。这种重载除非有明确理由，否则不要写。

### 5. 顺序重载 + 自动拓宽 = 二义性

```java
void f(int a, double b) { }
void f(double a, int b) { }
// f(1, 2);    // ❌ 两个都适用，无法抉择
```

### 6. 可变参数与数组不能共存

```java
void f(int[] arr) { }
// void f(int... arr) { }   // ❌ 签名冲突
```

### 7. 最佳实践

- **只有语义相同的方法才重载**。`print(String)` 和 `print(int)` 合理；`add(int, int)` 和 `add(String, String)` 做字符串拼接就会让人困惑。
- **避免为了凑重载而颠倒参数顺序**，特别是参数类型能互相转换的时候。
- **避免同时重载基本类型和对应的包装类型**。
- **参数很多时不要硬堆重载**，考虑 Builder 模式或参数对象。
- **重载方法之间尽量保持一致的行为**，不要一个返回 `null`、一个抛异常。

---

## 十三、注意事项

1. **重载看方法签名**，签名 = 方法名 + 参数类型列表。
2. **返回类型不参与重载判断**，只改返回值会编译报错。
3. **参数名、访问修饰符、`throws` 都不参与判断**。
4. **泛型实参在擦除后可能相同**，这时不能重载。
5. **`int[]` 与 `int...` 是同一个签名**，不能共存。
6. **重载在编译期决定**，与运行期对象的实际类型无关。
7. **重载解析按「严格 → 宽松 → 可变参数」三阶段进行**，找到即停。
8. **同一阶段内选最具体的方法**；互不相关的类型会导致二义性。
9. **基本类型拓宽优先于装箱**，装箱优先于可变参数。
10. **`null` 实参容易产生二义性**，必要时显式强转。
11. **子类可以重载父类方法**，但可调用的版本受编译期类型限制。
12. **静态方法能重载、不能重写**；构造方法能重载、不能重写。

## 十四、常见面试题

| 问题 | 答案 |
| --- | --- |
| 重载和重写的区别？ | 重载发生在同类或父子类之间，方法名同、参数不同、编译期绑定；重写发生在父子类之间，方法名和参数都相同、运行期绑定 |
| 返回值类型不同算重载吗？ | 不算。签名不包含返回值，只改返回值会编译错误 |
| 参数名不同算重载吗？ | 不算 |
| 访问修饰符不同算重载吗？ | 不算 |
| `List<String>` 和 `List<Integer>` 能重载吗？ | 不能，泛型擦除后签名相同 |
| 重载是编译期还是运行期决定的？ | 编译期（静态绑定） |
| 同时有 `f(int)` 和 `f(Integer)`，`f(1)` 调哪个？ | `f(int)`，精确匹配优先 |
| 同时有 `f(long)` 和 `f(Integer)`，`f(1)` 调哪个？ | `f(long)`，基本类型拓宽（阶段 ①）优先于装箱（阶段 ②） |
| 同时有 `f(Object)` 和 `f(String)`，`f(null)` 调哪个？ | `f(String)`，String 比 Object 更具体 |
| 同时有 `f(String)` 和 `f(Integer)`，`f(null)` 调哪个？ | 编译错误，二义性 |
| 固定参数和可变参数同时匹配时选谁？ | 固定参数优先 |
| 构造方法能重载吗？ | 能，只要参数列表不同 |
| 静态方法能重载吗？ | 能；但不能重写 |
| 子类可以重载父类方法吗？ | 可以，参数不同即可；但通过父类引用只能调用父类可见的版本 |

---

## 十五、一句话总结

> **重载就是「同名不同参」：签名只看方法名和参数类型，返回值、修饰符、参数名都不算数。编译器在编译期按「精确 → 拓宽 → 装箱 → 可变参数」的顺序挑最具体的版本。**
