# Java 对象的复用

> 关联笔记：[[继承]]、[[面向抽象编程]]、[[UML]]、[[成员变量]]、[[对象的引用和实体]]

## 一句话解释

==**对象的复用，就是"别再重写一遍"——把别的类已经造好的对象拿来当自己的成员（组合），或直接继承它已有的能力（继承）。**==

复用是面向对象最核心的好处之一：==代码写一次、处处用==。Java 里主要有三条路——==**继承、组合、委托**==。它们各有适用场景，选错了会让类之间的关系越缠越乱。

---

## 一、为什么要复用

假设要写一个"汽车"类，汽车有一个"发动机"。笨办法是把发动机的排量、点火逻辑全塞进 `Car` 里：

```java
class Car {
    double displacement;          // 排量
    void ignite() { /* 点火逻辑 */ }
    void drive() { /* 驱动逻辑 */ }
}
```

问题很明显：换一辆车要重抄一遍点火逻辑；`Truck`（卡车）、`Motorbike`（摩托）都得各写一份。==**重复的代码是 bug 的温床**——改一处忘了改另一处，问题就来了。==

复用的思路是：**把"发动机"单独封装成类，谁需要就拿谁的对象来用。**

---

## 二、复用的三条路：继承 / 组合 / 委托

| 方式     | 关系          | 一句话             | UML 中的表现    |
| ------ | ----------- | --------------- | ----------- |
| **继承** | is-a（是一个）   | 子类天生拥有父类的成员     | 空心三角 + 实线   |
| **组合** | has-a（有一个）  | 把别的对象当自己的成员变量   | 实心菱形 或 普通关联 |
| **委托** | uses-a（用一下） | 自己不动手，转发给内部对象去做 | 普通关联/依赖     |

三种方式的具体对比如下。

---

## 三、继承复用：is-a

继承是"最省事"的复用——子类直接白拿父类的字段和方法。

```java
class Vehicle {
    protected String brand;
    public void move() {
        System.out.println("前进");
    }
}

class Car extends Vehicle {      // Car is-a Vehicle
    // 没写 move()，但已经继承了
}
```

```java
Car c = new Car();
c.move();                        // 直接可用，方法是从 Vehicle 继承来的
```

> [!note] 继承的前提
> 只有==**确实是"子类是父类的一种"**==（Car is-a Vehicle）时才用继承。若只是"用到一个部件"，用继承会把不该有的方法也一起继承进来，是典型的误用。

---

## 四、组合复用：has-a（重点）

**组合 = 把一个类的对象作为另一个类的成员变量。** 这是复用里最常用、也最推荐的方式。

```java
class Engine {
    private double displacement;
    public void ignite() {
        System.out.println("点火，排量 " + displacement);
    }
}

class Car {
    private Engine engine;        // ① 把 Engine 对象当成成员 → 组合

    public Car(Engine engine) {
        this.engine = engine;     // ② 运行时把"某个发动机对象"装进来
    }

    public void start() {
        engine.ignite();          // ③ 复用发动机的点火能力
    }
}
```

```java
Car car = new Car(new Engine());
car.start();                      // 点火，排量 0.0
```

用一张关系图看 `Car` 和 `Engine`：

```
┌──────────────┐          ┌──────────────┐
│    Car       │  拥有    │   Engine     │
│--------------│ ◆───────▶│--------------│
│ - engine  ●──┼──────────┼─ displacement│
│--------------│  1    1  │--------------│
│ + start()    │          │ + ignite()   │
└──────────────┘          └──────────────┘
```

- 左边的 `Car` ==**持有一个 `Engine` 引用**==（就是 [[对象的引用和实体]] 里说的"引用指向实体"）。
- `Car` 不需要知道发动机内部怎么点火，==只要调它的 `ignite()` 就行==——这叫**封装**，也是组合天然带来的好处。

### 组合为什么比继承更灵活

| 对比点 | 继承 | 组合 |
| --- | --- | --- |
| 关系强度 | 强耦合（编译期定死） | 弱耦合（运行期可换） |
| 能否运行时替换 | ❌ 不能 | ✅ 换一个对象就行 |
| 复用范围 | 父类**全部**成员（包括不需要的） | 只挑需要的用 |
| 数量限制 | 只能继承**一个**父类 | 想组合几个就几个 |

运行时替换的示例：

```java
class Car {
    private Engine engine;
    public void setEngine(Engine e) {   // 可以中途换发动机
        this.engine = e;
    }
}
```

> [!tip] 设计原则
> ==**"优先使用组合，而不是继承"**==（Favor composition over inheritance）。继承留给"真的是同一种东西"的场景，其余情况一律先想组合。

## 五、委托复用：uses-a

**委托 = 自己不干活，把调用转交给内部对象。** 它其实是组合的一种"用法"——组一个对象进来，然后把自己的方法转发给它。

```java
class Printer {
    public void print(String s) {
        System.out.println(s);
    }
}

class Logger {
    private Printer printer = new Printer();   // 组一个进来

    public void log(String msg) {
        printer.print("[LOG] " + msg);          // 自己不打印，委托给 printer
    }
}
```

`Logger` 没有打印能力，它把 `print` 这件事**委托**给内部的 `printer`。==调用方只知道 `logger.log(...)`，打印细节被藏起来了。==

> [!note] 委托 vs 组合
> 组合说的是"**持有**对象"（结构关系），委托说的是"**把活转交出去**"（行为关系）。同一个成员变量，既是组合，用法上也可能就是委托。

## 六、在 UML 类图里怎么看

`UML.md` 会详细讲，这里先记住三种复用对应的画法：

```
继承  子 ──▷ 父          空心三角，指向父类
组合  整体 ◆── 部分      实心菱形，菱形在"整体"一端
关联  类A ──▶ 类B        普通箭头/直线，表示"持有引用"
依赖  类A ┄┄▶ 类B        虚线箭头，表示"只是用一下"
```

对应到本节的例子：

```
Car ──▷ Vehicle        （Car 继承 Vehicle）
Car ◆── Engine         （Car 组合 Engine，实心菱形在 Car 一端）
```

> [!warning] 别把"组合"和"聚合"搞混
> UML 里 ==**实心菱形是组合（composition）**==，部分随整体一起生灭（车毁了，车上的发动机会一起没）；==**空心菱形是聚合（aggregation）**==，部分可以独立存在（车队解散了，车还在）。日常口语里的"组合"往往泛指"把对象当成员"。

## 七、组合与继承一起用：面向抽象的组合

把 [[面向抽象编程]] 的思路套进来，组合的威力更大——成员变量的类型写成**抽象类/接口**，运行时再决定装哪个子类对象：

```java
abstract class Engine {
    public abstract void ignite();
}

class Car {
    private Engine engine;        // 面向抽象：类型是 Engine，不是具体发动机
    public Car(Engine e) { this.engine = e; }
    public void start() { engine.ignite(); }
}
```

这样 `Car` 不依赖任何具体发动机，==将来加"电动引擎""氢燃料引擎"都不用改 `Car` 一行代码==——这正是 [[开闭原则]] 在组合上的体现。

---

## 八、注意事项

1. **复用不是照抄**。组合是"把对象当成员用"，不是把代码 Ctrl+C 过来。
2. **is-a 用继承，has-a 用组合**。判断不清就先问："X 是 Y 的一种吗？"是→继承，不是→组合。
3. **一个类只能继承一个父类**，组合不受这个限制，可以组合任意多个。
4. **优先用组合**：继承耦合强、编译期定死；组合耦合弱、运行期可替换。
5. **组合的成员要初始化**，否则就是 `null`，一用就 NPE（见 [[对象的引用和实体]]）。
6. **成员变量声明成抽象类型/接口**，可以进一步降低依赖、方便替换。
7. **注意生命周期**：实心菱形（组合）意味着"整体没了，部分也没了"，别把该共享的对象错误地独占。

---

## 九、一句话总结

> ==**复用就三条路：is-a 用继承、has-a 用组合、转交活用委托；继承耦合强、组合更灵活，所以"优先使用组合而非继承"；把组合的成员类型写成抽象类或接口，复用才真正可扩展。**==
