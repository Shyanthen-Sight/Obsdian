## 考察内容

- **块级元素水平居中**：定宽 + `margin: 0 auto`。
- **负 margin**：`margin-top: -20%` 让元素向上溢出，百分比参照包含块**宽度**。
- **行内替换元素**：`img` 受父级 `text-align: center` 影响而水平居中。
- **盒模型**：`box-sizing: border-box` 下 `width/height` 包含 `padding` 与 `border`。
- **Flex 布局**：`display: flex`、`justify-content`、`align-items` 控制导航栏内容位置。
- **表单与文字样式**：输入框、按钮的尺寸 / 颜色 / 字号 / 圆角，`font-weight` 不带单位。
- **外边距塌陷**：父元素与第一个子元素的上外边距合并，及 `padding-top` 等破解方式。
- **CSS 基础**：选择器、继承、`opacity` 与 `rgba()` 的区别、长度单位。

## 二、结论先行

题目真正要写的只有 `TODO` 之后这一段。其中**只有头像的处理需要动脑**，其余都是对着评分点填数值：

```css
.content img {
  width: 200px;
  height: 200px;
  border-radius: 50%;
  margin-top: -20%;   /* 关键：向上拽出卡片 */
}
```

**原理一句话：`img` 是行内替换元素，父级 `.content` 的 `text-align: center` 直接把它水平居中；再给一个负的 `margin-top`，元素就向上溢出卡片，形成"头像骑在顶边上"的效果。**

```
        ┌──────────────┐  ← 头像顶边（已经在卡片外）
        │              │
────────┼──────────────┼────────  .content 顶边（600px 高的卡片）
        │   头像 200px  │
        │              │
        └──────────────┘
             请登录
        ┌──────────────┐
        │    用户名     │
        └──────────────┘
        ┌──────────────┐
        │     密码      │
        └──────────────┘
          [登录] [重置]
        注册 | 忘记密码
```

`margin-top: -20%` 算出来是 **-90px**（`-20% × 450px`），头像 200px 高，所以约 90px 在卡片外、110px 在卡片内，视觉上正好卡在顶边中间。

## 四、三个关键点

### 1. 卡片为什么能水平居中

```css
.content {
  width: 450px;
  height: 600px;
  margin: 0 auto;
}
```

- `.content` 是 `div`，默认 `display: block`，会独占一行。
- 有了**确定宽度** `450px` 后，左右外边距设为 `auto`，浏览器会把剩余空间平均分到两侧，于是水平居中。
- `margin: 0 auto` 等于：上下 `0`、左右 `auto`。
- 如果宽度是 `auto`（默认撑满父级），剩余空间为 0，`auto` 也只会算成 0，**居不中**。
- 这里不是用 `text-align: center` 居中卡片本身；`text-align` 居中的是**行内内容**，卡片是块级元素，不受它影响。

父级 `.content-container` 没有设宽度，作为块级元素撑满整行；`.content` 在它内部靠 `margin: 0 auto` 居中。

### 2. 头像为什么能"骑"在卡片顶边上

先看 DOM 关系：

```html
<div class="content">
  <img src="./images/cat.png" />   <!-- 头像 -->
  <div class="form"> … </div>      <!-- 表单 -->
  <div class="text"> … </div>      <!-- 底部链接 -->
</div>
```

三个元素是**兄弟关系**，不是父子。头像要突出到卡片外面，靠的是一条组合拳：

1. **`img` 是行内替换元素**。它默认按行内元素参与排版，不会独占一行。
2. **`.content` 的 `text-align: center` 会继承**给 `img`，于是头像在卡片里水平居中。
3. **`margin-top: -20%` 把它向上拽**。负外边距让元素的盒子向上移动，视觉上溢出卡片顶部。
4. **`.content` 和 `.content-container` 都没有 `overflow: hidden`**，所以溢出的部分能正常显示。一旦加了 `overflow: hidden`，头像的脑袋就会被裁掉。

#### 为什么是 -20%，而不是 -120px

```css
margin-top: -20%;
```

CSS 规定：**margin 的百分比（包括上下方向）一律参照包含块的宽度**。

```
-20% × 450px（.content 的宽度）= -90px
```

不是 600px 的 20%，也不是头像自身 200px 的 20%。记住这句：**margin 百分比认宽度，不认高度。**

#### 和 `position: relative` 的区别

```css
/* 也可以，但会保留原来的 200px 占位 */
.content img {
  position: relative;
  top: -90px;
}
```

- `top` 只改变**绘制位置**，元素在文档流里仍占着原来的 200px，下面的标题不会跟着上移。
- 负 `margin-top` 同时改变**布局位置**，后面的内容会一起上移。本题正是要这种紧凑效果。
- 两种写法都能让头像露出卡片，参考解用负 margin，代码更少。

### 3. 输入框、按钮为什么能整齐竖排

```css
.content input {
  width: 300px;
  margin: 10px;
}
```

- `input`、`button` 默认是 `inline-block`，本来会像文字一样横向排列。
- 一个输入框占 `300 + 10 + 10 = 320px`，卡片内容宽 450px；两个并排需要 640px，放不下，所以**自动换行**，变成上下两个。
- `.content` 的 `text-align: center` 让每个 `inline-block` 输入框水平居中。
- `.btns` 是块级 `div`，会把按钮整体推到新的一行；两个按钮各 80px，能并排放下，于是显示为 `[登录] [重置]`。
- `h2` 是块级元素，独占一行，里面的文字被 `text-align: center` 居中。
- `.text` 也是块级，里面的两个 `<a>` 和 `<span>` 是行内元素，自然排成一行并居中。

## 五、另一种写法：父相子绝

如果不想依赖负 margin，可以把头像改为绝对定位。核心是**子绝父相**：

```css
.content {
  position: relative;   /* 给绝对定位的头像提供参照 */
  padding-top: 1px;     /* 关键：阻止 .form 的 margin-top 与父级塌陷 */
}

.content img {
  position: absolute;
  top: -100px;          /* 一半在卡片外 */
  left: 50%;            /* 左边缘先到中线 */
  margin-left: -100px;  /* 再退回自身宽度的一半 */
  width: 200px;
  height: 200px;
  border-radius: 50%;
}

.form {
  margin-top: 120px;    /* 头像脱流后，给表单让出位置 */
}
```

### 为什么要 `padding-top: 1px`

`img` 变成 `position: absolute` 后就**脱离文档流**了，`.form` 成为 `.content` 的第一个**在流内**子元素。

按照 CSS 的**外边距塌陷**规则：父元素没有上边框、没有上内边距、也没有行内内容隔开时，父元素的上外边距会和第一个子元素的上外边距合并。结果就是 `.form { margin-top: 120px }` 把**整张卡片**往下推，而不是把表单往下推。

```css
/* 三种常见破局方式 */
.content { padding-top: 1px; }                  /* 本题用这个，box-sizing 下不改变 600px 总高 */
.content { border-top: 1px solid transparent; } /* 加一条透明边框 */
.content { overflow: hidden; }                  /* 会建立 BFC，但会裁掉头像，本题不能用 */
```

### 水平居中的两种算法

```css
/* 写法 A：left 50% + 负 margin（参照自身宽度） */
left: 50%;
margin-left: -100px;

/* 写法 B：transform 回退自身一半（不需要知道宽度） */
left: 50%;
transform: translateX(-50%);
```

### 两种方案怎么选

| 方案 | 是否脱离文档流 | 需要额外处理 | 适用场景 |
| --- | --- | --- | --- |
| 负 `margin-top` | 否 | 后续内容间距要微调 | 改动最少，本题最省事 |
| 父相子绝 | 是 | 父级 `relative`、防 margin 塌陷、给表单让位 | 定位更可控，通用性更强 |
| Flex 列布局 | 否 | 把 `.content` 改成 `display: flex; flex-direction: column; align-items: center;` | 现代写法，但要重新安排所有子元素 |

> [!tip] 判分只认真实样式
> 两种写法只要最终计算出的 `width`、`height`、`border-radius`、颜色等对得上，都能通过。不要为了"标准答案"去改题目已给出的选择器和结构。

## 六、其他 CSS 不是"没用"，而是必要铺垫

### 1. `* { box-sizing: border-box }`

```css
* {
  box-sizing: border-box;
  margin: 0;
  padding: 0;
}
```

- `border-box`：`width` / `height` 包含 `padding` 和 `border`。所以 `.content` 写 450×600，再加 `padding-top: 1px` 也不会变成 601px。
- `margin: 0; padding: 0`：清掉 `h2`、`p`、`body` 等元素的浏览器默认间距，避免布局被莫名撑开。

### 2. `body` 的背景

```css
body {
  background-image: url("../images/background-pic.jpeg");
  background-size: cover;
  color: #fff;
}
```

- CSS 文件在 `css/` 目录，图片在 `images/` 目录，所以路径是 `../images/background-pic.jpeg`。
- `background-size: cover`：等比缩放背景图，直到**完全覆盖**视口，多出的部分裁掉。
- `color: #fff` 会被继承，页面上所有文字默认白色，所以链接还要单独去下划线。

### 3. `.nav-bar` 把图标推到右上角

```css
.nav-bar {
  display: flex;
  align-items: center;
  justify-content: flex-end;
}
.nav-bar img {
  height: 50px;
  width: 50px;
  border-radius: 50%;
  margin: 15px;
}
```

- `display: flex` 开启弹性布局。
- `justify-content: flex-end` 让主轴（水平）靠右。
- `align-items: center` 让交叉轴（垂直）居中。
- 图标 50×50 再 `border-radius: 50%`，变成圆形头像。

### 4. `.content-container { margin-top: 70px }`

- 块级元素默认贴顶，导航栏高度约 `50 + 15 × 2 = 80px`，再加 70px 让登录卡片下移，避免视觉拥挤。
- 这个值只影响观感，不影响评分点。

### 5. `body` 里的 `height: 945; width: 1920;` 是无效声明

题目给的初始 CSS 中：

```css
body {
  height: 945;   /* ❌ 缺单位，整条声明被浏览器丢弃 */
  width: 1920;   /* ❌ 同上 */
}
```

- CSS 中除 `0` 和少数无单位属性外，长度必须带单位；缺单位时浏览器**直接忽略该条声明**。
- 所以这两个值实际上没生效，页面高度仍由内容撑开。
- 想让页面铺满一屏，正确写法是 `min-height: 100vh;`，但本题**没必要改**，背景图已经靠 `background-size: cover` 铺满。

## 七、常见坑

1. **改文件名、文件夹路径、类名、图片名**：题目明确规定不能改，判题会直接失败。
2. **`font-weight: 800px`**：字重没有单位，写了 `px` 整条声明无效，标题不会变粗。正确是 `font-weight: 800`。
3. **以为 `-20%` 是高度的 20%**：margin 百分比一律按包含块**宽度**算，这里是 `-90px`。
4. **`.content` 没定宽却写 `margin: 0 auto`**：宽度 `auto` 时没有剩余空间可分配，居中失效。
5. **给 `.content` 加 `overflow: hidden`**：本意是"裁剪"，结果把伸出卡片的头像裁掉。本题必须让溢出可见。
6. **只写 `border-radius: 50%` 不设宽高**：图片尺寸不固定，圆会变成椭圆。头像必须同时写 `width: 200px; height: 200px`。
7. **按钮只写 `border-color`**：颜色虽然对，但边框样式和粗细仍由浏览器默认值决定。用 `border: 1px solid #041c32` 更可控。
8. **漏写按钮 `font-size: 16px`**：题目明确要求，很多网上题解没写，照抄可能丢分。
9. **输入框不加 `text-align: center`**：占位文字会左对齐，和效果图不一致。
10. **把 450×600 和背景色拆到不同层级**：`.content-container` 和 `.content` 只能选一个作为卡片本体；拆开后判题取到的盒子可能对不上。
11. **用 `opacity` 做半透明背景**：`opacity` 作用于整个元素，文字和头像也会变透明；要用 `rgba()` 只让背景透明。
12. **给头像加 `display: block` 后用 `margin: 0 auto` 居中**：也能居中，但会改变行盒行为，负 margin 的效果和间距要重新调。用 `text-align: center` 更省事。

## 九、记忆口诀
