# 安装配置

装 Docker 前先定一件事：这台机器是开发机还是服务器。两条路装出来的东西差别不小，选错了后面会反复踩坑。

| 场景 | 推荐 | 原因 |
| --- | --- | --- |
| Windows / macOS 本地开发 | [[01-Docker 桌面版|Docker 桌面版]] | 开箱即用 |
| Linux 服务器 | [[02-Docker 引擎|Docker 引擎]] | 开销小，便于配置管理 |
| CI runner | 引擎版或 rootless | 非交互、可重复安装 |
| 公司不让用 Desktop | 引擎版、Podman、Colima | 授权或合规限制 |

装完先确认四件事：CLI 和 daemon 版本、存储驱动、cgroup 版本、能否拉镜像。

```bash
docker version
docker info -f '{{.ServerVersion}} | {{.Driver}} | cgroup v{{.CgroupVersion}}'
docker run --rm hello-world
docker context ls
```

`hello-world` 验证守护进程可达、镜像能拉、容器能起、网络正常。失败时按顺序查：`systemctl status docker` 看服务，`docker context ls` 看连的是不是本机，`journalctl -u docker -n 100` 看日志。

权限是最常见的坑。`sudo usermod -aG docker $USER` 之后必须重新登录或执行 `newgrp docker`，否则仍报 `permission denied while trying to connect to the Docker daemon socket`。docker 组等价于 root，多用户机器考虑 rootless，参见 [[02-用户与组|用户与组]]。

国内网络下给 daemon 配 registry mirror，或在桌面版设置里填代理；它只影响 pull，配置写进 `daemon.json` 后要重启。

> [!warning] 别在生产服务器装桌面版
> 桌面版带图形界面、自动更新和额外组件，授权也按商业使用收费。服务器按发行版仓库装引擎版，别直接 `curl | sh` 跑来源不明的脚本。

装好后从 [[00-基础|基础]] 开始。
