# 项目结构树解析

> [!abstract] 一句话
> 一个 Vue 3 项目（`npm create vue@latest` 脚手架，Vite 驱动）的目录不是随便摆的：==**根目录**放"构建/工具/入口页面"这类工程配置，**`public/`** 放"原样拷贝、不经处理"的静态文件，**`src/`** 才是我真正写代码的地方==。记住这条三层分工，整棵树就一眼看得懂。

---

## 一、三层解析

不管脚手架怎么变，Vue 3 项目都能切成这三块：

```text
my-vue-app/
│
├── 📦 根目录 ─────────── 工程配置区（给"构建工具"看的，不是给浏览器看的）
│   ├── index.html        唯一的 HTML 入口（SPA 只此一个）
│   ├── package.json      依赖清单 + 脚本命令
│   ├── vite.config.js    Vite 构建配置（别名、插件、代理）
│   ├── eslint / prettier 代码规范
│   └── jsconfig.json     编辑器路径提示（@ 别名）
│
├── 📁 public/ ────────── 静态资源区（原样拷贝，不参与打包）
│   └── favicon.ico       直接按 /favicon.ico 访问
│
└── 📁 src/ ───────────── 源码区（==真正写业务的地方==）
    ├── main.js           应用入口：创建并挂载 App
    ├── App.vue           根组件：所有页面的外壳
    ├── assets/           会被打包处理的资源（图片/CSS）
    ├── components/       可复用的公共组件（"零件"）
    ├── views/            路由页面组件（"整页"）
    ├── router/           路由表
    └── stores/           全局状态（Pinia）
```

> [!info] 一句话记三层
> **根目录 = 怎么构建**，**`public/` = 原样拷贝**，**`src/` = 我写的代码**。
> 分不清某个文件放哪时，先问："它是工程配置、原样静态文件，还是业务源码？"

---

## 二、整体结构树

下面是带注释的完整树，把不同类型项目里**可能出现的**文件都列上了，可以直接当"地图"用（标 `可选` 的按需出现，不必每个项目都有）：

```text
my-vue-app/
│
├── 📁 .vscode/                      ← 编辑器推荐配置（可选）
│   ├── extensions.json              ← 提示队友装哪些 VSCode 插件
│   └── settings.json                ← 工作区个性化设置（保存自动格式化等）
├── 📁 .github/                      ← GitHub 自动化（可选）
│   └── workflows/
│       └── ci.yml                   ← CI 流水线：构建 / 测试 / 部署
├── 📁 .husky/                       ← Git 钩子（可选）
│   └── pre-commit                   ← 提交前自动跑 lint / 格式化
│
├── 📁 public/                       ← 静态资源：原样拷贝到产物根目录
│   ├── favicon.ico                  ← 通过 /favicon.ico 访问
│   └── robots.txt                   ← 搜索引擎抓取规则
│
├── 📁 src/                          ← ★ 源码目录，几乎只动这里
│   ├── 📁 assets/                   ← 会被 Vite 打包的资源
│   │   ├── images/                  ← 图片（被打包 + 可加哈希）
│   │   ├── fonts/                   ← 字体文件
│   │   ├── styles/                  ← 全局样式（变量 / 混入）
│   │   │   └── variables.scss
│   │   ├── base.css                 ← 全局基础样式
│   │   ├── main.css                 ← 全局主样式
│   │   └── logo.svg
│   ├── 📁 components/               ← 可复用组件（零件）
│   │   ├── icons/                   ← 图标子组件
│   │   │   └── IconSupport.vue      ← 最小零件
│   │   ├── base/                    ← 无业务色彩的基础组件（按钮 / 输入框）
│   │   ├── common/                  ← 通用业务组件（弹窗 / 表格）
│   │   ├── HelloWorld.vue
│   │   └── TheWelcome.vue
│   ├── 📁 composables/              ← 组合式函数 useXxx()（可复用逻辑）
│   │   └── useCounter.js
│   ├── 📁 directives/               ← 自定义指令 v-xxx（可选）
│   │   └── focus.js
│   ├── 📁 layouts/                  ← 页面布局（导航 / 侧栏外壳，可选）
│   │   ├── DefaultLayout.vue
│   │   └── BlankLayout.vue
│   ├── 📁 plugins/                  ← 自定义插件（app.use 的封装，可选）
│   │   └── index.js
│   ├── 📁 router/                   ← 路由
│   │   └── index.js                 ← 路由表：路径 → 组件
│   ├── 📁 stores/                   ← Pinia 全局状态
│   │   ├── counter.js
│   │   └── user.js
│   ├── 📁 views/                    ← 路由页面（整页容器）
│   │   ├── HomeView.vue
│   │   └── AboutView.vue
│   ├── 📁 api/                      ← 接口封装（axios 实例 + 各业务模块，可选）
│   │   └── user.js
│   ├── 📁 utils/                    ← 纯工具函数（格式化 / 校验，无副作用）
│   │   └── format.js
│   ├── 📁 types/                    ← TypeScript 类型声明（TS 项目，可选）
│   │   └── global.d.ts
│   ├── 📁 locales/                  ← 国际化文案（vue-i18n，可选）
│   │   ├── zh-CN.json
│   │   └── en-US.json
│   ├── App.vue                      ← 根组件：所有页面的外壳
│   └── main.js                      ← ★ 应用入口（真正的起跑线）
│
├── 📁 tests/                        ← 测试（可选）
│   ├── unit/                        ← 单元测试（Vitest）
│   └── e2e/                         ← 端到端测试（Cypress / Playwright）
│
├── 📁 node_modules/                 ← 依赖（npm install 生成，不提交）
├── 📁 dist/                         ← 构建产物（npm run build 生成，不提交）
│
├── .browserslistrc                  ← 目标浏览器范围（可选）
├── .editorconfig                    ← 跨编辑器统一缩进 / 换行
├── .env                             ← 环境变量（所有环境共享）
├── .env.development                 ← 开发环境变量
├── .env.production                  ← 生产环境变量
├── .env.local                       ← 本地私有变量（不入库）
├── .gitattributes                   ← 行尾换行等 Git 处理规则
├── .gitignore                       ← 告诉 Git 别提交 node_modules / dist
├── .npmrc                           ← npm 源 / 安装行为（可选）
├── .prettierrc.json                 ← Prettier 格式化规则
├── eslint.config.js                 ← ESLint 扁平配置
├── env.d.ts                         ← .vue 模块 / 环境变量的类型声明（TS，可选）
├── index.html                       ← ★ 唯一的 HTML 入口
├── jsconfig.json                    ← 让编辑器认识 @ → src 别名（JS 项目）
├── LICENSE                          ← 开源协议（可选）
├── package.json                     ← 依赖 + scripts 命令
├── package-lock.json                ← 锁定依赖版本（pnpm / yarn 则为对应 lock 文件）
├── postcss.config.js                ← PostCSS 插件配置（autoprefixer 等，可选）
├── README.md                        ← 项目说明
├── tailwind.config.js               ← Tailwind CSS 配置（可选）
├── tsconfig.json                    ← TS 项目主配置（含 paths 别名）
├── tsconfig.node.json               ← 给 Vite 配置文件用的 TS 配置
├── uno.config.ts                    ← UnoCSS 配置（可选）
├── vite.config.js                   ← ★ Vite 构建配置
└── vitest.config.js                 ← 单元测试配置（可选）
```

> [!info] 怎么读这棵树
> - **★** = 理解全局的三把钥匙（入口 / 起跑线 / 构建配置）。
> - **`可选`** = 由项目类型决定：TS 项目才有 `tsconfig.json` / `types/` / `env.d.ts`，装了 UI 框架才有 `tailwind.config.js`，需要测试才有 `tests/`。
> - **不提交** = `node_modules/`、`dist/`、`.env.local` 这类生成物或私有配置，都进 `.gitignore`。

> [!tip] 三个 "★" 就是理解全局的钥匙
> `index.html`（进页面）→ `main.js`（起应用）→ `vite.config.js`（怎么构建）。
> 先把这三个读一遍，再回头看其他文件，就不晕了。

## 三、根目录文件解析

### 3.1 `index.html` —— 唯一的入口页面

```html
<!DOCTYPE html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <link rel="icon" href="/favicon.ico" />
    <title>My Vue App</title>
  </head>
  <body>
    <div id="app"></div>                      <!-- ① 挂载点：Vue 从这里接管 -->
    <script type="module" src="/src/main.js"></script> <!-- ② 入口脚本 -->
  </body>
</html>
```

> [!warning] 
> 一般不动这个文件，相当于一个接口文件

关键就两行：`<div id="app">`（挂载点）和 `<script src="/src/main.js">`（入口）。

### 3.2 `package.json` —— 依赖与命令

`package.json` 是 Node 项目的**身份证 + 说明书**：它记录"这个项目叫什么、怎么跑、装哪些包"。`npm install` 就是照着它还原出整个 `node_modules/`。

```jsonc
{
  // ── ① 项目身份 ──────────────────────────────
  "name": "my-vue-app",             // 项目名（小写、可带连字符）
  "version": "0.0.1",               // 语义化版本：主.次.修订
  "private": true,                  // 私有包：防止手滑 npm publish 发到公共仓库
  "type": "module",                 // 用 ESM 语法（import/export），而非 CommonJS

  // ── ② 命令脚本：npm run <key> 就能执行 ──────
  "scripts": {
    "dev": "vite",                  // 启动开发服务器（热更新 HMR）
    "build": "vite build",          // 打包生产产物 → dist/
    "preview": "vite preview",      // 本地预览打包结果（验证 build）
    "lint": "eslint . --fix",       // 代码规范检查并自动修复
    "format": "prettier --write .", // 代码格式化
    "test": "vitest",               // 跑单元测试（可选）
    "type-check": "vue-tsc --noEmit"// TS 类型检查（不产出文件，TS 项目）
  },

  // ── ③ 运行时依赖：打包进产物，浏览器/线上会用到 ──
  "dependencies": {
    "vue": "^3.4.0",                // 核心库
    "vue-router": "^4.3.0",         // 路由
    "pinia": "^2.1.0",              // 状态管理
    "axios": "^1.6.0",              // HTTP 请求（可选）
    "element-plus": "^2.5.0"        // UI 组件库（可选）
  },

  // ── ④ 开发依赖：只在开发/构建时用，不进产物 ──
  "devDependencies": {
    "vite": "^5.0.0",               // 构建工具
    "@vitejs/plugin-vue": "^5.0.0", // 让 Vite 认识 .vue 文件
    "eslint": "^8.57.0",            // 代码规范（可选）
    "prettier": "^3.2.0",           // 代码格式化（可选）
    "vitest": "^1.4.0",             // 单元测试（可选）
    "vue-tsc": "^2.0.0"             // TS 类型检查（TS 项目）
  },

  // ── ⑤ 包管理器与引用入口（可选）─────────────
  "packageManager": "pnpm@9.0.0",   // 锁定用哪个包管理器 + 版本（corepack）
  "engines": { "node": ">=18.0.0" },// 要求 Node 版本，不满足会报错
  "main": "dist/index.js",          // 作为"库"被 import 时的入口（应用项目通常不需要）
  "module": "dist/index.mjs",       // 库的 ESM 入口（可选）
  "browserslist": ["> 1%", "last 2 versions"] // 目标浏览器范围（可选，也可放 .browserslistrc）
}
```

> [!info] `dependencies` 还是 `devDependencies`？一句话判断
> **"打包后的线上代码还要不要它"**——要（`vue`、`axios`）放 `dependencies`；只在开发/构建/测试时用（`vite`、`eslint`、`vitest`）放 `devDependencies`。
> 装错地方通常也能跑，但会让 CI 安装变慢、依赖体积虚胖。

> [!note] 版本号前面的符号（语义化版本 semver）
> - `^3.4.0` —— **允许改次版本和修订版**，如升到 `3.9.1`，但不升到 `4.0.0`（不破坏 API）。
> - `~3.4.0` —— **只允许改修订版**，如升到 `3.4.9`，更保守。
> - `3.4.0` —— **锁定死**，只装这一个版本。
> - `*` / `latest` —— 永远装最新，**别用在生产项目**。
>
> 实际安装的精确版本记在 **lock 文件**里（`package-lock.json` / `pnpm-lock.yaml` / `yarn.lock`），它才是"团队所有人装到一模一样版本"的保证——**务必提交进 Git**。

> [!tip] `scripts` 里为什么不用写 `./node_modules/.bin/vite`
> `npm run` 会自动把 `node_modules/.bin/` 加进 PATH，所以直接写 `vite` 就能找到本地安装的命令。
> 顺带一提：`npx vite` 也能跑，但团队协作一律走 `npm run xxx`，保证命令口径统一。

### 3.3 `vite.config.js` —— 构建配置与别名

```js
import { fileURLToPath, URL } from 'node:url'
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],                       // ① 让 Vite 能编译 .vue
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url)) // ② @ → src
    }
  },
  server: {
    port: 5173,                           // ③ 开发端口
    proxy: { '/api': 'http://localhost:8080' } // ④ 跨域代理（对接后端）
  }
})
```

> [!note] `@` 别名是怎么"两头都认"的
> - **运行时/打包**：靠 `vite.config.js` 里的 `resolve.alias`。
> - **编辑器提示**：靠 `jsconfig.json`（JS）或 `tsconfig.json` 里的 `paths`。
> 两处都要配，只配一处会"能跑但没提示"或"有提示却跑不起来"。原理和 [[tsconfig.json]] 里说的路径别名坑完全一致。

### 3.4 `.gitignore` / 规范配置文件

```gitignore
node_modules    # 依赖，靠 npm install 还原，不入库
dist            # 打包产物，构建时重新生成
.DS_Store       # macOS 系统文件
*.local         # 本地私有配置
```

`eslint.config.js`（ESLint 扁平配置）、`.prettierrc.json`（格式化规则）都属于"团队规范"，与运行逻辑无关，可先跳过。

## 四、`public/` vs `src/assets/`：最容易搞混的一对

这是新手最常踩的坑，务必分清：

```text
             引用方式                     构建后
public/logo.png
  └── /logo.png（绝对路径）      ──▶   原样拷贝到 dist/logo.png
                                        （不做哈希、不做压缩）

src/assets/logo.png
  └── import logo from '@/assets/logo.png'  ──▶  打包进 dist/assets/logo-[hash].png
                                                   （走构建、可优化、文件名带哈希）
```

| 对比项 | `public/` | `src/assets/` |
| --- | --- | --- |
| 是否参与打包 | ❌ 原样拷贝 | ✅ 走构建流程 |
| 引用方式 | 绝对路径 `/xx.png` | `import` 或 `@/assets/xx.png` |
| 文件名哈希 | 无 | 有（利于缓存） |
| 会被压缩/优化 | 否 | 是 |
| 适合放什么 | `favicon.ico`、`robots.txt`、第三方 SDK | 组件里用到的图片、样式 |

> [!success] 一句话选择
> **"要被构建处理、组件里 import 的" → `src/assets/`；"必须保持文件名不变、按固定 URL 访问的" → `public/`。**
> 拿不准时优先放 `assets`，除非它有"固定对外地址"的需求。

## 五、`src/` 内部：各文件夹的职责

### 5.1 `main.js` —— 应用入口（真正的起跑线）

```js
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import App from './App.vue'
import router from './router'
import '@/assets/main.css'          // 全局样式

const app = createApp(App)

app.use(createPinia())              // ① 装状态管理
app.use(router)                     // ② 装路由
app.mount('#app')                   // ③ 挂到 index.html 的 #app 上
```

> [!info] 它做了三件事
> **创建应用 → 装插件（Pinia / Router）→ 挂载到 `#app`。**
> 全局只执行一次，是"从 HTML 到 Vue 世界"的交接点。

### 5.2 `App.vue` —— 根组件（页面外壳）

```vue
<script setup>
import { RouterView } from 'vue-router'
</script>

<template>
  <header>导航栏（所有页面共享）</header>
  <RouterView />        <!-- ★ 路由匹配到的页面在这里"长出来" -->
  <footer>页脚</footer>
</template>
```

`App.vue` 是**所有页面的公共外壳**：导航栏、页脚放这里，变的只有中间 `<RouterView />` 那块。

### 5.3 `components/` vs `views/` —— 零件 vs 整页

| 目录 | 角色 | 是否被路由指向 | 例子 |
| --- | --- | --- | --- |
| `views/` | **页面**（整页） | ✅ 路由表里指向它 | `HomeView.vue` |
| `components/` | **零件**（可复用） | ❌ 被页面/组件嵌套用 | `HelloWorld.vue` |

```text
views/HomeView.vue  ──引用──▶  components/TheWelcome.vue  ──引用──▶  components/icons/IconSupport.vue
   （整页）                        （区块组件）                          （最小零件）
```

> [!tip] 命名惯例
> 页面组件常以 `View` 结尾（`HomeView`、`AboutView`），一眼能看出"这是路由页面"。普通组件则用大驼峰（`HelloWorld`、`TheWelcome`）。

### 5.4 `router/index.js` —— 路由表

```js
import { createRouter, createWebHistory } from 'vue-router'
import HomeView from '@/views/HomeView.vue'

const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    { path: '/',      name: 'home',  component: HomeView },
    { path: '/about', name: 'about',
      component: () => import('@/views/AboutView.vue') }  // 懒加载
  ]
})

export default router
```

> [!note] 懒加载 `() => import(...)`
> `AboutView` 用**箭头函数动态导入**：只有真的访问 `/about` 时才下载这个组件，首屏更小、更快。首页 `HomeView` 直接静态导入，因为一进来就要用。

### 5.5 `stores/counter.js` —— Pinia 全局状态

```js
import { defineStore } from 'pinia'
import { ref } from 'vue'

export const useCounterStore = defineStore('counter', () => {
  const count = ref(0)                     // 状态
  const increment = () => count.value++    // 动作
  return { count, increment }              // 对外暴露
})
```

> [!info] 什么时候才需要 `stores/`
> 只有**多个组件要共享同一份数据**（比如登录用户、购物车）时才用。
> 单个组件自己用的数据，写在组件里就行，别硬塞进 store。

### 5.6 `assets/` 内的 CSS

`base.css` / `main.css` 是全局样式，在 `main.js` 里 import 一次即可作用于全站。组件专属样式则写在各自 `<style scoped>` 里。

## 六、把整条链路串起来

从"打开浏览器"到"看到页面"，数据是这样流动的：

```text
浏览器请求 /
      │
      ▼
index.html            ← Vite 返回唯一的 HTML 入口
      │  加载 /src/main.js
      ▼
main.js               ← createApp + use(router/pinia) + mount('#app')
      │  挂载到 <div id="app">
      ▼
App.vue               ← 渲染外壳（导航/页脚）
      │  遇到 <RouterView />
      ▼
router/index.js       ← 按当前 URL 找到对应页面组件
      │
      ▼
views/HomeView.vue    ← 渲染整页
      │  嵌套使用
      ▼
components/*.vue      ← 拼出最终界面
```

> [!quote] 一句话记忆
> **`index.html` 给一个挂载点，`main.js` 把 Vue 装上去，`App.vue` 当外壳，`RouterView` 按 URL 换 `views`，`views` 再用 `components` 拼页面。**

## 七、约定与规范速记

- **单文件组件（SFC）**：一个 `.vue` 文件 = `<script setup>` + `<template>` + `<style scoped>` 三块。
- **组件命名**：多单词大驼峰（`UserCard.vue`），避免单词（`Card.vue`）以免和 HTML 标签冲突。
- **导入时用 `@/`**：`import X from '@/components/X.vue'`，别写一长串 `../../`。
- **`node_modules/` 与 `dist/` 永不提交**，靠 `npm install` / `npm run build` 还原。
- **`public/` 保持精简**：能被构建处理的都放 `src/assets/`。

## 八、常见问题

> [!question] 为什么改了代码，页面自动就变了？
> 因为 `npm run dev` 跑的是 **Vite 开发服务器**，带 HMR（热模块替换）。改动只重编译受影响的模块并即时替换，不刷新整页。生产环境则靠 `npm run build` 出静态文件。

> [!question] 图片放 `public/` 还是 `src/assets/`？
> 看引用方式：要被 `import`、希望走打包优化和哈希 → `assets/`；要通过固定路径 `/xx` 访问、文件名不能变 → `public/`。详见第四节。

> [!question] `@/` 别名在编辑器里没提示、但能跑（或反过来）？
> 是"两边配置只配了一半"。打包侧在 `vite.config.js` 的 `resolve.alias`，编辑器侧在 `jsconfig.json` / `tsconfig.json` 的 `paths`，两处都要有。道理同 [[tsconfig.json]] 的路径别名坑。

> [!question] `components/` 和 `views/` 到底怎么分？
> 被路由表直接指向的"整页"放 `views/`；被别处嵌套复用的"零件"放 `components/`。分不清时问："它会作为路由的 `component` 出现吗？"

> [!question] 为什么只有一个 `index.html`，没有 about.html？
> Vue 是**单页应用（SPA）**：整站共用一份 HTML，路由切换是前端换组件，不请求新页面。多 HTML 是多页应用（MPA）的做法。

> [!question] `npm run build` 后多出来一个 `dist/`，要提交到 Git 吗？
> 不要。`dist/` 是构建产物，应写进 `.gitignore`。部署时由 CI 或你本地重新构建生成。
