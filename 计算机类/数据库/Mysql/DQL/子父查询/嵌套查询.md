# 嵌套查询 —— 子查询入门与分类

> [!abstract] 一句话
> 嵌套查询（子查询）就是==**一条 `SELECT` 里再套一条 `SELECT`**==：外层的语句把内层的结果**当成一个值 / 一组值 / 一张表**来用。
> 它比 `JOIN` 更贴近"先算出一个中间答案、再拿它做条件"的思维，但==**返回形态（单值 / 一列 / 一行 / 一张表）必须和用它的地方对得上**==，对不上就报错。

> [!info] 与其它笔记的分工
> 本篇讲**子查询的全景与分类**（按位置、按返回形态、按相关与否），重点在==**非相关子查询**==。
> - 引用了外层列、需要逐行重算的写法，见 [[相关子查询]]。
> - `NOT IN` 的 NULL 陷阱在 [[Where|DML/Where]] 已详述，本篇给最小必要版本。
> - 派生表当表用见 [[From|DML/From]]；`UPDATE/DELETE` 里子查询引用目标表的 `1093` 报错见 [[计算机类/数据库/Mysql/DML/Update|DML/Update]]。

---

> [!example] 本篇示例数据
> 与 [[相关子查询]]、以及 `连接查询/` 各篇**共用同一套 `dept` / `emp` 表**。
> 两处"不匹配"仍然有用：**财务部没人**（用来演示 `NOT IN` / `NOT EXISTS` 找缺失）、**孙七没部门**（`dept_id` 为 NULL，是 NULL 陷阱的导火索）。

```sql
CREATE TABLE dept (
    dept_id   INT PRIMARY KEY,
    dept_name VARCHAR(20)
);

CREATE TABLE emp (
    emp_id   INT PRIMARY KEY,
    emp_name VARCHAR(20),
    dept_id  INT,              -- 允许 NULL：孙七没有部门
    salary   DECIMAL(10,2)
);

INSERT INTO dept VALUES (1001, '研发部'), (1002, '销售部'), (1003, '财务部');

INSERT INTO emp VALUES (1, '张三', 1001, 12000),
                       (2, '李四', 1001, 15000),
                       (3, '王五', 1002,  9000),
                       (4, '赵六', 1002,  8500),
                       (5, '孙七', NULL,  7000);
```

```
-- dept（3 行）                       -- emp（5 行）
dept_id | dept_name                 emp_id | emp_name | dept_id | salary
--------+----------                 -------+----------+---------+--------
   1001 | 研发部                        1 | 张三     |    1001 |  12000
   1002 | 销售部                        2 | 李四     |    1001 |  15000
   1003 | 财务部  <-- 没人               3 | 王五     |    1002 |   9000
                                      4 | 赵六     |    1002 |   8500
                                      5 | 孙七     |    NULL |   7000  <-- 没部门
```

## 一、子查询的四类分法

看一条子查询，只需问三个问题，就能把它归位：

| 分类维度 | 取值 | 说明 |
| --- | --- | --- |
| **出现在哪** | `WHERE` / `HAVING` / `SELECT` / `FROM` | 决定它当"值 / 条件 / 表"用 |
| **返回什么** | 标量（1 值）· 一行 · 一列 · 一张表 | **必须和用它的位置匹配** |
| **能否独立跑** | 非相关（能单独运行）· 相关（依赖外层行） | 相关见 [[相关子查询]] |

> [!important] "返回几行几列"决定它能怎么用
> | 子查询返回 | 只能用在 | 例子 |
> | --- | --- | --- |
> | **单值**（1 行 1 列） | `=、>、<` 等标量比较、`SELECT` 列表 | `salary > (SELECT AVG(salary) ...)` |
> | **一列多行** | `IN` / `NOT IN` / `ANY` / `ALL` / `EXISTS` | `dept_id IN (SELECT dept_id ...)` |
> | **一行多列** | 行比较 `(a,b) IN (...)` | `(dept_id,salary) IN (...)` |
> | **多行多列（一张表）** | **只能放 `FROM`**（派生表，必须起别名） | `FROM (SELECT ...) t` |

## 二、标量子查询：当一个"值"用

括号里的子查询**只返回一个值**，就能像常量一样参与比较：

```sql
-- 找出工资高于公司平均工资的人
SELECT emp_name, salary
FROM emp
WHERE salary > (SELECT AVG(salary) FROM emp);
-- 全表平均 = (12000+15000+9000+8500+7000) / 5 = 10300
```

```
emp_name | salary
---------+--------
张三     |  12000
李四     |  15000
```

> [!warning] 标量子查询必须**最多返回一行一列**
> ```sql
> SELECT emp_name FROM emp WHERE salary > (SELECT salary FROM emp);
> -- ERROR 1242 (21000): Subquery returns more than 1 row
> ```
> 内层一旦返回多行，`>` 就不知道该跟哪个比。要"多行"就改用 `IN` / `ANY`。
>
> 反过来，若内层返回**零行**，标量结果是 `NULL`，于是外层条件变成 `salary > NULL` → 恒为 `UNKNOWN` → **一行都不返回**（不是报错，是静默为空）。

## 三、列子查询与 `IN` / `NOT IN`

子查询返回**一列多行**时，最常用的是 `IN`（是否属于这个集合）：

```sql
-- 找出"研发部"的所有员工
SELECT emp_name, salary
FROM emp
WHERE dept_id IN (SELECT dept_id FROM dept WHERE dept_name = '研发部');
```

```
emp_name | salary
---------+--------
张三     |  12000
李四     |  15000
```

`IN` 等价于"等于集合里的**任意一个**"：`x IN (a,b,c)` ≡ `x = a OR x = b OR x = c`。

### 3.1 ⚠️ `NOT IN` 的 NULL 陷阱（高频事故）

想找"**没有任何员工的部门**"，直觉会写 `NOT IN`：

```sql
-- ❌ 想找没员工的部门，结果 —— 空！
SELECT dept_name FROM dept
WHERE dept_id NOT IN (SELECT dept_id FROM emp);
-- Empty set
```

**为什么空？** 因为子查询返回的集合里**含 NULL**（孙七的 `dept_id` 是 NULL）：

```
NOT IN 展开后（对 1003 财务部）：
1003 <> 1001 AND 1003 <> 1002 AND 1003 <> NULL
 = TRUE   AND  TRUE    AND  UNKNOWN
 = UNKNOWN          ← 不是 TRUE，于是"不满足"，被排除
```

> [!danger] `NOT IN (含 NULL 的集合)` 恒为空
> 只要子查询结果里**有一个 NULL**，`NOT IN` 对**所有行**都会算出 `UNKNOWN`（而不是 `TRUE`），整条语句**一行都查不出来**——不报错，静默空集，极其难查。

两种修法：

```sql
-- ✅ 方案一：把 NULL 过滤掉（子查询里加 IS NOT NULL）
SELECT dept_name FROM dept
WHERE dept_id NOT IN (SELECT dept_id FROM emp WHERE dept_id IS NOT NULL);
-- → 财务部

-- ✅ 方案二：改用 NOT EXISTS（NULL 天然安全，推荐）
SELECT dept_name FROM dept d
WHERE NOT EXISTS (SELECT 1 FROM emp e WHERE e.dept_id = d.dept_id);
-- → 财务部
```

> [!tip] 结论：见到 `NOT IN` 先问一句"子查询那列会不会有 NULL"
> 会有 NULL → 要么加 `IS NOT NULL`，要么直接换 `NOT EXISTS`。`IN`（正向）不受影响，**只有 `NOT IN` 怕 NULL**。

## 四、行子查询：多列一起比

把多个列**打包成一个"行值"**再比，语法是 `(列1, 列2) 运算符 (子查询)`：

```sql
-- 找出和"张三"在同一部门、且工资也相同的人（用行值精确匹配）
SELECT emp_name, dept_id, salary
FROM emp
WHERE (dept_id, salary) IN (SELECT dept_id, salary FROM emp WHERE emp_name = '张三');
-- → 张三自己
```

行比较也支持**字典序**比较（先比第一列，相等再比第二列）：

```sql
-- 找出"部门号/工资"排在张三之后的人（字典序 >）
SELECT emp_name, dept_id, salary
FROM emp
WHERE (dept_id, salary) > (SELECT dept_id, salary FROM emp WHERE emp_name = '张三');
```

> [!note] 行子查询的价值
> 它把"多列同时相等/大小"合成一次比较，省掉 `a=.. AND b=..`。**MySQL 对行值比较的索引利用有限**，大数据量下别指望它提速。

## 五、表子查询 / 派生表：子查询当"表"用

返回**多行多列**的子查询不能参与标量比较，但可以放进 `FROM`，像一张临时表一样被外层查询：

```sql
-- 每个部门的平均工资，再筛选出平均 > 9000 的
SELECT t.dept_id, t.avg_sal
FROM (
    SELECT dept_id, AVG(salary) AS avg_sal
    FROM emp
    GROUP BY dept_id
) AS t                      -- 派生表必须起别名！
WHERE t.avg_sal > 9000;
```

```
dept_id | avg_sal
--------+--------
   1001 |   13500     <-- 研发：(12000+15000)/2
```
（销售 8750 < 9000 被筛掉；孙七那组 `dept_id` 为 NULL，平均值 7000 也被筛掉。）

> [!danger] 派生表**必须**有别名
> ```sql
> SELECT * FROM (SELECT 1);   -- ERROR 1248: Every derived table must have its own alias
> SELECT * FROM (SELECT 1) t; -- ✅
> ```
> MySQL 里派生表会**物化成临时表**（8.0 起优化器可能合并/消解），8.0.14+ 还支持在派生表里用 `LATERAL` 引用前面的表。

## 六、`SELECT` 列表里的标量子查询

子查询也能出现在 `SELECT` 的列里——**为每一行取一个"附加值"**：

```sql
-- 每个员工后面附上他的部门名（等价于 emp LEFT JOIN dept）
SELECT e.emp_name, e.salary,
       (SELECT d.dept_name FROM dept d WHERE d.dept_id = e.dept_id) AS dept_name
FROM emp e;
```

```
emp_name | salary | dept_name
---------+--------+----------
张三     |  12000 | 研发部
李四     |  15000 | 研发部
王五     |   9000 | 销售部
赵六     |   8500 | 销售部
孙七     |   7000 | NULL       <-- 没部门 → 标量子查询返回 0 行 → NULL
```

> [!warning] `SELECT` 里的标量子查询是**逐行执行**的
> 上面的写法，外层每行都要单独跑一次内层子查询——这正是**相关子查询**的特征（内层引用了 `e.dept_id`），详见 [[相关子查询]]。
> 这类"取关联列"的需求，**通常 `LEFT JOIN` 更快也更清晰**（[[LEFT JOIN]]）。

## 七、量词：`ANY` / `ALL` / `SOME`

`ANY` / `SOME`（同义）和 `ALL` 用来把标量比较"推广到集合"：

```sql
-- > ANY：大于集合中任意一个 → 等价于 > MIN(集合)
SELECT emp_name, salary FROM emp
WHERE salary > ANY (SELECT salary FROM emp WHERE dept_id = 1001);   -- dept 1001 = {12000,15000}

-- > ALL：大于集合中每一个 → 等价于 > MAX(集合)
SELECT emp_name, salary FROM emp
WHERE salary > ALL (SELECT salary FROM emp WHERE dept_id = 1001);
```

等价转换表：

| 写法 | 等价于 | `emp`（对比研发部 {12000,15000}）结果 |
| --- | --- | --- |
| `x > ANY (S)` | `x > MIN(S)` | `salary > 12000` → 李四 |
| `x > ALL (S)` | `x > MAX(S)` | `salary > 15000` → 无 |
| `x < ANY (S)` | `x < MAX(S)` | `salary < 15000` → 张三/王五/赵六/孙七 |
| `x < ALL (S)` | `x < MIN(S)` | `salary < 12000` → 王五/赵六/孙七 |

> [!tip] 记法：`ANY` 看**最松**的那端，`ALL` 看**最严**的那端
> `> ANY` 只要比**最小值**大就行（松）；`> ALL` 要比**最大值**还大（严）。
> `SOME` 是 `ANY` 的同义词，两者完全等价，MySQL 都支持。

## 八、`EXISTS` / `NOT EXISTS`：只问"有没有"

`EXISTS (子查询)` 不关心子查询查出什么，**只关心有没有行**：有行 → `TRUE`，无行 → `FALSE`。

```sql
-- 找出"至少有一名员工"的部门
SELECT dept_name FROM dept d
WHERE EXISTS (SELECT 1 FROM emp e WHERE e.dept_id = d.dept_id);
```

```
dept_name
---------
研发部
销售部
```

> [!note] `EXISTS` 里的内层 `SELECT` 写什么无所谓
> `SELECT 1`、`SELECT *`、`SELECT NULL` 效果一样——`EXISTS` 一旦发现第一行就短路返回，**根本不读 `SELECT` 列表里的东西**。

`EXISTS` 的内层几乎总要**引用外层的列**（`e.dept_id = d.dept_id`）才能建立关联，所以它天然属于**相关子查询**——这正是下一篇 [[相关子查询]] 的主题。

> [!tip] `IN` 还是 `EXISTS`？
> - `IN`：先把子查询**整体算出来**，再做集合成员判断；子查询结果**小**时更快、更直观。
> - `EXISTS`：**逐行**探测、命中即短路；外层行少、子查询结果大时往往更快，且**不受 NULL 影响**。
> 二者在多数场景由优化器改写成等价形态，**优先按语义清晰度选**：集合成员用 `IN`，存在性判断用 `EXISTS`。

## 九、子查询 vs `JOIN`

很多子查询能改写成连接，二者不是谁取代谁：

| 场景 | 更推荐 | 原因 |
| --- | --- | --- |
| 只要"某列的值"作条件 | 子查询 | `WHERE x IN (SELECT ...)` 一眼看懂意图 |
| 要"取另一张表的列" | `JOIN` | 子查询做不到"取多列"，得靠 `JOIN` |
| 存在性判断 | `EXISTS` | 短路、NULL 安全 |
| 反连接（找缺失） | `NOT EXISTS` / `LEFT JOIN + IS NULL` | 都行，见 [[LEFT JOIN]] |
| 需要聚合结果当条件 | 子查询（`HAVING` 里） | 聚合值只能先算出来 |

> [!note] 优化器常常把它们改写成同一种计划
> 简单的 `IN` / `EXISTS` 子查询，MySQL 优化器可能**自动转成半连接（semi-join）**，与手写 `JOIN` 的执行计划一致。所以**先写清楚，性能交给 `EXPLAIN`**。

## 十、常见错误合集

> [!failure] 位置与返回形态不匹配
> - 标量位置（`>`、`=`）放了多行子查询 → `ERROR 1242 Subquery returns more than 1 row`
> - 把多列子查询直接放标量位置 → `ERROR 1241 Operand should contain 1 column(s)`
> - 派生表忘写别名 → `ERROR 1248 Every derived table must have its own alias`

> [!failure] `NOT IN` 撞上 NULL，静默空集
> 见第三章——子查询集合里有 NULL，`NOT IN` 一行都返回不了。加 `IS NOT NULL` 或用 `NOT EXISTS`。

> [!failure] 标量子查询返回 0 行 → `NULL` 而不是报错
> `WHERE salary > (子查询查不到)` 会静默变成"无结果"。用 `IFNULL` 兜底或改写。

> [!failure] 在 `UPDATE` / `DELETE` 的子查询里引用目标表
> `ERROR 1093 You can't specify target table ... for update`。绕法：套一层派生表物化，或改成 `JOIN`。详见 [[计算机类/数据库/Mysql/DML/Update|DML/Update]]。

> [!failure] `SELECT` 列表里塞相关标量子查询导致逐行执行
> 看着像"加一列"，实则是**每行跑一次子查询**，数据量大时慢得离谱。这种"取关联列"改用 `JOIN`。

## 十一、速查表

| 需求 | 写法 | 子查询返回 |
| --- | --- | --- |
| 和一个值比较 | `WHERE x > (SELECT AVG(..) ...)` | 单值 |
| 属于某集合 | `WHERE x IN (SELECT .. )` | 一列多行 |
| 不属于某集合 | `WHERE x NOT IN (SELECT .. WHERE .. IS NOT NULL)` | 一列多行（防 NULL） |
| 多列打包比较 | `WHERE (a,b) IN (SELECT a,b ..)` | 一行/多行多列 |
| 当表用 | `FROM (SELECT .. ) AS t` | 多行多列（**必须别名**） |
| 取附加值 | `SELECT (SELECT .. ) AS col` | 单值（**逐行执行**） |
| 大于任意/所有 | `> ANY(..)` = `> MIN`；`> ALL(..)` = `> MAX` | 一列多行 |
| 存在性判断 | `WHERE EXISTS (SELECT 1 .. )` | 有无行 |

> [!question] 自测三连
> 1. 标量子查询返回了 3 行，用 `=` 比较会怎样？
> 2. `WHERE x NOT IN (SELECT ..)` 结果为空，最可能的原因是什么？怎么修？
> 3. 派生表为什么必须起别名？多列子查询能放 `WHERE x = (...)` 吗？

---

> [!quote] 一句话记忆
> **子查询按"返回形态"决定用法：单值用于比较、一列多行用于 `IN`/`ANY`/`ALL`、多行多列只能放 `FROM`；`NOT IN` 最怕子查询里有 NULL（改 `NOT EXISTS`），`SELECT` 列表里的子查询是逐行执行的。**
