# 构建镜像

会跑别人的镜像之后，下一步是把自己的应用做成镜像。`docker build` 读一份 Dockerfile，把构建上下文发给 builder，逐条执行指令，每条产生一个层，最后打上标签。

```bash
docker build -t my-app:1.0 .
docker run --rm -p 3000:3000 my-app:1.0
```

末尾的 `.` 是构建上下文，不是 Dockerfile 路径。`COPY` 和 `ADD` 只能读上下文里的文件，上下文太大会拖慢每次构建，所以 `.dockerignore` 和 Dockerfile 一样重要。

这一阶段三件事决定镜像质量：

- [[01-Dockerfile|Dockerfile]]：指令怎么写，构建上下文、多阶段、启动命令
- [[02-层缓存|层缓存]]：怎么让改一行代码后的重建从几分钟降到几秒
- [[03-镜像大小与安全|镜像大小与安全]]：基础镜像怎么选，非 root、密钥、漏洞扫描

顺序上建议先写一个能跑通的 Dockerfile，再调整指令顺序吃满缓存，最后做瘦身和安全加固。反过来先追求“最小镜像”，很容易卡在调试上，连个 shell 都没有。

构建慢的时候先分清是上下文传输、依赖下载还是某条 `RUN` 本身慢。`docker build --progress=plain` 会打印每一步的耗时，比盯着进度条猜有用。

一个能用的镜像，先满足“构建成功、能跑、重启后行为一致”，再谈优化。镜像的标签规范、推送和分发在 [[00-镜像仓库|镜像仓库]] 里讲。
