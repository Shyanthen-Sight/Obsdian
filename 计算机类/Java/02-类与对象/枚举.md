# 概念

Java ==枚举是一个特殊的类==，一般表示==一组常量==，比如一年的 4 个季节，一年的 12 个月份，一个星期的 7 天，方向有东南西北等。

Java 枚举类使用 ==enum 关键字来定义==，各个常量使用==逗号分割==。

```java
enum Color 
{ 
    RED, GREEN, BLUE; 
} 
```

以上枚举类 Color 颜色常量有 RED, GREEN, BLUE，分别表示红色，绿色，蓝色。

# 1. 基本使用

## 1.1 定义位置

枚举可以定义成独立的顶层类型，也可以定义在某个类内部（此时它就是一个==静态嵌套类型==，见 [[嵌套类]]）。

```java
// 方式一：独立的枚举类型
enum Color 
{ 
    RED, GREEN, BLUE; 
} 
  
public class Test 
{ 
    public static void main(String[] args) 
    { 
        Color c1 = Color.RED; 
        System.out.println(c1); 
    } 
}
```

```java
// 方式二：定义在类内部
public class Test 
{ 
    enum Color 
    { 
        RED, GREEN, BLUE; 
    } 
  
    public static void main(String[] args) 
    { 
        Color c1 = Color.RED; 
        System.out.println(c1); 
    } 
}
```

两个执行结果均为

```
RED
```

## 1.2 遍历枚举元素

`values()` 返回一个包含全部常量的数组（按声明顺序），可以直接用增强 for 遍历：

```java
enum Color 
{ 
    RED, GREEN, BLUE; 
} 

public class MyClass { 
    public static void main(String[] args) { 
        for (Color myVar : Color.values()) {
            System.out.println(myVar);
        }
    } 
}
```

输出结果为

```
RED
GREEN
BLUE
```

# 2. 枚举的本质

每个枚举都是通过 Class 在内部实现的，且所有的==枚举值都是 public static final== 的。上面的 Color 大致等价于：

```java
final class Color extends java.lang.Enum<Color> {

    public static final Color RED   = new Color("RED", 0);
    public static final Color GREEN = new Color("GREEN", 1);
    public static final Color BLUE  = new Color("BLUE", 2);

    private static final Color[] $VALUES = { RED, GREEN, BLUE };

    private Color(String name, int ordinal) {
        super(name, ordinal);
    }

    public static Color[] values() {
        return $VALUES.clone();
    }

    public static Color valueOf(String name) {
        // 按名字查找，找不到抛 IllegalArgumentException
        ...
    }
}
```

由此可以推出几条硬性规则：

| 特性 | 说明 |
| --- | --- |
| 隐式父类 | 枚举==隐式继承 `java.lang.Enum<E>`==，所以不能再 `extends` 其他类 |
| 隐式 final | 枚举类默认是 `final` 的，不能被继承（含"常量特定类体"时除外，见第 7 节） |
| 构造方法 | ==只能是 `private` 或默认（包级）访问==，不能写 `public` / `protected`，外部也不能 `new` |
| 常量 | 每个常量都是 `public static final` 字段，类型就是该枚举类型本身 |
| 实例创建时机 | 所有常量在==类初始化时==一次性创建，由 JVM 保证线程安全 |
| 可实现接口 | 可以 `implements` 一个或多个接口（见第 6 节） |
| 泛型 | 枚举==不能声明类型参数==，`enum Foo<T>` 编译报错 |

# 3. 常用方法

`java.lang.Enum` 已经为每个枚举类型提供了下面这些方法：

| 方法 | 作用 | 示例结果 |
| --- | --- | --- |
| `values()` | 返回所有常量组成的数组（按声明顺序），每次返回==新数组== | `[RED, GREEN, BLUE]` |
| `valueOf(String name)` | 按名字取常量，==找不到抛 `IllegalArgumentException`==，`null` 抛 `NullPointerException` | `Color.valueOf("RED")` → `RED` |
| `name()` | 返回常量名，==final 方法，不能重写== | `"RED"` |
| `ordinal()` | 返回声明顺序的序号，==从 0 开始== | `RED` → `0` |
| `compareTo(E o)` | 按 `ordinal()` 比较大小 | `RED.compareTo(BLUE)` → `-2` |
| `toString()` | 默认返回 `name()`，==可以重写== | `"RED"` |
| `equals()` / `hashCode()` | 由 `Enum` 提供 ==final 实现==，等同于按引用比较 | — |
| `getDeclaringClass()` | 返回常量所属的枚举类型（用于区分常量类体产生的子类） | `Color.class` |

```java
public class EnumMethodDemo {
    public static void main(String[] args) {
        Color c = Color.valueOf("GREEN");
        System.out.println(c.name());      // GREEN
        System.out.println(c.ordinal());   // 1
        System.out.println(c.toString());  // GREEN

        System.out.println(Color.RED.compareTo(Color.BLUE)); // -2
        System.out.println(Color.RED == Color.valueOf("RED")); // true
    }
}
```

> [!warning] `name()` 与 `toString()` 的区别
> `name()` 是 final 的，永远等于源码里写的常量名，反射、`valueOf` 都依赖它；`toString()` 可以重写用来做展示。不要把 `toString()` 的结果再拿去 `valueOf`。

> [!warning] `ordinal()` 不是业务编号
> `ordinal()` 只反映常量在源码里的声明顺序，插一个常量、调整一下顺序，所有数字就全变了。需要业务编号时，自己加字段（见第 5 节），也不要把它持久化到数据库或用于网络传输。

另外还有一个静态工具方法 `Enum.valueOf(Class<T>, String)`：

```java
Color c = Enum.valueOf(Color.class, "RED");
```

# 4. switch 与比较

## 4.1 switch

枚举是 `switch` 最典型的搭档，==case 标签通常只写常量名，不带枚举类名前缀==：

```java
Color c = Color.RED;

switch (c) {
    case RED:
        System.out.println("红色");
        break;
    case GREEN:
        System.out.println("绿色");
        break;
    case BLUE:
        System.out.println("蓝色");
        break;
}
```

> [!note] 版本差异
> 在 Java 21 之前，写成 `case Color.RED:` 会编译报错（`an enum switch case label must be the unqualified name of an enumeration constant`）；从 Java 21 起（JEP 441）允许带限定名。为了兼容老版本，统一写 `case RED:` 最稳妥。

## 4.2 比较方式

枚举实例是==全局唯一==的，所以：

* 判断相等用 ==`==`== 即可，不需要 `equals()`（`Enum.equals` 本身就是按引用比较）；
* 排序用 `compareTo()`（按 `ordinal()`），或者显式传入 `Comparator`；
* `Enum` 已经实现了 `Comparable`，可以直接丢进 `TreeSet`、`Collections.sort()`。

```java
Color[] colors = { Color.BLUE, Color.RED, Color.GREEN };
java.util.Arrays.sort(colors);
System.out.println(java.util.Arrays.toString(colors)); // [RED, GREEN, BLUE]
```

# 5. 带字段、构造方法和方法的枚举

枚举不只是"一堆名字"，它既然是类，就可以有==成员变量、构造方法、普通方法和静态方法==。常量声明时把参数写在括号里，就会调用对应的构造方法。

```java
import java.util.HashMap;
import java.util.Map;

enum OrderStatus {
    PENDING(0, "待支付"),
    PAID(1, "已支付"),
    SHIPPED(2, "已发货"),
    CANCELLED(9, "已取消");

    private final int code;        // 业务编号
    private final String desc;     // 中文描述

    // 枚举的构造方法只能是 private 或默认（包级）访问
    OrderStatus(int code, String desc) {
        this.code = code;
        this.desc = desc;
    }

    public int getCode() { return code; }
    public String getDesc() { return desc; }

    // 反向查找：编号 -> 枚举
    private static final Map<Integer, OrderStatus> BY_CODE = new HashMap<>();

    static {
        for (OrderStatus s : values()) {
            BY_CODE.put(s.code, s);
        }
    }

    public static OrderStatus of(int code) {
        OrderStatus s = BY_CODE.get(code);
        if (s == null) {
            throw new IllegalArgumentException("未知状态码: " + code);
        }
        return s;
    }
}
```

```java
public class Demo {
    public static void main(String[] args) {
        OrderStatus s = OrderStatus.of(1);
        System.out.println(s);              // PAID（默认 toString 输出常量名）
        System.out.println(s.getDesc());    // 已支付

        for (OrderStatus status : OrderStatus.values()) {
            System.out.println(status.getCode() + " -> " + status.getDesc());
        }
    }
}
```

输出：

```
PAID
已支付
0 -> 待支付
1 -> 已支付
2 -> 已发货
9 -> 已取消
```

写这种枚举时有几个语法约束：

1. ==常量列表必须放在最前面==，并且当后面还有成员时，==列表末尾的分号不能省==（只有常量时可以省略）；
2. 构造方法==不能是 `public` / `protected`==，只能是 `private` 或默认（包级）访问；
3. 常量的参数按声明顺序传给构造方法，一个常量只能调用一次构造方法；
4. ==构造方法里不能引用枚举自己的静态字段==（此时静态字段还没初始化），但可以调用静态方法、访问常量变量。

# 6. 枚举实现接口

枚举不能继承类，但==可以实现接口==，这样就能在需要多态的地方当作接口使用：

```java
interface Describable {
    String describe();
}

enum Level implements Describable {
    LOW, MID, HIGH;

    @Override
    public String describe() {
        return "等级: " + name();
    }
}

public class Demo {
    public static void main(String[] args) {
        java.util.List<Describable> list = java.util.List.of(Level.LOW, Level.HIGH);
        for (Describable d : list) {
            System.out.println(d.describe());
        }
    }
}
```

输出：

```
等级: LOW
等级: HIGH
```

# 7. 抽象方法与常量特定类体（策略枚举）

如果每个常量对同一方法要有==不同的实现==，可以在枚举里声明抽象方法，然后让每个常量用 `{ ... }` 提供自己的类体。这种写法叫==常量特定类体==（constant-specific class body），也叫==策略枚举==。

```java
enum Operation {
    PLUS("+") {
        @Override
        public int apply(int a, int b) { return a + b; }
    },
    MINUS("-") {
        @Override
        public int apply(int a, int b) { return a - b; }
    },
    TIMES("*") {
        @Override
        public int apply(int a, int b) { return a * b; }
    },
    DIVIDE("/") {
        @Override
        public int apply(int a, int b) { return a / b; }
    };

    private final String symbol;

    Operation(String symbol) {
        this.symbol = symbol;
    }

    public String getSymbol() { return symbol; }

    // 抽象方法，由每个常量各自实现
    public abstract int apply(int a, int b);
}
```

```java
public class Demo {
    public static void main(String[] args) {
        for (Operation op : Operation.values()) {
            System.out.println("6 " + op.getSymbol() + " 3 = " + op.apply(6, 3));
        }
    }
}
```

输出：

```
6 + 3 = 9
6 - 3 = 3
6 * 3 = 18
6 / 3 = 2
```

要点：

* 每个带类体的常量，编译器都会生成一个==匿名子类==（`Operation$1`、`Operation$2`……），所以此时枚举类在字节码层面不再是 `final`；
* 虽然生成了子类，但枚举构造方法仍是 `private`，外部依然无法再定义新的常量；
* 常量类体里可以访问枚举的私有成员（它本质上还是嵌套类，见 [[嵌套类]]）；
* 与"一个 `switch` 分发所有行为"相比，策略枚举把每个分支的实现放到对应常量旁边，==新增一种操作时只改一处==，也不会漏写分支。

# 8. 枚举实现单例

《Effective Java》推荐的单例写法：

```java
public enum Singleton {
    INSTANCE;

    public void doSomething() {
        System.out.println("doing something");
    }
}
```

使用：

```java
Singleton.INSTANCE.doSomething();
```

相比"私有构造 + 静态字段"的单例，枚举写法自动获得三个保证：

* ==线程安全==：常量在类初始化时创建，JVM 保证只执行一次；
* ==防反射==：对枚举类型调用 `Constructor.newInstance()` 会直接抛 `IllegalArgumentException`；
* ==防反序列化破坏==：枚举的序列化由 JVM 特殊处理，反序列化返回的永远是同一个实例。

# 9. EnumSet 与 EnumMap

这两个集合专门为枚举优化过，枚举元素天然有 `ordinal()`，底层可以用位向量/数组实现，==比 `HashSet` / `HashMap` 更省内存、更快==。

## 9.1 EnumSet

```java
import java.util.EnumSet;

public class EnumSetDemo {
    public static void main(String[] args) {
        EnumSet<Color> set = EnumSet.of(Color.RED, Color.BLUE);
        set.add(Color.GREEN);

        System.out.println(set);                          // [RED, GREEN, BLUE]
        System.out.println(EnumSet.allOf(Color.class));   // [RED, GREEN, BLUE]
        System.out.println(EnumSet.noneOf(Color.class));  // []
        System.out.println(EnumSet.complementOf(EnumSet.of(Color.RED))); // [GREEN, BLUE]
    }
}
```

* 内部是==位向量==，一个枚举常量只占一位，非常紧凑；
* 遍历顺序固定为常量的声明顺序；
* ==不允许 `null` 元素==，传入 `null` 会抛 `NullPointerException`；
* 一个 `EnumSet` 里的元素必须属于同一个枚举类型。

## 9.2 EnumMap

```java
import java.util.EnumMap;

public class EnumMapDemo {
    public static void main(String[] args) {
        EnumMap<Color, String> map = new EnumMap<>(Color.class);
        map.put(Color.RED, "红色");
        map.put(Color.GREEN, "绿色");

        System.out.println(map.get(Color.RED));   // 红色
        System.out.println(map);                  // {RED=红色, GREEN=绿色}
    }
}
```

* 内部就是一个按 `ordinal()` 下标索引的==数组==，没有哈希冲突；
* 构造时必须显式传入枚举的 `Class` 对象；
* ==键不能为 `null`==，值可以为 `null`；
* 遍历顺序同样是常量的声明顺序。

# 10. 与常量类的比较

传统写法是用 `static final` 常量代替枚举：

```java
public class Color {
    public static final int RED   = 0;
    public static final int GREEN = 1;
    public static final int BLUE  = 2;
}
```

它能用，但问题不少：

| 对比项 | `static final` 常量 | 枚举 |
| --- | --- | --- |
| 类型安全 | 参数写 `int`，任何整数都能传进来 | 只能传该枚举类型的常量，编译期检查 |
| 可读性 | 日志/调试里只有一个数字 | `toString()` 直接输出常量名 |
| 可遍历 | 需要自己维护数组或反射 | `values()` 直接遍历 |
| 可携带数据 | 要额外写 `Map` 或平行数组 | 每个常量自带字段和方法 |
| switch | 支持，但分支是数字 | 支持，case 写常量名 |
| 命名空间 | 常量散落在类里，容易重名 | 常量被收在枚举类型内部 |
| 修改常量值 | 编译期常量会被内联到调用方，改值后需重新编译所有依赖类 | 不存在这个问题 |
| 单例/序列化 | 需自己保证 | 天然保证唯一实例 |

所以只要"一组固定的、有限的取值"这个语义成立，就优先用枚举。

# 11. 注意事项与易错点

1. **不能 `new`**：`new Color()` 编译报错，枚举实例只能由 JVM 在类初始化时创建。
2. **不能继承其他类**：已经隐式继承了 `java.lang.Enum`，写 `enum A extends B` 直接报错；接口可以正常实现。
3. **不能声明泛型**：`enum Foo<T>` 编译报错。
4. **不能声明为 `abstract`**：枚举本身不能加 `abstract` 修饰符；需要"每个常量不同实现"时用第 7 节的写法。
5. **构造方法只能是 private 或包级访问**：写 `public` / `protected` 都编译报错。
6. **常量列表的位置和分号**：常量必须写在最前面；后面还有成员时，末尾的分号不能省。
7. **`switch` 的 case 不能带类名**：写 `case RED:`，不能写 `case Color.RED:`。
8. **`values()` 每次返回新数组**：在循环条件里反复调用会反复拷贝，可以先用局部变量接住：
   ```java
   Color[] all = Color.values();
   for (Color c : all) { ... }
   ```
9. **不要依赖 `ordinal()` 做业务编号**：它只是声明顺序，且不适合持久化。
10. **`equals` / `hashCode` / `compareTo` / `name` 都是 final**：不能重写；需要自定义展示就重写 `toString()`。
11. **枚举常量的序列化不可定制**：`writeObject` / `readObject` 对枚举不生效，反序列化永远返回同一个实例。
12. **构造方法里别碰静态字段**：枚举常量先于其他静态字段初始化，构造方法中引用静态字段会编译报错。

# 12. 小结

* 枚举的本质是==一个继承 `java.lang.Enum` 的 final 类==，每个常量都是 `public static final` 实例；
* 它同时具备==类型安全、可遍历、可携带数据、可多态==这几项能力，是 Java 中表达"固定集合"的标准方式；
* 常见进阶用法：带字段的枚举（状态码）、策略枚举（每个常量不同行为）、枚举单例、`EnumSet` / `EnumMap`。
