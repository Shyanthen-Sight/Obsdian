# 命名空间

宿主机上 `ps -ef` 能看到容器进程，它们和普通进程没区别，只是挂在不同命名空间里。`lsns` 能列出来：

```bash
lsns | head -4
#        NS TYPE  NPROCS   PID USER COMMAND
# 4026531836 pid      214     1 root /sbin/init
# 4026532320 net        3  9341 root nginx: master process
```

同一 TYPE 下编号不同就说明不共享。容器进程的 net、mnt、uts、ipc、pid 编号通常都和宿主机 1 号进程不同；user 命名空间要 rootless 或 `--userns-remap` 才会分叉。

| 类型 | 隔离的内容 | Docker 里的开关 |
| --- | --- | --- |
| pid | 进程号、`/proc` 里的进程视图 | `--pid=host`、`--pid=container:web` |
| net | 网卡、路由表、端口、iptables | `--network=host`、`--network=container:web` |
| mnt | 挂载点表 | 默认独立；`--privileged` 可挂宿主机目录 |
| uts | hostname、domainname | `--hostname`、`--uts=host` |
| ipc | SysV 共享内存、信号量 | `--ipc=host`、`--ipc=container:web` |
| user | UID/GID 映射 | `--userns=host`、rootless |

PID 命名空间里，容器 1 号进程就是应用入口。它不回收孤儿进程，应用不处理 `SIGCHLD` 会堆 `<defunct>`，`--init` 用 tini 补上。`--pid=host` 便于排查，但会暴露宿主机进程列表。

NET 给每个容器独立网卡和端口。`-p` 靠 NAT 或 docker-proxy 转发，`-p 8080:80` 后宿主机 `ss -lntp` 看到的是 proxy 或 iptables，不是 nginx。`--network=host` 复用宿主机网络栈，省一层 NAT，但端口冲突且不能用 `-p`。

MNT 装入容器的 rootfs、`/proc`、`/sys`、`/dev`。`docker exec` 靠 setns 进入目标容器的 mnt、pid、net；`--privileged` 或挂载 `/var/run/docker.sock` 会把隔离打穿。

IPC 默认一容器一个，`/dev/shm` 只有 64MB，PostgreSQL、Chrome 报共享内存不足时用 `--shm-size=1g`；共享内存段才用 `--ipc=container:`。

USER 把容器 UID 映射到宿主机普通 UID，rootless 和 `--userns-remap` 靠它；容器里的 root 在宿主机上不是 root，绑定挂载文件属主会变成 `100000:100000` 这类 ID。

## 手动隔离一次

```bash
sudo unshare --fork --pid --mount-proc bash
ps -ef
#   1 root 0:00 bash
#   2 root 0:00 ps -ef
echo $$        # 1
sudo unshare -n ip addr    # 只有 down 的 lo
```

`--fork` 先进新命名空间再 fork，否则 bash 仍是原 PID；`--mount-proc` 重挂 `/proc`，`ps` 才只看得到新空间。`unshare -n` 的 lo 是 down 的，要 `ip link set lo up`。

## 看 Docker 怎么用

```bash
docker run -d --name web nginx
PID=$(docker inspect -f '{{.State.Pid}}' web)
sudo lsns -p "$PID"
```

`lsns -p` 按进程过滤，能看到这个容器用了哪几个命名空间；排查网络时再用 `nsenter -t "$PID" -n ss -lntp` 进去看监听端口。

> [!warning] 隔离不是安全边界
> 命名空间只改“看得见什么”，不改权限模型。`--privileged`、挂载宿主目录、暴露 docker.sock 都可能拿到宿主机 root，还要配合 user 命名空间、seccomp 和 capabilities。
