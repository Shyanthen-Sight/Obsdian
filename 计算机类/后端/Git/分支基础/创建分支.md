# 创建分支 —— git branch 与 git switch -c

> [!abstract] 一句话
> ==创建分支，本质只是**在某个提交上贴一个新标签**==——Git 生成一个几十字节的小文件，里面写着那个提交的哈希。它不动任何文件、不复制任何代码，**毫秒完成**。所以"创建分支"在 Git 里便宜到可以随便造。

---

## 一、先纠正一个直觉

很多人以为"创建分支 = 把代码整个复制一份"。**不是。**

分支在 Git 里就是一个**指向提交的可移动指针**：

```text
C1 ── C2 ── C3   ← main
              ↑
           feature   ← 这个"分支"只是 .git/refs/heads/feature 里的一行哈希
```

此刻 `main` 和 `feature` **指向同一个提交**，两条线还没分开。
只有当你在 `feature` 上**提交**时，`feature` 指针才往前走，`main` 原地不动，历史才真正"分叉"。

> [!info] 分支的实体是一个文件
> `.git/refs/heads/<分支名>` 这个文件，内容就是一行 40 位 SHA-1 哈希。
> `git branch` 之所以快，是因为它只写这么一个文件。
> 对比 SVN——复制一个目录要几分钟——Git 建分支是**常量级**操作。

---

## 二、创建分支（不切换）

```bash
git branch <分支名>              # 在当前 HEAD 处新建分支，但不切过去
git branch <分支名> <起点>       # 从指定提交 / 分支 / tag 处新建
git branch <分支名> HEAD~3       # 从"当前提交往前数 3 个"处新建
```

> [!warning] `git branch` 只创建，**不切换**
> 执行完 `git branch feature`，你**还在原来的分支上**（`HEAD` 没动）。
> 想看当前在哪，看 `git branch` 里 `*` 落在哪一行。

```text
$ git branch feature
$ git branch
* main        ← 星号还在 main，说明你并没"进" feature
  feature
```

---

## 三、创建并立刻切换（日常最爱用）

```bash
git switch -c <分支名>            # ★ Git 2.23+ 推荐写法
git switch -c <分支名> <起点>     # 从指定起点创建并切换
git checkout -b <分支名>          # 老写法，等价的经典命令
```

> [!tip] `switch` 与 `checkout` 的分工
> Git 2.23 起把职责过载的 `checkout` 拆成两条更清晰的命令：
> - `git switch`：只管**切分支**
> - `git restore`：只管**恢复文件**
>
> 新代码请优先用 `switch` / `restore`；`checkout` 作为兼容保留。同理，"创建分支"的新写法是 `switch -c`，不再是 `checkout -b`。

---

## 四、切回上一个分支

```bash
git switch -          # 回到上一个分支（像 `cd -` 一样）
git switch main       # 切到已存在的分支 main
```

> [!note] `-` 记忆的是"上一个分支"
> 频繁在两个分支间横跳时，`git switch -` 省得打全名。

---

## 五、从远程分支创建（跟踪分支）

```bash
git switch feature                      # 若 origin/feature 存在且本地没有，自动创建并跟踪
git switch -c feature origin/feature    # 显式指定上游
git switch --track origin/feature       # 显式创建跟踪分支
git branch -u origin/feature            # 给"已存在"的本地分支设置上游
```

> [!info] DWIM 魔法（Do What I Mean）
> `git switch feature` 时若本地**没有** feature，但远程**恰好存在唯一的** `origin/feature`，
> Git 会自动帮你创建本地分支、切过去，并把上游设为 `origin/feature`。
> 这就是为什么克隆一个仓库后，直接 `git switch <某远程分支名>` 就能开工。

---

## 六、完整示例

```bash
git status                      # 1. 确认当前在 main、工作区干净
git switch -c feature/login     # 2. 建一个新分支开始干活
# ...编辑、提交...
git add .
git commit -m "feat: 登录页骨架"
git switch -                    # 3. 切回 main
```

> [!success] 成功标志
> `git branch` 里出现 `feature/login`，且 `*` 就在它那一行；
> 切回后 `git branch` 的 `*` 回到 `main`。

## 七、常见困惑

> [!question] 建分支会复制文件吗？占空间吗？
> 不会。指针文件只有几十字节。**只有内容对象**才占空间，而对象在多个分支之间**共享、去重**。
> 所以哪怕你建一百条分支，只要内容没变多，仓库几乎不变大。

> [!question] 工作区有未提交改动时，能建分支吗？
> **创建本身**没问题（它不碰工作区）。真正会出问题的是**切换**：若这些改动的文件在两个分支间内容不同，切过去会被覆盖，Git 会拒绝并要求你先处理。
> 稳妥做法：先 `git stash` 或先提交，再切。

> [!question] 分支名有什么限制？
> 不能含空格和 `~ ^ : ? * [ \` 等字符；不能以 `-` 或 `/` 结尾；不能出现连续的 `..`。
> 习惯上给分支加前缀，如 `feature/xxx`、`fix/xxx`、`hotfix/xxx`，一眼看出用途。

> [!question] `git branch <名字>` 建完了，我的文件变了吗？
> 没变。创建分支**不碰工作区和暂存区**——它们跟着 `HEAD` 走，而 `HEAD` 没动。

> [!question] 我想从某个旧的 tag 出发建分支，怎么做？
> 把 tag 当"起点"即可：`git switch -c fix/v1.2 v1.2.0`，新分支就从那个 tag 指向的提交开始。

---

> [!quote] 一句话记忆
> **分支 = 一张便利贴**，上面写着某个提交的哈希；"创建分支"就是把便利贴贴上去，**不搬家、不复印**。加 `-c`（switch）或 `-b`（checkout）则顺手把你带过去。
