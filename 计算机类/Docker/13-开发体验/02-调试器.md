# 调试器

容器里调试失败，十次有八次是监听地址的问题。调试器默认只绑 `127.0.0.1`，这个回环在容器自己的网络命名空间里，宿主上的 IDE 根本连不到。把它改成 `0.0.0.0`，再把端口映射出来，attach 才成立。

## Node.js

```bash
docker run --rm -it --name api \
  -p 127.0.0.1:3000:3000 \
  -p 127.0.0.1:9229:9229 \
  -v "$(pwd)":/app -w /app \
  node:20 \
  node --inspect=0.0.0.0:9229 server.js
```

`--inspect-brk` 会在第一行停住，适合调试启动阶段；`--inspect` 直接跑。VS Code 用 attach 配置：

```json
{
  "type": "node",
  "request": "attach",
  "name": "Docker: api",
  "address": "127.0.0.1",
  "port": 9229,
  "localRoot": "${workspaceFolder}",
  "remoteRoot": "/app",
  "restart": true
}
```

`localRoot`/`remoteRoot` 必须对上，否则断点显示为灰色“未绑定”。TypeScript 项目还要开 `sourceMap: true`，并确认编译产物里的 sourcemap 指向的路径在容器里存在。修改代码后 `restart: true` 会让调试器重新 attach。

## 其他语言

Python 用 debugpy：

```bash
python -m debugpy --listen 0.0.0.0:5678 --wait-for-client -m app
```

`--wait-for-client` 让进程停在入口等 IDE，适合调试初始化逻辑；不想等就去掉。JVM 用 JDWP：

```bash
JAVA_TOOL_OPTIONS=-agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=*:5005
```

Java 9 之后要写 `address=*:5005`，只写 `5005` 会绑回环。Go 用 Delve：

```bash
dlv debug --headless --listen=:2345 --api-version=2 --accept-multiclient
```

Delve 依赖 ptrace，容器需要 `--cap-add=SYS_PTRACE`，某些内核上还要 `--security-opt seccomp=unconfined`。这类权限只给开发容器，别带到生产。

## 没有调试工具时

线上镜像通常不含 shell、curl、tcpdump。别为了调试去改生产镜像，起一个工具容器共享命名空间更干净：

```bash
docker run --rm -it \
  --network container:api \
  --pid container:api \
  --cap-add SYS_PTRACE \
  nicolaka/netshoot
```

`--network container:api` 让它看到同一张网卡和回环，`--pid container:api` 让它看到目标进程，`ps`、`ss`、`strace` 都能用。Kubernetes 里对应的是 ephemeral container，思路一样。

## 边界

调试端口映射建议写成 `127.0.0.1:9229:9229`，只给本机。写成 `9229:9229` 时 Docker 会监听所有网卡，同一局域网的人可以连上来执行代码，这和把 shell 开放出去没区别。开发镜像单独一个构建阶段，生产阶段不装 debugpy、delve，也不带 `--inspect` 参数。

调试器连不上时按这个顺序查：端口有没有映射（`docker port api`）、容器里进程有没有监听（`docker exec api ss -lntp`）、监听地址是不是 `0.0.0.0`、宿主防火墙有没有拦。四个都对了，再看 IDE 的路径映射和 sourcemap。
