# 对象复用具体例子：圆柱体与圆

> 关联笔记：[[对象的复用]]、[[继承]]、[[UML]]、[[对象的引用和实体]]、[[成员变量]]、[[面向抽象编程]]

## 一句话解释

==**要写一个"圆柱体"类，而圆柱的体积、表面积都要用到圆的面积公式——正确的做法不是把公式抄过来，而是造一个 `Circle` 对象当 `Cylinder` 的成员（组合），需要面积就问它要。**==

这就是 [[对象的复用]] 里说的 ==**组合（has-a）**==：**圆柱"有一个"圆底面**。下面用完整的代码把这件事讲透，并对照"抄代码"和"错误继承"两种反例。

---

## 一、先看要解决的问题

需求很朴素：

- **圆**：半径 `r` → 面积 `πr²`，周长 `2πr`
- **圆柱**：底面半径 `r` + 高 `h` → 体积 `πr²h`，表面积 `2πr² + 2πrh`

一眼能看出：**圆柱的公式里，到处是圆的面积和周长**。所以问题的核心是——==圆柱该怎么"拿到"圆已经算好的东西？==

---

## 二、先定义好"圆"：一个自洽的类

复用的前提是**被复用的东西本身是完整、可独立使用的**。所以先把 `Circle` 写成一个只负责"圆"自己的事的类：

```java
// 圆类：只负责"圆"自己的事，不管谁来用它
class Circle {
    private double radius;                 // 半径

    public Circle(double radius) {
        this.radius = radius;
    }

    public double getRadius()    { return radius; }
    public void   setRadius(double radius) { this.radius = radius; }

    public double getArea() {              // 面积 πr²
        return Math.PI * radius * radius;
    }

    public double getPerimeter() {         // 周长 2πr
        return 2 * Math.PI * radius;
    }
}
```

`Circle` 不知道世界上有圆柱这回事，它只是**把自己该暴露的能力（`getArea`、`getPerimeter`）公开出来**。==谁需要谁就去调——这就是复用的接口。==

---

## 三、反例：不复用会怎样（把公式抄一遍）

最容易想到的写法是：`Cylinder` 自己存一个 `radius`，然后把圆的公式**再抄一份**：

```java
class Cylinder {
    private double radius;                 // 又存了一遍半径
    private double height;

    public double getVolume() {
        return Math.PI * radius * radius * height;   // ← 圆的面积公式被抄了一份
    }

    public double getSurfaceArea() {
        return 2 * Math.PI * radius * radius
             + 2 * Math.PI * radius * height;        // ← 又抄了一份
    }
}
```

它**能跑**，但问题很明显：

| 问题 | 说明 |
| --- | --- |
| **公式重复** | `πr²` 在 `Circle` 和 `Cylinder` 里各写了一遍 |
| **改一处要改多处** | 哪天圆的面积要用更高精度的 π，得记住每份拷贝都改 |
| **没有"圆"这个对象** | 圆和圆柱是两个互不相干的类，谈不上任何复用关系 |

> [!warning] 重复的代码是 bug 的温床
> 只要有一份忘了改，`Circle` 和 `Cylinder` 的算法就不一致了，而这种不一致极难排查。==复用的意义就在于：同一段逻辑全局只有一份。==

---

## 四、正例：组合复用（推荐）

正确做法是——==**让 `Cylinder` 持有一个 `Circle` 对象当底面**==。圆柱自己没有半径，它的半径**存在底面那个圆里**：

```java
class Cylinder {
    private Circle bottom;    // ① 组合：圆柱"有一个"圆底面（成员变量是另一个对象）
    private double height;    // 高

    public Cylinder(Circle bottom, double height) {
        this.bottom = bottom; // ② 运行时把"某个圆对象"装进来
        this.height = height;
    }

    public double getVolume() {                       // 体积 = 底面积 × 高
        return bottom.getArea() * height;             // ③ 复用圆的面积，自己不重写公式
    }

    public double getSurfaceArea() {                  // 表面积 = 两个底面 + 侧面
        return 2 * bottom.getArea()
             + bottom.getPerimeter() * height;
    }
}
```

使用：

```java
Circle   c   = new Circle(2);        // 半径 2 的圆
Cylinder cyl = new Cylinder(c, 5);   // 拿它当底面，高 5

System.out.println(cyl.getVolume());       // 62.83185307179586   (π·2²·5)
System.out.println(cyl.getSurfaceArea());  // 87.96459430051421   (2π·2² + 2π·2·5)
```

逐行看这三处标记：

1. **`private Circle bottom;`** —— 成员变量的类型是另一个类，这就是 ==**组合**==。它本质上就是 [[成员变量]]，只不过这个成员存的是 ==**一个引用**==，指向堆里的 `Circle` 实体（见 [[对象的引用和实体]]）。
2. **构造函数注入** —— 圆柱对象在**运行期**才决定用哪个圆当底面，非常灵活（换底面只需换个对象）。
3. **`bottom.getArea()`** —— `Cylinder` ==**完全不知道 `πr²` 怎么算**==，它只负责"要面积就问底面"。**算面积这件事，被委托给了 `bottom`**——这又是 [[对象的复用]] 里说的**委托**。

### UML 类图

```
┌───────────────────┐            ┌────────────────────┐
│     Cylinder      │   拥有     │       Circle       │
│───────────────────│  ◆───────▶ │────────────────────│
│ - bottom       ●──┼────────────┼─ - radius          │
│ - height          │   1    1   │────────────────────│
│───────────────────│            │ + getArea()        │
│ + getVolume()     │            │ + getPerimeter()   │
│ + getSurfaceArea()│            │ + getRadius()      │
└───────────────────┘            │ + setRadius()      │
                                 └────────────────────┘
        Cylinder ◆── Circle   实心菱形在"整体"一端，读作"圆柱组合了一个圆"
```

## 五、反例：为什么**不该**用继承？

既然要复用 `getArea()`，那让 `Cylinder extends Circle` 不就直接白拿了？——这是最容易犯的错：

```java
class Cylinder extends Circle {          // ❌ 圆柱 is-a 圆？不成立
    private double height;

    public Cylinder(double radius, double height) {
        super(radius);
        this.height = height;
    }

    public double getVolume() {
        return getArea() * height;       // 确实"白拿"了 getArea()
    }
}
```

代码更短，但**语义早就坏了**，四个具体问题：

| 问题 | 具体表现 |
| --- | --- |
| **语义不成立** | 圆柱**不是**圆（is-a 不成立）。判据：==问"圆柱是圆的一种吗？"答案是"不是"== |
| **继承了不该有的方法** | `Cylinder` 会莫名其妙拥有 `getPerimeter()`——圆柱的"周长"指什么？圆的周长还是底面周长？ |
| **无法表达"底面"** | 继承的含义是"它本身就是一个圆"，而圆柱要的是"**有一个**圆底面"。**继承给不了"部件"的概念** |
| **语义含糊的 setter** | `cyl.setRadius(5)` 到底改的是底面半径还是圆柱？调用者根本猜不到 |

> [!tip] 一句话判据
> ==**is-a 用继承，has-a 用组合。**== 圆柱和圆是典型的 **has-a**（圆柱有一个圆底面），所以用组合，不用继承。这也是 [[对象的复用]] 里"优先使用组合而非继承"的最直观案例。

## 六、复用的价值：改一处，处处生效

组合真正的好处，在**需求变化时**才显现。假设某天要把圆的面积算法改掉（比如定义一个更精确的 π，或加个保护）：

```java
// 只改 Circle 这一处
public double getArea() {
    return Math.PI * Math.pow(radius, 2);   // 换成 Math.pow，逻辑变了
}
```

此时——

- `Cylinder.getVolume()` **一行都不用动**，它调的还是 `bottom.getArea()`，自动跟着变；
- `getSurfaceArea()` 同理；
- 而如果用的是第二节"抄公式"的写法，就得到处找、到处改。

==**这就是复用的核心价值：同一份逻辑全局唯一，改一处，处处生效。**==

> [!note] 顺便：变量共享的坑
> 因为是组合，`Cylinder` 存的只是**引用**。如果两个圆柱共用同一个 `Circle` 对象：
> ```java
> Circle shared = new Circle(2);
> Cylinder a = new Cylinder(shared, 5);
> Cylinder b = new Cylinder(shared, 10);
> shared.setRadius(3);        // a 和 b 的底面半径【同时】变成了 3！
> ```
> ==要各自独立，就各 `new` 一个==。这就是 [[对象的引用和实体]] 里"引用 vs 实体"在组合上的直接体现。

## 七、再进一步：面向抽象，让复用更宽

现在把底面的类型从 `Circle` 换成**抽象类型**，`Cylinder` 的复用边界就从"只能是圆"扩展到"任何平面图形"：

```java
abstract class Shape2D {                     // 抽象"平面图形"
    public abstract double getArea();
    public abstract double getPerimeter();
}

class Circle extends Shape2D { /* 同上 */ }

class Cylinder {                             // 其实可以改名"柱体"
    private Shape2D bottom;                  // ← 成员类型是抽象类，不再是具体圆
    private double height;
    public Cylinder(Shape2D bottom, double height) {
        this.bottom = bottom;
        this.height = height;
    }
    public double getVolume() { return bottom.getArea() * height; }
}
```

这样一来，同一个 `Cylinder` 类——==**一行不用改**==——就能表示：

- 底面是圆 → 圆柱
- 底面是三角形/多边形 → 三棱柱/多棱柱

==把成员的**类型**写成抽象类或接口，复用才真正可扩展==，这是 [[面向抽象编程]] 在组合上的应用，也是 [[对象的复用]] 里"面向抽象的组合"那一节的具体落地。

---

## 八、三种方式对照（都在这个例子里）

| 方式 | 在本例中的写法 | 关系 | 评价 |
| --- | --- | --- | --- |
| **抄代码** | `Cylinder` 自己写 `πr²` | 无关 | ❌ 公式重复，改一处漏一处 |
| **继承** | `Cylinder extends Circle` | is-a | ❌ 语义不成立，白拿错误方法 |
| **组合** | `Cylinder` 持有 `Circle bottom` | has-a | ✅ **推荐**，松耦合、可替换、可扩展 |

---

## 九、注意事项

1. **组合的成员必须初始化**。`bottom` 若是 `null`，一调 `getVolume()` 就抛 `NullPointerException`（见 [[对象的引用和实体]]）。
2. **先判 is-a / has-a**。写之前问一句："圆柱是圆的一种吗？" 不是 → 用组合。
3. **复用 ≠ 复制**。组合是"把对象当成员来用"，不是把 `Circle` 的代码 Ctrl+C 进 `Cylinder`。
4. **能替换就暴露 setter**。给 `Cylinder` 加 `setBottom(Shape2D b)`，运行时就能换底面。
5. **注意共享与独占**。多个整体共用同一个部分对象时，改部分会连带影响所有整体；要独立就各 `new` 一个。
6. **成员类型尽量写抽象类/接口**。`Shape2D` 比 `Circle` 灵活得多。

---

## 十、一句话总结

> ==**圆柱要算体积，别把 `πr²` 抄进来，也别让 `Cylinder` 去继承 `Circle`（圆柱不是圆）；正确做法是让 `Cylinder` 持有一个 `Circle` 对象当底面（has-a 组合），需要面积就 `bottom.getArea()`（委托）。这样公式全局只有一份，改一处处处生效；把底面类型再写成抽象类，同一个 `Cylinder` 还能当棱柱用。**==
