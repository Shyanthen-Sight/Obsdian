# 查看分支 —— git branch 与分支全景

> [!abstract] 一句话
> ==`git branch` 是你的"分支仪表盘"==：不加参数就列出所有本地分支并用 `*` 标出你在哪；加各种选项还能看到每个分支的**最新提交、上游跟踪、是否已合并**。看分支的本质，就是看一堆**指针各自指向了哪个提交**。

---

## 一、最常用：当前有哪些分支

```bash
git branch            # 本地分支列表，* 标出当前分支
git branch -a         # 连远程分支一起显示（remotes/...）
git branch -r         # 只看远程分支
```

输出示例：

```text
* main
  feature/login
  remotes/origin/main
  remotes/origin/feature/login
```

> [!info] 三种"分支"要分清
> | 显示形式 | 是什么 | 实际存在哪 |
> | --- | --- | --- |
> | `main` | **本地分支** | `.git/refs/heads/` |
> | `remotes/origin/main` | **远程跟踪分支**（本地缓存） | `.git/refs/remotes/origin/` |
> | `origin/main`（引用时简写） | 同上，只是个书签 | 随 `fetch` 更新，**不能直接提交** |

---

## 二、看清每条分支走到哪了

```bash
git branch -v          # 每条分支的最新提交（哈希 + 说明）
git branch -vv         # ★ 额外显示上游分支 + 领先/落后几个提交
```

`-vv` 的输出：

```text
* main              a1b2c3d [origin/main: ahead 2] feat: 首页改版
  feature/login     9f8e7d6 [origin/feature/login] fix: 登录跳转
  experiment        4c5b3a2 [gone] chore: 试验
```

> [!tip] `-vv` 里最值钱的三样东西
> - `[origin/main: ahead 2]` —— 本地领先远程 2 个提交，==**该 push 了**==
> - `[behind 3]` —— 远程有你没有的提交，==**该 pull 了**==
> - `[gone]` —— 上游分支已被（远程）删除，通常在 PR 合并之后，==**该清理了**==

## 三、图形化历史：一眼看清分叉

```bash
git log --oneline --graph --all --decorate
```

```text
* a1b2c3d (HEAD -> main, origin/main) fix: 紧急修复
| * 9f8e7d6 (feature/login) feat: 登录页
|/
* 4c5b3a2 chore: 初始化
```

> [!tip] 这是理解"分支"的最佳视图
> - `--graph` 画出分叉与合并的线条
> - `--all` 把**所有**分支都纳入
> - `--decorate` 标出指针名字（`HEAD -> main` 等）
>
> 建议设成别名，天天用：
> ```bash
> git config --global alias.lg "log --oneline --graph --all --decorate"
> # 之后只要 git lg
> ```

## 四、按"合并状态"筛选

```bash
git branch --merged            # ★ 已经合并进当前分支的（多半可安全删）
git branch --no-merged         # 还没合并进来的（删之前要三思）
git branch --merged main       # 相对"指定分支"判断，而不是当前分支
```

> [!success] 清理分支的黄金组合
> ```bash
> git branch --merged | grep -v '\*'    # 列出"可删"的已合并分支（排除当前分支）
> ```
> 这些名字对应的提交都已在你的历史里，删掉分支指针**不会丢任何东西**。
> 详见 [[删除分支]]。

---

## 五、按提交反查分支

```bash
git branch --contains <提交>     # 哪些分支包含这个提交
git branch --no-contains <提交>
```

> [!info] 什么时候用
> 想知道某次修复、某个 tag "到底进了哪些分支"，这两条命令一目了然。
> 也可以配合 `git log <分支1>..<分支2>` 看"分支2 比分支1 多出哪些提交"。

---

## 六、完整示例

```bash
git branch -vv                                  # 1. 先看全貌：我在哪、各分支领先落后情况
git log --oneline --graph --all --decorate -10  # 2. 看历史形状
git branch --merged                             # 3. 哪些已经可以安全删了
```

## 七、常见困惑

> [!question] 我看到 `remotes/origin/xxx`，是不是说明远程真有这个分支？
> 不一定。远程跟踪分支是**上次 `fetch` 时的缓存快照**。远程真删了，本地可能还留着旧引用。
> 用 `git fetch --prune`（或 `git remote prune origin`）清理已消失的远程分支。

> [!question] 为什么 `git branch` 输出进了分页器、退不出来？
> 列表较长时 Git 会调分页器。按 `q` 退出，`空格` / `f` 翻页。
> 想一次性关掉：`git --no-pager branch`，或 `git config --global core.pager cat`。

> [!question] detached HEAD 时 `git branch` 显示什么？
> 仍列出所有分支，但 `*` 会显示在 `(HEAD detached at a1b2c3d)` 那一行，提示你**不在任何分支上**。
> 此时提交不属于任何分支，详见 [[提交]]。

> [!question] 分支太多看花眼，怎么只看几个？
> `git branch` 支持通配：`git branch "feature/*"` 只列匹配的名字；`git branch -a` 则一次看全。

---

> [!quote] 一句话记忆
> **`git branch` 看的是"指针们指向哪"**：`-v` 给哈希，`-vv` 给上下游，`--merged` 给"能不能删"，`--graph` 给"长什么样"。
