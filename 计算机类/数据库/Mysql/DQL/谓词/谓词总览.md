# 谓词总览 —— SQL 条件表达式的全景

> [!abstract] 一句话
> 谓词（predicate）是==**结果为 `TRUE` / `FALSE` / `UNKNOWN` 的表达式**==。`WHERE`、`HAVING`、`ON`、`CHECK`、`CASE WHEN` 里写的每一个条件，本质上都是谓词。
> 学会 SQL 过滤，不是背 `WHERE` 的语法，而是==**认全谓词、理解三值逻辑、知道哪个能走索引**==。

> [!info] 本篇定位
> 这是 `谓词/` 的**目录与总纲**：先给完整分类，再讲所有谓词共享的三件事——三值逻辑、优先级、索引。
> 每个谓词的具体语法、示例和坑，见对应笔记。
> `WHERE` 子句在整条查询里的执行位置见 [[Where]]；逻辑运算符的完整真值表见 [[计算机类/数据库/Mysql/sql运算符/逻辑运算符|逻辑运算符]]。

## 一、谓词长什么样

一条 `WHERE` 里的每个条件，都是一个谓词：

```sql
SELECT *
FROM student
WHERE age >= 18                    -- 比较谓词
  AND name LIKE '张%'              -- LIKE 谓词
  AND dept_id IN (1001, 1002)      -- IN 谓词
  AND remark IS NOT NULL;          -- 空值谓词
```

谓词的结果不是"一段文字"，而是**逻辑值**。MySQL 里可以直接 `SELECT` 出来看：

```sql
SELECT 1 = 1,       -- 1（TRUE）
       1 = 2,       -- 0（FALSE）
       NULL = 1;    -- NULL（UNKNOWN）
```

```
+-------+-------+----------+
| 1 = 1 | 1 = 2 | NULL = 1 |
+-------+-------+----------+
|     1 |     0 |     NULL |
+-------+-------+----------+
```

> [!important] `TRUE` / `FALSE` / `UNKNOWN` 在 MySQL 中的表示
> - `TRUE` 显示为 `1`，`FALSE` 显示为 `0`；
> - `UNKNOWN` 显示为 `NULL`；
> - 但**逻辑上它们是三个值**，`UNKNOWN` 不等于 `FALSE`，只是在 `WHERE` 里会被一起丢弃。

| 安全等于 | `<=>` | NULL 安全的相等比较 | [[安全等于]] |
| 范围谓词 | `BETWEEN a AND b` | 判断是否落在闭区间 | [[BETWEEN谓词]] |

| 模式匹配谓词 | `LIKE` / `NOT LIKE` | `%`、`_` 通配匹配 | [[LIKE谓词]] |

| 逻辑谓词 | `AND` `OR` `NOT` `XOR` | 组合多个谓词 | [[逻辑谓词]] |

> `=`、`>` 这些符号严格说是**比较运算符**，它们和操作数组合成"比较谓词"。
> 日常交流里两者常混着叫；本目录按"**整个条件表达式**"来分篇，更贴近写 SQL 时的实际使用。

## 三、谓词能出现在哪些地方

| 位置 | 作用 | 例子 |
| --- | --- | --- |
| `WHERE` | 分组前逐行过滤 | `WHERE age >= 18` |
| `HAVING` | 分组后按组过滤 | `HAVING COUNT(*) > 5` |
| `ON` | 连接条件 | `ON e.dept_id = d.dept_id` |
| `CHECK` | 建表时的约束 | `CHECK (age >= 0)` |
| `CASE WHEN` | 表达式内分支 | `CASE WHEN age >= 18 THEN '成年' END` |
| `IF()` | 函数内条件 | `IF(age >= 18, '成年', '未成年')` |
| `SELECT` 列表 | 直接输出布尔值 | `SELECT age >= 18 FROM student` |

> [!warning] 别名不能在 `WHERE` 谓词里用
> `WHERE` 在 `SELECT` 之前执行，`SELECT` 里定义的别名此时还不存在。
> ```sql
> -- ❌ Unknown column 'is_adult' in 'where clause'
> SELECT age >= 18 AS is_adult FROM student WHERE is_adult = 1;
> -- ✅ 重写表达式，或套一层派生表
> SELECT age >= 18 AS is_adult FROM student WHERE age >= 18;
> ```
> 详见 [[Select]] 的"书写顺序 vs 执行顺序"。

## 四、所有谓词共享的底层规则：三值逻辑

SQL 的谓词不是二值的。任何**含 NULL 的比较**都可能得到 `UNKNOWN`：

```sql
SELECT NULL = 1,        -- NULL（UNKNOWN）
       NULL <> 1,       -- NULL（UNKNOWN）
       NULL = NULL,     -- NULL（UNKNOWN）
       NULL IS NULL;    -- 1（TRUE，唯一可靠的判空）
```

`WHERE` 只保留结果为 **TRUE** 的行；`FALSE` 和 `UNKNOWN` 都被丢弃。

| A | B | `A AND B` | `A OR B` |
| --- | --- | --- | --- |
| TRUE | UNKNOWN | **UNKNOWN** | TRUE |
| FALSE | UNKNOWN | **FALSE** | **UNKNOWN** |
| UNKNOWN | UNKNOWN | UNKNOWN | UNKNOWN |

> [!tip] 两条口诀
> **`AND` 遇假即为假，`OR` 遇真即为真。**
> 其余涉及 `UNKNOWN` 的组合，多半还是 `UNKNOWN`。
> 这正是 `NOT IN` 带 NULL 会查不出任何数据、`= NULL` 永远为空集的根源。

## 五、优先级：什么时候必须加括号

从高到低，常用规则是：

```text
比较运算符（= <> > >= < <= <=>）
    ↓
IS NULL / LIKE / REGEXP / IN / BETWEEN / EXISTS
    ↓
NOT
    ↓
AND
    ↓
XOR
    ↓
OR
```

> [!danger] `AND` 比 `OR` 先算
> ```sql
> -- 本意：成年人，且性别为男或女
> WHERE age > 18 AND gender = 'M' OR gender = 'F'
> -- 实际：(age > 18 AND gender = 'M') OR (gender = 'F')
> -- 结果：未成年女生也会被查出来
> ```
> **只要一条条件里同时出现 `AND` 和 `OR`，就给每个 `OR` 分组加括号**——哪怕不加也对，加了是给下一个人看。

## 六、谓词与索引：哪些条件是"可搜索的"

> [!important] 核心概念：sargable
> 能利用 B+ 树索引快速定位的谓词叫 **sargable**（Search ARGument able）。
> 判断标准：==**索引列是否以"原始值"直接参与比较**==。

| 谓词写法 | 索引表现 | 原因 |
| --- | --- | --- |
| `col = 值` | ✅ 通常可走 | 等值查找 |
| `col > 值` / `BETWEEN` | ✅ 通常可走 | 范围扫描 |
| `col IN (...)` | ✅ 通常可走 | 多个等值查找 |
| `col IS NULL` | ✅ 通常可走 | 索引里存了 NULL 位置 |
| `col LIKE '张%'` | ✅ 可走 | 前缀匹配 |
| `col LIKE '%张%'` | ❌ 全表扫 | 前导 `%` 无法定位 |
| `col REGEXP '...'` | ❌ 全表扫 | 正则无法转成区间 |
| `DATE(col) = '...'` | ❌ 全表扫 | 列被函数包住 |
| `col + 1 = 100` | ❌ 全表扫 | 列参与运算 |
| `col <> 值` / `NOT IN` | ⚠️ 多半全表 | 否定条件选择性差 |
| `col <=> 值` | ✅ 非 NULL 时近似 `=` | NULL 安全相等 |
| `MATCH(col) AGAINST(...)` | ✅ 全文索引 | 专用倒排索引 |

> [!tip] 改写示例
> ```sql
> -- ❌ 索引失效
> WHERE DATE(created_at) = '2026-09-29'
> WHERE id + 1 = 100
> -- ✅ 改成范围 / 移走运算
> WHERE created_at >= '2026-09-29' AND created_at < '2026-09-30'
> WHERE id = 99
> ```

## 七、写谓词的六条建议

1. **判空只用 `IS NULL` / `IS NOT NULL`**，不要写 `= NULL`。
2. **`NOT IN` 遇到 NULL 会全空**，优先改 `NOT EXISTS` 或先过滤 NULL。
3. **索引列不套函数、不做运算**，`LIKE` 不要把 `%` 放开头。
4. **`AND` / `OR` 混用必须加括号**，别赌自己的优先级记忆。
5. **明确要不要保留 NULL 行**：`UNKNOWN` 在 `WHERE` 里等于"不通过"。
6. **拿不准就看 `EXPLAIN`**，别凭感觉判断走不走索引。

## 八、速查表

| 需求 | 谓词 |
| --- | --- |
| 等于 / 不等于 | `=` / `<>`（或 `!=`） |
| NULL 也参与相等判断 | `<=>` |
| 闭区间 | `BETWEEN a AND b` |
| 属于列表 | `IN (...)` |
| 模糊匹配 | `LIKE '%关键字%'`（注意索引） |
| 正则匹配 | `REGEXP` / `RLIKE` |
| 判空 | `IS NULL` / `IS NOT NULL` |
| 子查询是否有行 | `EXISTS` / `NOT EXISTS` |
| 与子查询所有值比较 | `> ALL (...)` / `= ANY (...)` |
| 组合条件 | `AND` / `OR` / `NOT` |
| 显式判断逻辑值 | `IS TRUE` / `IS FALSE` / `IS UNKNOWN` |
| 全文检索 | `MATCH (...) AGAINST (...)` |
| 判断 JSON | `IS JSON` / `MEMBER OF` |
