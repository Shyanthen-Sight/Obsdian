# 量化比较谓词 —— `ANY` / `SOME` / `ALL`

> [!abstract] 一句话
> `expr > ALL (子查询)` 表示"`expr` 比子查询返回的**每一个值都大**"；`expr > ANY (子查询)` 表示"`expr` 比其中**至少一个值大**"。
> 它们把"比较"和"集合"合在一起，==**`= ANY` 等价于 `IN`，`<> ALL` 等价于 `NOT IN`**==，但 NULL 和空集的语义更细。

> [!info] 与其它笔记的分工
> `IN` / `NOT IN` 见 [[IN谓词]]；`EXISTS` 见 [[EXISTS谓词]]。
> 本篇讲 `ANY` / `SOME` / `ALL` 的语义、等价改写、空集与 NULL 行为、以及 MySQL 的限制。

---

## 一、语法

```sql
expr 比较运算符 ANY (子查询)
expr 比较运算符 SOME (子查询)   -- SOME 是 ANY 的同义词
expr 比较运算符 ALL (子查询)
```

比较运算符可以是：

```text
=   <>   !=   >   >=   <   <=
```

```sql
-- 工资高于"销售部任意一名员工"的人
SELECT * FROM emp
WHERE salary > ANY (SELECT salary FROM emp WHERE dept_id = 1002);

-- 工资高于"销售部所有员工"的人
SELECT * FROM emp
WHERE salary > ALL (SELECT salary FROM emp WHERE dept_id = 1002);
```

> [!warning] MySQL 中 `ANY` / `ALL` 后面必须跟子查询
> ```sql
> -- ❌ MySQL 不支持这种写法
> WHERE salary > ANY (8000, 9000, 10000)
> -- ✅ 用 IN 或改成子查询
> WHERE salary > 8000
> ```
> PostgreSQL 等数据库支持数组形式，MySQL 不支持。需要多值时用 `IN` 或 `JOIN`。

---

## 二、语义：`ANY` 与 `ALL`

设子查询返回集合 `S = {s1, s2, ..., sn}`。

| 写法 | 含义 | 等价展开 |
| --- | --- | --- |
| `x > ANY (S)` | 至少大于一个 | `x > s1 OR x > s2 OR ...` |
| `x > ALL (S)` | 大于每一个 | `x > s1 AND x > s2 AND ...` |
| `x = ANY (S)` | 等于至少一个 | `x = s1 OR x = s2 OR ...`（即 `IN`） |
| `x <> ALL (S)` | 不等于每一个 | `x <> s1 AND x <> s2 AND ...`（即 `NOT IN`） |

```sql
-- ANY：命中任意一个即可
salary > ANY (SELECT salary FROM emp WHERE dept_id = 1002)
-- 等价于
salary > 9000 OR salary > 8500
-- 也就是 salary > 8500（最小值）

-- ALL：必须全部满足
salary > ALL (SELECT salary FROM emp WHERE dept_id = 1002)
-- 等价于
salary > 9000 AND salary > 8500
-- 也就是 salary > 9000（最大值）
```

> [!important] 记住这两个化简
> **`> ANY` 看最小值，`> ALL` 看最大值。**
> 反过来：
> - `x < ANY (S)` 等价于 `x < MAX(S)`；
> - `x < ALL (S)` 等价于 `x < MIN(S)`。

---

## 三、完整等价对照表

| 量化比较 | 等价于聚合 | 等价于 `IN` / `NOT IN` |
| --- | --- | --- |
| `x = ANY (S)` | `x IN (S)` | `x IN (S)` |
| `x <> ALL (S)` | `x NOT IN (S)` | `x NOT IN (S)` |
| `x > ANY (S)` | `x > (SELECT MIN(...) FROM ...)` | — |
| `x >= ANY (S)` | `x >= (SELECT MIN(...))` | — |
| `x < ANY (S)` | `x < (SELECT MAX(...))` | — |
| `x <= ANY (S)` | `x <= (SELECT MAX(...))` | — |
| `x > ALL (S)` | `x > (SELECT MAX(...))` | — |
| `x >= ALL (S)` | `x >= (SELECT MAX(...))` | — |
| `x < ALL (S)` | `x < (SELECT MIN(...))` | — |
| `x <= ALL (S)` | `x <= (SELECT MIN(...))` | — |

```sql
-- 等价改写示例：工资高于销售部所有人
-- 写法一：ALL
WHERE salary > ALL (SELECT salary FROM emp WHERE dept_id = 1002)
-- 写法二：聚合
WHERE salary > (SELECT MAX(salary) FROM emp WHERE dept_id = 1002)
```

> [!tip] 实际写 SQL 时优先用聚合
> `> ALL` 的可读性不如 `> (SELECT MAX(...))`，而且优化器对后者的处理通常更成熟。
> `= ANY` / `<> ALL` 则直接写 `IN` / `NOT IN` 更清楚（注意 `NOT IN` 的 NULL 陷阱）。

---

## 四、空集：`ALL` 为真，`ANY` 为假

这是量化比较最反直觉、也最容易被忽略的规则。

> [!danger] 子查询返回 0 行时
> - `expr > ALL (空集)` → **TRUE**（"比每一个都大"在空集上平凡成立）
> - `expr > ANY (空集)` → **FALSE**（"至少比一个大"不存在）

```sql
-- 假设 dept_id = 9999 没有任何员工
SELECT 100 > ALL (SELECT salary FROM emp WHERE dept_id = 9999);  -- 1
SELECT 100 > ANY (SELECT salary FROM emp WHERE dept_id = 9999);  -- 0
```

> [!warning] 这会直接影响查询结果
> ```sql
> -- 如果子查询为空，这条会返回"所有员工"
> SELECT * FROM emp
> WHERE salary > ALL (SELECT salary FROM emp WHERE dept_id = 9999);
> ```
> 业务上"比某部门所有人都高"在"该部门没人"时是否应该返回所有人？多数场景下不应该。
> **空集语义要先想清楚，必要时加 `EXISTS` 保护。**

```sql
-- 更安全的写法：先确认子查询非空
SELECT * FROM emp
WHERE EXISTS (SELECT 1 FROM emp WHERE dept_id = 9999)
  AND salary > ALL (SELECT salary FROM emp WHERE dept_id = 9999);
```

## 五、NULL 行为

量化比较的 NULL 语义比普通比较更绕，因为它是"多个比较的 OR / AND 组合"。

### 5.1 子查询含 NULL

```sql
-- 假设销售部工资为 9000, 8500, NULL
salary > ANY (SELECT salary FROM emp WHERE dept_id = 1002)
-- 展开：salary > 9000 OR salary > 8500 OR salary > NULL
```

- 如果 `salary > 9000` 或 `salary > 8500` 为 TRUE → 整个 `OR` 为 TRUE；
- 如果都不满足，最后一项是 UNKNOWN → 整个 `OR` 为 UNKNOWN（被 `WHERE` 丢弃）。

```sql
salary > ALL (SELECT salary FROM emp WHERE dept_id = 1002)
-- 展开：salary > 9000 AND salary > 8500 AND salary > NULL
```

- 如果任何一个比较为 FALSE → 整个 `AND` 为 FALSE；
- 如果全部为 TRUE，但有一项是 UNKNOWN → 整个 `AND` 为 UNKNOWN（被丢弃）。

> [!important] 结论
> - `ANY`：只要有一个 TRUE 就 TRUE；否则可能 UNKNOWN。
> - `ALL`：只要有一个 FALSE 就 FALSE；否则可能 UNKNOWN。
> - **两者都不会把含 NULL 的比较"当成 FALSE"**，所以 NULL 行可能让结果静默变少。

### 5.2 用 `IS NOT NULL` 先清理

```sql
WHERE salary > ALL (
    SELECT salary FROM emp
    WHERE dept_id = 1002 AND salary IS NOT NULL
)
```

> [!tip] 大多数业务场景下这是对的
> "比所有人都高"通常指"比所有**有工资数据**的人都高"。
> 如果业务要求"有 NULL 就算不通过"，那保留 NULL 反而更符合语义——**先定义清楚口径**。

## 六、实用示例

### 6.1 高于本部门所有人

```sql
SELECT e.emp_name, e.dept_id, e.salary
FROM emp e
WHERE e.salary > ALL (
    SELECT x.salary FROM emp x
    WHERE x.dept_id = e.dept_id AND x.emp_id <> e.emp_id
);
```

> [!note] 注意排除自己
> 如果不加 `x.emp_id <> e.emp_id`，`salary > ALL (包含自己)` 永远为 FALSE（自己不可能大于自己）。
> 这是"组内比较"类量化查询最常见的错误。

### 6.2 等于任意一个

```sql
-- 等价于 IN
SELECT * FROM emp
WHERE dept_id = ANY (SELECT dept_id FROM dept WHERE dept_name LIKE '%部');
```

### 6.3 不等于所有

```sql
-- 等价于 NOT IN
SELECT * FROM emp
WHERE dept_id <> ALL (SELECT dept_id FROM dept WHERE dept_name LIKE '%部');
```

## 七、性能与改写建议

| 写法 | 建议 |
| --- | --- |
| `= ANY (子查询)` | 改 `IN` |
| `<> ALL (子查询)` | 改 `NOT EXISTS`（NULL 安全） |
| `> ALL (子查询)` | 改 `> (SELECT MAX(...))` |
| `> ANY (子查询)` | 改 `> (SELECT MIN(...))` |
| `ALL` / `ANY` + 相关子查询 | 注意逐行执行，`EXPLAIN` 确认 |

```sql
-- 量化比较
WHERE salary > ALL (SELECT salary FROM emp WHERE dept_id = 1002)

-- 聚合改写（通常更易读、优化器更熟）
WHERE salary > (SELECT MAX(salary) FROM emp WHERE dept_id = 1002)
```

> [!info] 优化器可能改写
> MySQL 会把部分 `ANY` / `ALL` 子查询改写成 semi-join 或聚合。
> 但不要依赖，**写清楚语义 + 看 `EXPLAIN`** 才是稳妥做法。

## 八、常见错误合集

> [!failure] 忘了排除自己
> `salary > ALL (SELECT salary FROM emp WHERE dept_id = e.dept_id)` 包含自己，永远为 FALSE。
> 加 `x.emp_id <> e.emp_id`。

> [!failure] 空集导致"全部返回"
> `> ALL (空集)` 为 TRUE。业务上通常不符合预期，加 `EXISTS` 保护。

> [!failure] 子查询含 NULL 导致结果变少
> `ANY` / `ALL` 遇到 NULL 可能得 UNKNOWN，被 `WHERE` 丢弃。先 `IS NOT NULL` 或明确口径。

> [!failure] `ANY` 后面跟值列表
> MySQL 只支持 `ANY (子查询)`，不支持 `ANY (1,2,3)`。多值用 `IN`。

> [!failure] 把 `ANY` 和 `ALL` 记反
> `ANY` = 至少一个（OR），`ALL` = 每一个（AND）。
> 口诀：**ANY 宽，ALL 严**。

> [!failure] 用 `<> ALL` 代替 `NOT IN` 却没意识到 NULL 陷阱
> 两者等价，所以 `NOT IN` 的 NULL 问题它也有。否定场景优先 `NOT EXISTS`。

## 九、速查表

| 需求 | 写法 | 更易读的等价写法 |
| --- | --- | --- |
| 等于任意一个 | `x = ANY (S)` | `x IN (S)` |
| 不等于任何一个 | `x <> ALL (S)` | `x NOT IN (S)` / `NOT EXISTS` |
| 大于至少一个 | `x > ANY (S)` | `x > (SELECT MIN(...))` |
| 大于所有 | `x > ALL (S)` | `x > (SELECT MAX(...))` |
| 小于至少一个 | `x < ANY (S)` | `x < (SELECT MAX(...))` |
| 小于所有 | `x < ALL (S)` | `x < (SELECT MIN(...))` |
| 空集时 | `ALL` → TRUE，`ANY` → FALSE | 加 `EXISTS` 保护 |
| 含 NULL 时 | 可能 UNKNOWN | 先 `IS NOT NULL` |

> [!question] 自测三连
> 1. `x > ANY (S)` 和 `x > ALL (S)` 分别等价于和 `S` 的哪个聚合值比较？
> 2. 子查询为空时，`ALL` 和 `ANY` 分别返回什么？为什么？
> 3. "高于本部门所有人"为什么必须排除自己？

---

> [!quote] 一句话记忆
> **`ANY` 是"至少一个"（OR），`ALL` 是"每一个"（AND）；`= ANY` 即 `IN`，`<> ALL` 即 `NOT IN`；大于 `ANY` 看最小值，大于 `ALL` 看最大值；空集时 `ALL` 真 `ANY` 假，含 NULL 可能 UNKNOWN。**
