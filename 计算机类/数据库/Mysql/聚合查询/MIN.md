# MIN —— 最小值

> [!abstract] 一句话
> `MIN` 取一组里的**最小值**，它是 `MAX` 的**镜像**——同样不挑类型（数字/字符串/日期），同样==**忽略 NULL**==，全组都是 NULL 或空集时同样返回 `NULL`。区别只有一个：它顺着**索引最左端**看，取的是**最早 / 最小 / 最低**的那个。

---

> [!example] 本篇示例数据
> 与同目录的 `COUNT` / `SUM` / `AVG` / `MAX` / `GROUP BY` / `HAVING` 各篇**共用同一张 `emp` 表**。
> `hire_date` 找**最早入职**、`salary` 找**最低工资**、`bonus` 有 NULL 演示"忽略"，`id` 找最小值即最小的那个人。

```sql
CREATE TABLE emp (
    id        INT AUTO_INCREMENT PRIMARY KEY,
    name      VARCHAR(20) NOT NULL,
    dept      VARCHAR(20),      -- 部门
    gender    CHAR(1),          -- M 男 / F 女
    salary    DECIMAL(10,2),    -- 月薪
    hire_date DATE,             -- 入职日期
    bonus     DECIMAL(10,2)     -- 年终奖，有人是 NULL
);

INSERT INTO emp (name, dept, gender, salary, hire_date, bonus) VALUES
('张伟', '研发部', 'M', 12000.00, '2018-03-11', 5000.00),
('李娜', '研发部', 'F',  9000.00, '2020-07-01',    NULL),
('王强', '研发部', 'M', 15000.00, '2019-05-20', 8000.00),
('赵敏', '销售部', 'F',  8000.00, '2021-09-15', 3000.00),
('陈晨', '销售部', 'M',  6500.00, '2022-02-08',    NULL),
('刘洋', '销售部', 'F',  7500.00, '2020-11-30', 3000.00),
('孙悦', '财务部', 'F',  7000.00, '2023-04-01',    NULL),
('周杰', '财务部', 'M',  9500.00, '2020-08-22', 4000.00);
```

## 一、语法

```sql
MIN([DISTINCT] 表达式)
```

| 要点 | 说明 |
| --- | --- |
| 参数 | 列名、常量、或表达式 |
| `DISTINCT` | 可选，但**毫无意义**（最小值去不去重都一样）——别写 |
| 忽略 NULL | ✅ 是 |
| 空集 / 全 NULL | ==**返回 `NULL`**==（不是 0） |
| 返回类型 | **和入参同类型**（日期入 → 日期出） |

```sql
SELECT
    MIN(salary)     AS 最低工资,      -- 6500.00
    MIN(bonus)      AS 最低奖金,      -- 3000.00
    MIN(hire_date)  AS 最早入职       -- 2018-03-11
FROM emp;
```

```
+----------+----------+------------+
| 最低工资 | 最低奖金 | 最早入职   |
+----------+----------+------------+
|  6500.00 |  3000.00 | 2018-03-11 |
+----------+----------+------------+
```

> [!info] `MIN(DISTINCT x)` 和 `MAX(DISTINCT x)` 一样，纯属多余
> 去重不影响谁最小。别写。

## 二、`MIN` 能比什么（与 MAX 完全对称）

| 类型 | 比法 | `emp` 表示例 |
| --- | --- | --- |
| 数字 | 数值大小 | `MIN(salary)` = `6500.00` |
| 日期 / 时间 | 时间先后（**越早越小**） | `MIN(hire_date)` = `2018-03-11` |
| 字符串 | 字符集排序规则（collation） | `MIN(gender)` = `'F'`（`F` < `M`） |
| 自增主键 | 数值大小 | `MIN(id)` = `1`（最早的记录） |

```sql
SELECT
    MIN(hire_date)  AS 最早入职,
    MIN(gender)     AS 字母最小的性别,    -- 'F' < 'M'
    MIN(id)         AS 最小主键           -- 1
FROM emp;
```

```
+------------+--------------------+----------+
| 最早入职   | 字母最小的性别     | 最小主键 |
+------------+--------------------+----------+
| 2018-03-11 | F                  |        1 |
+------------+--------------------+----------+
```

> [!tip] `MIN(id)` / `MIN(created_at)` 是"取最早一条"的快捷方式
> 想知道"**全表最早创建的记录**"，`MIN(id)` 就是个廉价探针（自增主键通常即创建顺序）。
> 但要注意：**`MIN` 只给值不给行**——真要那一整行，见第五节。

> [!warning] 字符串 `MIN` 同样依赖 collation
> 和 `MAX` 一样，中文的 `MIN(name)` **不是按拼音/笔画**排的，换 collation 结果会变。
> 别拿它当"姓名排序最小的人"，业务无意义。

## 三、`MIN` 与 NULL

```sql
SELECT
    MIN(bonus)  AS 最低奖金          -- 3000.00（3 个 NULL 被跳过）
FROM emp;
```

> [!important] NULL 不进候选集合
> `bonus` 是 `5000, NULL, 8000, 3000, NULL, 3000, NULL, 4000`，`MIN` 只在这 5 个非 NULL 值里挑，得 `3000.00`（有两个 3000，取其一）。
> **NULL 既不算最小、也不算最大，它根本不参与比较。**

> [!danger] 全组都是 NULL → 返回 `NULL`
> ```sql
> SELECT MIN(bonus) FROM emp WHERE bonus IS NULL;
> ```
> ```
> +-------------+
> | MIN(bonus)  |
> +-------------+
> |        NULL |
> +-------------+
> ```
> 空集同样返回 `NULL`。**展示时套 `IFNULL(MIN(x), 0)` 兜底。**

> [!note] 常见误解：以为 NULL 是最小值
> 如果 `MIN` 把 NULL 当最小值，那 `MIN(bonus)` 应该返回 `NULL` 才对。**实测返回 `3000.00`**——正好证明 NULL 被跳过了。
> 这也是面试常考的"NULL 在聚合函数里的地位"。

## 四、`MIN` 与 `GROUP BY`：分组取最小

```sql
SELECT dept,
       COUNT(*)       AS 人数,
       MIN(salary)    AS 最低工资,
       MIN(hire_date) AS 最早入职
FROM emp
GROUP BY dept;
```

```
+--------+--------+----------+------------+
| dept   | 人数   | 最低工资 | 最早入职   |
+--------+--------+----------+------------+
| 研发部 |      3 |  9000.00 | 2018-03-11 |
| 财务部 |      2 |  7000.00 | 2020-08-22 |
| 销售部 |      3 |  6500.00 | 2020-11-30 |
+--------+--------+----------+------------+
```

验算：
- 研发部最低 `MIN(12000, 9000, 15000) = 9000`，最早入职 `2018-03-11`（张伟）
- 财务部最低 `MIN(7000, 9500) = 7000`，最早入职 `2020-08-22`（周杰）
- 销售部最低 `MIN(8000, 6500, 7500) = 6500`，最早入职 `2020-11-30`（刘洋）

> [!danger] 别用 `SELECT dept, name, MIN(salary)` 蒙
> ```sql
> SELECT dept, name, MIN(salary) FROM emp GROUP BY dept;   -- ERROR 1055
> ```
> 关掉检查后 `name` 是**组内随机某行**，**不一定**是最低工资那位。详见 [[计算机类/数据库/Mysql/聚合查询/GROUP BY]]。

## 五、想拿到"最小值那一整行"

需求："**工资最低的员工是谁？最早入职的是谁？**" `MIN` 只给值不给行。三种姿势：

### 5.1 方法一：子查询（推荐，能处理并列）

```sql
-- 工资最低的员工
SELECT * FROM emp WHERE salary = (SELECT MIN(salary) FROM emp);
```

```
+----+--------+--------+--------+----------+------------+---------+
| id | name   | dept   | gender | salary   | hire_date  | bonus   |
+----+--------+--------+--------+----------+------------+---------+
|  5 | 陈晨   | 销售部 | M      |  6500.00 | 2022-02-08 |    NULL |
+----+--------+--------+--------+----------+------------+---------+
```

```sql
-- 最早入职的员工（用日期做 MIN）
SELECT * FROM emp WHERE hire_date = (SELECT MIN(hire_date) FROM emp);
```

```
+----+--------+--------+--------+----------+------------+---------+
| id | name   | dept   | gender | salary   | hire_date  | bonus   |
+----+--------+--------+--------+----------+------------+---------+
|  1 | 张伟   | 研发部 | M      | 12000.00 | 2018-03-11 | 5000.00 |
+----+--------+--------+--------+----------+------------+---------+
```

> [!success] 为什么推荐
> `列 = (最小值)` 能匹配，**并列最小会一起返回**，不漏。

### 5.2 方法二：`ORDER BY` + `LIMIT 1`

```sql
SELECT * FROM emp ORDER BY salary ASC LIMIT 1;      -- 按工资升序取第一条
SELECT * FROM emp ORDER BY hire_date ASC LIMIT 1;   -- 按入职日期升序取第一条
```

- 直观、好读。**并列时只返回 1 行**，适合"只要一个代表"。

### 5.3 方法三：窗口函数（每组取最小）

```sql
SELECT * FROM (
    SELECT *, RANK() OVER (PARTITION BY dept ORDER BY salary ASC) AS rk
    FROM emp
) AS t
WHERE rk = 1;
```

```
+----+--------+--------+--------+----------+------------+---------+----+
| id | name   | dept   | gender | salary   | hire_date  | bonus   | rk |
+----+--------+--------+--------+----------+------------+---------+----+
|  2 | 李娜   | 研发部 | F      |  9000.00 | 2020-07-01 |    NULL |  1 |
|  7 | 孙悦   | 财务部 | F      |  7000.00 | 2023-04-01 |    NULL |  1 |
|  5 | 陈晨   | 销售部 | M      |  6500.00 | 2022-02-08 |    NULL |  1 |
+----+--------+--------+--------+----------+------------+---------+----+
```

> [!important] 选法速查
> | 需求 | 用什么 |
> | --- | --- |
> | 全表取最小那一行（含并列） | `WHERE 列 = (SELECT MIN(列) ...)` |
> | 全表取一条（不要并列） | `ORDER BY 列 ASC LIMIT 1` |
> | **每组**取最小那一行 | `RANK() OVER (PARTITION BY 组 ORDER BY 列 ASC)` |

## 六、性能：`MIN` 也走索引，极快

> [!success] `MIN` 顺着索引最左端取
> 列上有索引时，`MIN` **不需要扫全表**——直接看 B+ 树的**最左端**。
> 执行计划显示 `Select tables optimized away`，表示优化器"直接把答案取出来了"。

```sql
CREATE INDEX idx_salary ON emp(salary);
CREATE INDEX idx_hire ON emp(hire_date);

EXPLAIN SELECT MIN(salary) FROM emp;   -- 走索引，极快
```

| 情况 | 是否走索引 | 说明 |
| --- | --- | --- |
| `MIN(salary)`，`salary` 有索引 | ✅ 极快 | 取 B+ 树最左端 |
| `MIN(salary)`，无索引 | ❌ 全表扫 | 老实扫一遍 |
| 联合索引 `(dept, salary)` + `GROUP BY dept` | ✅ 快 | 每部门各自取最小，一次索引扫完 |
| `MIN(hire_date)` 上有索引 | ✅ 极快 | 找最早入职尤其方便 |

> [!tip] `MAX` 和 `MIN` 是"索引友好的聚合"
> 对比 `SUM` / `AVG` / `COUNT`——那几个必须**扫完整个索引**才能得出结论，只有 `MAX` / `MIN` 能"看一眼端点"。
> 所以"取最新/最早一条"这类查询非常高效，**能走索引就别用 `ORDER BY ... LIMIT 1` 全排序**。

> [!warning] 但"取整行"的外层匹配可能不快
> 5.1 的子查询本身快，外层 `WHERE salary = 6500` 若没索引仍要扫表。
> 5.2 的 `ORDER BY salary ASC LIMIT 1` 在 `salary` 有索引时也是"读最左一行"，很快。

## 七、`MIN` 与 `HAVING`

```sql
-- 只要"最低工资低于 7000"的部门
SELECT dept, MIN(salary) AS 最低工资
FROM emp
GROUP BY dept
HAVING MIN(salary) < 7000;
```

```
+--------+----------+
| dept   | 最低工资 |
+--------+----------+
| 销售部 |  6500.00 |
+--------+----------+
```

> [!important] 常见误用
> `WHERE MIN(salary) < 7000` 报 `ERROR 1111`（还没分组，`MIN` 无从算起）。
> **组级条件一律进 `HAVING`。** 详见 [[计算机类/数据库/Mysql/聚合查询/HAVING]]。

## 八、和 `MAX` 对照着记

| 对比维度 | `MIN` | `MAX` |
| --- | --- | --- |
| 含义 | 一组里**最小 / 最早** | 一组里**最大 / 最晚** |
| 日期上 | 找**最早**入职 `2018-03-11` | 找**最晚**入职 `2023-04-01` |
| 忽略 NULL | ✅ | ✅ |
| 空集 / 全 NULL | `NULL` | `NULL` |
| 索引 | 顺 B+ 树**最左端** | 顺 B+ 树**最右端** |
| `emp` 表结果 | `salary` 6500 / `bonus` 3000 | `salary` 15000 / `bonus` 8000 |
| 典型误用 | `SELECT dept, name, MIN(salary)` → ERROR 1055 | 同左 |

> [!note] `MIN` 和 `MAX` 是同一次扫描里能一起拿到的
> ```sql
> SELECT MIN(salary) AS 最低, MAX(salary) AS 最高 FROM emp;
> -- 6500.00 | 15000.00
> ```
> 一条语句同时拿极值，比查两次省一次扫描。

## 九、常见错误合集

> [!danger] 坑一：以为 `MIN` 会带出整行
> `MIN` 只给值不给行。要整行用第五节。

> [!danger] 坑二：`MIN` + 裸列 = 随机结果
> `SELECT name, MIN(salary) FROM emp;` 的 `name` 不保证是最低工资那位。

> [!danger] 坑三：以为 NULL 是最小值
> `MIN(bonus)` 返回 `3000.00` 而不是 `NULL` —— **NULL 被跳过，不在候选里**。

> [!failure] 坑四：空集 / 全 NULL 返回 `NULL`
> 展示前 `IFNULL(MIN(x), 0)` 兜底。

> [!failure] 坑五：字符串 `MIN` 依赖 collation
> 中文 `MIN(name)` 无业务意义。

> [!failure] 坑六：ERROR 1111 / ERROR 1055
> 聚合条件放 `HAVING`，裸列别和聚合混 SELECT。

## 十、速查表

| 需求 | 写法 | `emp` 表结果 |
| --- | --- | --- |
| 全表最低工资 | `MIN(salary)` | `6500.00` |
| 最早入职日期 | `MIN(hire_date)` | `2018-03-11` |
| 忽略 NULL 取最小 | `MIN(bonus)` | `3000.00` |
| 各分组最小值 | `GROUP BY dept` + `MIN(salary)` | 每部门最低 |
| 最小那一整行（含并列） | `WHERE salary = (SELECT MIN(salary) ...)` | 陈晨 |
| 最小那一行（只取一条） | `ORDER BY salary ASC LIMIT 1` | 陈晨 |
| 每组最小那一行 | `RANK() OVER (PARTITION BY dept ORDER BY salary ASC)` | 每组 Bottom1 |
| 同时取极值 | `MIN(x), MAX(x)` | 一次扫描两个值 |
| 空集兜底 | `IFNULL(MIN(x), 0)` | `0` |

> [!question] 自测三连
> 1. `bonus` 有 3 个 NULL，`MIN(bonus)` 返回几？如果 NULL 是最小值，应该是几？
> 2. "取最早入职的那名员工"，为什么 `SELECT MIN(hire_date), name FROM emp;` 不靠谱？
> 3. `MIN(salary)` 和 `MAX(salary)` 为什么比 `SUM` / `AVG` "更省"？

---

> [!quote] 一句话记忆
> **`MIN` 取最小、忽略 NULL、空集返回 `NULL`**；它和 `MAX` 完全对称，只是走索引的**最左端**；**`MIN` 只给值不给行**——想拿整行用 `WHERE 列 = (SELECT MIN(列))`。
