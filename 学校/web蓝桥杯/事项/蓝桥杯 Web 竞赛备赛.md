# 蓝桥杯 Web 应用开发：备赛总览（第十八届）

> [!info] 这份笔记解决什么
> 以参赛者视角，把备赛前必须搞清的六件事一次说清：**题量分值、模块考点、评分与时间分配、比赛环境、分周路线、高频失分点**。
> 目标赛事：第十八届蓝桥杯（2027 年 4 月省赛）。「10 题 / 150 分 / 4 小时」是近几届的稳定结构；`5/5/10/10/15/15/20/20/25/25` 的分值梯度来自第 13–16 届公开真题，**官方未逐年公布分值表，2027 年以题面为准**。

> [!summary] 速记版
> - **10 题，150 分，4 小时**（通常 9:00–13:00），分值梯度约为 `5/5/10/10/15/15/20/20/25/25`，难度总体递增。
> - **前 6 题（60 分）必须拿稳**，第 7–8 题（40 分）争取，第 9–10 题（50 分）冲刺。
> - 全离线：VS Code + Chrome + Live Server，**不能联网、不能 `npm install`**，库都是题包里的本地文件。
> - 技术栈：HTML5 / CSS3 / JS+ES6 / Axios / **Vue 3** + Element Plus + vue-router 4 + Pinia / **ECharts 5**；Node.js 仅大学组。
> - 每题**单独打 zip 上传**，可多次提交、取最后一次；**不许改文件名和目录结构**。
> - 最大的坑往往不是难题，而是**没交、交错、样式差一点、异步没 `await`**。

## 二、分模块考点

### 1. HTML + CSS（约 15–30 分）

| 必考 | 常考题型 | 易错点 |
| --- | --- | --- |
| 语义化标签、表单元素 | 还原设计稿的静态页 | 盒模型、默认 margin、行高 |
| Flex 主轴/换行/对齐 | 卡片列表、导航、居中 | `flex: 1` 与 `min-width: 0` |
| Grid 行列/区域 | 宫格、后台布局 | `fr` 与固定宽混用 |
| 定位、层叠 | 角标、遮罩、弹窗 | `z-index` 失效（父级未定位） |
| 媒体查询、响应式 | 移动端适配 | 漏写 `viewport` |
| transition / animation | 展开、轮播、加载 | 动画属性写错、`keyframes` 名不匹配 |

**业务场景**：商品详情页、课程卡片、登录页、后台侧边栏、活动页。
**站内真题**：[[学校/web蓝桥杯/HTML和CSS/4.水果拼盘|水果拼盘]]、[[学校/web蓝桥杯/HTML和CSS/1.用户名片|用户名片]]、[[学校/web蓝桥杯/HTML和CSS/2.西游记之西天取经|西游记之西天取经]]、[[学校/web蓝桥杯/HTML和CSS/3.给页面化个妆|给页面化个妆]]。

> [!tip] 布局题通常「全对才给分」
> 像水果拼盘 5 分题，差一点就是 0 分。练的时候不要「看着差不多」，要用 DevTools 量尺寸、对间距、对颜色。

### 2. JavaScript + ES6（约 40–65 分）

| 必考 | 常考题型 | 易错点 |
| --- | --- | --- |
| DOM 查询、增删改、classList/style | 列表渲染、Tab 切换、弹窗 | 渲染前查询拿到 `null` |
| 事件绑定、冒泡、委托、阻止默认 | 动态列表删除、表单提交 | 动态元素没绑上事件 |
| 数组方法 `map/filter/reduce/sort/find` | 搜索、筛选、统计、排序 | `sort` 改原数组、比较函数写错 |
| 字符串、正则、日期 | 格式化、校验、截取 | 正则贪婪、`replace` 只换第一个 |
| ES6：解构、箭头函数、模板字符串、模块化 | 数据处理、工具函数 | 箭头函数 `this` |
| Promise、`async/await`、`Promise.all` | 接口取数、并发请求 | 忘 `await`、没 `try/catch` |
| localStorage / sessionStorage | 购物车、草稿、登录态 | 存对象变 `[object Object]` |

**业务场景**：抽奖、购物车、分页、搜索过滤、表单校验、数据看板。
**站内笔记**：[[学校/web蓝桥杯/JS/1.传送门|传送门]]、[[学校/web蓝桥杯/其他/数组 API 全解|数组 API 全解]]、[[学校/web蓝桥杯/其他/字符串API全解|字符串 API 全解]]、[[学校/web蓝桥杯/事项/Ajax考点分析|Ajax 与 axios 考点]]。

### 3. ECharts（约 10–20 分）

| 必考 | 常考题型 | 易错点 |
| --- | --- | --- |
| `init` → `option` → `setOption` | 柱/折/饼/散点 | 容器高度为 0 |
| `xAxis` / `yAxis` / `series` | 多系列、双 Y 轴、堆叠 | 类目轴与数值轴混用 |
| `tooltip` / `legend` / `grid` / `dataZoom` | 交互组件 | 字段层级写错 |
| 异步数据加载与更新 | 接口取数后渲染 | 数据没到就 `setOption` |
| `chart.on('click')` | 点击联动、跳详情 | `params` 取错字段 |
| `resize` / `dispose` | 自适应、切换页面 | 重复 `init`、没监听窗口 |

**业务场景**：销售看板、学生信息统计、实时数据、排行榜。
**站内笔记**：[[学校/web蓝桥杯/事项/Echart考点分析|ECharts 考点]]、[[学校/web蓝桥杯/Echarts/1.学生信息统计|学生信息统计]]、[[学校/web蓝桥杯/Echarts/2.和手机相处的时光|和手机相处的时光]]、[[学校/web蓝桥杯/Echarts/3.商品销量和销售额实时展示看板|商品销量看板]]、[[学校/web蓝桥杯/Echarts/4.粒粒皆辛苦|粒粒皆辛苦]]。

### 4. Vue 3 生态（约 50–65 分）

| 必考 | 常考题型 | 易错点 |
| --- | --- | --- |
| 模板语法、`v-if/v-for/v-model` | 列表、表单、条件渲染 | `v-if` 与 `v-for` 同用、`key` 用索引 |
| `ref` / `reactive` / `computed` / `watch` | 计数器、筛选、联动 | script 里忘 `.value`；解构 `reactive` 失去响应 |
| 组件通信 `props` / `emit` / 插槽 / `provide-inject` | 父子、兄弟、弹窗 | 子组件直接改 `props` |
| 生命周期 `onMounted` 等 | 初始化请求、图表挂载 | 在 `setup` 顶层直接操作 DOM |
| vue-router 4 | 列表→详情、动态路由、守卫 | history 模式本地刷新 404 |
| Pinia | 购物车、登录态、跨页共享 | 解构 store 失去响应（用 `storeToRefs`） |
| Axios 封装、拦截器 | 列表/详情/增删改 | 忘了 `res.data` |
| Element Plus | 表单校验、表格、弹窗、分页 | 规则字段与 `prop` 不对应 |

**业务场景**：后台管理、内容列表、登录鉴权、多步表单、数据看板。
**站内真题**：[[学校/web蓝桥杯/Vue/1.搜一搜呀|搜一搜呀]]。

> [!warning] Vue 2 的旧题只能练思路
> 第 13–14 届真题大量使用 Vue 2 + Vuex + Element UI；第 15 届起已切到 **Vue 3 + Element Plus + Pinia**。旧题可以练业务拆解，但**代码要按 Vue 3 写**，别把 `this.$store`、`beforeDestroy` 带进考场。

### 5. Node.js（大学组，0–25 分）

- **fs**：读写文件、遍历目录、批量重命名、统计。
- **path / url**：路径拼接、后缀判断。
- **http / Express**：RESTful 接口、路由、中间件、返回 JSON。
- **命令行工具**：`process.argv`、交互式输入。
- **简易 webpack / Vue CLI**：入口、出口、loader 概念。
- **Markdown 解析**：标题、列表、代码块转 HTML。

职业院校组不考 Node，可跳过。

## 三、评分标准与拿分策略

### 1. 机器怎么判

- **功能题**：按测试点/多组测试数据判分，行为符合预期才给分；有的题**全对才给分**，有的题按测试点给部分分。
- **布局/样式题**：把渲染结果与目标效果比对（尺寸、位置、颜色、间距），**差一点就可能 0 分**。
- **代码规范**：省赛机器评分基本不单独计分；国赛有人工复核，冗余代码、命名混乱会影响评价（据选手经验，非官方公布的权重）。
- **提交**：同一题可多次提交，**以最后一次为准**；所以「先交一版能跑的」永远不亏。

> [!important] 官方没有公布「还原度 / 功能 / 规范」的百分比
> 任何精确权重都是机构推测。可操作的结论只有一句：**先把功能跑通并提交，再抠样式，最后才谈代码整洁**。

### 2. 四小时时间表

| 时段 | 分钟 | 任务 |
| --- | --- | --- |
| 9:00–9:15 | 15 | 通读 10 题，解压题包，跑通模板，标记难易 |
| 9:15–9:35 | 20 | 第 1–2 题（5+5） |
| 9:35–10:00 | 25 | 第 3–4 题（10+10） |
| 10:00–10:35 | 35 | 第 5–6 题（15+15） |
| 10:35–11:30 | 55 | 第 7–8 题（20+20） |
| 11:30–12:35 | 65 | 第 9–10 题（25+25） |
| 12:35–12:55 | 20 | 逐题打包、上传、核对文件名和题号 |
| 12:55–13:00 | 5 | 缓冲，确认全部提交成功 |

**执行原则**：

1. **先易后难，但不死磕**：单题超过 30 分钟没进展，先提交当前版本，跳到下一题。
2. **边做边交**：每完成一题立即压缩上传一次，防止最后网络拥堵或误操作。
3. **先跑通再美化**：功能题先让数据出来，再调样式；布局题先搭结构，再对像素。
4. **最后 20 分钟只做提交**：不再改代码，逐题确认「压缩包对应题号、能解压、能运行」。
5. **战略性放弃**：第 9–10 题 30 分钟仍无思路，回补第 7–8 题的细节分；但**不要整题不交**，能实现的部分先交。

**分数目标**：前 6 题 ≥55/60；总分 90+ 在多数赛区已很有竞争力，110+ 属高分。据往年选手经验，不少赛区省一线在 50–70 分区间（非官方，各省差异大），**别把分数线当复习目标**。

## 四、比赛环境与离线演练

### 1. 环境清单

| 项目 | 结论 | 对备赛的影响 |
| --- | --- | --- |
| 编辑器 | VS Code，插件通常只有 Live Server | 没有 Vue/JS 智能提示，练手写 |
| 浏览器 | Chrome 正式版（往届要求 v100+） | 用 DevTools 调样式、看请求 |
| 网络 | 无互联网，仅竞赛局域网 | 不能查文档、不能用 CDN |
| 依赖 | 不能 `npm install`，库随题包提供（本地 `.js`） | 习惯 `<script src="./libs/xxx.min.js">` |
| Vue | Vue 3（Composition API） | 旧真题是 Vue 2，注意 API 差异 |
| UI 库 | Element Plus（2.3.6+） | 表单校验、表格、弹窗要熟 |
| 路由/状态 | vue-router 4、Pinia | 动态路由、store 增删改查 |
| ECharts | 5.x，本地引入 | 不要写 CDN 地址 |
| Node | 大学组考；职业院校组不考（往届大纲 Node v12.x） | fs、http/Express、CLI、简易 webpack |
| 压缩软件 | WinRAR / 7-Zip（以考场提供为准） | 提前熟悉「选中文件夹→压缩为 zip」 |
| 分辨率 | 最低 1024×768 | 页面至少在这个宽度下不崩 |
| 提交 | 每题单独 zip，浏览器上传 | 边做边交 |

> [!warning] 每年可能微调
> 以上来自第 15–17 届的公开信息和选手复盘。**考前一周以准考证、竞赛手册和监考说明为准**，尤其是 Vue/Element Plus 版本和是否允许纸质资料。

### 2. 离线演练（建议每周一次）

1. 断网，只开 VS Code + Chrome。
2. 新建空项目，用本地 `vue.global.prod.js`、`element-plus`、`echarts.min.js`、`axios.min.js` 写一个「列表 + 筛选 + 详情弹窗」页面。
3. 用 **Live Server** 打开，不跑 `npm run dev`。
4. 按题目的目录要求打包成 zip，再解压到另一个目录，确认双击/预览能直接运行。
5. 全程计时，目标 2 小时内完成；熟练后压到 90 分钟。

> [!note] 题包可能是完整工程
> 有些题会给 `package.json`、`src/` 甚至预置 `node_modules`。**先读题面 README，按它说的方式启动**；不要上来就 `npm install`，也不要擅自改构建配置。

### 3. 不要踩的规则

- 不改文件名、文件夹名、目录结构，不改题目已有的 `id` / `class`（有的题会校验）。
- 压缩包内不要出现姓名、学校、学号。
- 压缩包不要设密码；不要多套一层文件夹（按题目要求的结构来）。
- 不插 U 盘、不连外网、不装额外插件。
- 截止前至少留 15 分钟上传，别等到 12:59。

## 六、高频失分点与正确写法

| # | 失分点 | 典型表现 | 一句话规避 |
| --- | --- | --- | --- |
| 1 | ECharts 容器高度为 0 | 图表不显示，控制台无报错 | 给容器写死高度 |
| 2 | Vue 3 响应式丢失 | 数据改了页面不变 | script 里 `.value`，别解构 `reactive` |
| 3 | 异步没接住 | 页面空白 / `undefined` | `await` 后再赋值 |
| 4 | `v-for` 用 index 做 key | 删除后内容错位 | 用唯一 id |
| 5 | localStorage 存对象 | 读出来是 `[object Object]` | `JSON.stringify/parse` |
| 6 | history 路由本地 404 | 刷新页面白屏 | 本地用 hash 模式 |
| 7 | 事件绑在渲染之前 | 点击没反应 | 事件委托或渲染后绑定 |
| 8 | 样式还原差一点 | 布局题 0 分 | 盒模型、间距、颜色逐项对 |
| 9 | 提交事故 | 没交 / 交错 / 打不开 | 边做边交，最后 20 分钟核对 |

### 1. ECharts：容器没有高度

```html
<!-- 错误：div 没有高度，init 后画布是 0×0 -->
<div id="chart"></div>
```

```css
/* 正确：容器必须有确定尺寸 */
#chart {
  width: 100%;
  height: 360px;
}
```

```js
// 正确：DOM 就绪后再 init；窗口变化时 resize
const chart = echarts.init(document.getElementById('chart'))
chart.setOption(option)
window.addEventListener('resize', () => chart.resize())
```

补充：同一容器重复 `init` 会警告/失效，切换页面时用 `echarts.getInstanceByDom(el)` 或 `chart.dispose()`。

### 2. Vue 3：`ref` 忘 `.value`、解构 `reactive`

```js
import { ref, reactive, toRefs } from 'vue'

const list = ref([])
list.push(item)        // 错：改的是 ref 对象本身
list.value.push(item)  // 对：script 里必须 .value
// 模板里自动解包，写 list 即可
```

```js
const state = reactive({ count: 0 })
const { count } = state        // 错：count 是普通数字，失去响应
const { count } = toRefs(state) // 对：仍是 ref
// 或者始终写 state.count
```

子组件不要直接改 `props`，用 `emit` 通知父组件；跨层级用 `provide/inject`。

### 3. 异步：没 `await` 就渲染

```js
// 错误：res 是 Promise，res.data 是 undefined
const res = axios.get('/api/list')
list.value = res.data

// 正确
try {
  const { data } = await axios.get('/api/list')
  list.value = data
} catch (err) {
  console.error(err)
}
```

多个互不依赖的请求用 `Promise.all`；有依赖就串行 `await`。请求期间给 `loading` 状态，避免页面空白被误判为没做完。

### 4. `v-for` 的 `key`

```html
<!-- 错误：删除中间项后，后续项复用错误 DOM -->
<li v-for="(item, index) in list" :key="index">{{ item.name }}</li>

<!-- 正确 -->
<li v-for="item in list" :key="item.id">{{ item.name }}</li>
```

### 5. localStorage 存对象

```js
// 错误：存进去是 "[object Object]"
localStorage.setItem('cart', cart)

// 正确
localStorage.setItem('cart', JSON.stringify(cart))
const cart = JSON.parse(localStorage.getItem('cart') || '[]')
```

写入时机：每次增删改后立即写；初始化时读，读失败要给默认值。

### 6. 路由 history 模式在本地 404

```js
// 本地用 Live Server / file:// 打开时，刷新会 404
createRouter({ history: createWebHistory(), routes })

// 改为 hash 模式
createRouter({ history: createWebHashHistory(), routes })
```

如果题目已经配好路由，**不要乱改**；先看它用的是哪种模式，以及是否有服务端回退。

### 7. 事件绑在渲染之前

```js
// 错误：列表还没渲染，querySelectorAll 得到空集合
document.querySelectorAll('.del').forEach(btn => {
  btn.addEventListener('click', handleDelete)
})

// 正确：事件委托，动态元素也能响应
list.addEventListener('click', e => {
  if (e.target.classList.contains('del')) {
    handleDelete(e.target.dataset.id)
  }
})
```

### 8. 样式还原的细节

- `* { box-sizing: border-box; }`，否则 padding 会把宽度撑开。
- Flex 子项被内容撑破：加 `min-width: 0`。
- 图片变形：`object-fit: cover`。
- `height: 100%` 无效：父级没有确定高度，改用 `100vh` 或 Flex。
- 间距优先用 `gap`，少用 margin 叠加。
- 颜色、圆角、字号、行高逐个对设计稿，别凭感觉。
- 至少检查 1024×768 和 1440 宽两档。

### 9. 提交事故（最冤的 0 分）

- 改了题目文件夹名/目录结构 → 机器找不到文件。
- 压缩包多套了一层文件夹，或解压后文件散落 → 判分失败。
- 压缩包带密码、带姓名学校 → 成绩无效。
- 最后一题忘了上传，或传到别的题号 → 0 分。
- 12:59 才开始打包，网络拥堵 → 传不上去。

**做法**：每完成一题立刻打一次包、传一次；最后 20 分钟逐题核对「题号—压缩包—能解压—能运行」。
