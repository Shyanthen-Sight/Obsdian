# Java 多态

> 多态（Polymorphism）的字面意思是“多种形态”：==同一份调用代码，作用在不同类型的对象上，会执行不同的实现==。
> 本文用同一个“公司薪资系统”案例贯穿始终：从写死类型的 `if / else`，到一行 `calculateSalary()` 搞定所有员工。

## 1. 贯穿全文的案例

### 1.1 需求

公司有三类人员：

| 类型 | 薪资算法 | 工作内容 |
| --- | --- | --- |
| 固定薪资员工 | 月薪 | 处理日常事务 |
| 经理 | 月薪 + 奖金 | 开会 |
| 小时工 | 工时 × 时薪 | 产线工作 |

系统需要：统一保存所有人员、打印工资单、统计薪资；未来还会增加“实习生”等新类型。

### 1.2 两个接口

```java
interface Payable {
    double calculateSalary();
}

interface Workable {
    void work();
}
```

`Payable` 约定“能算薪资”，`Workable` 约定“能工作”。后文会看到，接口引用可以指向任何实现类对象。

### 1.3 抽象父类

```java
abstract class Employee implements Payable, Workable {
    protected String name;
    protected double baseSalary;

    public Employee(String name, double baseSalary) {
        this.name = name;
        this.baseSalary = baseSalary;
    }

    public String getName() {
        return name;
    }

    public double getBaseSalary() {
        return baseSalary;
    }

    // 模板方法：工资单流程固定，变化点交给子类
    public final void printPayslip() {
        System.out.println("===== 工资单 =====");
        System.out.println("姓名：" + name);
        System.out.println("岗位：" + getRole());
        System.out.println("应发：" + calculateSalary());
        System.out.println("==================");
    }

    public String getRole() {
        return "员工";
    }

    @Override
    public abstract double calculateSalary();   // 具体子类必须实现

    @Override
    public abstract void work();                // 具体子类必须实现
}
```

`Employee` 不知道每类人的薪资怎么算，但它规定了：==所有子类都必须会算薪资、都会工作==。`printPayslip()` 是 `final` 的，流程不允许子类改，但其中调用的 `getRole()`、`calculateSalary()` 会动态绑定到子类实现。

### 1.4 三个子类

```java
class SalariedEmployee extends Employee {
    public SalariedEmployee(String name, double baseSalary) {
        super(name, baseSalary);
    }

    @Override
    public double calculateSalary() {
        return baseSalary;
    }

    @Override
    public void work() {
        System.out.println(name + " 在处理日常事务");
    }

    @Override
    public String getRole() {
        return "固定薪资员工";
    }
}

class Manager extends Employee {
    private double bonus;

    public Manager(String name, double baseSalary, double bonus) {
        super(name, baseSalary);
        this.bonus = bonus;
    }

    @Override
    public double calculateSalary() {
        return baseSalary + bonus;
    }

    @Override
    public void work() {
        System.out.println(name + " 在开会");
    }

    @Override
    public String getRole() {
        return "经理";
    }

    public double getBonus() {
        return bonus;
    }
}

class HourlyEmployee extends Employee {
    private int hours;
    private double rate;

    public HourlyEmployee(String name, int hours, double rate) {
        super(name, 0);
        this.hours = hours;
        this.rate = rate;
    }

    @Override
    public double calculateSalary() {
        return hours * rate;
    }

    @Override
    public void work() {
        System.out.println(name + " 在产线工作");
    }

    @Override
    public String getRole() {
        return "小时工";
    }

    public int getHours() {
        return hours;
    }

    public double getRate() {
        return rate;
    }
}
```

### 1.5 客户端

```java
public class PayrollDemo {
    public static void main(String[] args) {
        Employee[] staff = {
            new SalariedEmployee("王五", 5000),
            new Manager("张三", 5000, 2000),
            new HourlyEmployee("李四", 20, 100)
        };

        for (Employee e : staff) {
            e.printPayslip();
        }
    }
}
```

输出：

```
===== 工资单 =====
姓名：王五
岗位：固定薪资员工
应发：5000.0
==================
===== 工资单 =====
姓名：张三
岗位：经理
应发：7000.0
==================
===== 工资单 =====
姓名：李四
岗位：小时工
应发：2000.0
==================
```

这段客户端代码==不认识任何一个子类==，却正确打印出了三种工资单。为什么？这就是本文要解释的多态。

## 2. 没有多态会怎样

如果调用方不用多态，而是自己判断类型、分别计算：

```java
for (Employee e : staff) {
    double salary;
    if (e instanceof Manager m) {
        salary = m.getBaseSalary() + m.getBonus();
    } else if (e instanceof HourlyEmployee h) {
        salary = h.getHours() * h.getRate();
    } else {
        salary = e.getBaseSalary();
    }
    System.out.println(e.getName() + " 的薪资: " + salary);
}
```

输出和之前一样：

```
王五 的薪资: 5000.0
张三 的薪资: 7000.0
李四 的薪资: 2000.0
```

但问题很明显：

1. ==薪资规则本来属于各个子类，却被搬到了调用方==；
2. 每新增一种人员，就要在这里加一个 `else if`；
3. 一旦漏加分支，新类型可能悄悄走进 `else`，算出错误的薪资；
4. 调用方被迫知道所有子类的细节，和“我只想打印工资”这件事毫无关系。

`printPayslip()` 里的 `calculateSalary()` 则完全不同：调用方只写一次，具体执行哪段代码由对象在==运行期==决定。

## 3. 多态是什么

多态可以概括为：

> ==统一的调用入口 + 各自不同的实现 + 运行期决定用哪一个。==

看同一行 `e.calculateSalary()`：

| 视角 | 看到的内容 |
| --- | --- |
| 调用方 | 只看到 `Employee`（或 `Payable`）上有 `calculateSalary()`，不关心对象具体是哪个子类 |
| 子类 | `SalariedEmployee`、`Manager`、`HourlyEmployee` 各自重写，提供自己的算法 |
| JVM | 根据 `e` 指向对象的==实际类型==，选择对应的方法版本执行（见 [[动态绑定]]） |

所以多态不是某一个关键字，而是三件事共同作用的结果：

1. 子类与父类之间==有共同的类型契约==；
2. 子类==重写==了契约中的方法；
3. 调用方通过==父类引用==使用子类对象。

一句话：==调用方写的是“父类”，运行的是“子类”。==

## 4. 多态的三要素

还是这组员工类，三个条件==缺一不可==：

```java
abstract class Employee implements Payable, Workable {   // ① 继承 / 实现
    ...
}

class Manager extends Employee {                          // ① 继承
    @Override
    public double calculateSalary() {                     // ② 方法重写
        return baseSalary + bonus;
    }
}

Employee e = new Manager("张三", 5000, 2000);             // ③ 父类引用指向子类对象
e.calculateSalary();                                      // 多态调用：执行 Manager 的版本
```

### 4.1 缺少任意一个会怎样

| 缺少的条件 | 结果 |
| --- | --- |
| 没有继承 / 实现关系 | 类型之间没有共同契约，无法用同一个引用统一处理 |
| 子类没有重写 | 无论实际对象是谁，都执行父类版本，行为没有差异 |
| 没有父类引用指向子类对象 | 调用点只涉及一种类型，体现不出“同一调用、多种形态” |
| 不是可重写的实例方法 | 字段、`static`、`private`、`final`、构造方法都不参与动态分派 |

前三条是==设计层面==的三要素；最后一条是==语言机制层面==的限制。严格来说，多态调用还必须通过实例方法进行：

```java
Manager m = new Manager("张三", 5000, 2000);
m.calculateSalary();      // 执行的确实是 Manager 版本，
                          // 但调用点只可能遇到 Manager 一种类型，
                          // 这不是“多态”的典型使用场景

Employee e = new Manager("张三", 5000, 2000);
e.calculateSalary();      // 同一个调用点，可以接待任意 Employee 子类 → 多态
```

> [!note] 为什么第三点重要
> 多态的价值在于“一份代码处理多种子类”。如果直接拿子类引用调用，代码已经和具体子类绑死，虽然方法仍按对象类型分派，但失去了统一处理的能力。

接口版本同理，只是把“父类引用”换成“接口引用”：

```java
Payable p = new Manager("张三", 5000, 2000);   // 接口引用指向实现类对象
p.calculateSalary();                            // 多态调用
```

这里 `Manager` 既继承了 `Employee`，又通过 `Employee` 间接实现了 `Payable`。`p` 只认识 `calculateSalary()` 这个契约，至于对象是经理还是小时工，由运行期决定。

## 5. 编译时类型与运行时类型

理解多态，必须先分清引用变量的两个类型：

| 概念 | 含义 | 由谁决定 |
| --- | --- | --- |
| ==编译时类型==（静态类型） | 变量声明时写的类型，编译器只认它 | 变量声明，如 `Employee e` |
| ==运行时类型==（实际类型） | 引用实际指向的对象的类型 | `new` 出来的对象，如 `new Manager()` |

```java
Employee e = new Manager("张三", 5000, 2000);
```

* `e` 的编译时类型是 `Employee`；
* `e` 的运行时类型是 `Manager`；
* 对象从创建到销毁一直是 `Manager`，==转型不会改变对象本身==。

由此得到多态最重要的两条规则：

> **能调用哪些成员，看编译时类型；**
> **被重写的方法执行哪一个版本，看运行时类型。**

```java
Employee e = new Manager("张三", 5000, 2000);

System.out.println(e.calculateSalary());           // 7000.0（运行期看 Manager）
System.out.println(e.getRole());                   // 经理（运行期看 Manager）
System.out.println(e.getClass().getSimpleName());   // Manager（对象没变）
// e.getBonus();                                   // 编译错误：Employee 上没有 getBonus()
```

编译期检查保证了==类型安全==：编译器只允许调用父类声明过的成员，不会让你误用某个子类特有的方法。运行期分派则保证了==行为正确==：真正执行的是实际对象的那份实现。

> [!tip] 记忆口诀
> ==编译看左边，运行看右边。==
> 左边是引用的静态类型，右边是对象的实际类型。

关于向上转型、向下转型的完整规则，见 [[向上转型与向下转型]]。

## 6. 多态的形式

广义上，多态有三种常见形式：

| 形式 | 别称 | 机制 | 决定时机 | 本文案例 |
| --- | --- | --- | --- | --- |
| ==运行时多态== | 动态多态、子类型多态 | 重写 + 向上转型 + 动态绑定 | 运行期 | `Employee e = new Manager(...); e.calculateSalary()` |
| ==编译时多态== | 静态多态 | 方法重载 | 编译期 | `PayrollService.print(Employee)` / `print(Manager)` |
| ==参数化多态== | 泛型 | 类型参数 | 编译期（运行期类型擦除） | `List<Employee>` |

日常语境中说“Java 的多态”，==默认指运行时多态==。另外两种也常被提及，但机制完全不同，不能混为一谈。

### 6.1 运行时多态

就是本文前面讨论的形式：

* 子类重写父类 / 接口方法；
* 父类或接口引用指向子类或实现类对象；
* 调用时由 JVM 按对象实际类型选择实现。

### 6.2 编译时多态：重载

在同一个类中，方法名相同、参数列表不同，调用哪一个版本在编译期就按==参数的静态类型==选定了：

```java
class PayrollService {
    public void print(Employee e) {
        System.out.println("员工：" + e.getName() + "，薪资=" + e.calculateSalary());
    }

    public void print(Manager m) {
        System.out.println("经理：" + m.getName() + "，薪资=" + m.calculateSalary() + "（含奖金）");
    }
}
```

```java
PayrollService service = new PayrollService();
Employee e = new Manager("张三", 5000, 2000);
Manager m = new Manager("张三", 5000, 2000);

service.print(e);              // 员工：张三，薪资=7000.0
service.print(m);              // 经理：张三，薪资=7000.0（含奖金）
service.print((Manager) e);    // 经理：张三，薪资=7000.0（含奖金）
```

注意：`e` 实际指向的是 `Manager` 对象，但 `service.print(e)` 仍然选择 `print(Employee)`。==重载只看静态类型，不看对象实际类型==，所以它不涉及运行期动态分派。

> [!warning] 不要把重载当成“运行时多态”
> 很多教材把重载称为“编译时多态”，这个说法可以接受；但如果你以为“传入子类对象就会自动选子类重载版本”，那就错了。重载在编译期已经定死。详见 [[重载]] 和 [[动态绑定]]。

### 6.3 参数化多态：泛型

泛型让同一份代码适配多种类型，同时保留编译期类型检查：

```java
List<Employee> staff = new ArrayList<>();
staff.add(new SalariedEmployee("王五", 5000));
staff.add(new Manager("张三", 5000, 2000));
staff.add(new HourlyEmployee("李四", 20, 100));

Employee first = staff.get(0);
```

`ArrayList<E>` 只写一次，就能用于 `Employee`、`String`、`Integer` 等各种元素类型。Java 的泛型在编译后会发生==类型擦除==，运行期并不保留 `E` 的具体类型，因此它的“多态”主要体现在编译期的类型安全，而不是运行期的动态分派。

## 7. 多态的典型用法

下面所有代码都继续使用第 1 节的员工类。

### 7.1 统一方法参数

方法只针对父类写一次，所有子类对象都能传进来：

```java
public static void printSalary(Employee e) {
    System.out.println(e.getName() + " 的薪资: " + e.calculateSalary());
}

printSalary(new SalariedEmployee("王五", 5000));          // 5000.0
printSalary(new Manager("张三", 5000, 2000));             // 7000.0
printSalary(new HourlyEmployee("李四", 20, 100));         // 2000.0
```

新增子类时，`printSalary` 一行都不用改。

### 7.2 数组与集合

数组元素声明为父类型，槽位里可以放任意子类对象：

```java
List<Employee> staff = List.of(
    new SalariedEmployee("王五", 5000),
    new Manager("张三", 5000, 2000),
    new HourlyEmployee("李四", 20, 100)
);

for (Employee e : staff) {
    e.printPayslip();          // 各自执行自己的 calculateSalary / getRole
}
```

这是多态最常见的落地点：==用父类型容器装子类对象，循环里统一调用==。

### 7.3 工厂方法返回父类型

工厂负责创建具体对象，调用方只看到父类型：

```java
class EmployeeFactory {
    public static Employee create(String type) {
        if ("manager".equals(type)) {
            return new Manager("张三", 5000, 2000);
        }
        if ("hourly".equals(type)) {
            return new HourlyEmployee("李四", 20, 100);
        }
        return new SalariedEmployee("王五", 5000);
    }
}
```

```java
Employee e = EmployeeFactory.create("manager");
System.out.println(e.calculateSalary());   // 7000.0，调用方不知道也不关心具体类
```

### 7.4 接口回调

把对象交给框架、线程、监听器时，本质上都是把实现类对象向上转型为接口引用。这里用 `Workable` 统一启动所有人员：

```java
public static void startAll(Workable[] workers) {
    for (Workable w : workers) {
        w.work();          // 调用各实现类自己的版本
    }
}

startAll(new Workable[] {
    new SalariedEmployee("王五", 5000),
    new Manager("张三", 5000, 2000),
    new HourlyEmployee("李四", 20, 100)
});
```

输出：

```
王五 在处理日常事务
张三 在开会
李四 在产线工作
```

`startAll` 只依赖 `Workable`，任何实现类都能接入，接入时不需要修改 `startAll`。

### 7.5 模板方法：父类定流程，子类填步骤

第 1 节的 `Employee.printPayslip()` 就是模板方法：

```java
public final void printPayslip() {
    System.out.println("===== 工资单 =====");
    System.out.println("姓名：" + name);
    System.out.println("岗位：" + getRole());        // 变化点 1
    System.out.println("应发：" + calculateSalary()); // 变化点 2
    System.out.println("==================");
}
```

```java
Employee e = new Manager("张三", 5000, 2000);
e.printPayslip();
```

输出：

```
===== 工资单 =====
姓名：张三
岗位：经理
应发：7000.0
==================
```

`printPayslip()` 声明为 `final`，子类不能改流程；它只负责“打印哪几行”，==具体岗位和金额由子类通过重写 `getRole()`、`calculateSalary()` 注入==。父类调用自己会被子类重写的方法，这就是模板方法模式的核心，也是多态在框架设计中最典型的应用之一。

## 8. 多态与抽象类、接口

第 1 节的案例同时用到了抽象类和接口，这里把它们的分工说清楚。

### 8.1 抽象类：强制子类给出实现

```java
abstract class Employee implements Payable, Workable {
    ...
    @Override
    public abstract double calculateSalary();   // 具体子类必须实现

    @Override
    public abstract void work();                // 具体子类必须实现
}
```

`Employee` 自己不知道薪资怎么算、工作内容是什么，但它可以规定：==每个具体子类都必须会算、会工作==。`SalariedEmployee`、`Manager`、`HourlyEmployee` 都必须给出自己的版本，否则编译不通过。

抽象类可以有字段、构造方法、具体方法（如 `getName()`、`printPayslip()`），适合“有共同状态，又有部分通用实现”的场景。

### 8.2 接口：只约定能力，不关心实现

```java
interface Payable {
    double calculateSalary();
}

interface Workable {
    void work();
}
```

`payAll` 只依赖 `Payable`：

```java
public static void payAll(Payable[] payables) {
    for (Payable p : payables) {
        System.out.println(p.calculateSalary());
    }
}

payAll(new Payable[] {
    new SalariedEmployee("王五", 5000),
    new Manager("张三", 5000, 2000),
    new HourlyEmployee("李四", 20, 100)
});
```

接口把“能发工资”这件事从继承体系中解放出来：==任何实现 `Payable` 的类型都能传进 `payAll`，不必是 `Employee` 的子类==。如果未来公司接入不继承 `Employee` 的外部合作方，只要它实现 `Payable`，`payAll` 一行都不用改。

### 8.3 三者对比

| 形式 | 对子类的约束 | 可以定义的内容 | 继承 / 实现数量 | 在案例中的角色 |
| --- | --- | --- | --- | --- |
| 普通父类 | 重写是可选的 | 字段、构造方法、具体方法 | 单继承 | 不适合：`Employee` 不知道默认薪资算法 |
| 抽象类 | 具体子类必须实现 `abstract` 方法 | 字段、构造方法、具体方法、抽象方法 | 单继承 | `Employee`：共享 `name`、`baseSalary`、`printPayslip()` |
| 接口 | 实现类必须实现抽象方法（`default` 方法除外） | 常量、抽象方法、`default` / `static` 方法（Java 8+） | 多实现 | `Payable` / `Workable`：约定能力，解耦调用方 |

> [!tip] 多态不要求必须用抽象类或接口
> 把 `Employee` 改成普通类，给 `calculateSalary()` 一个默认实现，`Employee e = new Manager(); e.calculateSalary()` 仍然是多态。抽象类和接口的价值在于：把“子类必须提供哪些行为”写成编译期契约，让多态从“可以这样用”变成“必须这样实现”。

这就是[[面向抽象编程]]：调用方依赖抽象，不依赖具体实现。它带来的直接收益是[[开闭原则]]——对扩展开放，对修改关闭。

## 9. 多态管不到的地方

多态只作用于==可被重写的实例方法==。下面这些成员不参与动态分派。

### 9.1 字段不参与多态

在 `Employee` 和 `Manager` 中各加一个同名字段 `title`（其余代码不变）：

```java
class Employee {
    protected String title = "员工";
}

class Manager extends Employee {
    protected String title = "经理";
}

Employee e = new Manager("张三", 5000, 2000);
System.out.println(e.title);              // 员工
System.out.println(((Manager) e).title);  // 经理
```

两个 `title` 在对象里==同时存在==，`Manager.title` 隐藏了 `Employee.title`。通过 `Employee` 类型的引用访问，拿到的永远是父类那份字段。

### 9.2 static 方法不参与多态

再在 `Employee` 和 `Manager` 中各加一个同名 `static` 方法（其余代码不变）：

```java
class Employee {
    public static String company() {
        return "示例科技（Employee）";
    }
}

class Manager extends Employee {
    public static String company() {
        return "示例科技（Manager）";
    }
}

Employee e = new Manager("张三", 5000, 2000);
System.out.println(e.company());          // 示例科技（Employee）
System.out.println(Manager.company());    // 示例科技（Manager）
```

`static` 方法在编译期就按“引用变量的静态类型 / 类名”确定，和对象无关。实际开发中应通过类名调用静态方法，这里用 `e.company()` 只是为了演示静态类型决定结果。

### 9.3 构造方法中的陷阱

把 `Employee` 的构造方法改成下面这样（其余代码不变），再创建 `Manager`：

```java
abstract class Employee {
    protected String name;
    protected double baseSalary;

    public Employee(String name, double baseSalary) {
        this.name = name;
        this.baseSalary = baseSalary;
        System.out.println("构造中：" + getRole());   // 反例
    }

    public String getRole() {
        return "员工";
    }
}

class Manager extends Employee {
    private double bonus = 2000;

    public Manager(String name, double baseSalary, double bonus) {
        super(name, baseSalary);
        this.bonus = bonus;
    }

    @Override
    public String getRole() {
        return "经理，奖金=" + bonus;
    }
}

new Manager("张三", 5000, 2000);
```

输出：

```
构造中：经理，奖金=0.0
```

创建 `Manager` 对象时，`Employee` 的构造方法先执行；其中的 `getRole()` 发生动态绑定，进入 `Manager.getRole()`，但此时 `Manager` 的字段初始化 `bonus = 2000` 和构造方法体都==还没有执行==，所以读到默认值 `0.0`。

> [!warning] 不要在构造方法中调用可被重写的方法
> * 子类字段尚未初始化，可能读到 `0` / `null` / `false`；
> * 子类重写方法可能依赖自己的初始化逻辑，行为不可预期；
> * 如果一定要调用，把方法声明为 `private` 或 `final`，杜绝被重写。

更完整的字节码与方法表分析见 [[动态绑定]]，父类构造方法与子类的执行顺序见 [[父类的构造方法与子类的关系]]。

### 9.4 一张表总结

| 成员 | 是否多态 | 原因 |
| --- | --- | --- |
| 被重写的实例方法 | ==是== | 运行期按对象实际类型分派 |
| 未被重写的实例方法 | 否 | 执行父类继承来的版本 |
| 字段 | 否 | 按引用的静态类型访问；子类同名字段只是隐藏 |
| `static` 方法 | 否 | 属于类；子类同名方法只是隐藏，不是重写 |
| `private` 方法 | 否 | 对子类不可见，无法重写 |
| `final` 方法 | 否 | 禁止重写，不存在第二个版本 |
| 构造方法 | 否 | 不继承、不重写 |
| 重载方法的选择 | 否 | 编译期按参数的静态类型选择 |

## 10. 多态的价值与代价

### 10.1 价值

**（1）解耦调用方与实现方**

`printPayslip()`、`payAll()`、`startAll()` 都只依赖父类或接口，不需要知道具体子类。实现类可以独立修改、替换、扩展。

**（2）支持开闭原则**

新增“实习生”时，只需要加一个子类：

```java
class Intern extends Employee {
    public Intern(String name, double dailyWage) {
        super(name, dailyWage);
    }

    @Override
    public double calculateSalary() {
        return baseSalary;
    }

    @Override
    public void work() {
        System.out.println(name + " 在实习");
    }

    @Override
    public String getRole() {
        return "实习生";
    }
}
```

```java
List<Employee> staff = new ArrayList<>(List.of(
    new SalariedEmployee("王五", 5000),
    new Manager("张三", 5000, 2000),
    new HourlyEmployee("李四", 20, 100)
));

staff.add(new Intern("赵六", 150));   // 新增子类

for (Employee e : staff) {
    e.printPayslip();                  // 这段循环代码没有修改
}
```

如果换成第 2 节的 `if / else` 写法，这里就必须再加一个分支。

**（3）统一处理**

参数、返回值、数组、集合、框架回调都可以用父类型统一表达，代码更简洁，也更容易扩展。

**（4）设计模式的基础**

策略模式、工厂模式、模板方法模式、观察者模式等，底层都依赖多态：==先约定抽象，再在运行时替换实现==。

### 10.2 代价与适用边界

多态不是越多越好：

* **抽象设计有成本**：必须提前想清楚“哪些行为是共同的”。抽象错了，比不用多态更难改；
* **需要子类特有功能时仍要向下转型**：例如拿到 `Employee e` 后想调用 `Manager.getBonus()`，必须先 `instanceof` 再强转，这会重新暴露具体类型（见 [[向上转型与向下转型]]、[[instanceof]]）；
* **调试时不够直观**：看到的是父类方法调用，实际执行的方法可能在某个子类里，需要结合运行时类型排查；
* **没有变化点的地方不必强行抽象**：类型固定、行为不变的小段代码，直接写反而更清楚。

> [!tip] 判断标准
> 多态用来隔离==会变化的部分==。如果一组类型确实存在“同一行为、不同实现”，并且未来可能新增实现，就值得抽象；如果永远只有一种实现，先写简单代码。

## 11. 常见误区

1. **以为“多态 = 继承”**：`Manager extends Employee` 解决的是复用和类型关系；多态体现在 `Employee e = new Manager(); e.calculateSalary()`。继承是多态的前提之一，但两者不是同义词。
2. **以为重载是运行时多态**：`PayrollService.print(Employee)` 和 `print(Manager)` 在编译期就按静态类型选好了，不会因为对象实际是 `Manager` 就改选另一个版本。
3. **以为字段有多态**：`e.title` 取的是 `Employee.title`，不是 `Manager.title`；字段只是隐藏，不会覆盖。
4. **以为 `static` 方法可以重写**：`Employee.company()` 和 `Manager.company()` 是隐藏关系，调用看引用类型或类名。
5. **以为 `private` / `final` 方法可以重写**：`Manager.bonus` 是 `private`，子类不可见；`printPayslip()` 是 `final`，子类不能改流程。
6. **以为向上转型后对象变成了父类**：`Employee e = new Manager(...)` 之后，`e.getClass()` 仍然是 `Manager`，变的只是引用的静态类型。
7. **以为多态必须用抽象类或接口**：把 `Employee` 改成普通类并给 `calculateSalary()` 默认实现，多态仍然成立；抽象类和接口只是把契约显式化。
8. **以为多态能调用子类特有方法**：`e.getBonus()` 编译不通过；需要子类功能时，必须先 `instanceof` 检查再向下转型（见 [[instanceof]]）。
9. **以为 `@Override` 是多态的必要条件**：它只是编译期校验，不写也能构成重写；但强烈建议写，能及早发现签名写错。
10. **在构造方法中调用可重写方法**：会触发动态绑定，读到子类尚未初始化的字段，如 9.3 节的 `bonus=0.0`。

## 12. 小结

* 多态 = ==统一调用入口 + 不同实现 + 运行期决定==；
* 三要素：==继承 / 实现==、==方法重写==、==父类或接口引用指向子类或实现类对象==；
* 严谨地说，还必须通过==可重写的实例方法==调用，字段、`static`、`private`、`final`、构造方法都不参与；
* 编译期看引用的静态类型（能否调用、重载选谁），运行期看对象的实际类型（重写执行谁）；
* 运行时多态依赖[[动态绑定]]；重载是编译时多态；泛型是参数化多态；
* 多态让调用方依赖抽象，新增子类无需修改调用方，是[[面向抽象编程]]和[[开闭原则]]的基础。
