

## 集中式 vs 分布式

其他 VCS（CVS、SVN、Perforce 等）大多是==**集中式**==：版本库只存于一台中央服务器，本地只保留当前版本的一份拷贝，做任何操作都要连服务器。

Git 是==**分布式**==：==每个开发者本地都有一份**完整的版本库**，包含全部历史==。

| 方面    | 集中式（SVN/CVS） | 分布式（Git）       |
| ----- | ------------ | -------------- |
| 完整历史  | 只在服务器        | ==每台机器都有==     |
| 提交    | 必须联网         | ==本地即可提交==     |
| 服务器故障 | 历史可能全丢       | ==任一本地副本都能恢复== |
| 分支/合并 | 慢，通常不敢多用     | ==快，鼓励经常用==    |


## Git 观念上的不同

**存快照，不是存差异**

多数 VCS 记录的是"这一版相对上一版改了哪些行"；Git 记录的是==**每次提交时全部文件的快照**==（未变的文件只是指向同一份对象，并不重复存储）。因此切换分支、回退版本都极快。

**几乎一切都在本地完成**

因为历史就在本地，==查看日志、比较版本、提交、切分支都无需网络==，只有==推送（push）和拉取（fetch）才需要连服务器==。这让 Git 在飞机、地铁上照样能工作。

**完整性由内容保证**

Git 中一切内容在存储前都会计算 **SHA-1 校验和**，并用它来索引。任何文件被悄悄改动都会被发现，不可能"在 Git 不知情的情况下"改坏内容。

**分支是轻量的**

SVN 的分支实质是复制一份目录，代价高；Git 的分支只是一个 41 字节的指针，创建、切换、合并都在毫秒级。这正是 Git 工作流（功能分支、Pull Request）得以普及的基础。

## 与其他工具的简要对比

- **CVS / SVN**：集中式代表，概念简单、上手容易，但离线不可用、分支笨重，适合小团队或对历史要求不高的场景。
- **Perforce**：集中式，擅长管理**超大二进制资产**（游戏美术资源），但部署重、成本高。
- **Mercurial**：同为分布式，设计与 Git 相近、命令更一致，只是生态与流行度不及 Git。
- **Git**：分布式、快、分支便宜，加上 GitHub/GitLab 的普及，已成为事实标准；代价是命令多、概念（暂存区等）略陡。

## 一句话理解

> 其他 VCS 是"连到服务器上改文件"，Git 是"每人手里都有一整个人类的历史，改完再互相同步"。
