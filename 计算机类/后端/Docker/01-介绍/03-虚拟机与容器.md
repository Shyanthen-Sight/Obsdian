# 虚拟机与容器

| | 虚拟机 | 容器 |
| --- | --- | --- |
| 隔离层 | Hypervisor + 完整 Guest OS | 命名空间 + cgroups |
| 内核 | 每个 VM 一个 | 共享宿主内核 |
| 启动 | 秒级到分钟级 | 毫秒级到秒级 |
| 体积 | GB 级 | MB 级 |
| 密度 | 一台机器几十个 | 一台机器几百个 |
| 安全边界 | 强，硬件级隔离 | 较弱，内核漏洞可穿透 |

虚拟机把硬件虚拟化。Type 1 的 ESXi、KVM 直接跑在硬件上，Type 2 的 VirtualBox、VMware Workstation 跑在宿主系统上。每个 VM 有自己的内核，所以能跑不同版本甚至不同种类的系统。

容器只是给进程加了命名空间和 cgroups，内核还是宿主的。下面两条命令在容器内外看到的版本一样：

```bash
$ docker run --rm alpine uname -r
6.8.0-45-generic
$ uname -r
6.8.0-45-generic
```

这个实验解释了几个常见限制：容器里不能随便 `modprobe` 加载内核模块；Windows 容器必须和宿主 Windows 内核版本兼容；宿主内核爆出提权漏洞时，容器逃逸的风险比 VM 高。

## 隔离差在哪

共享内核意味着很多系统级操作会被挡住。比如在容器里改内核参数：

```bash
docker run --rm alpine sysctl -w vm.swappiness=10
# sysctl: permission denied on key "vm.swappiness"
```

加 `--privileged` 能改，但等于把宿主内核的控制权交出去；虚拟机里随便改，坏了只影响那台 VM。需要调内核、装驱动、加载模块的负载，容器不是好选择。

镜像分层还放大了密度优势：十个基于 `nginx` 的容器共享同一份只读层，磁盘上只有一份；虚拟机每个都要复制系统盘，快照和迁移也重得多。

## 怎么选

- 多租户、跑不可信代码、需要不同内核：虚拟机
- 内部服务、快速交付、高密度：容器
- 既要隔离又要效率：VM 里跑容器，或者用 Kata、gVisor 这类安全容器

生产上最常见的不是二选一。Kubernetes 节点本身就是 VM，容器跑在 VM 里，两层边界一起用；云厂商的托管集群也是这个结构。

> [!tip] 数字感受
> 同样 16GB 内存，虚拟机光系统就占 1–2GB，容器只占应用本身。启动 50 个容器可能几秒，启动 50 个 VM 要几分钟。
