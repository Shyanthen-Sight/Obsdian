## 一、三个基础组件

### 1.1 MyComponent：最小 `<script setup>`

```vue
<!-- src/components/MyComponent.vue -->
<script setup>
import { ref } from 'vue'

// 直接定义响应式数据，无需 return，自动暴露给模板
const msg = ref('连雨不知春去，一晴方觉夏深。')
</script>

<template>
  <h3>{{ msg }}</h3>
</template>
```

要点：

- `<script setup>` 顶层声明的 `msg` **自动暴露**给模板，不用 `return {}`。
- 没有 `export default`，编译器自动生成组件导出。
- 详见 [[setup语法糖]]。

### 1.2 FirstComponent：`v-model` 双向绑定

```vue
<!-- src/components/FirstComponent.vue -->
<template>
  <h2>{{ msg }}</h2>
  <input type="text" v-model="msg" />
</template>

<script setup>
import { ref } from 'vue'

const msg = ref('连雨不知春去，一晴方觉夏深。')
</script>
```

要点：

- `v-model` 在原生 `<input>` 上是 `:value` + `@input` 的语法糖。
- 输入框内容变化 → `msg` 更新 → `<h2>` 同步更新。
- **组件上的 `v-model`** 则是 `modelValue` prop + `update:modelValue` 事件，见 [[Exp2 子传父 emit]] 第七节。

### 1.3 SecondComponent：响应式全家桶

```vue
<!-- src/components/SecondComponent.vue -->
<template>
  <h2>计数：{{ count }}</h2>
  <h2>双倍计数：{{ dbIncrement }}</h2>
  <h2>watch count的信息:{{ watchMsg }}</h2>
  <h2>生命周期mouted信息:{{ lifeMouted }}</h2>
  <button @click="increment">增加</button>
  <button @click="decrement">减少</button>
</template>

<script setup>
import { computed, onMounted, ref, watch } from 'vue'

const count = ref(0)

const increment = () => {
  count.value++
}
// const decrement = () => {
//   count.value--
// }
function decrement() {
  return count.value--
}

const dbIncrement = computed(() => count.value * 2)

const watchMsg = ref('未改变')
watch(count, (newValue, oldValue) => {
  watchMsg.value = `count从${oldValue}变成了${newValue}`
})

const lifeMouted = ref('未挂载')
onMounted(() => {
  lifeMouted.value = '已挂载'
})
</script>
```

| API | 作用 | 本例表现 |
| --- | --- | --- |
| `ref(0)` | 响应式基本类型 | `count` 变化驱动视图 |
| `computed` | 派生状态，自动缓存 | `count × 2` |
| `watch` | 侦听变化并执行副作用 | 记录"从旧值到新值" |
| `onMounted` | 挂载后执行一次 | 文案变为"已挂载" |

> [!warning] 小笔误
> `lifeMouted` 少了一个 `n`（应为 `lifeMounted`），属于变量命名笔误，不影响运行。

> [!tip] 为什么 `decrement` 里 `return count.value--`？
> 这是"先返回旧值再自减"的写法。作为事件处理函数，返回值无人接收，效果等同于 `count.value--`。与上面的箭头函数 `increment` 形成两种写法对照。

## 二、工程入口与配置

### 2.1 入口链路

```text
index.html
  └── <script type="module" src="/src/main.js">
        └── createApp(App).mount('#app')
              └── App.vue
                    └── <Exp6_DynamicSlotName_Parent />
```

`index.html`：

```html
<div id="app"></div>
<script type="module" src="/src/main.js"></script>
```

`src/main.js`：

```js
// import './assets/main.css'
// import MyComponent from './components/MyComponent.vue'

import { createApp } from 'vue'
// import { createPinia } from 'pinia'

import App from './App.vue'
// import router from './router'

const app = createApp(App)

// app.use(createPinia())
// app.use(router)

// 全局注册组件，在main里一次注册，整个工程范围内均可直接使用。
// 在vue3和vite开发环境下，尽量避免或不用
// app.component('my-component', MyComponent)

app.mount('#app')
```

> [!important] 三点说明
> 1. **当前只挂载了 `App.vue`**：Pinia、Router、全局组件注册都被注释掉了，项目是一个"纯组件实验场"。
> 2. **全局注册被刻意注释**：源码注释明确说"Vue 3 + Vite 下尽量避免或不用"。原因是全局注册会让依赖关系隐形、不利于 tree-shaking。
> 3. **`App.vue` 当前演示 Exp6**，想切实验就改 import 与标签。

### 2.2 `App.vue`

  <Exp6_DynamicSlotName_Parent />

<script setup>
import Exp6_DynamicSlotName_Parent from './components/Exp6_DynamicSlotName_Parent.vue'

> [!tip] 切换实验模板
> ```vue

> </script>
>
> <template>
>   <Demo />
> </template>
> ```
> 把 `ExpN_XXX_Parent.vue` 换成任意一个 `_Parent` 文件即可。

### 2.3 `@` 别名的来历

`vite.config.js`：

```js
resolve: {
  alias: {
    '@': fileURLToPath(new URL('./src', import.meta.url)),
  },
},
```

`jsconfig.json`：

```json
{
  "compilerOptions": {
    "paths": { "@/*": ["./src/*"] }
  },
  "exclude": ["node_modules", "dist"]
}
```

- `vite.config.js` 让**构建工具**认识 `@`。
- `jsconfig.json` 让**编辑器**认识 `@`（跳转、提示）。
- 所以 Exp3 里可以写 `import loadingOverUrl from '@/assets/img/loadingOver.jpg'`。

## 五、把实验串起来看

```text
父组件 ──props──▶ 子组件 ──emit──▶ 父组件
   │
   └──插槽──▶ 子组件的"坑"里放父组件的结构
                 │
                 └──作用域插槽──▶ 子组件把数据递回父组件的结构
```

> [!success] 最后一句话
> **组件通信解决"数据怎么走"，插槽解决"结构怎么放"，作用域插槽是两者的交叉点。** 八个实验其实就是这一张图的八种展开方式。
