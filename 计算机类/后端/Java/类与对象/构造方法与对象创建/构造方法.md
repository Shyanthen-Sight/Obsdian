# Java 构造方法

> 关联笔记：[[类的声明]]、[[方法]]、[[重载]]、[[this关键字]]、[[父类的构造方法与子类的关系]]

## 一句话解释

**==构造方法是一段名字与类名完全相同==、==没有返回值类型的特殊方法==，==它只在 `new` 的时候被自动调用==，==用来给刚出生的对象做初始化。**==

字段（成员变量）描述对象的状态，方法描述对象的行为，而构造方法负责在对象被创建的那一刻，把这些状态摆到位。没有构造方法，`new` 出来的对象就是一堆没赋值的死数据。

---

## 一、最完整的语法结构

```java
[修饰符] 类名([参数列表]) {
    // 初始化代码
}
```

对比普通方法：

```java
[修饰符] 返回值类型 方法名([参数列表]) { 方法体 }   // 普通方法，有返回值类型
[修饰符]          类名([参数列表]) { 方法体 }       // 构造方法，没有返回值类型
```

普通方法与构造方法普通方法与构造方法的语法差别就是==构造方法没有返回值类型==，而且==方法名必须与类名相同==。

```java
public class Dog {
    private String name;

    // 这就是构造方法
    public Dog(String name) {
        this.name = name;
    }
}
```

创建对象时用 `new` 触发：

```java
Dog d = new Dog("旺财");
```

> [!note] 名字里的那个「构造」
> 中文叫构造方法，英文是 constructor（构造器）。它不叫「构造函数」，因为它不是普通的函数——它不返回任何东西，连 `void` 的位置都被占掉了。

---

## 二、逐段拆解

### 1. 修饰符

| 修饰符 | 作用 | 备注 |
| --- | --- | --- |
| `public` | 任何地方都能 `new` 出对象 | 最常见 |
| `protected` | 同包内、以及子类可以调用 | 抽象类里常用 |
| 默认（不写） | 只有同包内能 `new` | 少见 |
| `private` | 只有本类内部能 `new` | 用来禁止外部创建对象，见第五节 |
| `static` / `final` / `abstract` | 都不允许 | 写了直接编译报错 |

```java
public class Student {
    private String name;

    public Student(String name) {      // 对外公开的构造方法
        this.name = name;
    }

    private Student() { }              // 只有本类能用
}
```

> [!warning] 三个不能写的修饰符
> `static`、`final`、`abstract` 都不能修饰构造方法。
> 原因很直白：构造方法属于对象而不属于类，所以不能 `static`；它本来就不能被继承和重写，所以 `final` / `abstract` 也没有意义。

### 2. 方法名

==必须与类名完全相同，大小写也要一致==。

```java
public class Person {
    public Person() { }      // 正确
    // public person() { }   // 错误，这不是构造方法，而且缺返回值类型
}
```

### 3. 参数列表

==可以是 0 个到多个，写法和普通方法一样==（见 [[方法]]）。

```java
Dog() { }                          // 无参构造方法
Dog(String name) { }               // 一个参数
Dog(String name, int age) { }      // 两个参数
```

参数个数不同、类型不同，就构成不同的构造方法，这叫构造方法重载。

### 4. 方法体与返回值

- 方法体里写初始化代码，==最常见的就是给字段赋值==。
- **构造方法体内不能写 `return 值`**，只能写空的 `return;`（表示提前结束），因为构造方法没有返回值类型。

```java
public Dog(String name) {
    if (name == null) {
        return;              // 合法，提前结束初始化
    }
    this.name = name;
    // return name;         // 错误，构造方法不能返回值
}
```

### 5. 没有返回值类型

这是最容易出错的一点：

```java
public Dog() { }          // 正确，构造方法
public void Dog() { }     // 错误理解！这是普通方法，名字再像也不是构造方法
```

一旦在类名前面加上 `void`，它就被编译器当成一个普通的、碰巧与类同名的方法，`new Dog()` 就再也调不到它了。

## 三、默认构造方法

如果一个类里**一个构造方法都没写**，编译器会自动送一个无参空构造方法：

```java
public class Cat {
    private String name;

    // 编译器自动生成：public Cat() { }
}

new Cat();    // 合法，调用的就是编译器送的那个
```

但只要自己写了任意一个构造方法，这个默认的就不再生成：

```java
public class Cat {
    private String name;

    public Cat(String name) {      // 手写了一个带参的
        this.name = name;
    }
}

new Cat("咪咪");    // 合法
// new Cat();     // 编译错误：无参构造方法已不存在
```

想两个都能用，就把无参的那个也补上：

```java
public class Cat {
    private String name;

    public Cat() {}               // 手动补上无参构造
    public Cat(String name) {
        this.name = name;
    }
}
```

| 情况        | 编译器是否生成默认无参构造       |
| --------- | ------------------- |
| 一个构造方法都没写 | 生成                  |
| 只写了带参构造   | 不生成                 |
| 写了无参 + 带参 | 不生成（但你自己写了无参的，效果一样） |

> [!tip] 实践建议
> 用 IDE 或 Lombok 时，只要实体类里写了带参构造，就顺手加一个无参构造（如 `@NoArgsConstructor`）。很多框架（反射、JSON 反序列化）都会默认调无参构造，缺了它容易在运行期莫名报错。

## 四、构造方法重载

同一个类里可以写多个构造方法，只要参数列表不同，这就是重载（详见 [[重载]]）。

```java
public class Student {
    private String name;
    private int score;

    public Student() {                       // 无参
        this("匿名", 0);                      // 委托给下面的构造方法
    }

    public Student(String name) {            // 一个参数
        this(name, 0);
    }

    public Student(String name, int score) { // 两个参数
        this.name = name;
        this.score = score;
    }
}
```

调用：

```java
new Student();                  // 走第一个
new Student("小明");             // 走第二个
new Student("小明", 95);         // 走第三个
```

> [!note] 为什么常用 this(...) 委托
> 把真正的赋值逻辑集中到参数最全的那个构造方法里，其余构造方法通过 `this(...)` 转过去，避免同一段赋值代码抄好几遍。这也是重载最常见的实用场景。

---

## 五、this(...)：在构造方法里调用另一个构造方法

`this(...)` 表示「调用本类的另一个构造方法」，可以把初始化逻辑串起来。

规则有三条：

1. **`this(...)` 必须是构造方法的第一条语句。**
2. 一个构造方法里**只能调用一次** `this(...)`。
3. `this(...)` 和 `super(...)` **不能同时出现**在同一个构造方法里。

```java
public class Point {
    private int x;
    private int y;

    public Point() {
        this(0, 0);          // 必须放在第一行
    }

    public Point(int x, int y) {
        this.x = x;
        this.y = y;
    }
}
```

顺带区分两个 `this` 的用法：

| 写法         | 含义                     | 出现位置            |
| ---------- | ---------------------- | --------------- |
| `this.字段名` | ==指向当前对象的字段==，用于区分同名参数 | 任何实例方法/构造方法     |
| `this(参数)` | ==调用本类的另一个构造方法==       | ==只能是构造方法的第一行== |

```java
public Student(String name, int score) {
    this.name = name;      // this. 指向字段
    this.score = score;
}

public Student(String name) {
    this(name, 0);         // this(...) 调用另一个构造方法
}
```

更详细的 `this` 用法见 [[this关键字]]。

## 六、与 super(...) 的关系

子类构造方法执行时，父类的构造方法一定会被调用，这是 JVM 的保证，目的是让父类那部分字段先完成初始化。

- 如果子类构造方法里没写 `super(...)` 或 `this(...)`，编译器会自动在第一行插入 `super()`，即调用父类的无参构造方法。
- 如果父类只定义了带参构造方法，那么子类必须显式写 `super(参数)`，否则编译报错。

```java
class Parent {
    String name;

    Parent(String name) {          // 只定义了带参构造，没有无参的
        this.name = name;
    }
}

class Child extends Parent {
    Child() {
        super("默认名");             // 必须显式调用，否则编译不过
    }
}
```

关于调用顺序、父类构造中调用被子类重写的方法等坑，单独记在 [[父类的构造方法与子类的关系]] 里。

## 七、私有构造方法的作用

构造方法设为 `private`，外部就无法直接 `new` 出对象。常见有两种用途。

### 1. 工具类：禁止实例化

```java
public final class MathUtil {
    private MathUtil() { }         // 谁也别想 new 我

    public static int max(int a, int b) {
        return a > b ? a : b;
    }
}
```

全是静态方法的工具类没有实例化的意义，私有构造方法可以从语法层面挡住这种用法。JDK 里的 `Math`、`Arrays` 就是这么做的。

### 2. 单例模式：把创建权收归自己

```java
public class Singleton {
    private static final Singleton INSTANCE = new Singleton();

    private Singleton() { }        // 外部无法 new

    public static Singleton getInstance() {
        return INSTANCE;
    }
}
```

所有实例的创建都必须经过类自己的静态方法，从而保证整个程序里只有一个对象。

## 八、初始化顺序

创建一个对象时，各部分的执行顺序是先父后子、先静态后实例，构造方法排在这条流水线的最后：

1. 父类静态变量、静态代码块（只执行一次）
2. 子类静态变量、静态代码块（只执行一次）
3. 父类实例变量赋值、构造代码块
4. 父类构造方法
5. 子类实例变量赋值、构造代码块
6. 子类构造方法

单看一个类的话，顺序是：**父类构造 → 本类实例变量/构造代码块 → 本类构造方法**。

```java
public class Demo {
    int a = 1;                        // ① 实例变量赋值
    { System.out.println("构造代码块"); }  // ② 构造代码块
    Demo() { System.out.println("构造方法"); } // ③ 构造方法
}
```

要理解构造方法到底在哪一步干活，记住一句话：**构造方法体内的代码，是在实例变量已经赋过默认值和显式初值之后才执行的。**

---

## 九、构造方法不能被继承

构造方法不参与继承。子类不会「继承」父类的构造方法，只能通过 `super(...)` 去调用它。

```java
class Parent {
    Parent(int x) { }
}

class Child extends Parent {
    Child(int x) {
        super(x);         // 是「调用」，不是「继承」
    }
}
```

因此，如果一个类被声明为 `final`，或者构造方法都是 `private`，那么它实际上就失去了被继承的可能——子类根本没法完成 `super(...)` 这一步。

---

## 十、注意事项

1. **构造方法没有返回值类型**，连 `void` 都不能写；写了 `void` 就变成普通方法。
2. **方法名必须与类名完全一致**，包括大小写。
3. **`static`、`final`、`abstract` 不能修饰构造方法**。
4. **`this(...)` / `super(...)` 必须是第一条语句**，且两者不能共存于同一个构造方法。
5. **一旦手写了构造方法，编译器就不再生成默认无参构造**。需要无参版本要自己补。
6. **构造方法体内不能 `return 值`**，只能写空的 `return;`。
7. **构造方法可以被重载，但不能被重写**。
8. **抽象类也有构造方法**，虽然它不能被 `new`，但供子类 `super(...)` 调用。
9. **不要在构造方法里调用可被重写的方法**，子类字段可能还没初始化，容易出意外结果。

## 十一、常见面试题

| 问题 | 答案 |
| --- | --- |
| 构造方法与普通方法的区别？ | 名字必须与类名相同、没有返回值类型、只能靠 `new` 调用、不能被继承和重写 |
| 写 `void Dog() { }` 是构造方法吗？ | 不是，加了 `void` 就是普通方法 |
| 什么时候编译器会生成默认构造方法？ | 类里一个构造方法都没写时，生成一个空的公开无参构造 |
| 构造方法能重载吗？能重写吗？ | 能重载，不能重写 |
| `this(...)` 和 `super(...)` 能同时出现吗？ | 不能，且都必须是第一条语句 |
| 构造方法能被 `static` 修饰吗？ | 不能，构造方法属于对象 |
| 抽象类有构造方法吗？ | 有，但不能被 `new`，只供子类调用 |
| 单例模式为什么要用私有构造方法？ | 阻断外部 `new`，把创建权收归类自己的静态方法 |

## 十二、一句话总结

> **`[修饰符] 类名(参数列表) { 初始化代码 }` —— 名字必须与类名相同、没有返回值类型、只能被 `new` 触发，负责在对象诞生的那一刻把字段摆到位。**
