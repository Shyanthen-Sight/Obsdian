# 管理远程 —— git remote

> [!abstract] 一句话
> ==远程（remote）不过是给一串 URL 起的一个**名字**==。`origin` 不是 Git 的什么魔法关键字，它只是克隆时默认给"来源仓库"起的昵称。你在本地敲 `git remote add upstream git@github.com:team/repo.git`，等于告诉 Git："以后我说 `upstream`，就是指这个地址。"

---

## 一、先纠正一个直觉

很多人以为"远程"是 Git 服务器上真实存在的某个东西。**其实不是。**

远程信息**只存在你自己仓库的配置里**（`.git/config`），长这样：

```text
[remote "origin"]
	url = git@github.com:me/repo.git
	fetch = +refs/heads/*:refs/remotes/origin/*
```

> [!info] 远程 = 名字 + URL + 抓取规则
> - **名字**：`origin`、`upstream`……随你怎么起
> - **URL**：真正的地址（HTTPS 或 SSH）
> - **fetch 规则**：告诉 Git "把远程的分支抓下来后，放在本地的哪个命名空间"

所以"管理远程"其实就是**增删改这几行配置**，它不联网、不传数据，只是登记一个地址。真正和数据打交道的是 [[fetch跟pull]] 与 [[推送远程]]。

## 二、查看现有远程

```bash
git remote                    # 只列名字
git remote -v                 # ★ 连 URL 一起看（fetch / push 各一行）
git remote show origin        # 详细信息：分支跟踪、push/pull 对应关系
```

`git remote -v` 的输出：

```text
origin  git@github.com:me/repo.git (fetch)
origin  git@github.com:me/repo.git (push)
```

> [!info] 为什么 fetch 和 push 各显示一行？
> 因为两者**可以配成不同的地址**。绝大多数时候一样，但有的团队用"只读镜像拉、主仓库推"的混合配置（见第六节 `pushurl`）。

`git remote show origin` 会额外告诉你：

```text
* remote origin
  Fetch URL: git@github.com:me/repo.git
  Push  URL: git@github.com:me/repo.git
  HEAD branch: main
  Remote branches:
    main    tracked
    dev     tracked
  Local ref configured for 'git push':
    main pushes to main (up to date)
```

> [!tip] 想知道"我这条本地分支推给谁、从谁拉"？
> `git remote show <名字>` 是唯一一处把这些关系**一次摊开**的地方，比 `-v` 信息量大。

## 三、添加远程

```bash
git remote add <名字> <URL>              # 起个名，登记一个地址
git remote add origin git@github.com:me/repo.git
git remote add upstream https://github.com/team/repo.git
```

> [!note] 名字只是标签
> `git remote add bob git@...` 完全合法，之后你就用 `git push bob main`。
> 只是**社区惯例**让 `origin` 表示"我克隆来的那个"，`upstream` 表示"上游官方仓库"。约定俗成，便于协作时彼此看懂。

> [!warning] 一个名字只能对应一个远程
> 若 `origin` 已存在，再 `git remote add origin <新URL>` 会报 `error: remote origin already exists.`。
> 想换地址用 `git remote set-url`（下一节），别 add。

## 四、改名与改地址

```bash
git remote rename <旧名> <新名>          # 改名
git remote set-url <名字> <新URL>        # 换 fetch 与 push 的地址
git remote set-url --push <名字> <URL>   # ★ 只换 push 地址
git remote get-url <名字>                # 打印当前 URL（脚本里好用）
```

> [!success] `rename` 很贴心：会顺手改掉本地跟踪引用
> 执行 `git remote rename origin upstream` 后，你本地原来的一堆
> `refs/remotes/origin/main` 会**自动变成** `refs/remotes/upstream/main`。
> 你不用手动清理——这正是为什么**改名要用 `git remote rename`，而不是去编辑 `.git/config`**。

> [!tip] HTTPS 与 SSH 之间切换
> 同一仓库换个协议，就是换 URL：
> ```bash
> # 从 HTTPS 换成 SSH（免每次输密码）
> git remote set-url origin git@github.com:me/repo.git
> # 从 SSH 换回 HTTPS
> git remote set-url origin https://github.com/me/repo.git
> ```

## 五、删除远程

```bash
git remote remove <名字>      # 与 git remote rm 等价
git remote rm origin
```

> [!warning] 删远程 ≠ 删远程仓库
> `git remote remove` 只删**你本地的登记信息**，顺带清掉该远程对应的**远程跟踪分支**（`refs/remotes/origin/*`）。
> 它**绝不会**去动服务器上的任何东西。真正的"删远程分支"是 `git push origin --delete <分支>`，见 [[删除分支]] 与 [[推送远程]]。

## 六、多个远程与常见工作流

一个本地仓库可以挂多个远程，这是 fork 工作流的基础：

```bash
git remote add upstream https://github.com/官方/repo.git   # 上游官方
# origin 仍是"我 fork 出来的那份"
git fetch upstream                # 从官方拉最新
git switch -c fix upstream/main   # 基于官方的 main 开发
git push origin fix               # 推回我的 fork
```

> [!info] 典型三角关系
> ```text
>        upstream (官方)  ←── fetch 同步
>            │
>   fork 出 │ 我提交 PR 回 upstream
>            ▼
>        origin (我的 fork) ←── push 我的分支
>            │
>   clone   │ pull
>            ▼
>        本地仓库
> ```
> `origin` 负责"我推哪去"，`upstream` 负责"我拉哪来"。这就是为什么这两个名字值得熟记。

> [!tip] `pushurl`：拉与推走不同地址
> ```bash
> git remote set-url         origin https://mirror.example.com/repo.git  # 拉：只读镜像
> git remote set-url --push origin git@github.com:me/repo.git            # 推：我有写权限的
> ```
> 读多写少、或想走加速镜像时很实用。

## 七、完整示例

```bash
git remote -v                         # 1. 先看现在挂了哪些远程
git remote add upstream git@github.com:team/repo.git   # 2. 加一个上游
git remote -v                         # 3. 确认登记成功
git fetch upstream                    # 4. 拉取上游（见 fetch 跟 pull）
git remote show upstream              # 5. 看看跟踪关系是否清楚
git remote rename upstream official   # 6. 名字不满意就改
git remote remove official            # 7. 不想要了就删
```

> [!success] 成功标志
> 每一步后 `git remote -v` 的列表随之增减；
> `rename` 之后用 `git branch -r` 能看到跟踪引用也换了前缀。

## 八、常见困惑

> [!question] `origin` 这个名字是不是必须的？
> 不是。它只是 `git clone` 的默认名。你完全可以 `git remote add bob ...` 并用 `git push bob main`。
> 但团队协作时请沿用惯例，否则别人看不懂你的命令。

> [!question] 我改了远程 URL，本地的提交会丢吗？
> 不会。改 URL 只动配置里一行字，**本地所有提交、分支、历史原封不动**。
> 下次 fetch / push 就连到新地址去了。

> [!question] 为什么我 `git remote remove origin` 后，`git branch -r` 还残留东西？
> 通常不会——remove 会一并清掉对应跟踪引用。若确实残留，检查是不是手动改过 `.git/config`，
> 或用 `git fetch --prune` 清理。详见 [[删除分支]]。

> [!question] clone 和 remote add 有什么区别？
> `clone` = 建目录 + `init` + **隐式地 `remote add origin`** + 抓取 + 检出。
> 也就是说克隆**顺便帮你登记好了 origin**；`remote add` 则是给"已存在的本地仓库"补登记一个远程。见 [[克隆仓库]]。

> [!question] 一台机器上能同时配 HTTPS 和 SSH 两个远程吗？
> 能。它们就是两个不同名字的远程（如 `origin` 用 SSH、`public` 用 HTTPS），
> 你按需 fetch / push 即可。

---

> [!quote] 一句话记忆
> **远程就是"地址簿里的一行"**：`add` 登记、`-v` 查看、`rename` 改名（连带更新跟踪引用）、`set-url` 换址、`remove` 销号。==它只管记账，不搬数据==——搬数据是 push 与 fetch。
