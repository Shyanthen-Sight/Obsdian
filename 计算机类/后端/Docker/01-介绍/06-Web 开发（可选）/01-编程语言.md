# 编程语言

Docker 不挑语言，但语言决定了镜像怎么分层。编译型语言可以把构建工具留在构建阶段，最终镜像只放二进制；解释型语言得把运行时和依赖一起带上，重点变成"别把开发依赖装进去"。

| 语言 | 常见构建方式 | 运行镜像里留什么 |
| --- | --- | --- |
| Go | 静态编译 + 多阶段 | 一个二进制，甚至 scratch |
| Rust | release 构建 + 多阶段 | 二进制和 libc |
| Node | `npm ci` + 多阶段 | `node_modules` 和构建产物 |
| Python | 虚拟环境/uv + 多阶段 | 解释器、依赖、源码 |
| Java | Maven/Gradle + JRE | jar 和 JRE |

Go 的典型写法：

```dockerfile
FROM golang:1.23 AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o /app ./cmd/server

FROM gcr.io/distroless/static-debian12
COPY --from=build /app /app
USER nonroot:nonroot
ENTRYPOINT ["/app"]
```

`CGO_ENABLED=0` 得到静态二进制，才能放进没有 libc 的 distroless/static 或 scratch；`-ldflags="-s -w"` 去掉符号表和调试信息，体积能小几 MB。`COPY go.mod go.sum` 单独一层，源码改动时依赖缓存还能命中。

Node 项目：

```dockerfile
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:20-alpine
WORKDIR /app
ENV NODE_ENV=production
COPY package*.json ./
RUN npm ci --omit=dev && npm cache clean --force
COPY --from=build /app/dist ./dist
USER node
CMD ["node", "dist/server.js"]
```

`npm ci` 按 lockfile 安装，比 `npm install` 可复现；`--omit=dev` 去掉测试和构建依赖。带原生模块的包（`sharp`、`bcrypt`）在 Alpine 上可能要装 `python3 make g++`，或者干脆用 `node:20-slim`。

Python 和 Java 的思路一样：构建阶段装编译器/构建工具，运行阶段只留产物。Python 注意 `--no-cache-dir`，Java 用 JRE 而不是 JDK，Spring Boot 可以分层解包 jar 提升缓存命中。

> [!tip] 先写 .dockerignore
> `node_modules`、`.git`、`target`、`dist`、本地 `.env` 都排除掉。构建上下文小，`COPY . .` 才不会把无关文件塞进镜像，也能避免密钥泄漏。
