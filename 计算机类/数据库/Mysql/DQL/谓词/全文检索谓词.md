# 全文检索谓词 —— `MATCH ... AGAINST`

> [!abstract] 一句话
> `MATCH (列) AGAINST ('关键词')` 是 MySQL 的**全文检索谓词**，靠 `FULLTEXT` 倒排索引工作，能做分词、相关性排序和布尔查询。
> 它是 `LIKE '%关键词%'` 的==**大文本替代方案**==，但==**必须先建 `FULLTEXT` 索引，且列清单必须与索引一致**==。

> [!info] 与其它笔记的分工
> 通配匹配见 [[LIKE谓词]]；正则见 [[REGEXP谓词]]。
> 本篇讲 `MATCH ... AGAINST` 的三种模式、布尔语法、中文分词、相关性与限制。

---

## 一、语法

```sql
MATCH (col1, col2, ...) AGAINST ('搜索词' [搜索模式])
```

搜索模式：

```sql
IN NATURAL LANGUAGE MODE            -- 自然语言模式（默认）
IN NATURAL LANGUAGE MODE WITH QUERY EXPANSION
IN BOOLEAN MODE                     -- 布尔模式
WITH QUERY EXPANSION                -- 等价于 NATURAL LANGUAGE MODE WITH QUERY EXPANSION
```

```sql
SELECT * FROM article
WHERE MATCH (title, body) AGAINST ('MySQL 索引');
```

> [!important] 前提：必须有 `FULLTEXT` 索引
> ```sql
> ALTER TABLE article ADD FULLTEXT INDEX ft_article (title, body);
> ```
> 没有全文索引，`MATCH ... AGAINST` 会报错：
> `ERROR 1191 (HY000): Can't find FULLTEXT index matching the column list`

---

## 二、建全文索引

```sql
-- 建表时
CREATE TABLE article (
    id    INT PRIMARY KEY AUTO_INCREMENT,
    title VARCHAR(200),
    body  TEXT,
    FULLTEXT INDEX ft_article (title, body)
) ENGINE=InnoDB;

-- 已有表追加
ALTER TABLE article ADD FULLTEXT INDEX ft_article (title, body);
```

> [!warning] `MATCH` 的列必须和索引列完全一致
> 索引是 `(title, body)`，就只能 `MATCH (title, body)`。
> `MATCH (title)` 或 `MATCH (title, body, author)` 都会报 `1191`。
> 需要单独搜某一列时，为它单独建一个全文索引。
> **例外**：MyISAM 表的布尔模式可以对未建全文索引的列做搜索（但很慢）；InnoDB 没有这个例外。

### 2.1 InnoDB vs MyISAM

| 维度 | InnoDB | MyISAM |
| --- | --- | --- |
| 事务 | ✅ | ❌ |
| 全文索引 | ✅（5.6+） | ✅ |
| 最小词长 | `innodb_ft_min_token_size`（默认 3） | `ft_min_word_len`（默认 4） |
| 停用词 | `innodb_ft_server_stopword_table` | `ft_stopword_file` |
| 50% 阈值 | ❌ 无 | ✅ 自然语言模式有 |

> [!tip] 生产环境优先 InnoDB
> InnoDB 支持事务、行锁、崩溃恢复，全文检索能力也足够。
> 除非遗留系统，不要为了全文索引选 MyISAM。

## 三、自然语言模式（默认）

```sql
SELECT id, title,
       MATCH (title, body) AGAINST ('MySQL 索引') AS score
FROM article
WHERE MATCH (title, body) AGAINST ('MySQL 索引')
ORDER BY score DESC;
```

特点：

- 按**词**匹配，不是按子串；
- 返回一个**相关性分数**（relevance），可以 `ORDER BY`；
- 默认忽略**停用词**（the、a、的、了等）和**过短的词**；
- MyISAM 下还会忽略"出现在超过 50% 行中的词"（InnoDB 没有这个规则）。

> [!warning] 自然语言模式不是"包含子串"
> `AGAINST ('索引')` 匹配的是分词后的"索引"这个词，不是 `LIKE '%索引%'`。
> 如果字段是 `"数据库索引优化"`，分词后可能匹配；如果是 `"索引优化"` 这类没有空格的连续中文，需要 `ngram` 解析器（见第六节）。

## 四、布尔模式

布尔模式支持操作符，适合精确控制：

```sql
SELECT * FROM article
WHERE MATCH (title, body) AGAINST ('+MySQL -Oracle' IN BOOLEAN MODE);
```

| 操作符 | 含义 | 示例 |
| --- | --- | --- |
| `+` | 必须包含 | `+MySQL` |
| `-` | 必须不包含 | `-Oracle` |
| `>` | 提高相关性权重 | `>MySQL` |
| `<` | 降低相关性权重 | `<MySQL` |
| `~` | 降低相关性（否定权重） | `~MySQL` |
| `*` | 后缀通配 | `MySQ*` |
| `"..."` | 短语匹配 | `"MySQL 索引"` |
| `()` | 分组 | `+(MySQL Redis) -Oracle` |
| `@distance` | 词间距离（InnoDB） | `"MySQL 索引" @5` |

```sql
-- 必须包含 MySQL，且不能包含 Oracle
WHERE MATCH (title, body) AGAINST ('+MySQL -Oracle' IN BOOLEAN MODE);

-- 包含 MySQL 或 Redis 任意一个
WHERE MATCH (title, body) AGAINST ('MySQL Redis' IN BOOLEAN MODE);

-- 短语匹配
WHERE MATCH (title, body) AGAINST ('"InnoDB 全文索引"' IN BOOLEAN MODE);

-- 前缀匹配
WHERE MATCH (title, body) AGAINST ('optim*' IN BOOLEAN MODE);
```

> [!note] 布尔模式不排序
> 布尔模式主要回答"匹配不匹配"，相关性排序能力弱于自然语言模式。
> 需要排序时，可以仍用自然语言模式计算分数，或结合 `ORDER BY` 其他字段。

## 五、查询扩展

```sql
SELECT * FROM article
WHERE MATCH (title, body) AGAINST ('MySQL' WITH QUERY EXPANSION);
```

查询扩展（blind query expansion）会：

1. 先用原关键词搜一遍；
2. 从结果中提取高频词；
3. 用"原词 + 扩展词"再搜一遍。

适合"关键词太短、结果太少"的场景，但容易**引入噪声**，相关性可能下降。

> [!warning] 查询扩展要谨慎
> 它会让结果集变大、变模糊。生产环境建议先用自然语言模式，确实需要再开扩展。

## 六、中文与 `ngram` 解析器

MySQL 默认的全文解析器按**空格和标点**分词，对中文不友好（一整句可能被当成一个词）。

解决方案：使用 `ngram` 解析器。

```sql
CREATE TABLE article (
    id    INT PRIMARY KEY AUTO_INCREMENT,
    title VARCHAR(200),
    body  TEXT,
    FULLTEXT INDEX ft_article (title, body) WITH PARSER ngram
) ENGINE=InnoDB;
```

`ngram` 会把中文切成 n 元组（默认 `ngram_token_size = 2`），从而支持中文关键词检索。

```sql
-- 中文搜索
SELECT * FROM article
WHERE MATCH (title, body) AGAINST ('数据库' IN BOOLEAN MODE);
```

> [!tip] 中文全文检索的参数
> - `ngram_token_size`：默认 2，决定切词粒度；
> - 查询词长度小于 token size 时可能搜不到；
> - 修改参数后需要**重建全文索引**。
> 数据量大、检索要求高时，仍建议用 Elasticsearch 等专用搜索引擎。

## 七、相关性与排序

```sql
SELECT id, title,
       MATCH (title, body) AGAINST ('MySQL 索引') AS score
FROM article
WHERE MATCH (title, body) AGAINST ('MySQL 索引')
ORDER BY score DESC
LIMIT 20;
```

- `MATCH ... AGAINST` 在 `SELECT` 里返回**相关性分数**（`FLOAT`）；
- 在 `WHERE` 里作为过滤条件；
- 分数受词频、文档长度、词在多少文档中出现等因素影响；
- 可以和其他条件组合：

```sql
WHERE MATCH (title, body) AGAINST ('MySQL')
  AND created_at >= '2026-01-01'
```

> [!note] 全文索引 + 普通索引的组合
> MySQL 可能先用普通索引缩小范围，再用全文条件过滤，也可能反过来。
> 用 `EXPLAIN` 看实际计划；必要时用 `FORCE INDEX` 或调整查询结构。

## 八、限制与坑

> [!danger] 常见限制
> 1. **列清单必须与某个 `FULLTEXT` 索引完全一致**，否则 `1191`。
> 2. **停用词和短词会被忽略**：搜 `the`、`a`、`的` 可能没有结果。
> 3. **自然语言模式按词匹配**，不是子串匹配；中文需要 `ngram`。
> 4. **MyISAM 有 50% 阈值**：常见词可能被忽略；InnoDB 没有。
> 5. **`MATCH` 不能用于没有全文索引的列**。
> 6. **布尔模式的 `-` 必须配合至少一个 `+` 或普通词**，否则可能返回空集。
> 7. **全文索引更新有开销**：频繁写入的大表要评估维护成本。

```sql
-- ❌ 列清单与索引不一致
ALTER TABLE article ADD FULLTEXT INDEX ft_title (title);
SELECT * FROM article WHERE MATCH (title, body) AGAINST ('MySQL');  -- 1191

-- ✅ 与索引一致
SELECT * FROM article WHERE MATCH (title) AGAINST ('MySQL');
```

> [!failure] `MATCH` 和 `LIKE` 混着理解
> `MATCH ... AGAINST ('索引')` 不是 `LIKE '%索引%'`。
> 前者按分词后的词匹配，后者按字符子串匹配。语义不同，结果自然不同。

> [!failure] 忘了建索引
> 直接写 `MATCH` 会报 `1191`。先 `ALTER TABLE ... ADD FULLTEXT`。

> [!failure] 中文没配 `ngram`
> 一整句中文可能被当成一个词，搜不到。建索引时加 `WITH PARSER ngram`。

## 九、`MATCH` vs `LIKE` vs `REGEXP`

| 维度 | `MATCH ... AGAINST` | `LIKE` | `REGEXP` |
| --- | --- | --- | --- |
| 索引 | ✅ 全文倒排索引 | 仅前缀 | ❌ |
| 分词 | ✅ | ❌ | ❌ |
| 相关性排序 | ✅ | ❌ | ❌ |
| 布尔查询 | ✅ | ❌ | 部分 |
| 中文 | ✅（ngram） | ✅（子串） | ✅（子串） |
| 大文本性能 | ✅ | ❌ 全表 | ❌ 全表 |
| 精确子串 | ❌ | ✅ | ✅ |

> [!tip] 选择顺序
> - 大文本、按关键词搜 → `MATCH ... AGAINST` + `FULLTEXT`；
> - 小表、精确子串 → `LIKE`；
> - 复杂模式、小数据量 → `REGEXP`；
> - 搜索体验要求高 → Elasticsearch / OpenSearch。

## 十、速查表

| 需求 | 写法 |
| --- | --- |
| 建全文索引 | `ALTER TABLE t ADD FULLTEXT INDEX ft (col1, col2)` |
| 自然语言搜索 | `MATCH (col1, col2) AGAINST ('词')` |
| 布尔搜索 | `... AGAINST ('+词1 -词2' IN BOOLEAN MODE)` |
| 短语匹配 | `... AGAINST ('"短语"' IN BOOLEAN MODE)` |
| 前缀匹配 | `... AGAINST ('词*' IN BOOLEAN MODE)` |
| 查询扩展 | `... AGAINST ('词' WITH QUERY EXPANSION)` |
| 相关性排序 | `SELECT MATCH(...) AGAINST(...) AS score ... ORDER BY score DESC` |
| 中文 | 建索引时 `WITH PARSER ngram` |
| 检查索引 | `SHOW INDEX FROM t` |
