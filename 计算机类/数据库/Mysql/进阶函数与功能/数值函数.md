# 数值函数 —— 取整、取余、舍入与数学运算

> [!abstract] 一句话
> 数值函数不难，难的是**选对口径**：`ROUND` 是四舍五入、`TRUNCATE` 是直接截断、`CEIL` / `FLOOR` 往哪边取整、`MOD` 的符号跟谁走。再叠加 **`DECIMAL` 精确 vs `FLOAT` / `DOUBLE` 近似**，金额算错往往就出在这几个字上。

---

> [!example] 本篇示例数据
> 下面用一张 `product` 表演示。`price` 是 `DECIMAL`（精确），`cost` 是 `DOUBLE`（近似）——同一个数用两种类型存，就是为了对比精度差异。

```sql
DROP TABLE IF EXISTS product;
CREATE TABLE product (
    id    INT           PRIMARY KEY,
    name  VARCHAR(50)   NOT NULL,
    price DECIMAL(10,2) NOT NULL,
    cost  DOUBLE        NOT NULL,
    stock INT           NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

INSERT INTO product (id, name, price, cost, stock) VALUES
(1, '键盘',   199.00, 120.5,   35),
(2, '鼠标',    89.90,  45.25,   0),
(3, '显示器', 1299.00, 800.75, 12),
(4, '耳机',    25.50,  18.333, 100),
(5, '硬盘',   499.99, 320.4,    7);
```

`SELECT * FROM product;`：

```
+----+--------+---------+---------+-------+
| id | name   | price   | cost    | stock |
+----+--------+---------+---------+-------+
|  1 | 键盘   |  199.00 |   120.5 |    35 |
|  2 | 鼠标   |   89.90 |   45.25 |     0 |
|  3 | 显示器 | 1299.00 |  800.75 |    12 |
|  4 | 耳机   |   25.50 |  18.333 |   100 |
|  5 | 硬盘   |  499.99 |   320.4 |     7 |
+----+--------+---------+---------+-------+
```

## 一、先记四条总规则

### 1.1 精确数 vs 近似数

| 类型 | 存储方式 | 典型用途 | 精度 |
| --- | --- | --- | --- |
| `DECIMAL(M,D)` | 十进制精确存储 | **金额**、库存、评分 | 精确 |
| `FLOAT` / `DOUBLE` | 二进制浮点近似 | 科学计算、坐标 | 有误差 |
| `INT` / `BIGINT` | 整数 | 计数、id | 精确 |

```sql
-- DECIMAL 字面量：精确
SELECT 0.1 + 0.2 = 0.3;              -- 1（真）

-- DOUBLE 字面量（科学计数法 e0）：近似
SELECT 0.1e0 + 0.2e0 = 0.3e0;        -- 0（假）
SELECT 0.1e0 + 0.2e0;                -- 0.30000000000000004
```

> [!danger] 金额一律 `DECIMAL`，不要 `FLOAT` / `DOUBLE`
> 浮点是二进制近似存储，`0.1 + 0.2` 在浮点里不等于 `0.3`。
> 一笔订单差一分钱，对账时就是事故。见 [[Create Table]] 的类型选型。

### 1.2 `ROUND` 是舍入，`TRUNCATE` 是截断

```sql
SELECT ROUND(2.9);        -- 3
SELECT TRUNCATE(2.9, 0);  -- 2   ← 直接砍掉小数，不四舍五入
```

### 1.3 除零不报错，返回 `NULL`

```sql
SELECT 10 / 0;      -- NULL（附一条 warning）
SELECT 10 DIV 0;    -- NULL
SELECT MOD(10, 0);  -- NULL
```

> [!warning] `SELECT` 里除零是 `NULL`，`INSERT` 里可能是错误
> 在严格 SQL 模式下，把 `1/0` 写进 `INSERT` / `UPDATE` 可能直接报 `ERROR 1365 (22012): Division by 0`。
> 不管哪种，业务代码都不该依赖"除零会变 NULL"来兜底，应该显式用 `NULLIF` 防住（见 [[条件]]）。

### 1.4 负数取整看方向

| 表达式 | 结果 | 规则 |
| --- | --- | --- |
| `CEIL(1.2)` | `2` | 向上（朝 `+∞`） |
| `CEIL(-1.2)` | `-1` | 向上（朝 `+∞`，不是朝 0） |
| `FLOOR(1.8)` | `1` | 向下（朝 `-∞`） |
| `FLOOR(-1.2)` | `-2` | 向下（朝 `-∞`） |
| `ROUND(-2.5)` | `-3` | 四舍五入，远离 0 |
| `TRUNCATE(-2.9, 0)` | `-2` | 截断，朝 0 |

> [!tip] 一句话区分
> **`CEIL` 永远往大了走，`FLOOR` 永远往小了走**（在数轴上，不是绝对值）。
> **`TRUNCATE` 永远朝 0 砍**，所以 `-2.9` 变 `-2`。

## 二、绝对值、符号与取整

### 2.1 `ABS` / `SIGN`

```sql
SELECT ABS(-5);        -- 5
SELECT ABS(5);         -- 5
SELECT ABS(NULL);      -- NULL

SELECT SIGN(-5);       -- -1
SELECT SIGN(0);        -- 0
SELECT SIGN(5);        -- 1
SELECT SIGN(NULL);     -- NULL
```

> [!note] `SIGN` 只返回三种值
> `-1 / 0 / 1`。它常用于"判断涨跌方向"，但注意 `SIGN(0.0001)` 也是 `1`，不区分大小。

### 2.2 `CEIL` / `CEILING` / `FLOOR`

```sql
SELECT CEIL(1.2);       -- 2
SELECT CEIL(1.0);       -- 1
SELECT CEIL(-1.2);      -- -1
SELECT CEILING(1.2);    -- 2，CEIL 的别名

SELECT FLOOR(1.8);      -- 1
SELECT FLOOR(1.0);      -- 1
SELECT FLOOR(-1.2);     -- -2
```

```sql
SELECT id, name, price,
       CEIL(price)  AS 向上取整,
       FLOOR(price) AS 向下取整
FROM product;
```

```
+----+--------+---------+----------+----------+
| id | name   | price   | 向上取整 | 向下取整 |
+----+--------+---------+----------+----------+
|  1 | 键盘   |  199.00 |      199 |      199 |
|  2 | 鼠标   |   89.90 |       90 |       89 |
|  3 | 显示器 | 1299.00 |     1299 |     1299 |
|  4 | 耳机   |   25.50 |       26 |       25 |
|  5 | 硬盘   |  499.99 |      500 |      499 |
+----+--------+---------+----------+----------+
```

### 2.3 `ROUND`（四舍五入）

```sql
ROUND(X)          -- 取整
ROUND(X, D)       -- 保留 D 位小数
ROUND(X, -D)      -- 把小数点左边 D 位变成 0
```

```sql
SELECT ROUND(1.4);          -- 1
SELECT ROUND(1.5);          -- 2
SELECT ROUND(1.298, 1);     -- 1.3
SELECT ROUND(1.298, 0);     -- 1
SELECT ROUND(23.298, -1);   -- 20
SELECT ROUND(25.5, -1);     -- 30
```

```sql
SELECT name, price,
       ROUND(price, 1) AS 保留一位,
       ROUND(price, 0) AS 取整,
       ROUND(price,-1) AS 十位取整
FROM product;
```

```
+--------+---------+----------+------+----------+
| name   | price   | 保留一位 | 取整 | 十位取整 |
+--------+---------+----------+------+----------+
| 键盘   |  199.00 |    199.0 |  199 |      200 |
| 鼠标   |   89.90 |     89.9 |   90 |       90 |
| 显示器 | 1299.00 |   1299.0 | 1299 |     1300 |
| 耳机   |   25.50 |     25.5 |   26 |       30 |
| 硬盘   |  499.99 |    500.0 |  500 |      500 |
+--------+---------+----------+------+----------+
```

> [!danger] 精确数和近似数的舍入规则可能不同
> - **精确数**（`DECIMAL`、整数）：`ROUND` 用"**四舍五入、远离 0**"，所以 `ROUND(2.5) = 3`、`ROUND(-2.5) = -3`。
> - **近似数**（`DOUBLE` / 科学计数法）：结果取决于 C 库，很多系统用"**四舍六入五成双**"（银行家舍入），`ROUND(2.5e0)` 可能是 `2`。
>
> ```sql
> SELECT ROUND(2.5);        -- 3（DECIMAL 字面量，精确）
> SELECT ROUND(2.5e0);      -- 2（DOUBLE，银行家舍入，常见结果）
> SELECT ROUND(2.675e0, 2); -- 2.67（不是 2.68，浮点表示本身就不精确）
> ```
>
> 金额计算请用 `DECIMAL`，不要用 `DOUBLE`；需要严格控制舍入规则时，在应用层或用 `DECIMAL` 显式处理。

### 2.4 `TRUNCATE`（截断）

```sql
TRUNCATE(X, D)
```

```sql
SELECT TRUNCATE(1.999, 2);     -- 1.99
SELECT TRUNCATE(1.999, 0);     -- 1
SELECT TRUNCATE(-1.999, 0);    -- -1
SELECT TRUNCATE(123.456, -1);  -- 120
SELECT TRUNCATE(123.456, -2);  -- 100
SELECT TRUNCATE(123.456, -3);  -- 0
```

> [!tip] `D` 可以是负数
> `TRUNCATE(X, -1)` 把个位砍掉，`TRUNCATE(X, -2)` 把十位和个位一起砍掉。
> 这在做"按百元取整""按千元取整"时很好用。

> [!warning] `TRUNCATE` 不改变数据类型
> `TRUNCATE(123.456, 2)` 仍是 `DECIMAL`，只是小数位变少。
> 它不会像 `CAST(... AS SIGNED)` 那样改变类型。

## 三、取余与整除

### 3.1 `MOD` / `%`

```sql
MOD(N, M)
N % M
```

```sql
SELECT MOD(10, 3);      -- 1
SELECT 10 % 3;          -- 1，等价写法
SELECT MOD(10, 4);      -- 2
SELECT MOD(10, 0);      -- NULL
```

> [!danger] 负数取余：符号跟着**被除数**
> ```sql
> SELECT MOD(-10,  3);   -- -1
> SELECT MOD( 10, -3);   --  1
> SELECT MOD(-10, -3);   -- -1
> ```
> 结果的正负号由**第一个参数**（被除数）决定，不是除数。
> 这和数学上的"模运算"（结果永远非负）不一样，跨语言迁移时要特别小心。

```sql
SELECT name, price,
       MOD(price, 10) AS 除10余数,
       price DIV 10   AS 整除10
FROM product;
```

```
+--------+---------+----------+--------+
| name   | price   | 除10余数 | 整除10 |
+--------+---------+----------+--------+
| 键盘   |  199.00 |     9.00 |     19 |
| 鼠标   |   89.90 |     9.90 |      8 |
| 显示器 | 1299.00 |     9.00 |    129 |
| 耳机   |   25.50 |     5.50 |      2 |
| 硬盘   |  499.99 |     9.99 |     49 |
+--------+---------+----------+--------+
```

### 3.2 `DIV` 与 `/`

| 运算符 | 含义 | 示例 | 结果 |
| --- | --- | --- | --- |
| `/` | 小数除法 | `10 / 4` | `2.5000` |
| `DIV` | 整数除法，**朝 0 截断** | `10 DIV 4` | `2` |
| `MOD` / `%` | 取余 | `10 MOD 4` | `2` |

```sql
SELECT 10 / 4;        -- 2.5000
SELECT 10 DIV 4;      -- 2
SELECT -10 DIV 3;     -- -3
SELECT 10 DIV -3;     -- -3
SELECT -10 DIV -3;    -- 3
```

> [!danger] `DIV` 不是 `FLOOR`
> ```sql
> SELECT -10 DIV 3;        -- -3（朝 0 截断）
> SELECT FLOOR(-10 / 3);   -- -4（朝 -∞）
> ```
> 正数时两者一样，负数时差 1。分页、分桶如果允许负数，别想当然用 `DIV`。

### 3.3 业务里的三种用法

```sql
-- 1. 判断奇偶：id 为奇数
SELECT * FROM product WHERE MOD(id, 2) = 1;

-- 2. 分桶：每 10 个一组
SELECT id, FLOOR((id - 1) / 10) AS 桶号 FROM product;

-- 3. 分页偏移量：第 page 页，每页 size 条
-- offset = (page - 1) * size
SELECT * FROM product ORDER BY id LIMIT 10 OFFSET 20;
```

> [!tip] 奇偶判断别写 `id % 2 = 1` 就完事
> 负数 `-3 % 2 = -1`，不等于 1，会漏掉负奇数。
> 要兼容负数，用 `MOD(id, 2) <> 0` 或 `ABS(id) % 2 = 1`。

## 四、幂、开方、对数与指数

| 函数 | 作用 | 示例 | 结果 |
| --- | --- | --- | --- |
| `POW(X,Y)` / `POWER(X,Y)` | X 的 Y 次方 | `POW(2,10)` | `1024` |
| `SQRT(X)` | 平方根 | `SQRT(16)` | `4` |
| `EXP(X)` | e 的 X 次方 | `EXP(1)` | `2.718281828...` |
| `LN(X)` | 自然对数 | `LN(EXP(1))` | `1` |
| `LOG(B,X)` | 以 B 为底的对数 | `LOG(2,8)` | `3` |
| `LOG2(X)` | 以 2 为底 | `LOG2(8)` | `3` |
| `LOG10(X)` | 以 10 为底 | `LOG10(1000)` | `3` |

```sql
SELECT POW(2, 10);        -- 1024
SELECT POW(2, -3);        -- 0.125
SELECT POW(-2, 3);        -- -8
SELECT SQRT(16);          -- 4
SELECT SQRT(2);           -- 1.4142135623730951
SELECT LOG(2, 8);         -- 3
SELECT LOG10(1000);       -- 3
SELECT LOG2(8);           -- 3
SELECT EXP(1);            -- 2.718281828459045
SELECT LN(EXP(1));        -- 1
```

> [!warning] 定义域外返回 `NULL`，不报错
> ```sql
> SELECT SQRT(-1);   -- NULL
> SELECT LN(0);      -- NULL
> SELECT LN(-1);     -- NULL
> SELECT LOG(1, 10); -- NULL（底数不能为 1）
> ```
> 业务里拿到 NULL 再参与计算，整条结果都会变 NULL，记得兜底。

> [!note] `LOG(X)` 只有一个参数时
> `LOG(X)` 等价于 `LN(X)`（自然对数），**不是**以 10 为底。
> 以 10 为底要写 `LOG10(X)` 或 `LOG(10, X)`。

## 五、三角函数与角度

```sql
SELECT PI();                    -- 3.141593
SELECT RADIANS(180);            -- 3.141592653589793
SELECT DEGREES(PI());           -- 180

SELECT SIN(RADIANS(30));        -- 0.49999999999999994
SELECT COS(RADIANS(60));        -- 0.5000000000000001
SELECT TAN(RADIANS(45));        -- 0.9999999999999999

SELECT ASIN(1);                 -- 1.5707963267948966（π/2）
SELECT ACOS(1);                 -- 0
SELECT ATAN(1);                 -- 0.7853981633974483（π/4）
SELECT ATAN2(1, 1);             -- 0.7853981633974483
SELECT COT(1);                  -- 0.6420926159343306
```

> [!warning] 三角函数的结果是**弧度**
> `SIN(30)` 不是 `sin 30°`，而是 `sin(30 rad)`。
> 要算角度先 `RADIANS(30)`；反过来用 `DEGREES()`。
> 浮点结果出现 `0.49999999999999994` 是正常的，比较时用 `ROUND` 或容差，不要写 `= 0.5`。

> [!note] `ATAN2(Y, X)` 的参数顺序
> 它是 `ATAN(Y/X)`，但能根据符号判断象限，返回值范围 `(-π, π]`。
> 参数顺序是 **Y 在前、X 在后**，写反了角度会差 90°。

## 六、随机数

### 6.1 `RAND`

```sql
RAND()        -- 返回 [0, 1) 的随机浮点数
RAND(N)       -- 以 N 为种子，返回可复现的序列
```

```sql
SELECT RAND();        -- 0.123456789...（每次不同）
SELECT RAND(42);      -- 固定值（同一个 seed 每次相同）
```

> [!tip] `RAND(N)` 的用途
> 造可复现的测试数据：同一个 seed，每次跑出来的序列一样，方便对比结果。
> 它不是"返回第 N 个随机数"，而是"用 N 初始化随机数发生器"。

### 6.2 随机取 N 条

```sql
-- ⚠️ 小表可以，大表很慢：全表算随机数再排序
SELECT * FROM product ORDER BY RAND() LIMIT 3;
```

> [!danger] `ORDER BY RAND()` 在大表上是灾难
> 它会给**每一行**生成一个随机数，然后对整张表排序，复杂度约 `O(n log n)`。
> 百万行表上，这一条 SQL 就能把数据库拖垮。

更可用的替代方案：

```sql
-- 方案一：按主键随机定位（要求 id 连续、无大空洞）
SELECT * FROM product
WHERE id >= (SELECT FLOOR(RAND() * (SELECT MAX(id) FROM product)))
ORDER BY id
LIMIT 3;

-- 方案二：随机取一个桶，再在桶内取
SELECT * FROM product
WHERE id % 100 = FLOOR(RAND() * 100)
LIMIT 3;
```

> [!note] 方案一不是严格均匀
> 如果 id 有大量空洞，落在空洞上的随机值会取到"下一条存在的记录"，导致某些行被选中的概率偏高。
> 对随机性要求高的场景（抽奖、实验分组），应该在应用层或用专门的随机服务处理。

## 七、`GREATEST` / `LEAST`

```sql
SELECT GREATEST(1, 5, 3);        -- 5
SELECT LEAST(1, 5, 3);           -- 1
SELECT GREATEST('a', 'c', 'b');  -- 'c'（按排序规则比较）
```

```sql
-- 给商品保底价：不低于 50
SELECT name, price, GREATEST(price, 50) AS 保底价 FROM product;

-- 封顶价：不高于 500
SELECT name, price, LEAST(price, 500) AS 封顶价 FROM product;
```

> [!danger] 只要有一个参数是 `NULL`，结果就是 `NULL`
> ```sql
> SELECT GREATEST(1, NULL, 3);   -- NULL
> SELECT LEAST(NULL, 2);         -- NULL
> ```
> 这跟 `MAX()` 聚合函数忽略 NULL 的行为**完全不同**。
> 要忽略 NULL，先 `COALESCE`：`GREATEST(COALESCE(a,0), COALESCE(b,0))`。

| 写法 | 结果 | 说明 |
| --- | --- | --- |
| `GREATEST(1, 5, 3)` | `5` | 多数值取最大 |
| `GREATEST(1, NULL, 3)` | `NULL` | NULL 传染 |
| `MAX(col)` | 忽略 NULL | 聚合函数，不是逐行函数 |

> [!note] `GREATEST` / `LEAST` 是**逐行函数**，不是聚合
> `GREATEST(a, b)` 比较的是**同一行的两个列**；`MAX(col)` 是**一列跨行**取最大。
> 别把两者混着用。

## 八、进制转换与位运算

### 8.1 进制转换

| 函数 | 作用 | 示例 | 结果 |
| --- | --- | --- | --- |
| `BIN(N)` | 十进制 → 二进制字符串 | `BIN(12)` | `'1100'` |
| `OCT(N)` | 十进制 → 八进制字符串 | `OCT(12)` | `'14'` |
| `HEX(N)` | 十进制 → 十六进制字符串 | `HEX(255)` | `'FF'` |
| `CONV(N, from, to)` | 任意进制转换 | `CONV('ff',16,10)` | `'255'` |

```sql
SELECT BIN(12), OCT(12), HEX(255), CONV('ff', 16, 10), CONV(255, 10, 2);
```

> [!warning] 返回的是**字符串**
> `BIN(12)` 返回 `'1100'`，不是数字 1100。拿它做算术会触发隐式转换（`'1100'` → 1100），结果完全不是二进制语义。
> 要转回数值用 `CONV(str, 2, 10)`。

### 8.2 位运算

| 运算符 | 含义 | 示例 | 结果 |
| --- | --- | --- | --- |
| `&` | 按位与 | `5 & 3` | `1` |
| `\|` | 按位或 | `5 \| 3` | `7` |
| `^` | 按位异或 | `5 ^ 3` | `6` |
| `~` | 按位取反 | `~5` | 很大的无符号数 |
| `<<` | 左移 | `1 << 3` | `8` |
| `>>` | 右移 | `8 >> 1` | `4` |
| `BIT_COUNT(N)` | 二进制中 1 的个数 | `BIT_COUNT(12)` | `2` |

```sql
SELECT 5 & 3, 5 | 3, 5 ^ 3, 1 << 3, 8 >> 1, BIT_COUNT(12);
```

> [!note] 位运算按 `BIGINT UNSIGNED` 处理
> `~5` 不是 `-6`，而是一个很大的无符号数（64 位取反）。
> 权限位、状态位常用这套；普通业务里可读性差，能用 `ENUM` / 关联表就别硬编码位。

## 九、精度、类型转换与溢出

### 9.1 `DECIMAL` 的精度

```sql
CREATE TABLE t_money (
    a DECIMAL(10,2),   -- 总共 10 位，其中 2 位小数 → 整数部分最多 8 位
    b DECIMAL(5,4)     -- 总共 5 位，其中 4 位小数 → 整数部分最多 1 位
);
```

| 类型 | 最大值（约） | 说明 |
| --- | --- | --- |
| `DECIMAL(10,2)` | `99999999.99` | 金额常用 |
| `DECIMAL(5,4)` | `9.9999` | 比例、税率 |
| `DECIMAL(20,6)` | `99999999999999.999999` | 高精度金额 / 汇率 |

> [!danger] `DECIMAL` 插入多余小数会**舍入**
> `DECIMAL(10,2)` 插入 `1.005`，实际存成 `1.01`（或在严格模式下报错/警告，取决于版本与 SQL 模式）。
> 金额字段的精度必须在建表时定清楚，别指望数据库帮你"保留原样"。

### 9.2 `FLOAT` / `DOUBLE` 的误差

```sql
SELECT CAST(0.1 AS DOUBLE) + CAST(0.2 AS DOUBLE);   -- 0.30000000000000004
SELECT CAST(0.1 AS DOUBLE) + CAST(0.2 AS DOUBLE) = 0.3;  -- 0
```

> [!warning] 浮点数不要用 `=` 比较
> ```sql
> -- ❌ 可能永远不成立
> SELECT * FROM t WHERE double_col = 0.3;
>
> -- ✅ 用范围或容差
> SELECT * FROM t WHERE ABS(double_col - 0.3) < 0.000001;
> ```
> 金额、库存、积分这类"不能差一分"的字段，从一开始就用 `DECIMAL`。

### 9.3 `CAST` / `CONVERT`

```sql
CAST(expr AS type)
CONVERT(expr, type)
```

```sql
SELECT CAST('123.45' AS DECIMAL(10,2));   -- 123.45
SELECT CAST(123.456 AS SIGNED);           -- 123（CAST 对小数会四舍五入）
SELECT CAST('123abc' AS UNSIGNED);        -- 123（附 warning）
SELECT CAST('abc' AS UNSIGNED);           -- 0（附 warning）
```

> [!danger] `CAST` 不是严格的校验器
> `'123abc'` 转数字得到 `123`，`'abc'` 得到 `0`——**不报错，只给 warning**。
> 指望 `CAST` 拦住脏数据是不现实的；导入前先 `WHERE col REGEXP '^[0-9]+$'` 过滤，或让应用层校验。
> `CAST(x AS SIGNED)` 对小数可能**四舍五入**，不是截断；要截断用 `TRUNCATE`。

### 9.4 整数溢出

```sql
SELECT 9223372036854775807 + 1;
-- ERROR 1690 (22003): BIGINT value is out of range
```

> [!danger] 严格模式下溢出直接报错
> 非严格模式可能截断/钳制，结果不可靠。
> `INT` 最大约 21 亿，自增 id 用 `BIGINT`；计数器、金额 cents 也要预估上限。

## 十、业务实战

### 10.1 计算总页数

```sql
-- 每页 10 条，5 条数据 → 1 页
SELECT CEIL(COUNT(*) / 10) AS 总页数 FROM product;
-- 结果：1
```

> [!tip] 别用 `FLOOR` + 1 硬拼
> `FLOOR(n / size) + 1` 在 `n` 正好整除时会多算一页（10 条数据算成 2 页）。
> 正确写法是 `CEIL(n / size)`，或者 `(n + size - 1) DIV size`。

### 10.2 折扣与税费

```sql
SELECT name, price,
       ROUND(price * 0.85, 2) AS 八五折,
       ROUND(price * 1.13, 2) AS 含税价
FROM product;
```

```
+--------+---------+--------+---------+
| name   | price   | 八五折 | 含税价  |
+--------+---------+--------+---------+
| 键盘   |  199.00 | 169.15 |  224.87 |
| 鼠标   |   89.90 |  76.42 |  101.59 |
| 显示器 | 1299.00 | 1104.15| 1467.87 |
| 耳机   |   25.50 |  21.68 |   28.82 |
| 硬盘   |  499.99 | 424.99 |  564.99 |
+--------+---------+--------+---------+
```

> [!warning] 折扣要**先乘后舍入**，且明确舍入规则
> `ROUND(price * 0.85, 2)` 和 `price * 0.85` 再在应用层舍入，结果可能差一分。
> 财务口径通常规定"四舍五入到分"或"银行家舍入"，代码里要统一，不能有的地方 `ROUND`、有的地方 `TRUNCATE`。

### 10.3 求占比

```sql
SELECT name,
       price,
       ROUND(price / (SELECT SUM(price) FROM product) * 100, 2) AS 占比百分比
FROM product
ORDER BY price DESC;
```

> [!tip] 占比最后一位对不上 100% 是正常的
> 每个值独立四舍五入，累加后可能多 0.01 或少 0.01。
> 报表里通常把差额补到最大项，或者标注"因四舍五入，合计可能不等于 100%"。

### 10.4 库存分箱

```sql
-- 每 10 件装一箱，向上取整
SELECT name, stock,
       CEIL(stock / 10) AS 箱数
FROM product;
```

```
+--------+-------+------+
| name   | stock | 箱数 |
+--------+-------+------+
| 键盘   |    35 |    4 |
| 鼠标   |     0 |    0 |
| 显示器 |    12 |    2 |
| 耳机   |   100 |   10 |
| 硬盘   |     7 |    1 |
+--------+-------+------+
```

> [!note] 库存为 0 时 `CEIL(0/10) = 0`
> 这是符合直觉的；但如果你要区分"无库存"和"未上架"，别用箱数 0 表示，另加状态字段。

### 10.5 金额拆分（把总额按比例分）

```sql
-- 把 100 元按 3:3:4 拆给三个人，先算各自份额再补差额
SELECT ROUND(100 * 0.3, 2) AS A,   -- 30.00
       ROUND(100 * 0.3, 2) AS B,   -- 30.00
       ROUND(100 * 0.4, 2) AS C;   -- 40.00
```

> [!warning] 比例拆分必然遇到"分不平"
> `100 / 3 = 33.333...`，三个人各 `33.33` 只有 `99.99`，少一分。
> 正确做法：前 n-1 个人按规则舍入，最后一个人拿 `总额 - 前面之和`，保证总和精确。

## 十一、常见错误合集

> [!danger] 坑一：用 `ROUND` 当 `TRUNCATE`
> `ROUND(2.9) = 3`，`TRUNCATE(2.9, 0) = 2`。要"砍掉小数"必须用 `TRUNCATE`。

> [!danger] 坑二：负数取整方向搞反
> `CEIL(-1.2) = -1`（往大走），`FLOOR(-1.2) = -2`（往小走）。不是按绝对值。

> [!danger] 坑三：`MOD` 的符号
> `MOD(-10, 3) = -1`，不是 2。结果符号跟**被除数**。

> [!danger] 坑四：金额用 `DOUBLE`
> `0.1 + 0.2 != 0.3`，对账必炸。金额用 `DECIMAL`。

> [!danger] 坑五：`ROUND` 的浮点陷阱
> `ROUND(2.675e0, 2)` 可能是 `2.67`，因为 `2.675` 在二进制里存不准。
> 要精确舍入，先把值转成 `DECIMAL`：`ROUND(CAST(2.675 AS DECIMAL(10,3)), 2)`。

> [!failure] 坑六：除零当 0
> `10 / 0` 返回 `NULL`，不是 0。后续 `NULL + 1` 还是 `NULL`。
> 用 `10 / NULLIF(0, 0)` 显式得到 NULL，或 `IFNULL(10 / NULLIF(divisor, 0), 0)` 兜底。

> [!failure] 坑七：`ORDER BY RAND()` 拖垮大表
> 全表生成随机数 + 排序。大表用随机主键或分桶方案。

> [!failure] 坑八：`GREATEST` / `LEAST` 遇 NULL
> 只要有一个参数是 NULL，结果就是 NULL，不是"忽略 NULL 取最大"。

> [!failure] 坑九：`CAST` 静默转换脏数据
> `CAST('abc' AS UNSIGNED)` 得到 0 而不是报错。脏数据校验不能靠 `CAST`。

> [!failure] 坑十：整数溢出
> `INT` 上限约 21 亿；自增 id 用 `BIGINT`。严格模式下溢出直接 `ERROR 1690`。

## 十二、速查表

| 需求 | 写法 | 示例 → 结果 |
| --- | --- | --- |
| 绝对值 | `ABS(x)` | `ABS(-5)` → `5` |
| 符号 | `SIGN(x)` | `SIGN(-5)` → `-1` |
| 向上取整 | `CEIL(x)` | `CEIL(1.2)` → `2` |
| 向下取整 | `FLOOR(x)` | `FLOOR(1.8)` → `1` |
| 四舍五入 | `ROUND(x[,d])` | `ROUND(1.298,1)` → `1.3` |
| 截断 | `TRUNCATE(x,d)` | `TRUNCATE(1.999,2)` → `1.99` |
| 取余 | `MOD(n,m)` / `n % m` | `MOD(10,3)` → `1` |
| 整数除法 | `n DIV m` | `10 DIV 4` → `2` |
| 小数除法 | `n / m` | `10 / 4` → `2.5000` |
| 幂 | `POW(x,y)` | `POW(2,10)` → `1024` |
| 平方根 | `SQRT(x)` | `SQRT(16)` → `4` |
| 自然对数 | `LN(x)` | `LN(1)` → `0` |
| 任意底对数 | `LOG(b,x)` | `LOG(2,8)` → `3` |
| 随机数 | `RAND()` | `RAND()` → `[0,1)` |
| 两列取大 / 小 | `GREATEST` / `LEAST` | `GREATEST(1,5,3)` → `5` |
| 进制转换 | `CONV(n,from,to)` | `CONV('ff',16,10)` → `'255'` |
| 二进制 1 的个数 | `BIT_COUNT(n)` | `BIT_COUNT(12)` → `2` |
| 类型转换 | `CAST(x AS type)` | `CAST('1.5' AS DECIMAL(3,1))` → `1.5` |
| 总页数 | `CEIL(总数 / 每页)` | `CEIL(5/10)` → `1` |

> [!question] 自测三连
> 1. `ROUND(2.5)`、`ROUND(2.5e0)`、`TRUNCATE(2.9, 0)` 各是多少？为什么？
> 2. `MOD(-10, 3)` 是多少？`-10 DIV 3` 和 `FLOOR(-10 / 3)` 为什么不一样？
> 3. 为什么金额字段必须用 `DECIMAL`？`DOUBLE` 的 `0.1 + 0.2` 会得到什么？

---

> [!quote] 一句话记忆
> **`ROUND` 舍入、`TRUNCATE` 截断、`CEIL` 往大、`FLOOR` 往小**；**`MOD` 的符号跟被除数**，`DIV` 朝 0 截断；**除零返回 NULL**；**金额用 `DECIMAL`，永远别用 `FLOAT/DOUBLE`**；**`GREATEST/LEAST` 遇 NULL 变 NULL**。
