# 组件关系与父子通信

> [!abstract] 一句话
> `Rent_page.vue` 是租车功能的==父组件与业务容器==，`VehicleToolbar` / `VehicleGrid` / 两个弹窗都是它的子组件。通信只有两条通道：**父传子用 `props`（只读）**，**子传父用 `emit` 事件**；当两者成对出现时，用 `v-model` 把它们合成一个双向绑定。

---

## 一、组件之间的关系

项目的组件关系可以表示为：

```text
App.vue
├─ Nav_header.vue
└─ router-view
   ├─ Home_hero_page.vue
   └─ Rent_page.vue
      ├─ SuccessToast.vue
      ├─ AddVehicleModal.vue
      ├─ DeleteVehicleModal.vue
      ├─ VehicleToolbar.vue
      └─ VehicleGrid.vue
```

其中 `Rent_page.vue` 是租车功能的父组件和业务容器。

它负责：

- 保存车辆列表
- 保存筛选条件
- 保存选中的车辆
- 控制添加弹窗
- 控制删除弹窗
- 接收子组件事件
- 根据条件计算过滤后的车辆

子组件负责展示界面和收集用户操作。

这是一种很常见的组件设计：

```text
父组件：管理状态和业务规则
子组件：展示数据和发出用户操作事件
```

## 二、父传子：Props

父组件向子组件传递数据，需要使用 props。

例如 `Rent_page.vue` 向 `VehicleGrid.vue` 传递：

```vue
<VehicleGrid
  :cars="filteredCars"
  :total-cars="cars.length"
  :selected-car-id="selectedCarId"
  @select="selectedCarId = $event"
/>
```

这里传递了三个 props：

| 父组件绑定 | 子组件接收字段 | 含义 |
|---|---|---|
| `:cars="filteredCars"` | `cars` | 当前筛选后的车辆 |
| `:total-cars="cars.length"` | `totalCars` | 所有车辆总数 |
| `:selected-car-id="selectedCarId"` | `selectedCarId` | 当前选中的车辆 ID |

子组件中使用：

```ts
defineProps<{
  cars: Car[];
  totalCars: number;
  selectedCarId: string | null;
}>();
```

### 2.1 为什么使用 `defineProps`

`defineProps` 是 `<script setup>` 中的编译宏，用于声明组件可以接收哪些数据。

它不需要手动导入：

```ts
const props = defineProps<{
  visible: boolean;
}>()
```

如果需要在脚本中访问，可以保存返回值：

```ts
const props = defineProps<{
  visible: boolean;
}>()

console.log(props.visible)
```

如果只在模板中使用，也可以不保存返回值。

### 2.2 Props 是单向数据流

父组件可以修改传给子组件的数据，子组件不能直接修改 props。

正确的流程是：

```text
父组件拥有数据
  ↓ props
子组件读取数据
  ↓ emit
子组件通知父组件
  ↓
父组件修改数据
```

这可以避免多个组件随意修改同一份数据，使数据来源更加清晰。

## 三、子传父：defineEmits 和 emit

子组件不能直接修改父组件状态，因此要通过事件通知父组件。

`VehicleGrid.vue` 中声明事件：

```ts
const emit = defineEmits<{
  select: [carId: string];
}>();
```

当用户点击车辆卡片时：

```vue
<article
  v-for="car in cars"
  :key="car.id"
  @click="emit('select', car.id)"
>
```

它会发出：

```text
事件名称：select
事件参数：car.id
```

父组件监听：

```vue
<VehicleGrid @select="selectedCarId = $event" />
```

其中 `$event` 就是子组件传出的车辆 ID。

完整数据流：

```text
用户点击 CAR-003
  ↓
VehicleGrid emit('select', 'CAR-003')
  ↓
Rent_page 接收到 $event
  ↓
selectedCarId = 'CAR-003'
  ↓
Vue 重新渲染选中样式和删除按钮状态
```

### 3.1 TypeScript 类型事件

例如 `VehicleToolbar.vue`：

```ts
const emit = defineEmits<{
  'update:minBudget': [value: number];
  'update:maxBudget': [value: number];
  'update:isFilterOpen': [value: boolean];
  toggleType: [type: CarType];
  resetFilters: [];
}>();
```

这表示：

- `update:minBudget` 必须传入数字
- `update:maxBudget` 必须传入数字
- `update:isFilterOpen` 必须传入布尔值
- `toggleType` 必须传入合法的 `CarType`
- `resetFilters` 不需要参数

这样可以在编译阶段发现错误，例如误传字符串：

```ts
emit('update:minBudget', '100')
```

TypeScript 会提示类型不匹配。

## 四、`v-model` 和自定义双向绑定

父组件中：

```vue
<VehicleToolbar
  v-model:min-budget="minBudget"
  v-model:max-budget="maxBudget"
/>
```

这是 Vue 的多参数 `v-model` 写法。

它等价于：

```vue
<VehicleToolbar
  :min-budget="minBudget"
  :max-budget="maxBudget"
  @update:min-budget="minBudget = $event"
  @update:max-budget="maxBudget = $event"
/>
```

Vue 会自动把：

```text
v-model:min-budget
```

转换成：

```text
prop: minBudget
event: update:minBudget
```

子组件因此需要声明：

```ts
defineProps<{
  minBudget: number;
  maxBudget: number;
}>();

const emit = defineEmits<{
  'update:minBudget': [value: number];
  'update:maxBudget': [value: number];
}>();
```

输入框发生变化时：

```vue
<input
  :value="minBudget"
  @input="emit(
    'update:minBudget',
    Number(($event.target as HTMLInputElement).value)
  )"
/>
```

数据流是：

```text
用户修改输入框
  ↓
子组件读取 input.value
  ↓
转换成 number
  ↓
emit('update:minBudget', 新值)
  ↓
父组件更新 minBudget
  ↓
filteredCars 重新计算
```

### 4.1 为什么不用子组件直接修改 `minBudget`

因为 `minBudget` 是父组件传入的 prop。直接修改会破坏 Vue 的单向数据流。

错误思路：

```ts
props.minBudget = 100
```

正确思路：

```ts
emit('update:minBudget', 100)
```
