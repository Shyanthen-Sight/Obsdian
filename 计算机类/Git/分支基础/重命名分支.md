# 重命名分支 —— git branch -m

> [!abstract] 一句话
> ==`git branch -m` 改的只是分支**指针文件的名字**==：它指向的提交、历史、内容**一个字都不变**。所以重命名又快又安全——但**远程分支的名字不会**跟着改，那是另一套动作。

---

## 一、基本用法

```bash
git branch -m <新名字>              # 重命名"当前所在"的分支
git branch -m <旧名字> <新名字>     # 重命名"指定"的分支（不必切到它上面）
git branch -M <旧名字> <新名字>     # -M = --move --force：目标名已存在时强制覆盖
```

> [!warning] 改"当前分支"时，别把旧名写进去
> 假设你在 `main` 上跑 `git branch -m main trunk`——Git 会报错，因为"当前分支"与"旧名"指向同一个分支、产生歧义。
> 只给**一个**名字即可：`git branch -m trunk` 表示"把当前分支改叫 trunk"。

---

## 二、改完立即验证

```bash
git branch            # 确认新名字出现、* 仍落在它上面
git branch -vv        # 确认上游跟踪没丢
```

> [!tip] 重命名通常会保留上游跟踪
> 本地分支名改了，`branch.<旧名>.remote` 之类的本地配置 Git 一般会**自动迁移**到新名字下，多数情况下无需重设上游。
> 但请记住：这只是**本地**的事——远程分支仍是旧名，见第四节。

---

## 三. 把 `master` 改成 `main`（最常见的场景）

```bash
# 1. 本地改名
git branch -m master main

# 2. 把新名字推到远程并设为上游
git push -u origin main

# 3. 删掉远程的旧分支
git push origin --delete master
```

> [!note] 用 GitHub 时还差一步
> 若 `main` 要当默认分支，先到仓库 **Settings → Default branch** 把默认分支切成 `main`，
> 否则远程删除 `master` 可能被拒绝——因为不能删除"当前默认分支"。

---

## 四、远程分支改名（本地 + 远端整套动作）

远程分支**没法原地改名**，只能"删旧的、推新的"：

```bash
# 1. 本地改名
git branch -m old-name new-name

# 2. 推新分支上去，并设置上游
git push origin -u new-name

# 3. 删掉远程的旧分支
git push origin --delete old-name

# 4. 让队友清理过期的远程跟踪引用
git fetch --prune
```

> [!danger] 删远程分支会影响队友
> 第 3 步之后，所有依赖 `origin/old-name` 的人会看到 `[gone]`，再往旧名 `push` 会失败。
> 若该分支已合并/废弃，通常无妨；==**若是活跃分支，务必先和团队打招呼**==。

---

## 五、完整示例

```bash
git switch -c feature/login      # 1. 建完发现名字起错了
git branch -m feature/user-login # 2. 改成一个更准确的名字
git branch -vv                   # 3. 验证：名字变了、上游还在
```

> [!success] 成功标志
> `git branch` 里出现 `feature/user-login`、`feature/login` 消失，且 `*` 仍在同一行；
> `git branch -vv` 没出现异常提示。

---

## 六、常见困惑

> [!question] 改名会不会丢提交？
> 不会。分支只是指针，改的是"名字"，不改它指向的提交。历史原封不动。

> [!question] `-m` 和 `-M` 有什么区别？
> 当**目标名已经存在**时：`-m` 会拒绝并报错（保护你不误覆盖），`-M` 强制覆盖。
> 日常一律用 `-m`；只有明确知道要覆盖时才用 `-M`。

> [!question] 正被别的工作区（worktree）检出的分支能改名吗？
> 不能。Git 会报错。要先在对应的 worktree 里切走，或先移除那个 worktree。

> [!question] 改名后 `git log` 里的历史会变吗？
> 不会。历史由**提交**组成，和分支名字无关。你在 `--graph` 里看到的还是同一批提交，只是标签名换了。

> [!question] 队友那边需要做什么？
> 若只是**本地**改名，队友不受影响。若动了**远程**分支名，队友执行 `git fetch --prune` 清掉旧引用，
> 并把本地旧分支按需重命名/删除即可。

---

> [!quote] 一句话记忆
> **重命名分支 = 给便利贴换个标签**：贴着的提交没动，只是名字变了。远程分支贴不了新标签，只能"**撕旧的、贴新的**"。
