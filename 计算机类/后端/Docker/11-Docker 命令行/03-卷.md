# 卷

卷是 Docker 管理的持久化存储，生命周期独立于容器。删容器，卷还在；删卷，数据就真没了。命令本身不复杂，风险集中在清理和备份。

## 创建和查看

```bash
docker volume create pgdata
docker volume ls --format 'table {{.Name}}\t{{.Driver}}'
docker volume inspect -f '{{.Mountpoint}}' pgdata
# /var/lib/docker/volumes/pgdata/_data
docker volume ls --filter dangling=true
docker volume ls --filter label=env=prod
```

`Mountpoint` 是宿主机上的真实路径，排查权限和磁盘占用时用得上，但别直接改里面的文件。创建时带标签，后面可以按标签筛选和清理。

`-v` 和 `--mount` 都能挂卷，后者更啰嗦也更明确：

```bash
docker run -d --name pg \
  -v pgdata:/var/lib/postgresql/data \
  postgres:16

docker run -d --name pg2 \
  --mount type=volume,source=pgdata,target=/var/lib/postgresql/data \
  postgres:16
```

`-v pgdata:/data` 在卷不存在时会自动创建；`--mount` 默认不会，行为更可预测。同一套脚本里别混着用。

## 备份与恢复

命名卷不能直接 `cp`，标准做法是起一个临时容器，把卷和宿主备份目录同时挂进去：

```bash
# 备份
docker run --rm \
  -v pgdata:/data \
  -v "$(pwd)":/backup \
  alpine tar czf /backup/pgdata.tar.gz -C /data .

# 恢复
docker run --rm \
  -v pgdata:/data \
  -v "$(pwd)":/backup \
  alpine sh -c 'cd /data && tar xzf /backup/pgdata.tar.gz'
```

数据库卷要先停容器或用 `pg_dump` 做一致性备份，直接 tar 正在写入的数据文件可能得到损坏的备份。恢复时目标卷最好是空的，覆盖前先确认。

## 卷驱动

默认 `local` 驱动把数据放在 `/var/lib/docker/volumes`。它也能接 NFS、CIFS，不必装插件：

```bash
docker volume create --driver local \
  --opt type=nfs \
  --opt o=addr=10.0.0.10,rw,nfsvers=4 \
  --opt device=:/export/pgdata \
  nfsdata
```

`type` 是文件系统类型，`device` 是远端导出路径，`o` 是挂载选项。宿主机必须能访问该 NFS，且装了 `mount.nfs`。Compose 里对应 `driver_opts`，Swarm 服务用 `--mount volume-driver=...`。再往上就是 Portworx、Longhorn 这类插件/CSI 方案，适合多主机和快照需求。

## 清理

```bash
docker volume prune     # 默认只清匿名卷
docker volume prune -a  # 连未使用的命名卷一起清
docker system df -v     # 先看每个卷占多少
```

`prune` 不会给你逐条确认，删完不可恢复。生产机上先 `ls --filter dangling=true` 看清楚，再决定是否加 `-a`。

> [!warning] 权限问题
> 容器内非 root 用户写卷时可能遇到 `Permission denied`，因为卷目录默认属于 root。用 `--user` 对齐 UID，或在初始化容器里 `chown` 一次，别直接 `chmod 777`。
