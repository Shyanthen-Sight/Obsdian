# 卷挂载

命名卷是 Docker 自己管的一块存储，默认落在 `/var/lib/docker/volumes/<名字>/_data`。它的生命周期和容器解耦：删容器不删卷，删卷才算真删。

```bash
docker volume create pgdata
docker run -d --name pg \
  -e POSTGRES_PASSWORD=secret \
  -v pgdata:/var/lib/postgresql/data \
  postgres:16
```

`-v pgdata:/var/...` 冒号左边是卷名，右边是容器内路径。卷不存在时 Docker 会自动创建，所以 `volume create` 不是必须的，但显式创建便于命名和排查。

`--mount` 写法更啰嗦，胜在明确：

```bash
docker run -d --name pg \
  --mount type=volume,src=pgdata,dst=/var/lib/postgresql/data \
  -e POSTGRES_PASSWORD=secret postgres:16
```

`-v` 把参数挤在一串冒号里，路径带冒号或参数写错时容易静默变成别的意思；`--mount` 用 `key=value`，写错直接报错。脚本和编排文件里更推荐 `--mount`。

一个容易忽略的行为：卷第一次挂到一个非空目录上时，Docker 会把镜像里该目录的内容复制进卷。所以 PostgreSQL 的卷初始不是空的，`initdb` 已经跑过；反过来，绑定挂载不会复制，宿主空目录会直接盖住镜像内容。

备份最省事的办法是起个临时容器，把卷和宿主目录同时挂进去：

```bash
docker run --rm \
  -v pgdata:/data:ro \
  -v "$(pwd)":/backup \
  alpine tar czf /backup/pgdata-$(date +%F).tar.gz -C /data .
```

恢复把源和目标调换，解压到卷里即可。注意 `:ro` 只影响这个临时容器，不影响其他使用者。数据库热备份更稳的做法还是在应用层 `pg_dump` 或 `mysqldump`，tar 适合停机维护窗口。

在 compose 里声明卷，名字会自动加项目前缀，避免和其他项目撞名：

```yaml
services:
  db:
    image: postgres:16
    volumes:
      - pgdata:/var/lib/postgresql/data
volumes:
  pgdata:
```

> [!tip] 卷也会占空间
> 删容器不会删卷，匿名卷尤其容易攒。`docker volume ls` 里那串 64 位十六进制就是匿名卷。`docker volume prune` 只清没有被任何容器引用的卷，加 `-a` 会连命名卷一起清，执行前先看清楚。
