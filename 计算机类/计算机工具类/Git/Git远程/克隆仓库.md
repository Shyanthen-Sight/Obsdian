# 克隆仓库 —— git clone

> [!abstract] 一句话
> ==`git clone` 是"一条命令搞定从零到能开工"==：它把远程仓库整个搬到你本地——建目录、`git init`、登记 `origin`、抓取全部历史、检出默认分支并设好上游。你在 GitHub 上点"复制"得到的那行地址，喂给 `clone`，本地就多出一个和远程一模一样的仓库。

---

## 一、克隆到底做了什么

别把 `clone` 当成不透明的黑盒。它其实是**一串你熟悉的命令的打包**：

```text
git clone <URL> [目录名]
   ≈ mkdir <目录名> && cd <目录名>
   + git init
   + git remote add origin <URL>       ← 自动登记远程，见 [[管理远程]]
   + git fetch origin                  ← 抓取全部分支与历史
   + git checkout <默认分支>            ← 检出默认分支并设置上游
```

> [!info] 克隆后你立刻拥有什么
> - 一个 `origin` 远程（指向你克隆的地址）
> - 远程分支的**跟踪引用**：`origin/main`、`origin/dev`……（`.git/refs/remotes/`）
> - 一个**本地分支**（通常是 `main`），其上游已指向 `origin/main`
> - 完整历史（除非用了浅克隆）
>
> 换句话说：`clone` 之后你就能直接 `git pull`、`git push`、`git switch`，==无需任何手工配置==。

---

## 二、最常用

```bash
git clone <URL>                    # 目录名默认取仓库名
git clone <URL> my-project         # 指定本地目录名
git clone <URL> .                  # 克隆到当前目录（目录须为空）
```

```bash
git clone https://github.com/team/repo.git
git clone git@github.com:team/repo.git          # SSH，推荐，免输密码
```

> [!tip] 目录名默认怎么来的
> Git 取 URL 末尾那段、去掉 `.git` 后缀。`.../repo.git` → 目录 `repo`。
> 想换成别的，就在 URL 后跟一个参数。

---

## 三、三种 URL 协议

```bash
git clone https://github.com/me/repo.git     # HTTPS：易过防火墙，常要输令牌
git clone git@github.com:me/repo.git         # SSH：配好密钥后免密，★ 日常首选
git clone git://github.com/me/repo.git       # git 协议：只读、无加密，少见
```

> [!info] HTTPS 与 SSH 怎么选
> | | HTTPS | SSH |
> | --- | --- | --- |
> | 认证 | 用户名 + 令牌/密码 | SSH 密钥 |
> | 穿透防火墙 | 好（走 443） | 一般 |
> | 便利性 | 每次可能提示 | ==配好一次，一劳永逸== |
>
> 公司内网限制多时选 HTTPS；个人机器长期开发者选 SSH。
> 两者**随时可换**：`git remote set-url origin <新地址>`（见 [[管理远程]]）。

## 四、按需裁剪：常用选项

```bash
git clone -b dev <URL>              # ★ 克隆后直接检出 dev（而非默认分支）
git clone --depth 1 <URL>           # 浅克隆：只取最新 1 个提交，历史不要
git clone --single-branch <URL>     # 只抓一个分支（默认配合 --branch）
git clone --recurse-submodules <URL> # 连子模块一起初始化并检出
git clone --bare <URL> repo.git     # 裸仓库：没有工作区，用作"服务端"
git clone --mirror <URL> repo.git   # 镜像：连远程引用结构一起照着复制
git clone -o upstream <URL>         # 远程名不叫 origin，叫 upstream
```

> [!warning] `--depth` 是把双刃剑
> 浅克隆**只下载最近的 N 个提交**，克隆巨大仓库时能快得惊人。
> 但代价是：`git log` 看不到远古历史，很多基于完整历史的操作（blame、部分 merge）会受限。
> 需要时再补全：`git fetch --unshallow`。

> [!info] `-b` 不只认分支，也认 tag
> `git clone -b v1.2.0 <URL>` 会把工作区直接**检出到那个 tag**（detached HEAD 状态）。
> 这常用于"只想拿某一版源码来看/编译"。

> [!tip] `--bare` 与 `--mirror` 是给"做服务器"用的
> 它们**没有工作区**，纯粹是仓库本体。搭建自建中央仓库、或做备份镜像时才需要；
> 日常开发用普通克隆就好。

## 五、克隆之后：这些配置已自动就位

```bash
git remote -v                 # 看到 origin 已登记
git branch -a                 # 看到 remotes/origin/* 跟踪引用
git branch -vv                # 看到本地 main 的上游是 origin/main
git log --oneline --graph -5  # 历史已被完整搬来
```

> [!success] 成功标志
> `git branch -vv` 中当前分支显示 `[origin/xxx]`（上游已设好），
> 之后 `git pull` / `git push` 不带参数就能对上默认对手。

> [!note] 默认检出哪条分支？
> 由远程的 `HEAD` 决定（通常是 `main` 或 `master`）。若远程 HEAD 没设好，
> Git 会提示默认分支无法确定，可按提示手动指定。

## 六、完整示例

```bash
# 场景：把团队仓库拉到本地，只想快速开工
git clone git@github.com:team/awesome.git      # 1. SSH 克隆
cd awesome
git remote -v                                  # 2. 确认 origin 指向团队仓库
git branch -vv                                 # 3. 确认 main 的上游是 origin/main

# 场景：仓库很大，先浅克隆赶时间
git clone --depth 1 https://github.com/big/mono.git

# 场景：还要顺手切到开发分支
git clone -b develop git@github.com:team/awesome.git

# 场景：晚了后悔没要全历史
git fetch --unshallow                          # 补全为完整仓库
```

## 七、常见困惑

> [!question] 克隆会不会把我的本地改动覆盖掉？
> 克隆是"往**新目录**里拉取"，它不碰任何已有文件。
> 唯一例外是 `git clone <URL> .`——它要求当前目录为空，正是为了防止覆盖。

> [!question] 克隆一个大仓库太慢怎么办？
> 依次考虑：`--depth 1`（不要历史）→ `--single-branch`（只要一条分支）→ `--filter=blob:none`（部分克隆，按需取文件）。
> 三者可叠加，能大幅减少传输量。

> [!question] 我克隆下来后能不能改远程地址？
> 能。`git remote set-url origin <新URL>` 即可，不必重新克隆。见 [[管理远程]]。

> [!question] 克隆出来的目录里有 `.git` 文件夹，能删吗？
> 别删——那里面就是整个仓库（对象库 + 引用 + 配置）。删了 `.git`，工作区就只剩普通文件，不再是 Git 仓库了。

> [!question] `clone` 和 `fetch` 都能"把远程弄到本地"，区别在哪？
> `clone` 是**第一次**、从无到有、包含建目录与检出；
> `fetch` 是**后续**、在已有仓库里更新跟踪引用。见 [[fetch跟pull]]。

> [!question] 克隆时提示 SSH 权限被拒（Permission denied）？
> 多半是 SSH 密钥没配好。检查 `ssh -T git@github.com` 能否通过；
> 不行就改用 HTTPS 地址克隆，或按 GitHub 文档配置密钥。

---

> [!quote] 一句话记忆
> **`clone` = `init` + `remote add origin` + `fetch` + `checkout` 的打包**。它一次给你：完整历史、一个 `origin`、一组远程跟踪分支、一条设好上游的本地分支。==要快，加 `--depth`；要别的分支，加 `-b`。==
