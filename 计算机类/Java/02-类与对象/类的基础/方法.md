# Java 方法

## 一句话解释

==**方法就是写在类体里的一段「有名字、能收参数、能返回结果」的代码块，用来描述对象能做什么==。**

==字段（成员变量）描述对象**的状态**==，==方法描述对象的**行为**==。二者合起来构成一个==类的全部内容==。

方法不写出来也能运行，但那样对象只是一袋死数据；调用方法才是让对象「动起来」的唯一方式。

---

## 一、最完整的语法结构

```java
[修饰符] 返回值类型 方法名([参数列表]) [throws 异常列表] {
    // 方法体
    return 返回值;   // 若返回值类型是 void，这条可省略
}
```

只有 **返回值类型、方法名、`( )`、`{ }`** 是必须的，其余都可以省：

```java
void hello() { }        // 合法，最短的实例方法
```

对比 [[类的声明]]：类的声明是画模板，方法的声明是往模板里填「能做的事」。

## 二、逐段拆解

### 1. 修饰符

可以写多个，顺序一般不影响编译。

| 修饰符                                     | 作用                        | 备注                |
| --------------------------------------- | ------------------------- | ----------------- |
| `public` / `protected` / 默认 / `private` | 控制谁能调用这个方法                | 见 [[java中的权限修饰符]] |
| `static`                                | 属于类而非对象，可以直接用类名调用         | 见 [[static关键字]]   |
| `final`                                 | 方法不能被重写（子类不能覆盖）           | 见 [[final关键字]]    |
| `abstract`                              | 抽象方法，只有声明没有方法体，必须以 `;` 结尾 | 见 [[abstract关键字]] |
| `synchronized`                          | 同一时刻只允许一个线程执行             | 多线程时再学            |
| `native`                                | 方法体由非 Java 语言实现（如 C）      | 少见                |

```java
public static void main(String[] args) { }   // 公开、静态
private int getScore() { return score; }     // 私有、实例
public abstract void run();                  // 抽象方法，注意是分号结尾
```

> [!warning] 最容易踩的坑
> `abstract` 方法绝对不能有方法体，写完括号直接 `;`。手动加一对 `{ }` 编译器立刻报错。

### 2. 返回值类型

写在方法名前面，表示这个方法「交出来的是什么」。

| 类型 | 含义 | 例子 |
| --- | --- | --- |
| `void` | 什么都不返回，`return;` 后面不能跟值 | `void print() { }` |
| 基本类型 | 返回 `int` / `double` / `boolean` … | `int add(int a, int b)` |
| 引用类型 | 返回对象、数组、`String`… | `String getName()` |
| 泛型 | 返回 `List<String>` 这类 | `List<String> findAll()` |

规则：

- 声明了非 `void` 的返回值，方法体里所有分支都必须能走到 `return`，否则编译不过。
- `return` 后面不能再写代码，那是「永远执行不到」的语句。

```java
int max(int a, int b) {
    if (a > b) {
        return a;      // 分支一
    }
    return b;          // 分支二 —— 必须有，不然编译报错
}
```

### 3. 方法名

- 规则和标识符一致：====字母、数字、`_`、`$` 组成====，不能以数字开头，不能是关键字。
- 约定：**小驼峰（camelCase）**，`getScore`、`findByName`，与类名的大驼峰区分开。
- 见名知意，优先用动词：`eat`、`save`、`calculateTotal`。

### 4. 参数列表

写在括号里，可以有 0 个到多个，用逗号分隔。

```java
void setScore(int score) { }                  // 一个参数
int add(int a, int b) { }                     // 两个参数
```

两个术语要分清：

| 术语 | 出现位置 | 作用 |
| --- | --- | --- |
| **形参**（parameter） | 方法声明处 | 占位符，接收传来的值 |
| **实参**（argument） | 方法调用处 | 真正传进去的值 |

```java
int add(int a, int b) {   // a、b 是形参
    return a + b;
}

add(3, 5);                // 3、5 是实参
```

括号里什么都不写也合法，叫无参方法：`void hello() { }`。

### 5. 方法体与 return

- `{ }` 里就是方法体，放真正干活的代码。
- `return` 干两件事：把值交出去 + 立刻结束方法。

```java
int divide(int a, int b) {
    if (b == 0) {
        return 0;      // 提前结束，后面的代码不会执行
    }
    return a / b;
}
```

## 三、方法的分类

### 1. 实例方法 vs 静态方法（最重要的一组）

| 对比项        | 实例方法（没有 `static`） | 静态方法（有 `static`） |
| ---------- | ----------------- | ---------------- |
| 属于谁        | ==对象==            | ==类==            |
| ==调用方式==   | `对象.方法名()`        | `类名.方法名()`       |
| 能否访问实例字段   | ✅ 可以              | ❌ 不可以            |
| 能否用 `this` | ✅ 可以              | ❌ 不可以            |
| 创建时机       | `new` ==出对象后才有==  | ==类加载后就存在==      |

```java
class Demo {
    private int score = 60;             // 实例字段

    void show() {                       // 实例方法
        System.out.println(score);      // ✅ 能读实例字段
    }

    static int add(int a, int b) {      // 静态方法
        // System.out.println(score);   // ❌ 编译报错：不能访问实例字段
        return a + b;
    }
}

Demo d = new Demo();
d.show();            // 实例方法靠对象
Demo.add(1, 2);      // 静态方法靠类名
```

> [!note] 记忆口诀
> **静态方法看类，实例方法看对象。**
> 调用前先问自己一句：这个方法属于「类」还是「对象」？
> 详细调用方式与常见报错见 [[Java方法的解释]]。

### 2. 其他分类

| 分类依据 | 种类 |
| --- | --- |
| 有无参数 | 无参方法 / 有参方法 |
| 有无返回值 | `void` 方法 / 带返回值方法 |
| 是否被 `static` 修饰 | 静态方法 / 实例方法 |
| 是否被 `abstract` 修饰 | 抽象方法（无方法体）/ 具体方法 |
| 是否为特殊方法 | 构造方法（名字与类名相同、没有返回值类型） |

> [!note] 构造方法的特殊性
> 构造方法虽然叫「方法」，但它没有返回值类型（连 `void` 都不能写），且只能用 `new` 触发。
> 一旦手写了 `void Dog() { }`，它就变成普通方法，不再是构造方法。详见 [[父类的构造方法与子类的关系]]。

## 四、参数传递：Java 只有「值传递」

**Java 里所有参数传递都是值传递（pass by value），没有引用传递。** 这是面试最常考、也最容易想错的一点。

区分两种情况：

### 1. 传基本类型 —— 传的是值的副本

方法里怎么改，都不会影响外面。

```java
void change(int x) {
    x = 100;              // 改的是副本
}

int a = 5;
change(a);
System.out.println(a);    // 结果仍是 5
```

### 2. 传引用类型 —— 传的是「地址的副本」

- 改对象内部的属性 → 会影响外面（因为两份地址指向同一个对象）。
- 让参数指向新对象 → 不影响外面（改的只是副本的指向）。

```java
void modify(Student s) {
    s.name = "小明";          // ✅ 改对象内部，外面能看到
    s = new Student("小红");  // ❌ 只改副本指向，外面不受影响
}

Student stu = new Student("张三");
modify(stu);
System.out.println(stu.name);   // 输出「小明」，不是「小红」
```

> [!warning] 一句话记住
> **传的是钥匙的复印件。** 用复印件能打开同一间房（改对象内部有效）；但把复印件换成另一把钥匙，原主人手里那把不会跟着变（重新赋值无效）。

## 五、可变参数 `...`

当参数个数不确定时使用，语法是在类型后面加三个点。

```java
int sum(int... nums) {          // nums 本质是一个 int[]
    int total = 0;
    for (int n : nums) {
        total += n;
    }
    return total;
}

sum();              // 0
sum(1, 2);          // 3
sum(1, 2, 3, 4);    // 10
```

规则：

1. 可变参数必须是参数列表的**最后一个**。
2. ==一个方法最多只能有一个可变参数==。
3. ==编译器会把它当成数组处理==，所以 `sum(new int[]{1, 2, 3})` 也能调用。
4. 重载时，精确匹配优先于可变参数——`sum(1, 2)` 会先找 `sum(int, int)`，找不到才走 `sum(int...)`。

## 六、重载 vs 重写

这两个词长得像，含义完全不同：

| 对比项   | **重载（Overload）** | **重写（Override）** |
| ----- | ---------------- | ---------------- |
| 发生位置  | ==同一个类里==        | ==子类与父类之间==      |
| 方法名   | 相同               | 相同               |
| 参数列表  | ==必须不同==         | ==必须完全相同==       |
| 返回值   | 无所谓              | 相同或是父类返回值的子类型    |
| 权限修饰符 | 无所谓              | 不能比父类更严格         |
| 绑定时机  | 编译时（静态绑定）        | 运行时（动态绑定）        |
| 目的    | 提供同一功能的不同入参形式    | 让子类改造父类的行为       |

```java
class Animal {
    void speak() {
        System.out.println("动物叫");
    }
}

class Dog extends Animal {
    @Override
    void speak() {                 // 重写：名字、参数完全一样
        System.out.println("汪汪");
    }

    void speak(int times) {        // 重载：参数不同，与重写无关
        for (int i = 0; i < times; i++) {
            speak();
        }
    }
}
```

- 重载的详细规则见 [[重载]]。
- 重写是 [[继承]] 和 [[面向抽象编程]] 的基础。
- 写重写时养成加 `@Override` 的习惯，写错名字编译器会立刻提醒。

## 七、递归

方法自己调用自己，就叫递归。必须有一个「出口」终止调用，否则会栈溢出。

```java
int factorial(int n) {
    if (n <= 1) {
        return 1;              // 出口（基准情形）
    }
    return n * factorial(n - 1);  // 自己调用自己
}

factorial(4);   // 4 * 3 * 2 * 1 = 24
```

两个必备条件：

1. **基准情形**（出口）：什么时候直接返回，不再递归。
2. **向出口收敛**：每次递归都要让问题规模变小。

> [!warning] 忘了出口会怎样
> 会抛 `StackOverflowError`（栈溢出错误），不是普通异常，`try-catch` 抓不住。

## 八、注意事项

1. **`abstract` 方法没有方法体**，以 `;` 结尾，且只能出现在抽象类或接口里。
2. **非 `void` 方法的所有分支都要有 `return`**，编译器会逐个检查。
3. **`return` 后面是死代码**，写了会报错。
4. **静态方法里不能用 `this`、不能直接访问实例字段**，因为它执行时对象可能还没创建。
5. **构造方法没有返回值类型**，写了 `void` 就不再是构造方法。
6. **参数传递只有值传递**，别被「引用类型能被改」误导。
7. **可变参数必须放最后**，且一个方法只能有一个。
8. **重载看参数列表，不看返回值**——只有返回值不同不算重载。

---

## 九、一句话总结

> **`[修饰符] 返回值类型 方法名(参数列表) { 方法体 }` —— 修饰符管权限与归属，返回值管交出什么，方法名管标识，参数管接收什么，方法体管怎么做。**
