# 搜一搜呀案例：一个计算属性实现关键字实时过滤

> [!info] 原题
> 蓝桥云课 · 搜一搜呀（题目 1762）
> [题目链接](https://www.lanqiao.cn/problems/1762/learning/?page=1&first_category_id=2&second_category_id=11)

> [!summary] 速记版
> ```js
> computed: {
>   filteredList() {
>     if (this.search === "") {
>       return this.postList;
>     }
>     return this.postList.filter((post) =>
>       post.title.toLowerCase().includes(this.search.toLowerCase())
>     );
>   },
> }
> ```
> - `v-model="search"`：输入框与 `search` 双向绑定，输入即更新数据。
> - `v-for="post in filteredList"`：列表只渲染计算属性的结果。
> - `filter`：对每个 `post` 执行判断，返回 `true` 留下，`false` 丢掉。
> - `includes`：判断标题是否**包含**关键字，属于模糊匹配。
> - `toLowerCase()`：两边都转小写，忽略英文大小写；中文不受影响。
> - 输入为空时返回整个 `postList`，页面恢复显示全部帖子。

## 二、结论先行

题目要补的核心逻辑只有一句：

```js
return this.postList.filter((post) =>
  post.title.toLowerCase().includes(this.search.toLowerCase())
);
```

**原理一句话：`v-model` 把输入框的值同步进 `search`；`filteredList` 依赖 `search`，所以每次输入都会重新计算；`filter` 用 `includes` 判断标题是否包含关键字，`v-for` 再按新数组重新渲染卡片。**

```
用户在输入框输入“猫”
        │
        ▼
v-model 把值写进 data.search
        │
        ▼
Vue 发现计算属性 filteredList 依赖 search
        │
        ▼
filteredList 重新执行：
postList.filter(post => post.title.includes("猫"))
        │
        ▼
v-for="post in filteredList" 只渲染“小猫咪”一张卡片
```

## 三、解题思路

拿到题不要急着写代码，按下面六步走。

### 第 1 步：先确认“谁变、谁不变”

- 唯一会变的是用户输入的关键字 → `search`。
- 始终不变的是全部帖子 → `postList`。
- 页面要显示的是“根据 `search` 从 `postList` 里筛出来的结果” → 这是一个**派生值**。

结论：不要手动增删 DOM，也不要修改 `postList`，而是让一个计算属性根据 `search` 算出新数组。

### 第 2 步：读初始代码，找到 TODO 的边界

打开 `index.html`，先看四处：

| 位置  | 已经有什么                          | 说明         |
| --- | ------------------------------ | ---------- |
| 模板  | `v-model="search"`             | 输入框已经绑好数据  |
| 模板  | `v-for="post in filteredList"` | 列表已经在等计算结果 |
| 脚本  | `data.search`、`data.postList`  | 数据源已经准备好   |
| 脚本  | `computed.filteredList`        | 只有这里是 TODO |

所以本题**不是从零写页面**，只需要实现 `filteredList` 的返回值。模板、`Post` 类和 `data` 都不要动。

### 第 3 步：把需求翻译成过滤条件

题目要的效果可以拆成三条：

1. 初始不输入 → 显示全部；
2. 输入关键字 → 只显示标题**包含**关键字的帖子；
3. 清空关键字 → 恢复全部。

对应写法：

```js
if (this.search === "") return this.postList;          // 第 1、3 条
return this.postList.filter((post) =>                  // 第 2 条
  post.title.toLowerCase().includes(this.search.toLowerCase())
);
```

### 第 4 步：选对 API

这一行代码其实只用了四个 API，分工如下：

| API | 所属 | 作用 | 返回 |
| --- | --- | --- | --- |
| `filter` | `Array.prototype` | 遍历数组，留下回调为真的元素 | 新数组 |
| `includes` | `String.prototype` | 判断字符串是否包含子串 | 布尔值 |
| `toLowerCase` | `String.prototype` | 把字母转成小写 | 新字符串 |
| `search` | `String.prototype` | 按正则查找位置（本题不推荐） | 下标或 `-1` |

#### ① `Array.prototype.filter`：决定“留下谁”

```js
const newArray = arr.filter((element, index, array) => {
  return 条件;
}, thisArg);
```

**参数**

| 参数 | 说明 |
| --- | --- |
| `element` | 当前元素，本题里是一个 `Post` 实例 |
| `index` | 当前下标 |
| `array` | 正在遍历的原数组，本题里是 `postList` |
| `thisArg` | 可选，指定回调里的 `this`；箭头函数无效 |

**返回**：新数组。回调返回真值就保留该元素，返回假值就丢弃；一个都不满足时返回 `[]`。

**是否改原数组**：否。`filter` 不会动 `postList`，所以清空输入后还能恢复全部。

**套到本题**

```js
this.postList.filter((post) => {
  return post.title.toLowerCase().includes(this.search.toLowerCase());
});
```

`post` 是当前帖子，`post.title` 是标题；回调最终返回 `true` 或 `false`，`filter` 根据它决定留不留。

**注意**

- 回调返回 `true`、`1`、`"abc"` 等真值都会保留，不要求必须是布尔值。
- 不要用 `forEach` + `push` 代替：`filter` 直接返回新数组，语义更清楚。
- 不要用 `map` 代替：`map` 返回等长数组，不能减少元素。

#### ② `String.prototype.includes`：判断“包不包含”

```js
str.includes(searchString, position);
```

**参数**

| 参数 | 说明 |
| --- | --- |
| `searchString` | 要查找的子串，本题里是用户输入的关键字 |
| `position` | 可选，从哪个下标开始找，默认 `0` |

**返回**：布尔值。包含返回 `true`，不包含返回 `false`。

**是否改原字符串**：否。字符串本身不可变。

**套到本题**

```js
"小猫咪".includes("猫");    // true
"小猫咪".includes("猫咪");  // true
"小猫咪".includes("狗");    // false
"小猫咪".includes("猫", 2); // false，从下标 2 开始只剩“咪”
```

因为判断的是“标题是否包含关键字”，所以输入 `猫` 能命中 `小猫咪`；如果写成 `post.title === this.search`，就变成完全相等，`猫` 反而匹配不到。

**注意**

- **区分大小写**：`"Cat".includes("cat")` 是 `false`，所以两边都要 `toLowerCase()`。
- **空字符串永远算包含**：`"任意标题".includes("")` 为 `true`。这正是空输入时 `filter` 会返回全部元素的原因。
- 只判断“有没有”，不返回位置；需要位置用 `indexOf`。
- 数组也有 `includes`，但那是 `Array.prototype.includes`，判断的是“数组里有没有某个元素”，不要和字符串的混用。

#### ③ `String.prototype.toLowerCase`：统一大小写

```js
str.toLowerCase();
```

**参数**：无。

**返回**：转成小写后的新字符串。

**是否改原字符串**：否。

**套到本题**

```js
"Cat".toLowerCase();    // "cat"
"HELLO".toLowerCase();  // "hello"
"小猫咪".toLowerCase(); // "小猫咪"，中文原样返回
```

**为什么两边都要转**

```js
"Cat".includes("cat"); // false

// 只转标题
"Cat".toLowerCase().includes("cat"); // true
// 只转关键字
"Cat".includes("cat".toLowerCase()); // true

// 两边都转，输入 CAT / Cat / cat 都能匹配
"Cat".toLowerCase().includes("CAT".toLowerCase()); // true
```

只转一边时，总有一种输入组合会漏掉；两边都转才是彻底忽略大小写。

**注意**

- 中文、数字、符号没有大小写，转换后不变，不影响本题。
- 和 `toUpperCase()` 对称，统一用哪个都行，关键是两边一致。
- 需要按本地语言规则转换时用 `toLocaleLowerCase()`，例如土耳其语的 `I / ı` 问题。

#### ④ `String.prototype.search`：为什么不推荐

```js
str.search(regexp);
```

**参数**：正则表达式。如果传字符串，会被 `new RegExp(regexp)` 隐式转成正则。

**返回**：第一个匹配的下标；没有匹配返回 `-1`。

**套到本题（错误示范）**

```js
post.title.search(this.search) !== -1;
```

看起来和 `includes` 效果一样，但关键字会被当成正则：

```js
"小猫咪".search("猫");   // 1，正常
"a(b)c".search("(");     // SyntaxError：正则不完整
"a.b".search(".");       // 0，. 匹配任意字符，不是字面量点
"a[1]".search("[1]");    // 行为不符合“按字面量包含”的预期
```

用户输入 `(`、`[`、`*`、`+`、`?` 这类正则元字符时，轻则匹配错误，重则直接抛 `SyntaxError`。

**`includes` / `indexOf` / `search` 对比**

| 方法 | 参数 | 返回 | 是否按字面量 | 适合场景 |
| --- | --- | --- | --- | --- |
| `includes` | 子串 + 起始位置 | 布尔值 | 是 | 判断“有没有” |
| `indexOf` | 子串 + 起始位置 | 下标 / `-1` | 是 | 需要位置 |
| `search` | 正则 | 下标 / `-1` | 否 | 真的需要正则时 |

**结论**：做“按字面量包含”的关键字搜索，用 `includes`；需要位置用 `indexOf`；只有明确要用正则时才用 `search`。

#### 四个 API 如何串起来

```js
this.postList.filter((post) =>                    // ① 遍历并筛选数组
  post.title.toLowerCase()                        // ② 标题转小写
    .includes(this.search.toLowerCase())          // ③ 关键字转小写后判断包含
);
```

以输入 `猫` 为例，`filter` 依次判断 6 个帖子：

| `post.title` | 转小写后 | `includes("猫")` | 结果 |
| --- | --- | --- | --- |
| 小猫咪 | 小猫咪 | `true` | 保留 |
| 小狗狗 | 小狗狗 | `false` | 丢弃 |
| 北极熊 | 北极熊 | `false` | 丢弃 |
| 狮子 | 狮子 | `false` | 丢弃 |
| 小鸟 | 小鸟 | `false` | 丢弃 |
| 狐狸 | 狐狸 | `false` | 丢弃 |

最终 `filter` 返回 `[Post("小猫咪")]`，`v-for` 只渲染这一张卡片。

> [!tip] 想看完整的数组方法
> 根目录/JS 文件夹里的 [[数组 API 全解]] 收录了 `filter` 及其他所有数组 API 的语法、参数、返回值和易错点。

### 第 5 步：先写最小实现，再补边界

最小实现其实一行就够：

```js
filteredList() {
  return this.postList.filter((post) =>
    post.title.toLowerCase().includes(this.search.toLowerCase())
  );
}
```

因为 `"任意标题".includes("")` 为 `true`，空输入时这行会自然返回全部。
补上 `if (this.search === "")` 只是让意图更明确，并避免空输入时额外创建数组。

### 第 6 步：按顺序自测

```
初始不输入      → 6 张
输入“小”        → 小猫咪、小狗狗、小鸟（3 张）
输入“猫”        → 小猫咪（1 张）
输入“abc”       → 0 张
清空输入        → 恢复 6 张
```

全部通过后，保持 Live Server 运行，再点「提交检测」。

## 四、初始代码逐块拆解

### 1. 模板部分

```html
<input type="text" v-model="search" placeholder="请搜索" />
```

- `v-model="search"`：**双向绑定**。
  - 用户输入 → 自动写入 `this.search`；
  - 代码里改 `this.search` → 输入框内容也会跟着变。
  - 对文本输入框，Vue 2 监听的是 `input` 事件，所以每敲一个字符都会触发更新。

```html
<div class="card" v-for="post in filteredList">
  <a v-bind:href="post.link" target="_blank">
    <img v-bind:src="post.img" />
    {{ post.title }}
  </a>
</div>
```

- `v-for="post in filteredList"`：遍历**计算属性** `filteredList`，每个元素临时命名为 `post`。
- `v-bind:href="post.link"`：把 `post.link` 绑定到 `href` 属性；`v-bind:` 可以缩写为 `:`，即 `:href`。
- `v-bind:src="post.img"`：把图片路径绑定到 `src`。
- `{{ post.title }}`：插值表达式，把标题渲染成文本。
- 数组里有几个元素，就生成几张 `.card`；数组变了，卡片数量自动跟着变。

> [!tip] 为什么模板里写 `filteredList` 而不是 `filteredList()`
> `computed` 定义的是**属性**，不是方法。模板里直接写名字即可；
> 写成 `filteredList()` 会试图把计算结果当函数调用，直接报错。

### 2. `Post` 类

```js
class Post {
  constructor(title, link, img) {
    this.title = title;
    this.link = link;
    this.img = img;
  }
}
```

- 用一个类把“标题、链接、图片”打包成对象，后面 `new Post(...)` 创建 6 个帖子。
- 等价于直接写 `{ title: "小猫咪", link: "...", img: "..." }`，只是用类更整齐。
- `postList` 里装的就是这些 `Post` 实例。

### 3. `data`

```js
data: {
  search: "",
  postList: [ /* 6 个 new Post(...) */ ],
}
```

- `search`：保存当前输入的关键字，初始为空字符串。
- `postList`：保存全部帖子，是**原始数据**，全程不应该被修改。
- Vue 2 会递归地把 `data` 里的属性变成响应式：`search` 一变，依赖它的计算属性就会失效并重新计算。

### 4. `computed`

```js
computed: {
  filteredList() {
    // TODO: 请补充代码
  },
}
```

- `filteredList` 是**计算属性**，它的值由 `search` 和 `postList` 推导出来。
- 计算属性有缓存：依赖不变时重复读取不会重新执行；依赖一变才重新算。
- 这里只读取数据、返回新数组，**不修改 `postList`**，符合计算属性“纯计算”的定位。

## 五、过滤逻辑逐行拆

```js
if (this.search === "") {
  return this.postList;
}
```

- 输入为空时，直接返回完整的 `postList`，页面显示全部 6 张卡片。
- 这一句不是必须的：`filter` 遇到空字符串也会全部保留（因为 `"任意标题".includes("") === true`）。
- 但写上以后语义更清楚，而且空输入时直接返回原数组，不额外创建新数组。

```js
return this.postList.filter((post) => {
  return post.title.toLowerCase().includes(this.search.toLowerCase());
});
```

| 片段 | 作用 |
| --- | --- |
| `this.postList.filter(...)` | 遍历原数组，把回调返回 `true` 的元素收集成**新数组** |
| `post` | 当前正在判断的帖子对象 |
| `post.title` | 当前帖子的标题，例如 `"小猫咪"` |
| `.toLowerCase()` | 标题转小写，便于忽略英文大小写 |
| `this.search.toLowerCase()` | 关键字也转小写，两边标准一致 |
| `.includes(...)` | 判断标题中是否**包含**关键字，返回 `true` / `false` |

### 为什么两边都要 `toLowerCase()`

`includes` 区分大小写：

```js
"Cat".includes("cat"); // false
"Cat".toLowerCase().includes("cat".toLowerCase()); // true
```

只转标题、不转关键字，输入大写 `CAT` 仍然匹配不到；只转关键字、不转标题，同样不行。**两边都转**才彻底忽略大小写。

中文没有大小写，`toLowerCase()` 对中文原样返回，不会影响“小猫咪”等标题的匹配。

### `filter` 不会改动原数组

```js
const result = this.postList.filter(...);
// this.postList 仍然是原来的 6 个元素
// result 是新的数组，可能只有 1 个元素
```

这正是我们要的：原始数据保持完整，清空输入后才能立刻恢复全部列表。

## 六、Vue 的响应式工作流程

```
① 用户输入“猫”
        │
        ▼
② input 事件 → v-model 把 "猫" 赋给 this.search
        │
        ▼
③ Vue 的响应式系统发现 search 变了
        │
        ▼
④ 依赖 search 的计算属性 filteredList 被标记为“脏”
        │
        ▼
⑤ 重新执行 filteredList：
   postList.filter(post => post.title.includes("猫"))
   → 得到 [Post("小猫咪")]
        │
        ▼
⑥ v-for 按新数组打补丁（patch）：
   保留“小猫咪”卡片，移除其余卡片
        │
        ▼
⑦ 页面只剩 1 张卡片
```

几个关键点：

- **数据驱动视图**：全程没有手动操作 DOM，改的是数据，DOM 由 Vue 更新。
- **计算属性自动追踪依赖**：`filteredList` 里读了 `this.search` 和 `this.postList`，Vue 就记住这两个依赖。`postList` 不变，实际只有 `search` 会触发重算。
- **实时性**：`v-model` 监听 `input`，输入过程中就过滤，不需要按回车或点搜索按钮。

## 七、为什么用 `computed`，不用别的写法

| 写法 | 是否合适 | 原因 |
| --- | --- | --- |
| `computed.filteredList` | ✅ 推荐 | 有缓存；依赖变化自动重算；模板直接写属性名 |
| `methods.filteredList()` | ⚠️ 能跑 | 每次重新渲染都会执行，没有缓存；模板必须写括号 |
| `watch.search` 里改另一个数组 | ❌ 绕远 | 要额外维护 `filteredList` 数据，容易和原数据不同步 |
| 在 `filteredList` 里改 `this.postList` | ❌ 错误 | 计算属性产生副作用，可能触发循环更新 |
| 手动 `document.querySelector` 增删卡片 | ❌ 不符合题意 | 绕过了 Vue，判题和可维护性都差 |

### `computed` 和 `methods` 的本质区别

```js
// computed：模板写 filteredList
computed: {
  filteredList() { /* ... */ }
}

// methods：模板必须写 filteredList()
methods: {
  filteredList() { /* ... */ }
}
```

- `computed` 的结果会被缓存，只要 `search` 和 `postList` 没变，多次读取不会重复执行。
- `methods` 每次调用都重新执行；在模板里还会随着每次重新渲染被调用。
- 过滤列表属于“由现有数据推导出来的值”，天然适合 `computed`。

## 八、字符串匹配方法对比

| 方法 | 示例 | 返回值 | 说明 |
| --- | --- | --- | --- |
| `includes` | `title.includes(key)` | `true` / `false` | ES6，语义最清楚，**推荐** |
| `indexOf` | `title.indexOf(key) !== -1` | 下标或 `-1` | 兼容性好，写法稍绕 |
| `search` | `title.search(key) !== -1` | 下标或 `-1` | 参数会按**正则**处理，关键字含 `(`、`[` 等符号可能出错 |
| `startsWith` | `title.startsWith(key)` | `true` / `false` | 只匹配开头，不是“包含” |
| `RegExp.test` | `new RegExp(key).test(title)` | `true` / `false` | 灵活，但需要转义特殊字符 |

### 三种常见等价写法

```js
// ① includes（推荐）
post.title.toLowerCase().includes(this.search.toLowerCase());

// ② indexOf
post.title.toLowerCase().indexOf(this.search.toLowerCase()) !== -1;

// ③ search（关键字含正则符号时不安全）
post.title.search(this.search) !== -1;
```

> [!warning] 不推荐 `search`
> `String.prototype.search` 会把参数转成正则表达式。用户输入 `(`、`[`、`*` 这类字符时可能直接抛 `SyntaxError`，或者匹配结果不符合“按字面包含”的预期。做关键字搜索优先用 `includes` 或 `indexOf`。

### 如果还想忽略首尾空格

```js
const key = this.search.trim().toLowerCase();
if (key === "") return this.postList;
return this.postList.filter((post) =>
  post.title.toLowerCase().includes(key)
);
```

题目没有要求，但实际项目里很常见。

## 十、常见坑

1. **直接修改 `postList`**
   ```js
   // ❌ 计算属性里改原数据，可能循环更新，清空输入也恢复不了
   this.postList = this.postList.filter(...);
   return this.postList;
   ```
   正确做法是 `return this.postList.filter(...)`，让原数组保持不变。

2. **模板里写成 `filteredList()`**
   `computed` 是属性，不是方法，写括号会报错。

3. **用 `methods` 却在模板里不写括号**
   模板拿到的是函数本身，`v-for` 无法遍历，页面空白。

4. **忘记 `return`**
   ```js
   filteredList() {
     this.postList.filter(...); // ❌ 没有 return，结果是 undefined
   }
   ```

5. **把 `filter` 写成 `forEach` 或 `map`**
   - `forEach` 返回 `undefined`；
   - `map` 返回等长数组，起不到过滤作用。

6. **只对标题或只对关键字转小写**
   输入 `CAT` 时匹配不到 `Cat`，两边都要转。

7. **判断写成 `post.includes(...)`**
   `post` 是对象，不是字符串，应该判断 `post.title`。

8. **`filter` 回调里用普通函数导致 `this` 丢失**
   ```js
   // ❌ 普通函数的 this 不是 Vue 实例
   this.postList.filter(function (post) {
     return post.title.includes(this.search);
   });
   ```
   用箭头函数，或提前把 `this.search` 存成变量。

9. **`v-for` 没写 `:key`**
   本题不加也能显示，但控制台会有警告。标题唯一，可以写 `:key="post.title"`。

10. **改文件名、文件夹路径、class 名、图片名**
    题目明确规定不能改，判题会按原路径检查资源。

11. **用 Vue 3 的写法**
    本题环境是 Vue 2（`new Vue({ el: "#app" })`），不要写 `Vue.createApp(...).mount(...)`。

12. **手动操作 DOM**
    判题看的是 Vue 渲染结果；用 `querySelector` 删卡片既绕远又容易和 Vue 的更新冲突。

13. **把 `filteredList` 定义在 `data` 里**
    它是由 `search` 推导出来的，应该放 `computed`；放 `data` 不会随输入自动变化。

## 十二、延伸：多关键字搜索

如果需求变成“空格分隔多个关键字，标题要同时包含全部关键字”，可以这样写：

```js
computed: {
  filteredList() {
    const keys = this.search
      .trim()
      .toLowerCase()
      .split(/\s+/)
      .filter(Boolean);

    if (keys.length === 0) return this.postList;

    return this.postList.filter((post) =>
      keys.every((key) => post.title.toLowerCase().includes(key))
    );
  },
}
```

- `split(/\s+/)`：按一个或多个空白切分。
- `filter(Boolean)`：去掉空字符串。
- `every`：所有关键字都命中才保留（“与”关系）；换成 `some` 就是“或”关系。

### Vue 3 等价写法（了解即可）

```js
const { createApp, ref, computed } = Vue;

createApp({
  setup() {
    const search = ref("");
    const postList = [/* ... */];

    const filteredList = computed(() => {
      const key = search.value.trim().toLowerCase();
      if (!key) return postList;
      return postList.filter((post) =>
        post.title.toLowerCase().includes(key)
      );
    });

    return { search, postList, filteredList };
  },
}).mount("#app");
```

本题考试环境是 Vue 2，上面的 Vue 3 写法只作为知识延伸，不要写进答案。
