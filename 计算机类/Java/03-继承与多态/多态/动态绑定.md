# Java 动态绑定

> 多态在运行期的实现机制。理解动态绑定，才能解释"为什么父类引用调用的是子类的方法"。

## 1. 什么是"绑定"

==绑定（Binding）==指的是：把一个方法调用，关联到具体要执行的方法实现。

| 类型 | 其他叫法 | 决定时机 | 依据 |
| --- | --- | --- | --- |
| ==静态绑定== | 早期绑定（early binding） | 编译期 | 引用变量的==编译时类型== |
| ==动态绑定== | 晚期绑定（late binding） | 运行期 | 对象的==运行时类型== |

Java 中：

* ==实例方法默认使用动态绑定==（只要它可能被重写）；
* 被 `static`、`private`、`final` 修饰的方法，以及构造方法、字段访问，使用静态绑定；
* ==重载（Overload）在编译期决定，重写（Override）在运行期决定==。

## 2. 一个例子看懂

沿用[[继承]]中的员工案例（简化版）：

```java
class Employee {
    protected String name;

    public Employee(String name) {
        this.name = name;
    }

    public void work() {
        System.out.println(name + " 在完成员工的工作");
    }

    public double calculateSalary() {
        return 5000;
    }
}

class Manager extends Employee {
    private double bonus;

    public Manager(String name, double bonus) {
        super(name);
        this.bonus = bonus;
    }

    @Override
    public void work() {
        System.out.println(name + " 在开会");
    }

    @Override
    public double calculateSalary() {
        return 5000 + bonus;
    }
}
```

```java
Employee e = new Manager("张三", 2000);   // 向上转型

e.work();                                  // 张三 在开会
System.out.println(e.calculateSalary());   // 7000.0
```

编译器和 JVM 分别做了这些事：

1. **编译期**：`e` 的静态类型是 `Employee`，编译器检查 `Employee` 里确实有 `work()`，生成一条"调用 `Employee.work`"的虚方法调用指令；
2. **运行期**：JVM 发现 `e` 实际指向 `Manager` 对象，于是去 `Manager` 的方法表里找 `work()`，找到重写版本并执行。

所以输出的是 `张三 在开会`，而不是 `Employee` 的版本。

## 3. 动态绑定的四个前提

四个条件==缺一不可==：

1. **有继承或实现关系**：子类 `extends` 父类，或者类 `implements` 接口；
2. **方法被重写**：子类提供了签名相同、访问权限不更严的实现；
3. **父类（或接口）引用指向子类对象**：即发生向上转型；
4. **通过实例方法调用**：不能是 `static`、`private`、`final` 方法，也不能是构造方法。

```java
Employee e = new Manager("张三", 2000);   // 条件 1 + 3
e.work();                                  // 条件 2 + 4 → 动态绑定
```

少任何一个，都会退化为静态绑定或普通调用：

```java
Manager m = new Manager("张三", 2000);
m.work();             // 没有"父类引用"，只是一次普通调用

Employee e = new Manager("张三", 2000);
e.toString();         // Object.toString 未在 Manager 中重写 → 执行 Object 版本
```

## 4. 编译期与运行期各做什么

### 4.1 编译期

* 检查==引用类型==中是否存在可访问的同名、同参数方法；不存在直接编译错误；
* 如果存在==重载==，按参数的==静态类型==选出唯一版本（重载在编译期就定死了）；
* 生成 `invokevirtual`（类方法）或 `invokeinterface`（接口方法）指令。

```java
Employee e = new Manager("张三", 2000);
// e.approve();   // 编译错误：Employee 中没有 approve()
```

编译器不会去管 `Manager` 有没有 `approve()`，因为它只看 `Employee`。

### 4.2 运行期

1. 取出接收者对象的==实际类型==；
2. 在该类型的方法表中查找与签名匹配的实现；
3. 如果本类没有重写，就沿着继承链向上找，直到找到最近的一个版本；
4. 执行找到的方法。

```java
Manager 方法表：
    work            -> Manager.work            （重写，替换了父类表项）
    calculateSalary -> Manager.calculateSalary （重写）
    approve         -> Manager.approve          （子类新增）
    toString        -> Object.toString          （继承，指向父类实现）
```

## 5. 方法表：动态绑定的实现基础

> [!note] 实现细节
> 下面描述的是 HotSpot 等常见 JVM 的==概念模型==（vtable / itable）。Java 语言规范只规定"按运行时类型选择方法"，并不规定具体实现方式。

每个类在加载、链接完成后，都会有一张==方法表==：

* 表中每一项指向该类实际要执行的方法；
* 子类重写父类方法时，==替换表中对应项==；
* 子类新增的方法追加到表尾；
* 接口方法使用单独的接口方法表（itable）。

示意：

| 方法签名 | `Employee` 表项 | `Manager` 表项 |
| --- | --- | --- |
| `work()` | `Employee.work` | ==`Manager.work`== |
| `calculateSalary()` | `Employee.calculateSalary` | ==`Manager.calculateSalary`== |
| `approve()` | 不存在 | `Manager.approve` |

调用 `e.work()` 时，JVM 只需要：

```
对象头 → 类元数据 → 方法表 → work 对应槽位 → 实际方法地址
```

因此动态绑定不需要"从子类到父类逐个类搜索"，而是一次表查找，开销很小。

## 6. 哪些调用不是动态绑定

| 调用形式             | 绑定时机      | 原因                       |
| ---------------- | --------- | ------------------------ |
| `static` 方法      | 编译期       | 属于类，子类写同名方法只是==隐藏==，不是重写 |
| `private` 方法     | 编译期       | 对子类不可见，无法重写              |
| `final` 方法       | 编译期（目标唯一） | 不允许重写，不存在第二个版本           |
| 构造方法             | 编译期       | 构造方法不继承、不重写              |
| `super.method()` | 编译期       | 明确要求调用父类版本               |
| 字段访问             | 编译期       | 字段只有==隐藏==，没有多态          |
| 重载方法的选择          | 编译期       | 按参数的静态类型选版本              |


### 6.1 重载 + 重写：最容易混淆的组合

```java
class OA {
    public void f(Object o) { System.out.println("OA.f(Object)"); }
    public void g()        { System.out.println("OA.g"); }
}

class OB extends OA {
    public void f(String s) { System.out.println("OB.f(String)"); }  // 重载
    @Override
    public void g()         { System.out.println("OB.g"); }          // 重写
}

public class Demo {
    public static void main(String[] args) {
        OA oa = new OB();

        oa.f("x");    // OA.f(Object)
        oa.g();       // OB.g

        OB ob = new OB();
        ob.f("x");    // OB.f(String)
    }
}
```

输出：

```
OA.f(Object)
OB.g
OB.f(String)
```

关键点：

* `OB.f(String)` 的参数是 `String`，而父类方法是 `f(Object)`，参数列表不同 → 这是==重载==，不是重写；
* 重载在编译期按==引用的静态类型 `OA`== 选择，`OA` 中只有 `f(Object)`，所以执行 `OA.f(Object)`；
* `g()` 是真正的重写，运行期按实际类型 `OB` 选择，所以执行 `OB.g()`。

如果想让 `f` 也表现出多态，父类必须声明同样的 `f(String)` 并在子类重写：

```java
class OA {
    public void f(String s) { System.out.println("OA.f(String)"); }
}
class OB extends OA {
    @Override
    public void f(String s) { System.out.println("OB.f(String)"); }
}

OA oa = new OB();
oa.f("x");   // OB.f(String)
```

### 6.2 字段隐藏

```java
class A {
    String tag = "A";
}
class B extends A {
    String tag = "B";
}

A a = new B();
System.out.println(a.tag);          // A
System.out.println(((B) a).tag);    // B
```

两个 `tag` 在内存中==同时存在==，`B.tag` 隐藏了 `A.tag`，具体读哪一个由引用的静态类型决定。

### 6.3 static 方法隐藏

```java
class A {
    static void s() { System.out.println("A.s"); }
}
class B extends A {
    static void s() { System.out.println("B.s"); }
}

A a = new B();
a.s();     // A.s
B.s();     // B.s
```

静态方法在编译期就按"变量声明类型 / 类名"确定，和对象无关。

### 6.4 super 调用

```java
class P {
    void f() { System.out.println("P.f"); }
}

class C extends P {
    @Override
    void f() { System.out.println("C.f"); }

    void callSuper() {   // 注意：这不是重写，不能加 @Override
        super.f();       // 明确调用父类版本，不参与动态绑定
    }
}

new C().callSuper();     // P.f
```

`super.f()` 在编译期就锁定为 `P.f`，即使当前对象的实际类型是 `C`。

## 7. 字节码视角

用 `javap -c` 查看调用点：

```java
class P {
    void f() { System.out.println("P.f"); }
    static void s() { System.out.println("P.s"); }
    final void fin() { System.out.println("P.fin"); }
}

class C extends P {
    @Override void f() { System.out.println("C.f"); }
    void callSuper() { super.f(); }
}

P p = new C();
p.f();
P.s();
p.fin();
```

`javap -c` 的关键片段：

```
 9: invokevirtual #10    // Method P.f:()V
12: invokestatic  #15    // Method P.s:()V
16: invokevirtual #18    // Method P.fin:()V
```

而 `C.callSuper()` 中：

```
 1: invokespecial #21    // Method P.f:()V
```

| 指令 | 用于 | 是否动态绑定 |
| --- | --- | --- |
| `invokevirtual` | 普通实例方法 | ==是== |
| `invokeinterface` | 接口方法 | ==是== |
| `invokestatic` | `static` 方法 | 否 |
| `invokespecial` | 构造方法、`super.m()`、私有方法（传统实现） | 否 |
| `invokedynamic` | Lambda、字符串拼接等 | 由引导方法决定 |

> [!tip] 一个容易误解的细节
> `invokevirtual` 指令里写的 `Method P.f` 只是==编译期选定的符号引用==，并不是最终执行的方法。
> JVM 在运行时会根据接收者的实际类型重新解析，最终可能执行 `C.f`。这正是动态绑定发生的位置。

## 8. 构造方法中的动态绑定陷阱

```java
class Parent {
    Parent() {
        show();          // 构造方法中调用了可重写方法
    }

    void show() {
        System.out.println("Parent.show");
    }
}

class Child extends Parent {
    private int value = 42;

    @Override
    void show() {
        System.out.println("Child.show, value=" + value);
    }
}

public class Demo {
    public static void main(String[] args) {
        new Child();
    }
}
```

输出：

```
Child.show, value=0
```

为什么会是 `0`？创建 `Child` 对象的执行顺序是：

1. 分配内存，所有字段先置为==默认值==（`int` 为 `0`，引用为 `null`）；
2. 调用 `Parent` 的构造方法；
3. `Parent` 构造方法里的 `show()` 发生动态绑定，实际执行 `Child.show()`；
4. `Child` 的字段初始化 `value = 42` 这时==还没执行==；
5. 最后执行 `Child` 构造方法体。

所以 `Child.show()` 读到的是默认值 `0`。

> [!warning] 不要在构造方法中调用可被重写的方法
> * 子类字段尚未初始化，可能读到 `0` / `null` / `false`；
> * 子类重写方法可能依赖自己的初始化逻辑，行为不可预期；
> * 如果一定要在构造方法中调用，把方法声明为 `private` 或 `final`，杜绝被重写。

## 9. 转型和动态绑定无关

强转只改变引用的静态类型，==不改变对象的实际类型，也不改变方法分派结果==：

```java
Employee e = new Manager("张三", 2000);

((Employee) e).work();   // 张三 在开会，仍然是 Manager.work
Manager m = (Manager) e;
m.work();                // 张三 在开会
```

只要接收者是同一个 `Manager` 对象，`work()` 就执行 `Manager.work`。

## 10. 动态绑定的性能

早期有人担心"每次调用都要查表，会不会很慢"。实际上：

* 一次方法表查找本身已经是常数时间；
* JIT 会对==单态调用点==做内联（inline）；
* 对多态调用点使用==内联缓存==（inline cache）；
* 通过类层次分析（CHA）做==去虚化==（devirtualization），把虚调用变成直接调用。

因此，==不要为了性能把方法写成 `static` 或 `final`==。真正影响性能的是算法和内存访问，而不是一次方法表查找。

## 11. 动态绑定的意义

```java
Employee[] staff = {
    new Manager("张三", 2000),
    new HourlyEmployee("李四", 20, 100)   // 假设它同样继承 Employee 并重写 calculateSalary
};

for (Employee e : staff) {
    System.out.println(e.calculateSalary());   // 不需要 if/else 判断类型
}
```

* 调用方只依赖父类/接口，==新增子类时调用方一行都不用改==；
* 差异行为由子类各自重写，符合[[开闭原则]]；
* 这就是[[面向抽象编程]]能够成立的前提。

没有动态绑定，多态就只剩"父类引用可以指向子类对象"的语法，没有实际行为差异。

## 12. 常见误区

1. **以为字段有多态**：字段只看引用类型，只有方法才动态绑定。
2. **以为 `static` 方法会被重写**：那只是隐藏，调用看类/引用类型。
3. **以为重载会动态绑定**：重载在编译期按参数静态类型选定。
4. **以为 `private` 方法能被重写**：子类写同名方法只是新方法，不构成重写。
5. **以为强转能改变分派**：对象的实际类型不变，分派结果就不变。
6. **在构造方法里调用可重写方法**：会读到子类尚未初始化的字段。
7. **以为 `@Override` 是多态的必要条件**：它只是编译期校验，写不写都不影响分派；但强烈建议写。
8. **认为动态绑定只看"变量的值"**：准确说是看==变量指向的对象的实际类型==。

## 13. 小结

* 动态绑定 = ==运行期根据对象的实际类型选择方法实现==；
* 四个前提：继承/实现、重写、父类引用指向子类对象、实例方法调用；
* 编译期负责"这个方法存不存在、重载选哪个"，运行期负责"重写选哪个"；
* `static` / `private` / `final` / 构造方法 / `super.` / 字段 / 重载都是静态绑定；
* 对象的方法表让分派只需一次查找，JIT 还会进一步内联优化；
* 动态绑定是多态的行为基础，也是面向抽象编程、开闭原则的底层支撑。
