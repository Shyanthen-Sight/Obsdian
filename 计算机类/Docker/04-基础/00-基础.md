# 基础

这阶段不背命令，而是把“拉镜像、起容器、看日志、进容器、清理”跑顺，知道每步动了什么。

## 最小闭环

```bash
docker pull nginx
docker run -d --name web -p 8080:80 nginx
docker ps
curl -I http://localhost:8080
docker logs -f web
docker exec -it web sh
docker stop web && docker rm web
```

| 命令或参数 | 作用 |
| --- | --- |
| `-d` | 后台运行 |
| `-p 8080:80` | 宿主机 8080 转到容器 80 |
| `--name web` | 给容器命名，之后用名字代替 ID |
| `logs -f` | 跟主进程的 stdout/stderr；写进文件的日志看不到 |
| `exec -it` | 在已有命名空间里开一个进程，不是登录虚拟机；容器停止后不可用 |
| `ps` / `ps -a` | 前者只列运行中的，后者连退出的也列，STATUS 里有退出码 |
| `inspect` | 看实际生效的配置和状态，JSON 输出，`-f` 取字段 |
| `cp` | 容器与宿主之间拷文件，容器停着也能拷 |
| `stop` / `rm` | 先 SIGTERM 等 10 秒再 SIGKILL；删容器连可写层一起删 |

镜像名不写 tag 就是 `latest`，练习够用，项目里写死版本。一次性任务用 `docker run --rm`，跑完自动清理。

## 构建最小镜像

构建一个最小镜像，看清镜像和容器的分界。先在当前目录放一个 `index.html`：

```dockerfile
FROM nginx:alpine
COPY index.html /usr/share/nginx/html/index.html
```

```bash
docker build -t my-web .
docker run -d -p 8080:80 my-web
```

`FROM` 指定基础层，`COPY` 新增一层，`-t` 给镜像起名字，构建上下文是末尾的 `.`。

构建改的是镜像，`run` 出来的才是容器；在容器里改文件只落在可写层，删掉重建就回到镜像的样子。

## 容器状态

`docker run` 等于 `create` 加 `start`。需要分步控制时：

```bash
docker create --name demo -p 8081:80 nginx
docker start demo
docker restart demo
docker pause demo && docker unpause demo
docker rm -f demo
```

- `restart` 是 stop 加 start
- `pause` 只冻结进程，内存和状态还在
- `rm -f` 对运行中的容器直接 SIGKILL 再删

## 四个对象

Docker 的命令结构就是 `docker <对象> <动作>`，日常只需要记住四类：

| 对象 | 一句话 | 常用命令 |
| --- | --- | --- |
| 镜像 | 只读模板，由层叠加 | `pull` `build` `images` `rmi` |
| 容器 | 镜像加可写层和隔离 | `run` `ps` `logs` `exec` `cp` `rm` |
| 卷 | 生命周期独立的存储 | `volume create` `volume ls` `volume rm` |
| 网络 | 容器之间的虚拟网络 | `network create` `network inspect` |

## 清理

- 先删容器，再删镜像、卷和网络
- 镜像被容器引用时 `rmi` 会失败，先处理容器
- `docker system prune` 收掉停止的容器、未使用的网络、悬空镜像和构建缓存

> [!warning] prune 默认不动卷
> 加 `--volumes` 才会连卷一起删，删之前确认数据不要了。

## 常见报错

| 报错                                       | 多半是                  | 先做什么                                                                |
| ---------------------------------------- | -------------------- | ------------------------------------------------------------------- |
| `port is already allocated`              | 宿主端口被占               | `docker ps` 看 8080 被谁占用；Linux 用 `ss -lntp`，Windows 用 `netstat -ano` |
| `name "/web" is already in use`          | 同名容器还在，可能已退出         | `docker ps -a`，`docker rm web` 或换名字                                 |
| 容器起来就 `Exited`                           | 入口命令跑完或参数不对          | `docker logs web`，再看 `ps -a` 里的退出码                                  |
| `exec` 报 `is not running`                | 容器已停                 | `docker start web` 后再 exec                                          |
| `pull access denied`                     | 镜像名或 tag 写错，或私有仓库未登录 | 核对完整镜像名，必要时 `docker login`                                          |
| `COPY failed: file not found`            | 文件不在构建上下文            | 确认文件在当前目录，且没被 `.dockerignore` 排除                                    |
| `cannot remove ... container is running` | 容器还在跑                | 先 `stop`，或 `rm -f`                                                  |

## 学完的标准

| 标准 | 自检 |
| --- | --- |
| 能从镜像起一个服务，并从宿主访问 | `curl -I http://localhost:8080` 返回 200 |
| 容器异常时知道先看什么 | 能说清 `ps -a`、`logs`、`inspect` 各看什么 |
| 分得清镜像和容器 | 能解释为什么 exec 里改的配置重建后消失 |
| 能清理干净 | 用 `rm -f`、`rmi`、`system prune` 不留残余 |
