## 一、知识回顾：对象、引用与构造方法

### 1.1 声明 vs 实体

| 概念       | 语法               | 系统做了什么                  | 存在哪     |
| :------- | :--------------- | :---------------------- | :------ |
| **对象声明** | `Student s;`     | 分配一个变量，用来存放**引用**       | 栈（局部变量） |
| **实体分配** | `new Student();` | 在堆上分配内存 → 调用构造方法 → 返回引用 | 堆       |

**关键结论**：==声明与实体分配**不必写在同一行**：==

```java
Student s;              // 只声明，此时 s == null
s = new Student();      // 才真正创建实体，并把引用赋给 s
```

### 1.2 构造方法四条铁律

1. ==**名字必须与类名完全相同**==，且==**不写返回值类型**==（写 `void` 就变成普通方法了）；
2. 只能通过 ==`new` 调用==，**==不能**像普通方法那样用对象调用==；
3. 若**未手动声明任何**构造方法，编译器自动生成一个**无参默认构造方法**；
4. 一旦手动声明了**任意**构造方法（哪怕带参），**默认无参构造方法就不再生成**。

### 1.3 引用赋值的语义

```java
Student s2 = s1;   // 复制的是「引用」，不是对象
```

此后 ==`s1` 与 `s2` 指向**同一个实体**==，通过任一引用修改字段，另一个引用都看得到（这就是"引用别名"）。

# 参考答案与详细解析

## 选择题

### 第 1 题 答案：**C**
**解析**：C 是构造方法的**定义性特征**——名字与类名相同，且不写返回值类型。注意：一旦写了 `void`，它就变成普通方法，不再是构造方法。
- A **错**：只要==没有手动声明任何构造方法==，==编译器会自动生成无参默认构造方法==，所以"必须显式定义"不成立；
- B **错**：构造方法只能通过 `new` 调用。`obj.ClassName()` 是非法语法，==构造方法不能被当作普通方法用对象调用==； 
- D **错**：==分配内存空间的是 `new` 运算符==；==构造方法的职责是**初始化**对象（给字段赋初值）==，不是分配内存。

### 第 2 题 答案：**C**
**解析**：`Student s;` 只分配了一个**存放引用的变量**；`new Student()` 才在堆上分配实体并返回其引用，再赋给 `s`。所以"变量是引用，实体在堆上"。
- A **错**：==`s` 里存的是引用（地址）==，不是实体数据本身；
- B **错**：关系说反了；
- D **错**：`s` 就是这个 `new` 出来的实体的引用，二者不是"两个独立对象"。

### 第 3 题 答案：**B**
**解析**：`s2 = s1` 复制的是**引用**==，此后 `s1` 与 `s2` 指向同一个实体==。通过 `s2` 改 `name`，等于改同一个对象，所以 `s1.name` 也是 `Tom`。
**延伸**：这叫**引用别名**。若需要真正独立的副本，应使用 `clone()` 或 `new` 之后逐字段复制。

### 第 4 题 答案：**B**
**解析**：第1行只==**声明变量**==（分配引用空间，此时 `s == null`）；第2行 `new Student()` **分配实体**并把引用赋给 `s`，对象实体就是在这一行创建的；第3行只是给**已存在实体**的字段赋值。
**D 是干扰项**：=="声明"和"实体分配"是两件独立的事==，可以分开写——这正是本题要考的辨析点。

### 第 5 题 答案：**C**
**解析**：铁律——==只要手动声明了**任意**构造方法==（哪怕带参），==编译器就**不再**生成无参默认构造方法==。因此 `new A()` 编译报错。
- B **错**：==自动生成无参构造的前提是"**没有声明任何**构造方法"==；
- D **错**：==构造方法永远不写返回类型==。
**延伸**：若既要 `new A()` 又要 `new A(1)`，必须显式写出 `A() {}`（或让 `A()` 用 `this(...)` 委托给 `A(int)`）。

### 第 6 题 答案：**B**
**解析**：
- A **错**：`Study` 是实例方法，==必须通过对象调用（`s.Study()`）==。用类名调用实例方法会编译报错：`non-static method cannot be referenced from a static context`；
- B **对**：==通过对象访问字段的标准写法==；
- C **错**：`->` 是 C/C++ 的指针语法，==Java 没有指针概念==；
- D **错**：非法语法。

### 第 7 题 答案：**B**
**解析**：赋值 `p1 = p2` 把 `p2` 的引用（指向实体 B）复制给 `p1`，此后两个变量**都指向实体 B**。
- A **错**：实体 A 失去所有引用，成为**垃圾对象**，等待 GC 回收，并非"立即销毁"；实体 B 不受影响；
- C **错**：赋值是**单向**的，`p2` 不会反过来变成指向 A；
- D **错**：这不是"值互换"。互换两个变量指向的对象需要借助临时变量三步操作。

### 第 8 题 答案：**D**
**解析**：D **错**——声明与实体分配**可以分两行完成**（见第 4 题），"必须在同一行"是错误的强制要求。
- A **对**：声明对象 = 分配一个用来存放引用的变量；
- B **对**：实体（堆上的对象）存储了对象的具体数据。
  > [!note] B 选项表述有瑕疵
  > "实体是……变量"这个说法不严谨——严格讲**实体不是变量**，"对象变量"才是存放引用的变量。应按后半句「实体存储了对象的具体数据」来理解，这一句是**正确**的。原题如此，未作改动；
- C **对**：对象变量存放的是引用，可以被重新赋值为另一个实体的引用。

## 附：常见误区速查

| 常见误区                 | 正解                               |
| :------------------- | :------------------------------- |
| 构造方法必须自己写            | ==未声明**任何**构造方法时，编译器自动生成无参默认构造== |
| 构造方法可以写 `void`       | ==写了 `void` 就不再是构造方法==           |
| 声明对象就等于创建对象          | ==声明只分配引用变量，`new` 才创建实体==        |
| `s2 = s1` 得到一个新对象    | ==复制的是引用，两个变量指向**同一实体**==        |
| `p1 = p2` 后实体 A 立即销毁 | ==只是失去引用，成为垃圾对象，等 GC 回收==        |
| 声明与创建必须在同一行          | ==可以分开写，两者相互独立==                 |
| 用类名调用实例方法            | ==实例方法必须通过对象调用==                 |
