# 容器安全

容器安全要先接受一个前提：容器共享宿主机内核。命名空间和 cgroups 把进程的视野与资源圈起来，但内核漏洞、错误配置、过大的权限都能把隔离打穿。别把容器当成安全边界，它更像一层需要持续加固的部署单元。

风险可以拆成两段。构建阶段看基础镜像是否可信、版本是否固定、依赖有没有已知 CVE、镜像里有没有混进密钥和构建工具；运行阶段看进程是不是 root、capabilities 给了多少、根文件系统能不能写、有没有挂 docker.sock、资源有没有上限。两段的处理手段完全不同，排查时别混为一谈。

学习顺序建议先走 [[01-镜像安全|镜像安全]]，把镜像来源、扫描、签名这条线走通；再看 [[02-运行时安全|运行时安全]]，逐项收紧运行参数。之后回到 [[03-镜像大小与安全|镜像大小与安全]] 和 [[03-运行时配置|运行时配置]]，把原则落进 Dockerfile 和 `docker run`。

```bash
docker run --rm -it \
  --read-only --cap-drop ALL \
  --security-opt no-new-privileges \
  alpine sh
```

这条命令把根文件系统设为只读、丢掉全部 capabilities、禁止通过 setuid 提权，是运行时加固的最小组合。业务容器在此基础上按需 `--cap-add`，并为确实需要写入的目录单独挂 tmpfs 或卷。

学完这一阶段，应该能回答三个问题：这个镜像能不能上生产？容器被攻破后攻击者还能做什么？CI 里哪些检查必须卡住发布？答不上来，说明加固还停留在抄参数。
