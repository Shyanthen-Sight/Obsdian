# 运行时安全

运行时加固假设容器里的进程迟早会被攻破，目标是被攻破时攻击者拿不到宿主机权限。下面这些开关不必全开，但每项在防什么要清楚。

## capabilities：把 root 拆开看

Linux 把 root 的特权拆成几十个 capability。Docker 默认给容器约 14 个，包括 `CHOWN`、`NET_RAW`、`SETUID`、`DAC_OVERRIDE`。多数 Web 服务一个都不需要，先全丢再按需加。

```bash
docker run -d --name web \
  --user 1000:1000 \
  --cap-drop ALL --cap-add NET_BIND_SERVICE \
  --read-only --tmpfs /tmp:rw,size=64m \
  --security-opt no-new-privileges \
  --memory 512m --cpus 1 --pids-limit 200 \
  -p 8080:8080 nginxinc/nginx-unprivileged:1.27
```

`--user` 避免容器内 root；`--read-only` 让根文件系统只读，`/tmp` 用 tmpfs 单独给一块可写空间；`--pids-limit` 防 fork 炸弹，`--memory`、`--cpus` 防资源耗尽。`NET_BIND_SERVICE` 只在必须绑定 1024 以下端口时加，更常见的做法是直接监听 8080。

## seccomp、AppArmor、SELinux

三层机制各管一段。seccomp 过滤系统调用，Docker 默认 profile 会挡掉 `reboot`、`mount`、`kexec_load` 等一批危险调用；`--security-opt seccomp=unconfined` 等于把这层关掉，除了临时调试别用。AppArmor 按路径和操作做强制访问控制，Debian/Ubuntu 上默认加载 `docker-default`；SELinux 靠标签做 MAC，RHEL/CentOS 上更常见，容器进程通常落在 `container_t`。

```bash
docker inspect -f '{{json .HostConfig.SecurityOpt}}' web
docker exec web grep Seccomp /proc/self/status   # Seccomp: 2 表示过滤模式
```

高敏感服务可以自定义 seccomp profile：从默认 profile 出发，用 `strace` 收集实际调用再收紧。别手写全量白名单，漏一个调用就是启动即崩。

## no-new-privileges 与用户命名空间

`no-new-privileges` 阻止进程通过 setuid 二进制或文件 capability 获得更高权限。容器里就算装了 sudo、ping，也无法借它们提权，成本几乎为零，建议默认加。

用户命名空间重映射更进一步：把容器内的 root 映射到宿主机上一段非特权 UID。容器里是 root，落到宿主文件系统上只是普通用户。

```json
{
  "userns-remap": "default"
}
```

写进 `/etc/docker/daemon.json` 后重启。代价是绑定挂载的文件属主会变化，部分镜像和卷的权限会出问题，上线前得在测试环境验证。`docker info --format '{{.SecurityOptions}}'` 能看到 `userns` 是否生效。

## 挂 docker.sock 为什么等于给 root

Docker daemon 以 root 运行，能创建容器、挂载宿主目录。容器只要挂上 `/var/run/docker.sock`，就能通过 API 起一个挂载宿主根目录的容器：

```bash
docker run --rm -v /var/run/docker.sock:/var/run/docker.sock \
  -v /:/host alpine chroot /host sh
```

进去就是宿主 root。CI runner、Watchtower 这类工具经常这么挂，容器一旦被攻破，整台机器就易主。替代方案是 rootless Docker、只放行必要 API 的 socket proxy，或者把部署动作放到宿主机执行。只读挂载 socket 也没用，同样能发创建容器的请求。

> [!warning] `--privileged` 不是省事开关
> 它几乎关掉所有隔离，还暴露全部设备。设备用 `--device` 单独给，capability 按需单独加。
