# 安全等于 `<=>` —— 把 NULL 当成普通值来比

> [!abstract] 一句话
> `<=>` 是 MySQL 的**NULL 安全等于**（NULL-safe equal）：它像 `=` 一样比较，但==**把 NULL 当成一个普通值**==——两边都是 NULL 时返回 `TRUE`，一边 NULL 一边非 NULL 时返回 `FALSE`，**永远不会返回 UNKNOWN**。
> 它是 `= NULL` 写法的"正规替代品"，也是比较两个可空列是否真正相同的唯一简洁写法。

> [!info] 与其它笔记的分工
> 普通比较 `=` / `<>` 见 [[比较谓词]]；判空见 [[空值谓词]]。
> 本篇只讲 `<=>` 的语义、真值表、典型场景和坑。

---

## 一、语法与基本行为

```sql
表达式1 <=> 表达式2
```

| 左值 | 右值 | `=` 的结果 | `<=>` 的结果 |
| --- | --- | --- | --- |
| `1` | `1` | `1`（TRUE） | `1`（TRUE） |
| `1` | `2` | `0`（FALSE） | `0`（FALSE） |
| `1` | `NULL` | `NULL`（UNKNOWN） | **`0`（FALSE）** |
| `NULL` | `1` | `NULL`（UNKNOWN） | **`0`（FALSE）** |
| `NULL` | `NULL` | `NULL`（UNKNOWN） | **`1`（TRUE）** |

```sql
SELECT NULL <=> NULL,   -- 1
       NULL <=> 1,      -- 0
       1    <=> 1,      -- 1
       1    <=> 2;      -- 0
```

```
+---------------+------------+-----------+-----------+
| NULL <=> NULL | NULL <=> 1 | 1 <=> 1   | 1 <=> 2   |
+---------------+------------+-----------+-----------+
|             1 |          0 |         1 |         0 |
+---------------+------------+-----------+-----------+
```

> [!important] 一句话记住
> **`<=>` 的结果只有 TRUE / FALSE，没有 UNKNOWN。**
> 它把"两边都是 NULL"视为"相等"，把"一边 NULL 一边非 NULL"视为"不相等"。

---

## 二、和 `=` 的本质区别

| 维度 | `=` | `<=>` |
| --- | --- | --- |
| NULL 参与比较 | 返回 UNKNOWN | 返回 TRUE / FALSE |
| `NULL = NULL` | `NULL` | `1` |
| `NULL = 1` | `NULL` | `0` |
| 用在 `WHERE` | UNKNOWN 行被丢弃 | 不会有行因 UNKNOWN 被丢弃 |
| 标准 SQL | ✅ | ❌ MySQL 方言 |
| 可读性 | 高 | 较低，需知道语义 |

```sql
-- 这两条在"找 remark 为 NULL 的行"上等价
SELECT * FROM `order` WHERE remark IS NULL;
SELECT * FROM `order` WHERE remark <=> NULL;
```

> [!warning] `<=>` 不是"更安全的 `=`"，别到处替换
> 对非 NULL 值，`<=>` 与 `=` 结果相同；但对 NULL，语义完全不同。
> 如果你本意是"普通相等，NULL 行不要"，用 `=` 才对。
> `<=>` 只在**你明确希望 NULL 也参与相等判断**时使用。

## 三、典型场景 1：比较两个可空列

这是 `<=>` 最有价值的场景。

```sql
-- 表：两份配置快照，value 都允许 NULL
-- 找出"两份快照中该配置完全相同"的行（包括都为 NULL）
SELECT a.config_key
FROM snapshot_a a
JOIN snapshot_b b ON a.config_key = b.config_key
WHERE a.config_value <=> b.config_value;
```

如果写成 `a.config_value = b.config_value`：

- 两边都是 NULL → UNKNOWN → 行被丢弃；
- 一边 NULL 一边非 NULL → UNKNOWN → 行被丢弃。

结果就是"**都为 NULL 的配置永远对不上**"，而这恰恰是配置对比里最常见的"相同"。

> [!tip] 标准 SQL 的等价写法
> SQL 标准用 `IS NOT DISTINCT FROM` 表达"NULL 安全相等"：
> ```sql
> WHERE a.config_value IS NOT DISTINCT FROM b.config_value
> ```
> MySQL 不支持这个语法（见 [[其他谓词]]），所以用 `<=>` 代替。
> 反过来，"NULL 安全不等"写作 `NOT (a <=> b)`，对应标准的 `IS DISTINCT FROM`。

---

## 四、典型场景 2：可空外键的连接

```sql
-- emp.dept_id 允许 NULL；dept.dept_id 是主键（非 NULL）
-- 想连出"员工及其部门"，包括没有部门的员工
SELECT e.emp_name, d.dept_name
FROM emp e
LEFT JOIN dept d ON e.dept_id <=> d.dept_id;
```

这里用 `=` 和 `<=>` 结果其实一样，因为 `dept.dept_id` 不会为 NULL，`e.dept_id = NULL` 只会让该行不匹配，而 `LEFT JOIN` 本来就会保留左表行。

> [!note] 什么时候连接必须用 `<=>`
> 当**连接两边的列都可空**，且你希望"两边都为 NULL"也算匹配时。
> 例如两张表都存"可选上级 ID"，`NULL` 表示"没有上级"——用 `=` 会让两个"没有上级"的记录连不上。

## 五、典型场景 3：替代 `IS NULL` 的简写

```sql
-- 以下三组等价
WHERE remark IS NULL
WHERE remark <=> NULL

WHERE remark IS NOT NULL
WHERE NOT (remark <=> NULL)

-- 与字面量比较（非 NULL）
WHERE status <=> 1
WHERE status = 1          -- 仅当 status 非 NULL 时等价
```

> [!tip] 可读性优先
> 判空场景**优先写 `IS NULL`**，意图最清楚。
> `<=>` 留给"两个列/两个表达式都可能为 NULL，且要比较是否相同"的场景。

## 六、索引表现

- 对**非 NULL 值**，`col <=> 常量` 的查找语义与 `col = 常量` 相同，通常可以走索引。
- 对 `col <=> NULL`，语义接近 `col IS NULL`，通常也可以走索引。
- 但 `<=>` 的**选择性**和优化器估算可能不如 `=` 直观，别把它当成"性能优化手段"。

```sql
EXPLAIN SELECT * FROM `order` WHERE remark <=> NULL;
-- 观察 key 列是否用上了 remark 上的索引
```

> [!warning] 不要为了"少写 IS NULL"而用 `<=>`
> `<=>` 在团队协作里可读性差，很多开发者第一眼会把它误读成"小于等于某个东西"。
> 除非确实需要 NULL 安全相等，否则用 `=` / `IS NULL`。

---

## 七、常见错误

> [!failure] 把 `<=>` 当成"小于等于"
> `<=>` 不是 `<=`。`a <=> b` 是"NULL 安全相等"，不是"a 小于等于 b"。
> 小于等于是 `<=`，两者只差一个字符，代码 review 时要特别留意。

> [!failure] 用 `<=>` 替代所有 `=`
> 对非 NULL 值结果一样，但语义变了：NULL 行会从"被丢弃"变成"参与比较"。
> 如果业务要求"NULL 不参与"，用 `=`。

> [!failure] 以为 `<=>` 是标准 SQL
> 它是 MySQL 方言。跨库迁移时，标准写法是 `IS NOT DISTINCT FROM`（PostgreSQL 支持），Oracle 等则需用 `DECODE` / `NVL` 改写。

> [!failure] `NOT a <=> b` 的优先级
> `NOT` 的优先级低于比较运算符，`NOT a <=> b` 会被解析为 `NOT (a <=> b)`，通常符合预期。
> 但为了可读性，建议显式写括号：`NOT (a <=> b)`。

## 八、速查表

| 需求 | 写法 |
| --- | --- |
| 判断是否为 NULL | `col IS NULL` |
| NULL 安全相等 | `a <=> b` |
| NULL 安全不等 | `NOT (a <=> b)` |
| 两个可空列是否相同 | `a <=> b` |
| 两个可空列是否不同 | `NOT (a <=> b)` |
| 标准 SQL 等价（相等） | `a IS NOT DISTINCT FROM b`（MySQL 不支持） |
| 标准 SQL 等价（不等） | `a IS DISTINCT FROM b`（MySQL 不支持） |
