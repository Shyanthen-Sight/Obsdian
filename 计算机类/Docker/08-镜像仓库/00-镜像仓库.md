# 镜像仓库

镜像构建出来只是本地的一个文件，要给 CI、给同事、给生产机器用，就得有个地方存。仓库（registry）就是这个中间站。`docker pull nginx` 看着只是一条命令，背后是先在默认 registry 里找 `library/nginx` 这个仓库，再按 `latest` 找到对应的 manifest。

这一阶段解决四件事：镜像存哪、怎么认证、标签怎么打、拉不下来怎么查。顺序上建议先跑通 Docker Hub 的登录和推送，再换到公司实际在用的 GHCR、ECR、ACR 或 Harbor，等流程顺了再回头整理标签规范。仓库切换本身不难，难的是把命名和权限约定下来，否则半年后没人说得清线上跑的到底是哪一版。

几个概念先分清：

| 概念 | 例子 | 是否可变 |
| --- | --- | --- |
| registry | `ghcr.io` | - |
| repository | `ghcr.io/acme/api` | - |
| tag | `1.4.2`、`latest` | 可变 |
| digest | `sha256:9f2c...` | 不可变 |

一个 registry 下有多个 repository，一个 repository 下有多个 tag，每个 tag 最终指向一个 digest。部署时钉 digest 最稳，可读性差；日常用语义化版本，发布记录里附上 digest，两头都照顾到。

登录、打标签、推送是同一套动作：

```bash
docker login ghcr.io -u "$USER"
docker tag my-app:1.4.2 ghcr.io/acme/my-app:1.4.2
docker push ghcr.io/acme/my-app:1.4.2
docker pull ghcr.io/acme/my-app@sha256:9f2c...
```

登录凭据默认写在 `~/.docker/config.json`，CI 里用 `--password-stdin` 从 secret 读，别把密码写进命令历史。推送前确认仓库路径、命名空间和 token 权限，`denied` 多半不是网络问题。

学完这一阶段，应该能独立完成：登录私有仓库、给镜像打一套合理的标签、推送并在另一台机器拉取、遇到 `toomanyrequests` 或 `unauthorized` 时知道从哪儿查起。
