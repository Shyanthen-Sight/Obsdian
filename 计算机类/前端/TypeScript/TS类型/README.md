# TS 类型笔记

> [!abstract] 一句话
> 把 TypeScript 的类型按 ==能否装下任何值== 与 ==是否占据一个真实的值== 这两把尺子，分成 **顶层 / 原始 / 对象 / 底层** 四层——这是一张从"最宽"到"最窄、最空"的类型地图。

---

## 一、三层（+底层）分类的逻辑

TypeScript 的类型世界有两个"端点"：

- **宽的一端**：能容纳**任意值**——`unknown` / `any`，叫**顶层类型**。
- **窄的一端**：**一个值都不含**——`never`，叫**底层类型**。

夹在中间的，才是我们平时真正在用的**取值世界**：不可再分的单值（**原始类型**）与由成员拼起来的结构（**对象类型**）。

| 层级 | 成员 | 一句话特征 |
| --- | --- | --- |
| 🔝 **顶层类型** | `any`、`unknown` | 任何值都能赋给它（全集端点） |
| 🔹 **原始类型** | `boolean`、`number`、`string`、`void`、`undefined`、`null` | 不可再分的单个值 |
| 🧱 **对象类型** | `Interface`、`Class`、`Enum`、`Array`、`Tuple`、`Object` | 由多个成员组合成的结构 |
| 🔻 **底层类型** | `never` | 不含任何值（空集端点） |

> [!info] 为什么 `any` / `unknown` 单列一层
> 它们描述的不是"某一种值长什么样"，而是"**这里接受任何值**"。其它类型是形状，它们是**容量**。

## 二、类型层级关系图

```text
                    【宽】任何值都能落进来
        ┌───────────────────────────────────────────┐
        │              顶层类型 Top Types             │
        │     unknown                 any            │
        │  （安全的全集）        （关掉检查的全集）      │
        └─────────────────────┬─────────────────────┘
                              │
        ┌─────────────────────┴─────────────────────┐
        │            中间：真实的取值世界              │
        │                                           │
        │   原始类型 Primitive      对象类型 Object   │
        │   ────────────────       ───────────────  │
        │   boolean                Interface        │
        │   number                 Class            │
        │   string                 Enum             │
        │   void                   Array            │
        │   undefined              Tuple            │
        │   null                   Object           │
        └─────────────────────┬─────────────────────┘
                              │
        ┌─────────────────────┴─────────────────────┐
        │            底层类型 Bottom Types           │
        │                  never                     │
        │            （空集：没有任何值）             │
        └───────────────────────────────────────────┘
                    【窄】一个值都不属于
```

> [!tip] 读图口诀
> **值只能由窄流向宽**：具体类型 → 原始/对象 → `unknown`。反过来（宽→窄）必须先**收窄**（类型守卫）或**断言**。
> `never` 在最窄端，==可以流向任何类型，却没有任何值能流进它==。

## 四、一张速查表：谁能赋给谁

| 从 ↓ 赋给 → | any | unknown | 原始 | 对象 | never |
| --- | --- | --- | --- | --- | --- |
| `any` | ✅ | ✅ | ✅ | ✅ | ✅ |
| `unknown` | ✅ | ✅ | ❌ | ❌ | ❌ |
| 原始 / 对象 | ✅ | ✅ | 视具体类型 | 视具体类型 | ❌ |
| `never` | ✅ | ✅ | ✅ | ✅ | ✅ |

> [!warning] 三条最常踩的规律
> - **`unknown` 只能赋给 `any` / `unknown`**，赋给别的必须先收窄。
> - **`never` 可赋给一切**（因为它不含值，故不违反任何约束）。
> - **除 `never` 外，没有类型能赋给 `never`**。
> 各类型的精确赋值关系，见每篇"与其他类型的关系"一节。
