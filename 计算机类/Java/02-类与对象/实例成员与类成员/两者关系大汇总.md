# 实例成员与类成员（两者关系大汇总）

> 关联笔记：[[成员变量]]、[[方法]]、[[类的声明]]、[[对象的引用和实体]]、[[构造方法]]

## 一句话解释

==**同一个类体里的成员，按"有没有 `static`"分成两拨：没 `static` 的属于对象（实例成员），有 `static` 的属于类（类成员）。**==

- **实例成员** = 实例变量 + 实例方法 —— ==必须依附于对象==才有意义。
- **类成员（静态成员）** = 静态变量 + 静态方法 —— ==依附于类本身==，不需要对象。

一句话抓住分水岭：**`static` 一变，归属就从"对象"挪到了"类"。**

# 板块一 · 变量

## 方向 1：变量怎么声明

### 1.1 实例变量的声明

声明在**类体中、方法之外**，==不加 `static`==：

```java
class Dog {
    String name;     // 实例变量
    int age;         // 实例变量
}
```

每 `new` 一个 `Dog`，`name` 和 `age` 就各有一份，互不干扰：

```java
Dog a = new Dog();
Dog b = new Dog();
a.name = "旺财";       // 只改 a 这一份
System.out.println(b.name);   // null —— b 的那份没被动过
```

### 1.2 静态变量的声明

同样在类体中，==前面加上 `static`==：

```java
class Dog {
    static int count;    // 静态变量（类变量）
}
```

`count` 全类**只有一份**，所有 `Dog` 对象共享它：

```java
Dog a = new Dog();
Dog b = new Dog();
Dog.count = 5;
System.out.println(a.count);   // 5 —— a、b 看到的是同一份
```

### 1.3 声明格式对照

|      | 声明格式                               |
| ---- | ---------------------------------- |
| 实例变量 | `[访问权限] 类型 变量名 [= 初值];`            |
| 静态变量 | `[访问权限] static 类型 变量名 [= 初值];`     |
| 静态常量 | `public static final 类型 变量名 = 初值;` |

> [!tip] 修饰符顺序习惯
> 通常按「访问权限 → `static` → `final` → 类型 → 变量名」写，例如 `public static final int MAX_SIZE = 100;`。常量名一律**全大写加下划线**。

---

## 方向 2：两者的区别

| 维度 | ==实例变量== | ==静态变量（类变量）== |
| --- | --- | --- |
| 修饰符 | 无 `static` | 有 `static` |
| 归属 | **对象** | **类** |
| 份数 | 每个对象**各一份** | 全类**只有一份**，共享 |
| 存储位置 | 堆（对象体内） | 方法区（静态区） |
| 创建 / 销毁 | 随对象创建，随对象被回收 | 随类加载创建，程序结束才释放 |
| 初值时机 | 构造对象时 | **类加载时**（早于任何对象） |
| 访问方式 | `对象名.变量` / `this.变量` | `类名.变量`（推荐）/ `对象名.变量` |
| 默认值 | 有（0 / 0.0 / false / null） | 有（同上） |
| 与继承 | 子类可继承非 `private` 的 | 子类可继承，但**仍只有一份** |

**关键理解：**

1. **份数不一样**——这是唯一的分水岭。实例变量是"每个对象私有一份"，静态变量是"全班共用一个黑板"。
2. **时机不一样**——静态变量在**类加载**时就初始化了，那时候可能一个对象都还没造出来。
3. **访问习惯不一样**——静态变量虽可用 `对象名.变量` 访问，但==强烈推荐用 `类名.变量`==，否则会让人误以为它是实例变量（见 [[成员变量]] 里"变量隐藏"一节）。

```java
class Employee {
    private static int count = 0;   // 静态变量：所有员工共享
    private String name;            // 实例变量：每个员工独立

    public Employee(String name) {
        this.name = name;
        count++;                    // 每造一个对象，总人数 +1
    }
}
```

# 板块二 · 方法

## 方向 3：方法怎么声明

### 3.1 实例方法的声明

==不加 `static`==，最普通的方法就是实例方法：

```java
class Dog {
    String name;

    void bark() {                  // 实例方法
        System.out.println(name + " 在叫");
    }
}
```

调用时必须**先有对象**：

```java
Dog d = new Dog();
d.bark();          // 对象名.方法()
```

### 3.2 静态方法的声明

==前面加 `static`==，属于类：

```java
class Dog {
    static void info() {           // 静态方法
        System.out.println("这是一种动物");
    }
}
```

调用时**不需要对象**，直接用类名：

```java
Dog.info();        // 类名.方法()  —— 推荐
```

### 3.3 声明格式对照

| | 声明格式 |
| --- | --- |
| 实例方法 | `[访问权限] 返回类型 方法名(参数) { ... }` |
| 静态方法 | `[访问权限] **static** 返回类型 方法名(参数) { ... }` |

> [!note] 两个都是方法
> 重载（[[重载]]）对实例方法和静态方法**都适用**，区分点只在"有没有 `static`"，跟参数列表无关。

---

## 方向 4：两者的区别

| 维度 | ==实例方法== | ==静态方法== |
| --- | --- | --- |
| 修饰符 | 无 `static` | 有 `static` |
| 归属 | 对象 | 类 |
| 调用方式 | `对象名.方法()`（**必须先 new**） | `类名.方法()`（**可直接调用**） |
| 有无 `this` / `super` | 有 `this`（指向当前对象），可用 `super` | ==**没有 `this`，也没有 `super`**== |
| 能否访问实例成员 | ✅ 能 | ==❌ **不能**== |
| 能否访问静态成员 | ✅ 能 | ✅ 能 |
| 能否被重写 | ✅ 能被**重写**（运行期动态绑定，有多态） | ❌ 只能被**隐藏**（编译期静态绑定，无多态） |
| 能否是 `abstract` | ✅ 可以 | ❌ 不可以（`abstract` 与 `static` 互斥） |
| 典型例子 | 普通业务方法 | `main`、`Math.abs()`、工具类方法 |

**核心的一条硬规则：**

> [!warning] 静态方法里不能直接使用实例成员
> 静态方法属于**类**，它可能在任何对象诞生之前就被调用——==此时根本不知道该访问"哪一个对象"的实例变量==，所以编译器直接禁止。要用实例成员，只能先 `new` 一个对象，再通过对象访问。

```java
class Counter {
    int count = 0;              // 实例变量
    static int total = 0;       // 静态变量

    void inc() {                // 实例方法
        count++;                // ✅ 能访问实例变量（有 this）
        total++;                // ✅ 也能访问静态变量
        Counter.total++;        // ✅ 推荐写法：类名.静态变量
    }

    static void show() {        // 静态方法
        // count++;             // ❌ 编译错误：没有 this，不知道访问哪个对象的 count
        total++;                // ✅ 静态变量属于类，谁都能访问
    }
}
```

```java
Counter c = new Counter();
c.inc();              // 实例方法：必须先有对象
Counter.show();       // 静态方法：直接用类名
```

**为什么 `main` 里不能直接调用实例方法？**

因为 `main` 本身就是 `static` 的，它站在"类"这一侧，==没有对象就没有 `this`==，所以必须先 `new` 出对象再调用：

```java
public class Demo {
    void sayHi() { }              // 实例方法

    public static void main(String[] args) {
        // sayHi();               // ❌ 编译错误
        new Demo().sayHi();       // ✅ 先造对象，再调用
    }
}
```

# 汇总对照

| | 变量 | 方法 |
| --- | --- | --- |
| `static` 决定什么 | **存几份**：每个对象一份 / 全类一份 | **要不要对象**：要对象 / 不要对象 |
| 实例成员 | 每个对象各自一份 | 必须通过对象调用，有 `this` |
| 类成员 | 全类共享一份 | 类名直接调用，无 `this` |

> ==**变量看"份数"，方法看"归属"：`static` 一加上，变量从"人手一份"变成"全班共用"，方法从"得先有对象"变成"类名直接喊"。**==

---

# 常见陷阱

1. **在静态方法里写 `this`** → 编译错误，静态方法没有 `this`。
2. **在 `main` 里直接调用非静态方法** → 编译错误，必须先 `new` 对象。
3. **用 `对象名.静态方法()` 调用** → 能编过，但会制造"这是实例方法"的错觉，应改用 `类名.静态方法()`。
4. **以为静态能被"重写"** → 静态方法只能被**隐藏**（编译期按引用类型绑定），不具备多态，参见 [[成员变量]] 里"变量隐藏 vs 方法重写"的对比。
5. **把常量忘了加 `static final`** → 常量应当是 `public static final`，全大写命名。
