# Java 对象的引用和实体

> 关联笔记：[[创建对象]]、[[使用对象]]、[[成员变量]]、[[方法]]

## 一句话解释

==**`new` 出来的对象本体叫「实体」，存放在堆内存里；操作它的那个变量叫「引用」，存放在栈里，保存的是实体的地址。**==

引用和实体是两回事：==一个实体可以被多个引用同时指向，一个引用也可以随时改指向别的实体==。把这条想明白，`==` 和 `equals`、参数传递、NPE 这一堆问题就都能理顺。

---

## 一、内存里的两张地图：栈与堆

```java
Dog a = new Dog("旺财");
```

这一行在内存里分成两处：

| 位置           | 存放的东西    | 内容                  |
| ------------ | -------- | ------------------- |
| **栈（Stack）** | 引用变量 `a` | 一个地址，指向堆里的实体        |
| **堆（Heap）**  | 对象实体     | `name = "旺财"` 等实例变量 |

```
栈                          堆
┌──────────┐           ┌─────────────────┐
│  a  ●────┼──────────▶│ Dog 实体        │
└──────────┘           │  name = "旺财"  │
                       └─────────────────┘
```

- **引用**：本质是一个存了地址的变量，个头很小（通常 4 或 8 字节）。
- **实体**：真正占内存的对象，多个引用可以指它。

> [!note] 一个比喻
> 引用像「房间号」，实体像「房间」。你可以把同一个房间号抄给好几个人（多个引用），也可以把手里这张纸条上的号码擦掉改写成别的（改变指向）。房间号本身不是房间。

## 二、多个引用指向同一个实体

```java
Dog a = new Dog("旺财");
Dog b = a;              // 只是把地址抄了一份，没有创建新对象
b.setName("大黄");       // 改的是同一个实体

System.out.println(a.getName());   // 大黄！
```

`Dog b = a;` 这一句==不复制对象，只复制地址==，这就是**引用赋值**。执行后：

```
栈                          堆
┌──────────┐
│  a  ●────┼───┐
├──────────┤   ├────────▶┌─────────────────┐
│  b  ●────┼───┘         │ Dog 实体        │
└──────────┘             └─────────────────┘
```

所以通过 `b` 改字段，`a` 看到的也变了——它们本来就是同一个实体。

> [!warning] 「复制对象」要另外写
> `Dog b = a;` 得到的是「同一个对象」，不是「两个一样的对象」。若真要两个独立的实体，必须 `Dog b = new Dog(...);` 再逐个字段复制（或实现 `clone`）。

---

## 三、改变引用的指向

```java
Dog a = new Dog("旺财");
Dog b = new Dog("大黄");
a = b;                  // a 改指 b 的实体
```

执行 `a = b;` 后：

- `a` 和 `b` 现在都指向「大黄」那个实体；
- 原来「旺财」那个实体**再没有任何引用指向它**，成为垃圾，等着被 GC 回收。

这正是**垃圾回收**能自动工作的根据：==判断一个实体是不是垃圾，看有没有引用指向它。==

```java
Dog a = new Dog();
Dog b = new Dog();
a = null;               // 主动断掉引用 → a 原来指向的实体变成垃圾
```

## 四、空引用：`null`

```java
Dog a = null;           // a 这个引用不指向任何实体
System.out.println(a);  // 输出 null（打印引用本身是允许的）
a.bark();               // 运行时 NullPointerException
```

`null` 表示「这个引用手里没有地址」。对 `null` 引用做任何**成员访问**（读字段、调方法）都会抛 `NullPointerException`。

排查思路：NPE 出现时，问自己「这个引用是在哪一步被赋值成 `null` 的」——常见来源有三种：

1. 声明后忘了 `new`；
2. 显式写了 `= null`；
3. 数组元素、集合元素还没被赋过对象（默认就是 `null`）。

```java
Dog[] ds = new Dog[3];
ds[0].bark();          // NPE：ds[0] 还是 null
```

## 五、对象作为参数：传的还是「引用的值」

Java **只有值传递**。传对象时，传的是==引用的拷贝==（地址的拷贝），所以：

```java
void change(Dog d) {          // 形参 d 拿到的是实参地址的副本
    d.setName("改名");         // ① 两个引用指同一实体 → 影响外部
    d = new Dog("新狗");       // ② 只改了形参 d 自己 → 外部不受影响
}

Dog dog = new Dog("旺财");
change(dog);
System.out.println(dog.getName());   // 输出「改名」，不是"新狗"
```

逐条解释：

| 操作 | 是否影响外部 | 原因 |
| --- | --- | --- |
| `d.setName("改名")` | ✅ 影响 | 形参和实参指向同一个实体，改的是实体内部 |
| `d = new Dog("新狗")` | ❌ 不影响 | 只是让形参 `d` 改指向新实体，实参 `dog` 没变 |

> [!tip] 一句话记住
> ==传对象时「改实体的内容会影响外部，改引用的指向不会」。== 这和第一节的「引用 ≠ 实体」是同一件事的两种表现。

## 六、`==` 与 `equals`

| 比较方式 | 比的是什么 | 结果判断依据 |
| --- | --- | --- |
| `==` | ==引用（地址）== | 是不是**同一个实体** |
| `equals` | 默认也是地址，除非被重写 | 重写后可以比**内容** |

```java
Dog a = new Dog("旺财");
Dog b = new Dog("旺财");

System.out.println(a == b);          // false，两个不同实体
System.out.println(a.equals(b));     // false，Object 默认按地址比

Dog c = a;
System.out.println(a == c);          // true，同一个实体
```

许多类（`String`、`Integer`、`List` 等）重写了 `equals`，此时它比的是**内容**：

```java
String s1 = new String("abc");
String s2 = new String("abc");
System.out.println(s1 == s2);        // false，两个不同的 String 实体
System.out.println(s1.equals(s2));   // true，内容相同
```

> [!warning] 最经典的坑
> 判断两个对象「是不是相等」，==绝大多数场景要用 `equals`==。自定义类要让 `equals` 有意义，必须自己重写（并且通常一起重写 `hashCode`）。

## 七、垃圾回收（GC）

- 判断标准：==一个实体如果没有被任何引用指向，它就是垃圾==。
- 回收动作由 JVM 的 `System.gc()` 只是「建议」，==不保证立刻执行==。

```java
Dog a = new Dog();
a = null;               // 实体失去最后一个引用，等待 GC
```

因为引用和实体分离，所以 Java 不需要手写 `free` / `delete`——只要断开引用，剩下的交给 GC。

---

## 八、注意事项

1. **引用 ≠ 实体**。变量名操作的是引用，真正改动的是堆里的实体。
2. **`b = a` 是引用赋值**，两个引用指向同一实体，不是复制对象。
3. **一个实体可以有多个引用，一个引用只能指一个实体**。
4. **对 `null` 做成员访问必 NPE**，用前确保已 `new`。
5. **Java 是值传递**：传对象时传的是引用地址的副本，改内容影响外部、改指向不影响。
6. **`==` 比地址，`equals` 比内容**（前提是已重写），比较对象相等请优先用 `equals`。
7. **没有引用指向的实体会被 GC 回收**，`System.gc()` 只是建议而非命令。

---

## 九、一句话总结

> ==**引用在栈、实体在堆，引用手里拿的是实体的地址；`b = a` 是抄地址不是复制对象，`==` 比地址、`equals` 比内容，断开最后一个引用，实体就等着被 GC 收走。**==
