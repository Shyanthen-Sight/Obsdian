# 网络

Docker 网络命令主要干三件事：创建网络、把容器接进去、在不通的时候找出是哪一层断了。

## 创建和查看

```bash
docker network create app-net
docker network create --driver bridge \
  --subnet 172.28.0.0/16 --gateway 172.28.0.1 app-net
docker network ls
docker network inspect -f '{{json .IPAM.Config}}' app-net
docker network inspect -f '{{range .Containers}}{{.Name}} {{.IPv4Address}}{{"\n"}}{{end}}' app-net
```

不指定 subnet 时 Docker 从地址池自动分配。自定义 bridge 自带内嵌 DNS（`127.0.0.11`），容器名可以直接解析，这是它和默认 `bridge` 最大的区别。默认 bridge 只能靠 IP 或早已不推荐的 `--link`。

把容器接进去：

```bash
docker run -d --name db --network app-net postgres:16
docker run -d --name web --network app-net -p 8080:80 nginx
docker network connect --alias api app-net web
docker network disconnect app-net web
```

`--alias` 让同一容器在网络里多一个可解析的名字，做蓝绿切换或兼容旧服务名时有用。一个容器可以同时接多个网络，跨网络通信必须显式连接。

## 端口和方向

`-p 8080:80` 是宿主 8080 到容器 80，同一网络里的其他容器访问 `web:80`，不走宿主端口。只给本机访问就绑回环：

```bash
docker run -d -p 127.0.0.1:8080:80 nginx
docker port web
```

不写宿主 IP 等于监听 `0.0.0.0`，云主机上很容易把本不该公开的服务暴露出去。`-P` 随机映射所有 `EXPOSE` 端口，只适合临时调试。

## 排查顺序

容器互相访问不到，按这个顺序查：

```bash
docker network inspect app-net          # 两个容器在不在同一网络
docker exec web getent hosts db         # DNS 能不能解析
docker exec web nc -zv db 5432          # 端口通不通
docker exec db ss -lntp                 # 服务有没有在监听
docker logs db                          # 服务是不是根本没起来
```

先确认网络成员，再确认解析，最后确认端口和监听地址。很多“网络问题”其实是服务只监听了 `127.0.0.1`，容器外自然连不上。`ping` 不一定可用，镜像里可能没装，用 `nc` 或 `curl` 更实际。

宿主机侧看端口和事件：

```bash
ss -lntp | grep 8080
docker events --filter type=network
```

> [!warning] Docker 发布的端口会绕过 ufw
> Docker 直接写 iptables NAT 规则，`ufw deny 8080` 不一定挡得住 `-p 8080:80`。要限制来源，绑定 `127.0.0.1`，或在 `DOCKER-USER` 链里加规则。

网络不用了就删，但先断开容器：

```bash
docker network prune
docker network rm app-net
```

`prune` 只删没有被容器使用的网络，默认的 `bridge`、`host`、`none` 不会被删。
