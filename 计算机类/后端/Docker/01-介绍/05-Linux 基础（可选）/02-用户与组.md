# 用户与组

容器默认以 root 运行，这是很多安全问题的起点。镜像里用 `USER` 指定非 root 用户，运行时用 `--user` 覆盖：

```dockerfile
FROM alpine:3.20
RUN addgroup -S app && adduser -S -G app app
WORKDIR /app
COPY --chown=app:app . .
USER app
CMD ["./server"]
```

`addgroup -S` / `adduser -S` 创建系统用户，`-G` 指定主组；`COPY --chown` 让文件属主一次到位，省掉一层 `chown`。Debian 系则是 `groupadd --system app && useradd --system --gid app app`。

## UID 才是硬通货

宿主机和容器共享内核的 UID/GID 空间（没开 userns-remap 时）。绑定挂载能不能写，看的是数字 UID 是否匹配，用户名根本不参与：

```bash
$ id
uid=1000(shyanthen) gid=1000(shyanthen)
$ docker run --rm -v "$PWD":/work alpine touch /work/a.txt
$ ls -l a.txt
-rw-r--r-- 1 root root 0 ... a.txt
```

容器里 root 是 UID 0，写出来的文件在宿主上也归 root。反过来，镜像里 `USER app` 的 UID 如果是 100，宿主目录属于 1000，就会 `Permission denied`。排查时两边都跑 `id`，别只看用户名。

运行时覆盖：

```bash
docker run --rm --user 1000:1000 -v "$PWD":/work alpine id
```

## 几个边界

- 非 root 进程默认不能绑定 1024 以下端口，要么改端口，要么加 `CAP_NET_BIND_SERVICE`
- 镜像里 `USER` 之后再 `RUN apt-get install` 会失败，装包要放在切换用户之前
- OpenShift 会随机分配 UID，镜像要保证组 0 对配置目录有写权限
- userns-remap 能把容器 root 映射成宿主普通用户，但卷和权限会变复杂

> [!tip] 数据库镜像别乱改 USER
> 官方 PostgreSQL、MySQL 镜像的 entrypoint 会用 root 做数据目录 chown，再降权启动。自己覆盖 `USER` 或 `--user` 之前先读镜像文档，否则初始化直接失败。
