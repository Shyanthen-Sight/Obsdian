# 持续集成

CI 里的 Docker 不是“跑一条 docker build”。目标是把验证过的东西变成可部署镜像：构建、测试、扫描各一次，推送后用 digest 部署。任何一步重建，都可能产出不同的镜像。

## 一条 GitHub Actions 流水线

```yaml
on:
  push:
    branches: [main]
  pull_request:

permissions:
  contents: read
  packages: write

jobs:
  image:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: docker/setup-buildx-action@v3

      - uses: docker/login-action@v3
        if: github.event_name != 'pull_request'
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - uses: docker/build-push-action@v6
        id: build
        with:
          context: .
          push: ${{ github.event_name != 'pull_request' }}
          tags: ghcr.io/org/app:sha-${{ github.sha }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
          provenance: true
          sbom: true

      - if: github.event_name != 'pull_request'
        uses: aquasecurity/trivy-action@0.28.0
        with:
          image-ref: ghcr.io/org/app@${{ steps.build.outputs.digest }}
          severity: CRITICAL,HIGH
          exit-code: "1"
```

几个点：

- `permissions` 只给 `packages: write`，fork 来的 PR 没有推送凭据，登录直接跳过。
- PR 只构建不推送，仍能用缓存验证 Dockerfile；合并后再推送扫描。
- `provenance` 和 `sbom` 记录来源和依赖清单。
- 扫描用 digest 引用镜像，避免扫到同名不同内容。

## BuildKit 缓存

CI runner 每次都是干净机器，本地层缓存不存在。`type=gha` 把缓存存到 Actions 缓存服务，`mode=max` 连中间阶段一起缓存，多阶段构建的编译层也能复用。仓库大、构建频繁时可以换成 `type=registry`，代价是多一次拉取和推送，缓存和镜像挤在同一仓库。

分支共享要小心：PR 写出的 GHA 缓存只对该 PR 可见，默认分支的缓存才能被后续构建读到；用 registry cache 时别给不可信 PR 推送凭据，否则可能污染后续构建。

缓存不是越多越好。依赖清单频繁变化时，`mode=max` 会推大量失效层，时间反而花在传缓存上。

## digest 部署

标签会漂移，digest 不会。`steps.build.outputs.digest` 就是 `sha256:...`，部署时直接引用：

```bash
docker pull ghcr.io/org/app@sha256:3f2a...
kubectl set image deployment/api \
  api=ghcr.io/org/app@sha256:3f2a...
```

回滚就是把 digest 换成上一个，不用猜“上周的 v1.2 是哪个提交”。CI 可以把 digest 写进部署仓库的 values 文件交给 GitOps，或输出到 job summary。

> [!tip] 构建和部署分开
> CI 产出镜像、digest、SBOM 和扫描结果；CD 只认 digest。部署阶段不需要 Dockerfile，也不会出现“同一标签重建后内容变了”的事故。
