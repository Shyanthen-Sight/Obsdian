# Java 向上转型与向下转型

> 多态的三要素：==继承（或实现）==、==方法重写==、==父类引用指向子类对象==。
> 转型讨论的正是第三点：一个父类类型的引用，怎样指向子类对象，又怎样转回子类类型。

## 1. 先分清两个"类型"

Java 里的引用变量同时带着两个类型：

| 概念              | 含义               | 由谁决定              |
| --------------- | ---------------- | ----------------- |
| ==编译时类型==（静态类型） | 变量声明时写的类型，编译器只认它 | 变量声明 `Employee e` |
| ==运行时类型==（实际类型） | 引用实际指向的对象的类型     | `new` 出来的对象       |

```java
Employee e = new Manager("张三", 2000);
```

* `e` 的编译时类型是 `Employee`；
* `e` 的运行时类型是 `Manager`；
* ==对象本身从创建到销毁一直是 `Manager`==，转型改变的只是"用哪种类型的引用去看它"。

理解这一点，后面所有规则都能推出来：

> **能调用哪些成员，看编译时类型；方法最终执行哪一个版本，看运行时类型。**

## 2. 向上转型（Upcasting）

### 2.1 定义与语法

把==子类对象赋给父类引用==，称为向上转型。它是==自动完成==的，不需要强制类型转换符：

```java
Manager manager = new Manager("张三", 2000);
Employee e = manager;              // 隐式向上转型
```

也可以直接写在一起：

```java
Employee e = new Manager("张三", 2000);
```

接口同理，实现类对象可以自动赋给接口引用：

```java
Workable w = new Manager("张三", 2000);   // Manager implements Workable
```

> [!tip] 为什么叫"向上"
> 继承关系通常画成父类在上、子类在下；从子类转到父类，方向是==向上==，类型范围==变宽==。

### 2.2 为什么向上转型是安全的

因为子类对象==一定是一个父类对象==（is-a 关系）。父类声明的每一个可访问成员，子类对象都有：

* 父类的字段，子类对象里都存在；
* 父类的方法，子类对象都能响应（要么继承，要么重写）。

所以编译器允许自动完成，==永远不会在运行时失败==。

反过来不行：父类对象不一定是子类对象（员工不一定是经理），所以向下转型必须显式强转并由运行期检查。

### 2.3 向上转型后能访问什么

这是最容易出错的地方。先看一个贯穿全文的案例：

```java
class Employee {
    protected String name;

    public Employee(String name) {
        this.name = name;
    }

    public void work() {
        System.out.println(name + " 在完成员工的工作");
    }

    public double calculateSalary() {
        return 5000;
    }
}

class Manager extends Employee {
    private double bonus;

    public Manager(String name, double bonus) {
        super(name);
        this.bonus = bonus;
    }

    @Override
    public void work() {
        System.out.println(name + " 在开会");
    }

    @Override
    public double calculateSalary() {
        return 5000 + bonus;
    }

    // 子类特有方法
    public void approve() {
        System.out.println(name + " 审批报销单");
    }

    public double getBonus() {
        return bonus;
    }
}
```

```java
Employee e = new Manager("张三", 2000);   // 向上转型

e.work();                                  // 张三 在开会（运行期看 Manager）
System.out.println(e.calculateSalary());   // 7000.0（运行期看 Manager）
// e.approve();                            // 编译错误：Employee 类型上没有 approve
System.out.println(e.getClass().getSimpleName()); // Manager（对象本身没变）
```

规则汇总：

| 成员 | 编译期依据 | 运行期结果 |
| --- | --- | --- |
| 实例方法（被重写） | 父类是否有该方法 | ==子类重写版本==（动态绑定） |
| 实例方法（未重写） | 父类是否有该方法 | 父类版本 |
| 子类特有方法 | 父类没有 → ==编译错误== | — |
| 字段 | ==引用类型==的字段 | ==引用类型==的字段（字段不参与多态） |
| `static` 方法 | ==引用类型==的类 | ==引用类型==的类（静态方法被隐藏，不是重写） |
| `private` / `final` 方法 | 父类是否可访问 | 父类版本（不能重写） |

#### 字段不参与多态

```java
class A {
    String tag = "A";
    void hello() { System.out.println("A.hello"); }
}

class B extends A {
    String tag = "B";
    @Override
    void hello() { System.out.println("B.hello"); }
}

public class Demo {
    public static void main(String[] args) {
        A a = new B();                 // 向上转型
        System.out.println(a.tag);     // A
        a.hello();                     // B.hello
        System.out.println(((B) a).tag); // B
    }
}
```

输出：

```
A
B.hello
B
```

`B` 里的 `tag` 并没有"覆盖"`A` 的 `tag`，而是把父类字段==隐藏==了；通过 `A` 类型的引用访问，拿到的永远是 `A` 那份字段。

#### static 方法按引用类型选择

```java
class A {
    static void s() { System.out.println("A.s"); }
}
class B extends A {
    static void s() { System.out.println("B.s"); }   // 隐藏，不是重写
}

A a = new B();
a.s();   // A.s
```

`static` 方法属于类而不属于对象，JVM 直接用引用变量的编译时类型来选，谈不上多态。

### 2.4 向上转型的典型用途

#### （1）统一方法参数

```java
public static void printSalary(Employee e) {
    System.out.println(e.name + " 的薪资: " + e.calculateSalary());
}

printSalary(new Manager("张三", 2000));           // 7000.0
printSalary(new HourlyEmployee("李四", 20, 100)); // 2000.0（定义见第 4 节）
```

方法只需针对父类写一次，所有子类都能传进来，新增子类时这个方法==一行都不用改==。

#### （2）数组与集合

```java
Employee[] staff = {
    new Manager("张三", 2000),
    new HourlyEmployee("李四", 20, 100)
};

for (Employee e : staff) {
    System.out.println(e.name + " -> " + e.calculateSalary());
}
```

数组元素类型是 `Employee`，但每个槽位可以放任意子类对象。`List<Employee>`、`Map<String, Employee>` 同理。

#### （3）工厂方法返回父类型

```java
public static Employee create(String type) {
    if ("manager".equals(type)) {
        return new Manager("张三", 2000);
    }
    return new HourlyEmployee("李四", 20, 100);
}
```

调用方只依赖 `Employee`，不关心具体是哪个子类——这就是[[面向抽象编程]]的雏形。

#### （4）接口回调

```java
interface Workable {
    void work();
}

public static void startAll(Workable[] workers) {
    for (Workable w : workers) {
        w.work();          // 调用各实现类自己的版本
    }
}
```

把对象交给框架、线程、监听器时，本质上都是把实现类对象向上转型成接口/父类引用。

### 2.5 向上转型不会改变对象

```java
Manager m = new Manager("张三", 2000);
Employee e = m;

System.out.println(m == e);              // true，还是同一个对象
System.out.println(m.hashCode() == e.hashCode()); // true
```

向上转型只是换了一个"视野更窄的引用"，对象的状态、身份、实际类型都没有任何变化。

## 3. 向下转型（Downcasting）

### 3.1 定义与语法

把==父类引用转回子类引用==，称为向下转型。它必须显式写强制转换：

```java
Employee e = new Manager("张三", 2000);
Manager m = (Manager) e;      // 向下转型
m.approve();                  // 张三 审批报销单
```

> [!warning] 向下转型的前提
> ==引用实际指向的对象，必须是目标类型（或目标类型的子类）的实例==。
> 编译器只能检查"这两个类型有没有可能兼容"，真正的对象类型要到运行期才知道，所以向下转型==可能抛 `ClassCastException`==。

### 3.2 三种结果

| 情形 | 代码示例 | 编译 | 运行 |
| --- | --- | --- | --- |
| 合法转型 | `Employee e = new Manager(); Manager m = (Manager) e;` | 通过 | 成功 |
| 编译通过、运行失败 | `Employee e = new Employee(); Manager m = (Manager) e;` | 通过 | ==`ClassCastException`== |
| 编译期就拒绝 | `HourlyEmployee h = ...; Manager m = (Manager) h;` | ==报错== | — |

```java
Employee e = new Employee("李四");
Manager m = (Manager) e;     // 编译通过
// 运行：Exception in thread "main" java.lang.ClassCastException:
//       class Employee cannot be cast to class Manager
```

为什么第三种在编译期就报错？`HourlyEmployee` 和 `Manager` 是兄弟类，一个对象不可能同时是这两者，编译器直接判定==不可能兼容==（inconvertible types）。

但注意下面这段：

```java
Employee e = new HourlyEmployee("李四", 20, 100);   // 定义见第 4 节
Manager m = (Manager) e;     // 编译通过，运行抛 ClassCastException
```

因为引用的静态类型是 `Employee`，编译器只知道"Employee 有可能指向 Manager"，于是放行；实际对象却是 `HourlyEmployee`，运行期才会暴露问题。

### 3.3 安全的向下转型

#### 写法一：先 instanceof 再强转

```java
if (e instanceof Manager) {
    Manager m = (Manager) e;
    m.approve();
}
```

`instanceof` 在运行期检查实际类型，只有检查通过才强转，==不会抛 `ClassCastException`==。详见 [[instanceof]]。

#### 写法二：模式匹配（Java 16+）

```java
if (e instanceof Manager m) {
    m.approve();      // 变量 m 已经完成转型，可以直接用
}
```

编译器自动完成"判断 + 强转 + 声明变量"三件事，作用域被限制在"确定匹配"的分支里。推荐使用这种写法。

### 3.4 null 的特殊情况

```java
Employee e = null;
Manager m = (Manager) e;    // 合法，结果是 null，不会抛 ClassCastException
m.approve();                // NullPointerException
```

==`null` 可以转成任何引用类型==，因为根本没有对象需要检查；但拿着这个 `null` 去调用方法，就会抛 `NullPointerException`。

### 3.5 转型不会创建新对象

```java
Manager m = new Manager("张三", 2000);
Employee e = m;
Manager m2 = (Manager) e;

System.out.println(m == m2);   // true
```

全程只有 `new` 出来的那一个对象，向上、向下转型都只是改变引用的类型，==不复制、不包装、不改变对象状态==。

### 3.6 数组的转型

数组也遵循同样的规则，而且数组是==协变==的：

```java
Manager[] managers = { new Manager("张三", 2000) };
Employee[] staff = managers;      // 向上转型，自动完成

Manager[] back = (Manager[]) staff;   // 向下转型，成功
```

但把"实际是 `Object[]`"的数组转成 `String[]` 会在运行期失败：

```java
Object[] arr = new Object[2];
String[] strs = (String[]) arr;       // ClassCastException

Object[] arr2 = new String[2];        // 实际类型是 String[]
String[] strs2 = (String[]) arr2;     // 成功
```

`arr2` 的运行时类型是 `String[]`，所以可以转；`arr` 的运行时类型是 `Object[]`，里面可能装任何东西，JVM 不允许。

## 4. 完整案例：员工薪资统计

```java
abstract class Employee {
    protected String name;

    public Employee(String name) {
        this.name = name;
    }

    public abstract double calculateSalary();

    public void printInfo() {
        System.out.println(name + " 的薪资: " + calculateSalary());
    }
}

class Manager extends Employee {
    private double bonus;

    public Manager(String name, double bonus) {
        super(name);
        this.bonus = bonus;
    }

    @Override
    public double calculateSalary() {
        return 5000 + bonus;
    }

    public void approve() {
        System.out.println(name + " 审批报销单");
    }

    public double getBonus() {
        return bonus;
    }
}

class HourlyEmployee extends Employee {
    private int hours;
    private double rate;

    public HourlyEmployee(String name, int hours, double rate) {
        super(name);
        this.hours = hours;
        this.rate = rate;
    }

    @Override
    public double calculateSalary() {
        return hours * rate;
    }

    public double getRate() {
        return rate;
    }
}
```

```java
public class Payroll {
    public static void main(String[] args) {
        // 向上转型：父类数组装子类对象
        Employee[] staff = {
            new Manager("张三", 2000),
            new HourlyEmployee("李四", 20, 100)
        };

        double total = 0;
        for (Employee e : staff) {
            e.printInfo();                // 动态绑定，各自执行自己的 calculateSalary
            total += e.calculateSalary();
        }
        System.out.println("总薪资: " + total);

        // 向下转型：只有确实需要子类特有功能时才转
        for (Employee e : staff) {
            if (e instanceof Manager m) {
                m.approve();
            }
        }
    }
}
```

输出：

```
张三 的薪资: 7000.0
李四 的薪资: 2000.0
总薪资: 9000.0
张三 审批报销单
```

这段代码体现了转型的正确分工：

* ==默认用向上转型 + 多态== 完成通用逻辑（统计、打印），调用方不关心具体子类；
* ==确需子类特有方法时==，才用 `instanceof` 检查后向下转型。

## 5. 编译期规则速查表

| 源引用静态类型 → 目标类型 | 是否需要强转 | 编译 | 运行时 |
| --- | --- | --- | --- |
| 子类 → 父类 | 不需要 | 通过 | ==一定成功== |
| 父类 → 子类 | 需要 | 通过 | 实际对象是目标类型才成功，否则 ==CCE== |
| 兄弟类 → 兄弟类 | 需要 | ==编译错误== | — |
| 无关类（其中一个是 `final`） | 需要 | ==编译错误== | — |
| 非 `final` 类 → 接口 | 需要 | 通过 | 实现了该接口才成功，否则 ==CCE== |
| `final` 类 → 它未实现的接口 | 需要 | ==编译错误== | — |
| `null` → 任意引用类型 | 需要 | 通过 | 结果为 `null`，不抛异常 |
| 子类数组 → 父类数组 | 不需要 | 通过 | 一定成功 |
| 父类数组 → 子类数组 | 需要 | 通过 | 数组实际类型匹配才成功 |

> [!note] 编译期检查的本质
> 编译器只检查"静态类型之间是否存在转换的可能性"：
> * 有继承/实现关系 → 放行；
> * 两个 `final` 类且互不相干 → 不可能，直接报错；
> * 父类与子类 → 放行，把检查推迟到运行期。
> 因此==编译通过 ≠ 转型一定安全==。

## 6. 为什么应尽量少用向下转型

向下转型意味着"我现在必须知道这个对象的具体类型"，这会把代码重新绑死在子类上：

```java
// 坏味道：每加一种员工，就要加一个分支
for (Employee e : staff) {
    if (e instanceof Manager m) {
        System.out.println("经理奖金: " + m.getBonus());
    } else if (e instanceof HourlyEmployee h) {
        System.out.println("时薪: " + h.getRate());
    }
}
```

更好的做法是在父类/接口中声明统一的方法（如 `calculateSalary()`），让子类自己重写，调用方只依赖抽象：

```java
for (Employee e : staff) {
    e.printInfo();     // 不需要知道具体类型
}
```

这就是[[面向抽象编程]]和[[开闭原则]]：==新增子类时，调用方代码不需要修改==。

向下转型仍然有合理场景：

* 使用返回 `Object` 的旧 API 或框架回调；
* 实现 `equals()` 时需要访问同类对象的字段；
* 外部类型不受你控制，无法为其添加多态方法；
* 确实需要子类特有行为，且已经用 `instanceof` 做了保护。

## 7. 常见误区

### 7.1 以为向上转型后"对象变成了父类"

对象类型自始至终不变，变的只是引用的静态类型：

```java
Employee e = new Manager("张三", 2000);
System.out.println(e.getClass().getSimpleName());   // Manager
```

### 7.2 以为字段也会多态

```java
A a = new B();
System.out.println(a.tag);   // A，不是 B
```

字段在编译期就按引用类型绑定，==只有方法才有多态==。

### 7.3 以为编译通过就一定安全

```java
Employee e = new Employee("李四");
Manager m = (Manager) e;     // 编译通过，运行时 CCE
```

向下转型前必须确认实际类型，或者直接用 `instanceof` 模式匹配。

### 7.4 兄弟类直接强转

```java
HourlyEmployee h = new HourlyEmployee("李四", 20, 100);
Manager m = (Manager) h;     // 编译错误：inconvertible types
```

如果确实要通过父类引用中转，记住运行时照样会 CCE：

```java
Employee e = h;
Manager m = (Manager) e;     // 编译通过，运行时 CCE
```

### 7.5 对 null 掉以轻心

`(Manager) null` 不抛异常，但随后调用方法会 NPE。转型成功不代表对象可用。

### 7.6 把向下转型当常规设计手段

如果一个方法里出现了大量 `instanceof` + 强转，通常说明抽象没设计好；优先考虑把差异行为放进子类重写。

## 8. 小结

* ==向上转型==：子类 → 父类，自动完成、一定安全；用来统一类型、实现多态、面向抽象编程。
* ==向下转型==：父类 → 子类，必须强转；运行期检查实际类型，可能抛 `ClassCastException`。
* 转型只改变==引用的编译时类型==，不改变对象本身。
* 成员能否调用看==编译时类型==，被重写的方法执行哪个版本看==运行时类型==（见 [[动态绑定]]）。
* 向下转型前先 `instanceof` 检查，Java 16+ 优先用模式匹配；能用多态解决就不要向下转型。
