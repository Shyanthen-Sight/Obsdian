# 日期与时间 —— 取当前、格式化、加减与间隔

> [!abstract] 一句话
> 日期函数的核心不是"记住多少个函数名"，而是记住三组东西：**怎么取当前时间**（`NOW` / `CURDATE` / `UTC_TIMESTAMP`）、**怎么格式化和解析**（`DATE_FORMAT` / `STR_TO_DATE`）、**怎么加减和算间隔**（`DATE_ADD` / `DATEDIFF` / `TIMESTAMPDIFF`）。再加一条铁律：**别在索引列上套日期函数**。

---

## 一、先分清四种类型与三个"现在"

### 1.1 `DATE` / `TIME` / `DATETIME` / `TIMESTAMP`

| 类型 | 存什么 | 范围 | 时区 | 典型用途 |
| --- | --- | --- | --- | --- |
| `DATE` | 年-月-日 | `1000-01-01` ~ `9999-12-31` | 无 | 生日、发货日 |
| `TIME` | 时:分:秒 | `-838:59:59` ~ `838:59:59` | 无 | 营业时间、时长 |
| `DATETIME` | 年-月-日 时:分:秒 | `1000-01-01 00:00:00` ~ `9999-12-31 23:59:59` | **不随时区转换** | 订单创建时间（单时区） |
| `TIMESTAMP` | 年-月-日 时:分:秒 | `1970-01-01 00:00:01` UTC ~ `2038-01-19 03:14:07` UTC | **按 UTC 存储，进出按会话时区转换** | 多时区系统 |

```sql
CREATE TABLE demo_time (
    d   DATE,
    t   TIME,
    dt  DATETIME,
    ts  TIMESTAMP
);
```

> [!danger] 2038 年问题
> `TIMESTAMP` 用 4 字节存 Unix 时间戳，上限是 **2038-01-19 03:14:07 UTC**。
> 长期系统的主时间字段用 `DATETIME`，别用 `TIMESTAMP`。
> 只有"需要自动做时区换算"的场景才选 `TIMESTAMP`，并清楚它的上限。

> [!warning] `DATETIME` 和 `TIMESTAMP` 的时区行为不一样
> - `DATETIME`：存什么读什么，`'2026-10-17 10:00:00'` 进去，出来还是 `'2026-10-17 10:00:00'`
> - `TIMESTAMP`：存入时按会话时区转成 UTC，读出时再转回会话时区
>
> 服务器时区一变，`TIMESTAMP` 显示的值会跟着变，`DATETIME` 不会。跨时区业务必须把这件事想清楚。

### 1.2 日期时间字面量

标准写法：

```sql
'2026-10-17'                  -- DATE
'2026-10-17 10:00:00'         -- DATETIME
'2026-10-17 10:00:00.123'     -- 带毫秒
'10:00:00'                    -- TIME
```

> [!tip] 推荐统一用 `YYYY-MM-DD HH:MM:SS`
> 这是最不容易歧义的格式。`'10/11/2026'` 到底是 10 月 11 日还是 11 月 10 日，取决于 `date_format` 和地区设置，线上事故常从这儿来。
> 从应用层传参时，也用这个格式，不要传本地化字符串。

### 1.3 三个"现在"：`NOW` / `SYSDATE` / `UTC_TIMESTAMP`

```sql
SELECT NOW();                 -- 2026-10-17 10:00:00（会话时区）
SELECT SYSDATE();             -- 2026-10-17 10:00:00（会话时区）
SELECT UTC_TIMESTAMP();       -- 2026-10-17 02:00:00（UTC）
SELECT CURDATE();             -- 2026-10-17
SELECT CURTIME();             -- 10:00:00
```

| 函数 | 返回 | 时区 | 特点 |
| --- | --- | --- | --- |
| `NOW([fsp])` | `DATETIME` | 会话时区 | **语句开始执行时**取值，一条语句里多次调用结果相同 |
| `SYSDATE([fsp])` | `DATETIME` | 会话时区 | **实际执行到该函数时**取值，可能和 `NOW()` 不同 |
| `CURDATE()` | `DATE` | 会话时区 | 只要日期 |
| `CURTIME()` | `TIME` | 会话时区 | 只要时间 |
| `UTC_TIMESTAMP()` | `DATETIME` | UTC | 不受会话时区影响 |
| `UTC_DATE()` / `UTC_TIME()` | `DATE` / `TIME` | UTC | 同上 |

> [!note] `NOW()` 与 `SYSDATE()` 的差别
> 一条 SQL 如果执行很久（比如带 `SLEEP()`、复杂计算），`NOW()` 在整个语句里是**同一个值**，`SYSDATE()` 会随着执行时刻推进。
> ```sql
> SELECT NOW(), SLEEP(2), NOW(), SYSDATE();
> ```
> 两个 `NOW()` 相同，`SYSDATE()` 比它们晚约 2 秒。
> 业务记录"下单时间"用 `NOW()` 更稳定；记录"实际处理到这一步的时间"才考虑 `SYSDATE()`。

> [!tip] `CURRENT_TIMESTAMP` 系列都是同义词
> `NOW()`、`CURRENT_TIMESTAMP`、`CURRENT_TIMESTAMP()`、`LOCALTIME`、`LOCALTIME()`、`LOCALTIMESTAMP`、`LOCALTIMESTAMP()` 等价。
> `CURDATE()` 等价于 `CURRENT_DATE` / `CURRENT_DATE()`；`CURTIME()` 等价于 `CURRENT_TIME` / `CURRENT_TIME()`。

### 1.4 带小数秒（fsp）

```sql
SELECT NOW(3);                 -- 2026-10-17 10:00:00.123
SELECT NOW(6);                 -- 2026-10-17 10:00:00.123456
SELECT CURRENT_TIMESTAMP(3);   -- 同上
```

建表时对应：

```sql
created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3)
```

> [!note] 默认精度是 0
> `DATETIME` 不写括号就是**整秒**，插入 `'...10:00:00.123'` 会把毫秒舍入/截断。
> 需要毫秒、微秒就显式写 `DATETIME(3)` / `DATETIME(6)`。高并发订单号、日志时间建议至少 3 位。

## 二、拆出年月日时分秒

### 2.1 常用拆分函数

| 函数 | 返回 | 示例（`2026-10-17 09:30:45`） |
| --- | --- | --- |
| `DATE(expr)` | 日期部分 | `2026-10-17` |
| `TIME(expr)` | 时间部分 | `09:30:45` |
| `YEAR(d)` | 年 | `2026` |
| `MONTH(d)` | 月（1~12） | `10` |
| `DAY(d)` / `DAYOFMONTH(d)` | 日（1~31） | `17` |
| `HOUR(t)` | 时（0~23） | `9` |
| `MINUTE(t)` | 分（0~59） | `30` |
| `SECOND(t)` | 秒（0~59） | `45` |
| `MICROSECOND(t)` | 微秒（0~999999） | `0` |
| `QUARTER(d)` | 季度（1~4） | `4` |
| `DAYOFYEAR(d)` | 一年中的第几天（1~366） | `290` |

```sql
SELECT DATE(created_at)  AS 日期,
       TIME(created_at)  AS 时间,
       YEAR(created_at)  AS 年,
       MONTH(created_at) AS 月,
       DAY(created_at)   AS 日,
       HOUR(created_at)  AS 时,
       MINUTE(created_at)AS 分,
       SECOND(created_at)AS 秒,
       QUARTER(created_at) AS 季度,
       DAYOFYEAR(created_at) AS 年内第几天
FROM orders;
```

### 2.2 星期相关

| 函数 | 编号规则 | `2026-10-17`（周六） |
| --- | --- | --- |
| `DAYOFWEEK(d)` | **1 = 周日**，7 = 周六 | `7` |
| `WEEKDAY(d)` | **0 = 周一**，6 = 周日 | `5` |
| `DAYNAME(d)` | 英文星期名 | `Saturday` |
| `MONTHNAME(d)` | 英文月份名 | `October` |

```sql
SELECT DAYOFWEEK('2026-10-17');   -- 7（周六）
SELECT WEEKDAY('2026-10-17');     -- 5（从周一数第 5 天，即周六）
SELECT DAYNAME('2026-10-17');     -- 'Saturday'
SELECT MONTHNAME('2026-10-17');   -- 'October'
```

> [!danger] `DAYOFWEEK` 和 `WEEKDAY` 的起点不同
> `DAYOFWEEK`：**周日 = 1**（跟很多日历、报表习惯一致）
> `WEEKDAY`：**周一 = 0**（跟 ISO / 欧洲习惯一致）
> 写"每周一统计"时，先确认你要的是哪一个，别把 `1` 当成周一。

### 2.3 周数与 `WEEK` 的 8 种模式

```sql
WEEK(date[, mode])
WEEKOFYEAR(date)     -- 等价于 WEEK(date, 3)
```

| mode | 一周第一天 | 返回值范围 | 第 1 周的判定 |
| --- | --- | --- | --- |
| 0 | 周日 | 0~53 | 含 1 月 1 日的那个周日所在周 |
| 1 | 周一 | 0~53 | 含 1 月 1 日的那个周一所在周 |
| 2 | 周日 | 1~53 | 同上 |
| 3 | 周一 | 1~53 | **ISO 周**：第一个有 4 天以上在本年的周 |
| 4 | 周日 | 0~53 | 第一个有 4 天以上在本年的周 |
| 5 | 周一 | 0~53 | 同上 |
| 6 | 周日 | 1~53 | 同上 |
| 7 | 周一 | 1~53 | 同上 |

```sql
SELECT WEEK('2026-10-17');          -- 默认 mode=0
SELECT WEEK('2026-10-17', 3);       -- ISO 周，结果 42
SELECT WEEKOFYEAR('2026-10-17');    -- 42，等价于 WEEK(...,3)
```

> [!warning] 周数是最容易"跨系统对不上"的字段
> MySQL 的 `WEEK` 有 8 种模式，Java 的 `WeekFields`、Excel 的 `WEEKNUM`、ISO 8601 又各有规则。
> 跨系统传"第几周"时，**必须同时传模式和年份**；更稳的做法是直接传日期，让对方自己算。

### 2.4 `LAST_DAY` 与 `EXTRACT`

```sql
SELECT LAST_DAY('2024-02-01');    -- 2024-02-29（闰年）
SELECT LAST_DAY('2026-02-01');    -- 2026-02-28
SELECT LAST_DAY('2026-10-17');    -- 2026-10-31

SELECT EXTRACT(YEAR FROM '2026-10-17');         -- 2026
SELECT EXTRACT(MONTH FROM '2026-10-17');        -- 10
SELECT EXTRACT(YEAR_MONTH FROM '2026-10-17');   -- 202610
SELECT EXTRACT(DAY_HOUR FROM '2026-10-17 09:30:45');  -- 1709
```

> [!tip] `LAST_DAY` 是算月末的捷径
> 不用先判断闰年、再判断大小月：`LAST_DAY(日期)` 直接给出当月最后一天。
> 做"本月最后一天""下月第一天"这类边界计算非常方便：
> ```sql
> SELECT DATE_ADD(LAST_DAY('2026-10-17'), INTERVAL 1 DAY);  -- 2026-11-01
> ```

> [!note] `EXTRACT` 的组合单位
> `YEAR_MONTH`、`DAY_HOUR`、`DAY_MINUTE`、`DAY_SECOND`、`HOUR_MINUTE`、`HOUR_SECOND`、`MINUTE_SECOND` 都可以用。
> 组合单位返回的是一个**数字**（如 `202610`），不是带分隔符的字符串。

## 三、格式化与解析

### 3.1 `DATE_FORMAT`

```sql
DATE_FORMAT(date, format)
```

```sql
SELECT DATE_FORMAT('2026-10-17 09:30:45', '%Y-%m-%d %H:%i:%s');
-- '2026-10-17 09:30:45'

SELECT DATE_FORMAT('2026-10-17 09:30:45', '%Y年%m月%d日 %H:%i');
-- '2026年10月17日 09:30'

SELECT DATE_FORMAT('2026-10-17 09:30:45', '%b %d, %Y %h:%i %p');
-- 'Oct 17, 2026 09:30 AM'
```

常用格式符：

| 格式符 | 含义 | 示例 |
| --- | --- | --- |
| `%Y` | 4 位年 | `2026` |
| `%y` | 2 位年 | `26` |
| `%m` | 月，两位 | `10` |
| `%c` | 月，不补零 | `10` |
| `%M` | 英文月份全名 | `October` |
| `%b` | 英文月份缩写 | `Oct` |
| `%d` | 日，两位 | `17` |
| `%e` | 日，不补零 | `17` |
| `%H` | 24 小时制，两位 | `09` |
| `%k` | 24 小时制，不补零 | `9` |
| `%h` / `%I` | 12 小时制，两位 | `09` |
| `%l` | 12 小时制，不补零 | `9` |
| `%i` | 分钟，两位 | `30` |
| `%s` / `%S` | 秒，两位 | `45` |
| `%f` | 微秒，6 位 | `000000` |
| `%p` | AM / PM | `AM` |
| `%W` | 英文星期全名 | `Saturday` |
| `%a` | 英文星期缩写 | `Sat` |
| `%w` | 星期数字，**0 = 周日** | `6` |
| `%j` | 一年中的第几天，3 位 | `290` |
| `%T` | 24 小时时间 | `09:30:45` |
| `%r` | 12 小时时间带 AM/PM | `09:30:45 AM` |
| `%U` | 周数，周日为第一天（mode 0） | `41` |
| `%u` | 周数，周一为第一天（mode 1） | `41` |
| `%V` | 周数，周日为第一天（mode 2） | `42` |
| `%v` | 周数，周一为第一天（mode 3） | `42` |
| `%X` | `%V` 对应的 4 位年 | `2026` |
| `%x` | `%v` 对应的 4 位年 | `2026` |
| `%%` | 字面量 `%` | `%` |

> [!warning] `%i` 是分钟，不是月份
> 月份是 `%m`，分钟是 `%i`。把 `%i` 写成 `%m` 会得到"10 月 10 日 10:10:45"这种看起来像对、其实全错的结果。

> [!note] `%U` / `%u` / `%V` / `%v` 的年份
> 用 `%V` / `%v` 计算周数时，跨年那一周可能属于上一年或下一年，**必须配合 `%X` / `%x` 一起输出年份**，否则 12 月 31 日可能显示成"第 1 周"却还是旧年份，数据对不上。

### 3.2 `STR_TO_DATE`

```sql
STR_TO_DATE(str, format)
```

```sql
SELECT STR_TO_DATE('2026-10-17', '%Y-%m-%d');             -- 2026-10-17
SELECT STR_TO_DATE('17/10/2026', '%d/%m/%Y');             -- 2026-10-17
SELECT STR_TO_DATE('2026年10月17日', '%Y年%m月%d日');      -- 2026-10-17
SELECT STR_TO_DATE('2026-10-17 09:30:45', '%Y-%m-%d %H:%i:%s');
-- 2026-10-17 09:30:45
```

> [!danger] 解析失败返回 `NULL`，只给 warning
> ```sql
> SELECT STR_TO_DATE('2026-02-30', '%Y-%m-%d');   -- NULL（2 月没有 30 日）
> SELECT STR_TO_DATE('abc', '%Y-%m-%d');           -- NULL
> ```
> 不报错，直接 NULL。导入数据时一定要检查 `IS NULL`，否则脏数据会静默变成空值。

> [!tip] 解析和格式化是一对
> `DATE_FORMAT` 是"日期 → 字符串"，`STR_TO_DATE` 是"字符串 → 日期"。
> 两者用同一套格式符，记住一套就够了。

### 3.3 `GET_FORMAT`

```sql
SELECT GET_FORMAT(DATE, 'ISO');       -- '%Y-%m-%d'
SELECT GET_FORMAT(DATE, 'USA');       -- '%m.%d.%Y'
SELECT GET_FORMAT(DATE, 'EUR');       -- '%d.%m.%Y'
SELECT GET_FORMAT(DATETIME, 'ISO');   -- '%Y-%m-%d %H:%i:%s'
```

> [!note] `GET_FORMAT` 只是返回格式串
> 它不会帮你格式化，得配合 `DATE_FORMAT`：
> ```sql
> SELECT DATE_FORMAT('2026-10-17', GET_FORMAT(DATE, 'ISO'));  -- '2026-10-17'
> ```

## 四、日期加减

### 4.1 `DATE_ADD` / `DATE_SUB`

```sql
DATE_ADD(date, INTERVAL expr unit)
DATE_SUB(date, INTERVAL expr unit)
```

```sql
SELECT DATE_ADD('2026-10-17', INTERVAL 1 DAY);       -- 2026-10-18
SELECT DATE_SUB('2026-10-17', INTERVAL 1 DAY);       -- 2026-10-16
SELECT DATE_ADD('2026-10-17', INTERVAL -1 DAY);      -- 2026-10-16（负值等价于 SUB）
SELECT DATE_ADD('2026-10-17 10:00:00', INTERVAL 90 MINUTE);
-- 2026-10-17 11:30:00
SELECT DATE_ADD('2026-10-17', INTERVAL '1-2' YEAR_MONTH);
-- 2027-12-17
SELECT DATE_ADD('2026-10-17', INTERVAL '1 02:03:04' DAY_SECOND);
-- 2026-10-18 02:03:04
```

### 4.2 常用单位

| 单位 | 含义 | 示例 |
| --- | --- | --- |
| `MICROSECOND` | 微秒 | `INTERVAL 500 MICROSECOND` |
| `SECOND` | 秒 | `INTERVAL 30 SECOND` |
| `MINUTE` | 分 | `INTERVAL 90 MINUTE` |
| `HOUR` | 小时 | `INTERVAL 2 HOUR` |
| `DAY` | 天 | `INTERVAL 7 DAY` |
| `WEEK` | 周 | `INTERVAL 2 WEEK` |
| `MONTH` | 月 | `INTERVAL 1 MONTH` |
| `QUARTER` | 季度 | `INTERVAL 1 QUARTER` |
| `YEAR` | 年 | `INTERVAL 1 YEAR` |
| `YEAR_MONTH` | 年+月 | `INTERVAL '1-2' YEAR_MONTH` |
| `DAY_HOUR` | 天+时 | `INTERVAL '1 02' DAY_HOUR` |
| `HOUR_MINUTE` | 时+分 | `INTERVAL '1:30' HOUR_MINUTE` |
| `DAY_SECOND` | 天+时分秒 | `INTERVAL '1 02:03:04' DAY_SECOND` |

### 4.3 月末的"溢出"规则

```sql
SELECT DATE_ADD('2026-01-31', INTERVAL 1 MONTH);   -- 2026-02-28
SELECT DATE_ADD('2024-01-31', INTERVAL 1 MONTH);   -- 2024-02-29（闰年）
SELECT DATE_ADD('2026-10-31', INTERVAL 1 MONTH);   -- 2026-11-30
SELECT DATE_SUB('2026-03-31', INTERVAL 1 MONTH);   -- 2026-02-28
```

> [!danger] 加一个月不是"天数 +30"
> `2026-01-31 + 1 MONTH` 得到 `2026-02-28`，不是 `2026-03-03`。
> MySQL 的规则是：**结果日超过目标月末时，取目标月最后一天**。
> 做"每月同一天续费"这类业务时，必须明确"31 号在 2 月怎么办"，否则会漏扣或多扣。

### 4.4 `ADDDATE` / `SUBDATE` / `ADDTIME` / `SUBTIME`

```sql
SELECT ADDDATE('2026-10-17', 7);                       -- 2026-10-24（第二个参数是天数）
SELECT ADDDATE('2026-10-17', INTERVAL 7 DAY);          -- 2026-10-24
SELECT SUBDATE('2026-10-17', 7);                       -- 2026-10-10
SELECT SUBDATE('2026-10-17', INTERVAL 7 DAY);          -- 2026-10-10

SELECT ADDTIME('2026-10-17 10:00:00', '01:30:00');    -- 2026-10-17 11:30:00
SELECT SUBTIME('2026-10-17 10:00:00', '01:30:00');    -- 2026-10-17 08:30:00
```

> [!note] `ADDDATE(date, n)` 的 `n` 是**天**
> 写成 `ADDDATE(date, 7)` 就是加 7 天；要加月、年，必须用 `INTERVAL` 形式。
> `ADDTIME` 的第二个参数是**时间**，不是天数。

### 4.5 `TIMESTAMPADD`

```sql
TIMESTAMPADD(unit, interval, datetime_expr)
```

```sql
SELECT TIMESTAMPADD(DAY, 7, '2026-10-17');        -- 2026-10-24
SELECT TIMESTAMPADD(MONTH, 1, '2026-01-31');      -- 2026-02-28
SELECT TIMESTAMPADD(HOUR, 2, '2026-10-17 10:00:00'); -- 2026-10-17 12:00:00
```

> [!tip] `TIMESTAMPADD` 的 unit 不加引号
> 它是关键字参数：`TIMESTAMPADD(DAY, 7, ...)`，不是 `TIMESTAMPADD('DAY', 7, ...)`。
> 和 `DATE_ADD` 的 `INTERVAL` 写法不同，别混。

## 五、日期间隔：`DATEDIFF` / `TIMEDIFF` / `TIMESTAMPDIFF`

### 5.1 `DATEDIFF`：只按日期算天数

```sql
DATEDIFF(expr1, expr2)     -- expr1 - expr2，单位：天
```

```sql
SELECT DATEDIFF('2026-10-17', '2026-09-28');    -- 19
SELECT DATEDIFF('2026-10-17', '2026-10-10');    -- 7
SELECT DATEDIFF('2026-09-28', '2026-10-17');    -- -19
SELECT DATEDIFF('2026-10-17 23:59:59', '2026-10-17 00:00:00');  -- 0
```

> [!warning] `DATEDIFF` 只看日期，不看时间
> 同一天的 `23:59:59` 和 `00:00:00` 相差 `0` 天，不是 1 天。
> 需要精确到小时/分钟/秒，用 `TIMESTAMPDIFF`。需要"跨了多少个自然日"，用 `DATEDIFF`。

按订单算付款用了几天：

```sql
SELECT order_no,
       DATEDIFF(paid_at, created_at) AS 付款间隔天数
FROM orders;
```

```
+----------------+--------------+
| order_no       | 付款间隔天数 |
+----------------+--------------+
| NO20260928001  |            0 |
| NO20260930001  |            1 |
| NO20261001001  |            0 |
| NO20261017001  |         NULL |
| NO20251231001  |            1 |
| NO20260331001  |            0 |
+----------------+--------------+
```

### 5.2 `TIMEDIFF`：两个时间/日期时间之差

```sql
TIMEDIFF(expr1, expr2)     -- 返回 TIME
```

```sql
SELECT TIMEDIFF('2026-10-17 10:00:00', '2026-10-17 08:30:00');  -- '01:30:00'
SELECT TIMEDIFF('10:00:00', '08:30:00');                        -- '01:30:00'
SELECT TIMEDIFF('2026-10-17 10:00:00', '2026-10-16 10:00:00');  -- '24:00:00'
```

> [!warning] `TIMEDIFF` 的返回值是 `TIME`，有上限
> `TIME` 的范围是 `-838:59:59` ~ `838:59:59`，超过会截断/报错。
> 而且两个参数的类型必须一致：不能一个 `DATE`、一个 `DATETIME`。
> 算"相差多少天"用 `DATEDIFF`，算"相差多少秒/小时"用 `TIMESTAMPDIFF`，`TIMEDIFF` 更适合一天内的时间差。

### 5.3 `TIMESTAMPDIFF`：按指定单位算差值（最常用）

```sql
TIMESTAMPDIFF(unit, datetime_expr1, datetime_expr2)
-- 返回 datetime_expr2 - datetime_expr1，单位由 unit 指定
```

```sql
SELECT TIMESTAMPDIFF(SECOND, '2026-10-17 10:00:00', '2026-10-17 10:01:30');  -- 90
SELECT TIMESTAMPDIFF(MINUTE, '2026-10-17 10:00:00', '2026-10-17 10:01:30');  -- 1
SELECT TIMESTAMPDIFF(HOUR,   '2026-10-17 08:00:00', '2026-10-17 12:30:00');  -- 4
SELECT TIMESTAMPDIFF(DAY,    '2026-10-01', '2026-10-17');                    -- 16
SELECT TIMESTAMPDIFF(MONTH,  '2026-01-31', '2026-03-01');                    -- 1
SELECT TIMESTAMPDIFF(YEAR,   '2000-05-20', '2026-10-17');                    -- 26
```

| unit | 说明 |
| --- | --- |
| `MICROSECOND` | 微秒 |
| `SECOND` | 秒 |
| `MINUTE` | 分 |
| `HOUR` | 时 |
| `DAY` | 天 |
| `WEEK` | 周 |
| `MONTH` | 月 |
| `QUARTER` | 季度 |
| `YEAR` | 年 |

按订单算付款用了多少秒：

```sql
SELECT order_no,
       TIMESTAMPDIFF(SECOND, created_at, paid_at) AS 付款秒数,
       TIMESTAMPDIFF(MINUTE, created_at, paid_at) AS 付款分钟
FROM orders;
```

```
+----------------+----------+------------+
| order_no       | 付款秒数 | 付款分钟   |
+----------------+----------+------------+
| NO20260928001  |      270 |          4 |
| NO20260930001  |      301 |          5 |
| NO20261001001  |       60 |          1 |
| NO20261017001  |     NULL |       NULL |
| NO20251231001  |       61 |          1 |
| NO20260331001  |     1800 |         30 |
+----------------+----------+------------+
```

验算：
- 订单 1：`10:15:30 → 10:20:00`，4 分 30 秒 = 270 秒，不足 5 分钟 → `4`
- 订单 2：`09-30 23:59:59 → 10-01 00:05:00`，5 分 1 秒 = 301 秒，不足 6 分钟 → `5`
- 订单 5：`12-31 23:59:59 → 01-01 00:01:00`，1 分 1 秒 = 61 秒，不足 2 分钟 → `1`

> [!warning] `TIMESTAMPDIFF` 是"完整单位数"，不是四舍五入
> 90 秒按分钟算是 `1`，不是 `2`；差 1 天 23 小时按天算是 `1`，不是 `2`。
> 它只数**已经走完的完整单位**。

> [!danger] 月的算法不是"天数 / 30"
> `TIMESTAMPDIFF(MONTH, '2026-01-31', '2026-03-01')` 返回 `1`，不是 `2`。
> MySQL 先算年月差，再根据"日"是否够一整个月来修正。跨月、跨年的业务账期，别自己用天数除 30 硬算。

### 5.4 `PERIOD_ADD` / `PERIOD_DIFF`

```sql
PERIOD_ADD(P, N)       -- P 是 YYMM 或 YYYYMM，加 N 个月
PERIOD_DIFF(P1, P2)    -- P1 - P2，单位：月
```

```sql
SELECT PERIOD_ADD(202601, 9);       -- 202610
SELECT PERIOD_ADD(202612, 1);       -- 202701
SELECT PERIOD_DIFF(202610, 202601); -- 9
SELECT PERIOD_DIFF(202601, 202610); -- -9
```

> [!note] `PERIOD_*` 的参数是"年月数字"，不是日期
> `202610` 表示 2026 年 10 月，不是 2026-10-01。
> 账期、报表月份计算很好用；要具体日期还是用 `DATE_ADD`。

## 六、Unix 时间戳与转换

### 6.1 `UNIX_TIMESTAMP` / `FROM_UNIXTIME`

```sql
SELECT UNIX_TIMESTAMP();                          -- 当前 Unix 秒
SELECT UNIX_TIMESTAMP('2026-10-17 00:00:00');     -- 指定时间的 Unix 秒
SELECT FROM_UNIXTIME(0);                          -- '1970-01-01 08:00:00'（UTC+8）
SELECT FROM_UNIXTIME(UNIX_TIMESTAMP('2026-10-17 00:00:00'));
-- '2026-10-17 00:00:00'
```

> [!warning] 时间戳的数值依赖会话时区
> `UNIX_TIMESTAMP('2026-10-17 00:00:00')` 在不同时区会话里结果不同。
> `FROM_UNIXTIME(0)` 在 UTC+8 是 `1970-01-01 08:00:00`，在 UTC 是 `1970-01-01 00:00:00`。
> 跨时区系统里，时间戳本身是绝对的，但"把字符串解释成时间戳"这一步依赖时区。

```sql
SELECT FROM_UNIXTIME(UNIX_TIMESTAMP('2026-10-17 00:00:00'), '%Y-%m-%d %H:%i:%s');
-- '2026-10-17 00:00:00'
```

> [!note] `FROM_UNIXTIME` 的第二参数是格式串
> 它不是"时区"，是 `DATE_FORMAT` 的格式串。时区转换用 `CONVERT_TZ`。

### 6.2 `TIME_TO_SEC` / `SEC_TO_TIME`

```sql
SELECT TIME_TO_SEC('01:30:00');      -- 5400
SELECT TIME_TO_SEC('-01:30:00');     -- -5400
SELECT SEC_TO_TIME(5400);            -- '01:30:00'
SELECT SEC_TO_TIME(90000);           -- '25:00:00'
```

> [!tip] 用秒存"时长"更稳
> 会议时长、视频长度、任务耗时用 `INT` 存秒数，比 `TIME` 更好跨系统。
> 展示时再 `SEC_TO_TIME` 转成 `HH:MM:SS`。

### 6.3 `TO_DAYS` / `FROM_DAYS` / `TO_SECONDS`

```sql
SELECT TO_DAYS('2026-10-17');        -- 自公元 0 年以来的天数
SELECT FROM_DAYS(TO_DAYS('2026-10-17'));  -- '2026-10-17'
SELECT TO_SECONDS('2026-10-17 10:00:00'); -- 自公元 0 年以来的秒数
```

> [!note] 日常算天数差用 `DATEDIFF`
> `TO_DAYS` 的绝对值没有业务意义，只适合做相对比较或索引辅助。
> 可读性和正确性都不如 `DATEDIFF(a, b)`。

## 七、时区处理

### 7.1 会话时区

```sql
SELECT @@global.time_zone, @@session.time_zone;
-- 常见结果：SYSTEM, SYSTEM

SET time_zone = '+08:00';
SET time_zone = 'Asia/Shanghai';   -- 需要时区表
```

> [!warning] `Asia/Shanghai` 这种命名时区需要时区表
> MySQL 默认不一定加载 `mysql.time_zone*` 表。没加载时，`SET time_zone = 'Asia/Shanghai'` 会失败，`CONVERT_TZ(..., 'Asia/Shanghai', 'UTC')` 返回 `NULL`。
> 加载方式（Linux）：
> ```bash
> mysql_tzinfo_to_sql /usr/share/zoneinfo | mysql -u root mysql
> ```
> 不想折腾时区表，就统一用 `+08:00` 这种偏移量写法（但偏移量不处理夏令时）。

### 7.2 `CONVERT_TZ`

```sql
CONVERT_TZ(dt, from_tz, to_tz)
```

```sql
SELECT CONVERT_TZ('2026-10-17 10:00:00', '+08:00', '+00:00');
-- '2026-10-17 02:00:00'

SELECT CONVERT_TZ('2026-10-17 10:00:00', 'Asia/Shanghai', 'UTC');
-- 时区表已加载时：'2026-10-17 02:00:00'
-- 未加载时：NULL
```

> [!danger] `CONVERT_TZ` 返回 `NULL` 时先查时区表
> 很多"时区转换莫名其妙变 NULL"的问题，根源就是 `mysql.time_zone_name` 是空的。
> 用偏移量 `'+08:00'` 不需要时区表；用命名时区 `'Asia/Shanghai'` 才需要。

### 7.3 `TIMESTAMP` vs `DATETIME` 的时区行为

```sql
SET time_zone = '+08:00';
INSERT INTO demo_time (ts, dt) VALUES ('2026-10-17 10:00:00', '2026-10-17 10:00:00');

SET time_zone = '+00:00';
SELECT ts, dt FROM demo_time;
-- ts: '2026-10-17 02:00:00'   ← TIMESTAMP 跟着时区变
-- dt: '2026-10-17 10:00:00'   ← DATETIME 不变
```

> [!important] 选型口诀
> - **单时区 / 学校作业 / 内部系统**：`DATETIME`，直观、范围大
> - **用户遍布多时区、需要自动换算**：`TIMESTAMP`，但注意 2038 上限
> - **只存日期**：`DATE`
> - **只存时长**：`INT` 秒数或 `TIME`
>
> 不要在同一张表里混用两种时间语义，否则排查问题时要先猜"这个字段到底转没转时区"。

## 八、业务实战

### 8.1 今天

```sql
SELECT * FROM orders
WHERE created_at >= CURDATE()
  AND created_at <  CURDATE() + INTERVAL 1 DAY;
```

结果：订单 4（`2026-10-17 09:30:00`）。

> [!tip] 为什么不用 `DATE(created_at) = CURDATE()`
> 那样写会让 `created_at` 上的索引失效。用**半开区间** `>= 今天 00:00 AND < 明天 00:00`，既能走索引，又不会漏掉当天 23:59:59.999。

### 8.2 昨天

```sql
SELECT * FROM orders
WHERE created_at >= CURDATE() - INTERVAL 1 DAY
  AND created_at <  CURDATE();
```

结果：空（2026-10-16 没有订单）。

### 8.3 最近 7 天（含今天）

```sql
SELECT * FROM orders
WHERE created_at >= CURDATE() - INTERVAL 6 DAY
  AND created_at <  CURDATE() + INTERVAL 1 DAY;
```

结果：订单 4。`CURDATE() - INTERVAL 6 DAY` 是 10 月 11 日，覆盖 11~17 日。

> [!note] "最近 7 天"的两种口径
> - 含今天，从 6 天前 00:00 开始：`>= CURDATE() - INTERVAL 6 DAY`
> - 不含今天，从 7 天前 00:00 到昨天结束：`>= CURDATE() - INTERVAL 7 DAY AND < CURDATE()`
>
> 报表需求里必须问清楚，否则两边数据对不上。

### 8.4 本月

```sql
SELECT * FROM orders
WHERE created_at >= DATE_FORMAT(CURDATE(), '%Y-%m-01')
  AND created_at <  DATE_FORMAT(CURDATE() + INTERVAL 1 MONTH, '%Y-%m-01');
```

结果：订单 3、4（2026-10-01、2026-10-17）。

等价写法：

```sql
WHERE created_at >= DATE_SUB(CURDATE(), INTERVAL DAYOFMONTH(CURDATE()) - 1 DAY)
  AND created_at <  DATE_ADD(LAST_DAY(CURDATE()), INTERVAL 1 DAY)
```

> [!danger] 不要用 `YEAR(created_at) = YEAR(CURDATE()) AND MONTH(...) = MONTH(...)`
> 两条函数条件会让索引失效，而且写法更长。用范围条件，简单又快。

### 8.5 上月

```sql
SELECT * FROM orders
WHERE created_at >= DATE_FORMAT(CURDATE() - INTERVAL 1 MONTH, '%Y-%m-01')
  AND created_at <  DATE_FORMAT(CURDATE(), '%Y-%m-01');
```

结果：订单 1、2（2026-09-28、2026-09-30）。

> [!warning] "上月同日"不能用 `CURDATE() - INTERVAL 1 MONTH` 直接当边界
> 3 月 31 日减一个月是 2 月 28 日，再减一天才是 2 月 27 日——"上月同期"的边界要按业务定义单独算。
> 月度报表用"月初到下一个月初"的半开区间最稳。

### 8.6 本年

```sql
SELECT * FROM orders
WHERE created_at >= MAKEDATE(YEAR(CURDATE()), 1)
  AND created_at <  MAKEDATE(YEAR(CURDATE()) + 1, 1);
```

或用 `DATE_FORMAT(CURDATE(), '%Y-01-01')`。

### 8.7 按月汇总

```sql
SELECT DATE_FORMAT(created_at, '%Y-%m') AS 月份,
       COUNT(*)  AS 单数,
       SUM(amount) AS 金额
FROM orders
GROUP BY DATE_FORMAT(created_at, '%Y-%m')
ORDER BY 月份;
```

```
+---------+------+---------+
| 月份    | 单数 | 金额    |
+---------+------+---------+
| 2025-12 |    1 |   60.00 |
| 2026-03 |    1 |  300.00 |
| 2026-09 |    2 |  287.50 |
| 2026-10 |    2 | 1819.00 |
+---------+------+---------+
```

验算：2026-09 = 199.00 + 88.50 = 287.50；2026-10 = 1299.00 + 520.00 = 1819.00。

> [!tip] 按天汇总就把格式换成 `%Y-%m-%d`
> 按周汇总用 `YEARWEEK(created_at, 3)`（ISO 周）更稳，比 `WEEK()` 少踩模式坑。

### 8.8 算年龄

```sql
SELECT TIMESTAMPDIFF(YEAR, '2000-05-20', '2026-10-17') AS 年龄;
-- 26
```

> [!warning] 别用 `YEAR(今天) - YEAR(生日)`
> 那样会把还没过生日的人算大一岁。
> `TIMESTAMPDIFF(YEAR, birth_date, CURDATE())` 会正确处理"生日是否已过"。

### 8.9 订单超时

```sql
-- 下单超过 20 分钟仍未付款
SELECT order_no, created_at,
       TIMESTAMPDIFF(MINUTE, created_at, NOW()) AS 已等待分钟
FROM orders
WHERE paid_at IS NULL
  AND created_at < NOW() - INTERVAL 20 MINUTE;
```

结果：订单 4（09:30 下单，10:00 时已等待 30 分钟）。

> [!note] `NOW()` 在一条语句里是常量
> 所以 `NOW() - INTERVAL 20 MINUTE` 不会每行变化。
> 超时扫描通常由定时任务执行，注意任务本身的执行间隔不要大于超时阈值。

### 8.10 距离今天多少天

```sql
SELECT order_no,
       DATEDIFF(CURDATE(), DATE(created_at)) AS 距今天数
FROM orders
ORDER BY 距今天数;
```

> [!tip] `DATEDIFF` 只取日期部分
> 想精确到秒用 `TIMESTAMPDIFF(SECOND, created_at, NOW())`。

## 九、性能：日期条件怎么写才走索引

> [!important] 核心原则：**索引列上不要套函数**
> B+ 树按 `created_at` 的原始值排序。一旦写成 `DATE(created_at)`、`YEAR(created_at)`、`DATE_FORMAT(created_at, ...)`，每一行都要先算函数值再比较，索引顺序用不上。

```sql
-- ❌ 全表扫描
SELECT * FROM orders WHERE DATE(created_at) = '2026-10-17';
SELECT * FROM orders WHERE YEAR(created_at) = 2026;
SELECT * FROM orders WHERE DATE_FORMAT(created_at, '%Y-%m') = '2026-10';

-- ✅ 半开区间，能走索引
SELECT * FROM orders
WHERE created_at >= '2026-10-17' AND created_at < '2026-10-18';

SELECT * FROM orders
WHERE created_at >= '2026-01-01' AND created_at < '2027-01-01';

SELECT * FROM orders
WHERE created_at >= '2026-10-01' AND created_at < '2026-11-01';
```

### 9.1 `BETWEEN` 在日期上的经典坑

```sql
-- ❌ 只覆盖到 9 月 29 日 00:00:00，当天 10 点的数据查不到
SELECT * FROM orders
WHERE created_at BETWEEN '2026-09-01' AND '2026-09-29';

-- ✅ 用"下一天 00:00:00"作为开区间上界
SELECT * FROM orders
WHERE created_at >= '2026-09-01' AND created_at < '2026-09-30';
```

> [!danger] `BETWEEN` 是闭区间
> `BETWEEN '2026-09-01' AND '2026-09-29'` 等价于 `>= '2026-09-01 00:00:00' AND <= '2026-09-29 00:00:00'`。
> 9 月 29 日 10:00 的数据**大于**上界，被排除。
> 日期范围一律用 `>= 起 AND < 止`，别用 `BETWEEN`。

### 9.2 函数索引 / 生成列

MySQL 8.0.13+ 支持函数索引：

```sql
CREATE INDEX idx_created_date ON orders ((DATE(created_at)));
```

或者生成列 + 普通索引：

```sql
ALTER TABLE orders
  ADD COLUMN created_date DATE GENERATED ALWAYS AS (DATE(created_at)) STORED,
  ADD INDEX idx_created_date (created_date);
```

> [!note] 这是补救，不是首选
> 能改写成范围条件就改写法；函数索引会增加写入成本和存储。
> 只有"业务 SQL 改不动"或"必须按表达式查询"时才用。

### 9.3 其他注意点

- `ORDER BY created_at DESC LIMIT 10`：如果 `created_at` 有索引，可以直接取索引尾部，不用全表排序。
- `GROUP BY DATE_FORMAT(...)`：通常要临时表/排序，数据量大时考虑预聚合或生成列。
- 字符串和日期比较时，MySQL 会做隐式转换，但**不同版本的转换规则可能不同**；统一用 `YYYY-MM-DD HH:MM:SS` 字面量。

## 十、常见错误合集

> [!danger] 坑一：`BETWEEN` 查日期漏掉最后一天
> 上界写 `'2026-09-29'` 只到当天 00:00:00。改成 `< '2026-09-30'`。

> [!danger] 坑二：`DATE(created_at) = ...` 让索引失效
> 改成范围：`>= '2026-10-17' AND < '2026-10-18'`。

> [!danger] 坑三：`DAYOFWEEK` 和 `WEEKDAY` 混用
> `DAYOFWEEK` 周日 = 1；`WEEKDAY` 周一 = 0。写"周一"时先确认用哪个。

> [!danger] 坑四：`WEEK()` 不写 mode
> 默认 mode 0（周日为第一天），和 ISO 周（mode 3）可能差一周。跨系统统一用 `WEEKOFYEAR` 或 `YEARWEEK(..., 3)`。

> [!danger] 坑五：`DATE_ADD(..., INTERVAL 1 MONTH)` 的月末行为
> 1 月 31 日加一个月是 2 月 28 日，不是 3 月 3 日。续费、账期要专门处理。

> [!danger] 坑六：`TIMESTAMPDIFF` 当成四舍五入
> 它只数完整单位：90 秒按分钟是 1，不是 2。

> [!failure] 坑七：`STR_TO_DATE` 解析失败得到 NULL
> `2026-02-30`、`abc` 都返回 NULL，不报错。导入数据要检查 NULL。

> [!failure] 坑八：`TIMESTAMP` 的 2038 上限
> 超过 2038-01-19 03:14:07 UTC 会溢出。长期系统用 `DATETIME`。

> [!failure] 坑九：`CONVERT_TZ` 返回 NULL
> 命名时区需要时区表。没加载就用 `'+08:00'` 偏移量。

> [!failure] 坑十：零日期
> 严格模式（MySQL 8 默认包含 `NO_ZERO_DATE`）下，`'0000-00-00'` 会被拒绝。
> 非严格模式能存，但后续日期函数可能返回 NULL 或奇怪结果。别用零日期表示"未知"，用 NULL。

> [!failure] 坑十一：`NOW()` 和 `SYSDATE()` 混用
> 长语句里 `NOW()` 固定、`SYSDATE()` 推进。记录业务时间统一用 `NOW()`。

> [!failure] 坑十二：`DATETIME` / `TIMESTAMP` 时区语义混用
> 服务器时区一变，`TIMESTAMP` 显示值变、`DATETIME` 不变。跨时区系统要统一约定。

## 十一、速查表

| 需求 | 写法 | 示例 → 结果 |
| --- | --- | --- |
| 当前日期时间 | `NOW()` | `2026-10-17 10:00:00` |
| 当前日期 | `CURDATE()` | `2026-10-17` |
| 当前时间 | `CURTIME()` | `10:00:00` |
| UTC 当前时间 | `UTC_TIMESTAMP()` | `2026-10-17 02:00:00` |
| 日期部分 | `DATE(dt)` | `2026-10-17` |
| 时间部分 | `TIME(dt)` | `10:00:00` |
| 年 / 月 / 日 | `YEAR` / `MONTH` / `DAY` | `2026` / `10` / `17` |
| 时 / 分 / 秒 | `HOUR` / `MINUTE` / `SECOND` | `10` / `0` / `0` |
| 季度 | `QUARTER(d)` | `4` |
| 年内第几天 | `DAYOFYEAR(d)` | `290` |
| 星期几（周日=1） | `DAYOFWEEK(d)` | `7` |
| 星期几（周一=0） | `WEEKDAY(d)` | `5` |
| 周数（ISO） | `WEEKOFYEAR(d)` | `42` |
| 月末 | `LAST_DAY(d)` | `2026-10-31` |
| 格式化 | `DATE_FORMAT(d, fmt)` | `'%Y-%m-%d'` → `2026-10-17` |
| 解析字符串 | `STR_TO_DATE(s, fmt)` | `'2026-10-17'` |
| 加天数 | `DATE_ADD(d, INTERVAL n DAY)` | `2026-10-18` |
| 减月数 | `DATE_SUB(d, INTERVAL n MONTH)` | `2026-09-17` |
| 日期差（天） | `DATEDIFF(a, b)` | `19` |
| 时间差（指定单位） | `TIMESTAMPDIFF(unit, a, b)` | `90` 秒 |
| 时间差（TIME） | `TIMEDIFF(a, b)` | `'01:30:00'` |
| Unix 时间戳 | `UNIX_TIMESTAMP(d)` | 整数秒 |
| 时间戳转日期 | `FROM_UNIXTIME(ts)` | `2026-10-17 00:00:00` |
| 时区转换 | `CONVERT_TZ(dt, from, to)` | `'2026-10-17 02:00:00'` |
| 秒转时间 | `SEC_TO_TIME(n)` | `'01:30:00'` |
| 时间转秒 | `TIME_TO_SEC(t)` | `5400` |
| 本月起点 | `DATE_FORMAT(CURDATE(), '%Y-%m-01')` | `2026-10-01` |
| 下月起点 | `DATE_FORMAT(CURDATE() + INTERVAL 1 MONTH, '%Y-%m-01')` | `2026-11-01` |

> [!question] 自测三连
> 1. `NOW()` 和 `SYSDATE()` 在一条包含 `SLEEP(2)` 的语句里有什么区别？
> 2. 为什么 `WHERE created_at BETWEEN '2026-09-01' AND '2026-09-29'` 会漏数据？正确写法是什么？
> 3. `DATE_ADD('2026-01-31', INTERVAL 1 MONTH)` 返回什么？为什么不是 3 月 3 日？

---

> [!quote] 一句话记忆
> **`NOW()` 取语句开始时间、`SYSDATE()` 取执行到那一刻**；**日期加减用 `DATE_ADD/DATE_SUB`，天差用 `DATEDIFF`，秒/时/月差用 `TIMESTAMPDIFF`**；**日期范围一律 `>= 起 AND < 止`，别用 `BETWEEN`**；**索引列上别套 `DATE()` / `YEAR()` / `DATE_FORMAT()`**；**`TIMESTAMP` 有时区转换和 2038 上限，`DATETIME` 没有**。
