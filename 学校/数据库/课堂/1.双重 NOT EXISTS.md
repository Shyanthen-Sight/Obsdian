# 双重 NOT EXISTS：SQL 里如何表达「全部」

> [!info] 来源
> 课堂 PPT 示例（截图）
> 数据库系统概论 · 关系代数中的除法（division）运算

> [!summary] 速记版
> ```sql
> SELECT Sno
> FROM Student
> WHERE NOT EXISTS (
>     SELECT *
>     FROM SC SCX
>     WHERE SCX.Sno = '20180002'
>       AND NOT EXISTS (
>           SELECT *
>           FROM SC SCY
>           WHERE SCY.Sno = Student.Sno
>             AND SCY.Cno = SCX.Cno
>       )
> );
> ```
> - **语义**：查询**至少选修了 20180002 号同学所选全部课程**的学生的学号。
> - **双重否定**：`NOT EXISTS` 套 `NOT EXISTS`，即 `¬∃ … ¬∃ …` ≡ `∀ …`（「全部」）。
> - 中间子查询收集的是「20180002 选了、但当前学生**没选**」的**缺课**。
> - 外层 `NOT EXISTS` 为真 ⇔ 缺课为空 ⇔ 当前学生一门不缺。
> - `SCX`、`SCY` 两个别名**必须不同**：一个引用中间子查询的 SC，一个引用最内层的 SC。
> - `EXISTS` 只关心「有没有行」，`SELECT *` 与 `SELECT 1` 完全等价。

## 考察内容

- **相关子查询**：内层查询引用外层查询的列（本题跨越两层，`Student.Sno` 出现在最内层）。
- **`NOT EXISTS` 与全称量词**：SQL 没有 `∀`，用「不存在反例」表达「全部」。
- **自连接与别名**：同一张 `SC` 表被引用两次，必须用不同别名区分作用域。
- **除法运算**：关系代数 `R ÷ S` 在 SQL 中的标准实现方式。
- **量子作用域**：别名生效范围、内层能否看到外层列。
- **`SELECT *` 在 `EXISTS` 中的含义**：只判断行是否存在，不关心投影列。

## 一、题目与来源

图中是「关系代数除法」的教学示例，用 SQL 的**双重 `NOT EXISTS`** 实现：

```sql
SELECT Sno
FROM Student
WHERE NOT EXISTS
    (SELECT *
     FROM SC SCX
     WHERE SCX.Sno = '20180002' AND
        NOT EXISTS
        (SELECT *
         FROM SC SCY
         WHERE SCY.Sno = Student.Sno AND
               SCY.Cno = SCX.Cno));
```

PPT 右侧的批注点明了三个要点：

1. **这是一个相关子查询**：内层用到了外层（乃至最外层）的列。
2. **父查询和子查询均引用了 SC 表**：`SCX` 与最内层的 `SC` 是同一张表被用了两次。
3. **用别名 `SCX`、`SCY` 将父查询与子查询中的 SC 表区分开**，否则内层无法正确引用外层那一份。

黑板上的板书则给出了执行直觉：`for S`（遍历学生）、`for SCX`（遍历 20180002 的选课），以及 `S`、`SCX` 两张小表的示意数据。

## 二、这段 SQL 到底在查什么（结论先行）

**查询「选修了 20180002 号同学所选全部课程」的学生学号**（允许选得更多，即「至少包含」）。

用集合语言写：

$$
\text{结果} = \{\, s \in Student \mid \text{courses}(s) \supseteq \text{courses}(20180002) \,\}
$$

其中 `courses(20180002)` 不是固定的「所有课程表」，而是**由 SC 表中 20180002 的记录动态决定的课程集合**。这正是它和「选修了全部课程」那道经典题的差别（见第九节）。

## 三、从内到外逐层拆解

从最里往外读，共三层：

```sql
-- 第 3 层（最内）：判断「当前学生 s 有没有选 SCX.Cno 这门课」
SELECT *
FROM SC SCY
WHERE SCY.Sno = Student.Sno     -- 来自最外层 Student
  AND SCY.Cno = SCX.Cno         -- 来自中间层 SCX

-- 第 2 层（中间）：收集 20180002 选了、但 s 没选的「缺课」
SELECT *
FROM SC SCX
WHERE SCX.Sno = '20180002'      -- 固定常量
  AND NOT EXISTS (第 3 层)       -- 该课 s 没选 → 保留这行

-- 第 1 层（最外）：s 若没有任何缺课，就入选
SELECT Sno
FROM Student
WHERE NOT EXISTS (第 2 层)       -- 缺课集合为空 → 全部修完
```

| 层级 | 表 / 别名 | 作用 | 关键条件 |
| --- | --- | --- | --- |
| 第 1 层 | `Student` | 遍历每个学生 | `NOT EXISTS` 第 2 层 |
| 第 2 层 | `SC SCX` | 取 20180002 的选课 | `SCX.Sno = '20180002'` |
| 第 3 层 | `SC SCY` | 判断 s 是否选了同一门 | `SCY.Sno = Student.Sno AND SCY.Cno = SCX.Cno` |

## 四、为什么两个 `NOT EXISTS` 就表示「全部」

关系代数里没有直接的除法运算符，SQL 也没有 `∀`。通用技巧是**把「全部」翻译成「不存在反例」**：

$$
\forall x\,(P(x) \to Q(x)) \;\equiv\; \neg\exists x\,(P(x) \land \neg Q(x))
$$

代入本题：

- \(P(x)\)：课程 \(x\) 被 **20180002** 选修；
- \(Q(x)\)：课程 \(x\) 被**当前学生 s** 选修；
- \(P(x) \land \neg Q(x)\)：20180002 选了、但 s 没选的课；
- 外层 `NOT EXISTS`：**不存在**这样的课 → s 把 20180002 的课**全选了**。

两个 `NOT EXISTS` 正好对应式子的两层否定：

```
NOT EXISTS  ← 最外层的 ¬∃
  SELECT … FROM SC SCX            ← 枚举 P(x) 的全部 x
  WHERE P(x)
    AND NOT EXISTS                ← 内层的 ¬ 加上对 Q(x) 的否
      SELECT … WHERE Q(x)
```

所以记忆点不是「两个 NOT EXISTS」，而是**「不存在一门『他选了我没选』的课」**。

## 五、黑板上的理解：两层 for 循环

把 SQL 想成嵌套循环，和黑板上的 `for S` / `for SCX` 对应：

```
for s in Student:                    # 第 1 层
    missing = ∅
    for c in SC where Sno = '20180002':   # 第 2 层：枚举 20180002 的课
        if (s, c) not in SC:              # 第 3 层
            missing.add(c)
    if missing == ∅:                  # 外层 NOT EXISTS
        output s
```

- 只要发现一门缺课，`missing` 非空，该学生就被淘汰；
- 全都不缺，`missing` 为空，当前学生入选。

这也解释了 `NOT EXISTS` 为什么比 `COUNT` 写法更直观：它**一旦找到反例就停止**，不需要数完。

## 六、别名 `SCX` / `SCY` 为什么必须加

`SC` 这张表在同一查询里被引用了**两次**：

- 中间层：`FROM SC SCX` —— 代表「20180002 的选课记录」；
- 最内层：`FROM SC SCY` —— 代表「当前学生的选课记录」。

如果不加别名，SQL 的作用域规则会让最内层的 `SC.Cno` 指向**它自己那一层**的 SC，而不是中间层；结果 `SCX.Cno = SCY.Cno` 变成自己等于自己，条件恒成立或恒不成立，**整个查询语义就错了**。

> [!tip] 作用域规则
> 内层查询可以「看到」外层查询的表和列，但**同名表必须靠别名区分**；一旦起了别名，就只能通过别名引用。

### 7.2 逐层执行结果

中间子查询对每个学生枚举 `SCX` 的三门课，只保留「该学生**没选**」的课：

| 当前学生 s | SCX 枚举的课 | 内层 `NOT EXISTS` 命中（s 缺的课） | 中间子查询结果 | 外层 `NOT EXISTS` | 是否入选 |
| --- | --- | --- | --- | --- | --- |
| 20180001 | 1, 2, 3 | {3} | 非空（1 行） | false | ❌ 淘汰 |
| 20180002 | 1, 2, 3 | ∅ | 空 | true | ✅ 入选 |
| 20180003 | 1, 2, 3 | ∅ | 空 | true | ✅ 入选 |
| 20180004 | 1, 2, 3 | {2} | 非空（1 行） | false | ❌ 淘汰 |

### 7.3 手动模拟一例：`s = 20180001`

外层对 `s = 20180001` 求值，中间层枚举 20180002 的三条选课记录：

| SCX 行 | 内层 `SCY.Sno=20180001 AND SCY.Cno=SCX.Cno` | `NOT EXISTS` | 该行是否被中间层保留 |
| --- | --- | --- | --- |
| (20180002, 1) | 存在 `(20180001, 1)` | false | 否 |
| (20180002, 2) | 存在 `(20180001, 2)` | false | 否 |
| (20180002, 3) | **不存在** | **true** | **是** |

→ 中间子查询返回 1 行 `(20180002, 3)`，说明「20180001 缺了 3 号课」。
→ 外层 `NOT EXISTS` 对该非空结果求值 = **false** → 20180001 被淘汰。

### 7.4 手动模拟一例：`s = 20180003`

| SCX 行 | 内层 `SCY.Sno=20180003 AND SCY.Cno=SCX.Cno` | `NOT EXISTS` | 该行是否被中间层保留 |
| --- | --- | --- | --- |
| (20180002, 1) | 存在 `(20180003, 1)` | false | 否 |
| (20180002, 2) | 存在 `(20180003, 2)` | false | 否 |
| (20180002, 3) | 存在 `(20180003, 3)` | false | 否 |

→ 中间子查询**返回空**（缺课为空）。
→ 外层 `NOT EXISTS` 对空结果求值 = **true** → 20180003 入选。
（他多选的 4 号课不参与比较，因为 `SCX` 只枚举 20180002 的课。）

两个值得注意的点：

1. **20180002 自己一定入选**：他选了「自己」的全部课程，缺课必为空。
2. **多选不影响**：20180003 多选了 4 号课，只要 20180002 的课一门不缺就入选——题目是「至少」，不是「恰好」。
3. **与黑板对照**：黑板上 `SCX` 正是 `20180002 → 1/2/3`，7.2~7.4 节就是把这套板书按 SQL 逐层跑一遍。

## 八、常见坑

1. **两个 `SC` 不起别名或起了同名别名**：内层引用错表，条件退化，结果全错。
2. **把中间的 `SCX.Sno = '20180002'` 写成相关条件**：这里 `'20180002'` 是**常量**，不是 `Student.Sno`；写错就变成「查自己选了自己的全部课」，人人都入选。
3. **混淆「父查询」的层级**：真正跨两层相关的是 `Student.Sno`（第 1 层 → 第 3 层）；`SCX.Cno` 是第 2 层 → 第 3 层。
4. **以为 `SELECT *` 多余**：`EXISTS` 不看投影列，`SELECT *` / `SELECT 1` / `SELECT Cno` 结果完全相同，写 `*` 是习惯，不是错误。
5. **用 `NOT IN` 替代**：语义上等价，但**子查询结果里出现 `NULL` 时会踩坑**——`x NOT IN (..., NULL)` 恒为 `UNKNOWN`，整张表查不出来。`NOT EXISTS` 是 NULL 安全的，这也是除法查询更推荐它的原因。
6. **被除集合为空**：若 20180002 一门课都没选，中间子查询对所有人都返回空集，`NOT EXISTS` 全为真，**所有学生都会入选**（空集的「全部」是真空真）。这是逻辑上的正确行为，但业务上通常需要额外判断。
7. **重复选课/重复行**：若 `SC` 允许同一 `(Sno, Cno)` 重复，`EXISTS` 不受影响（只看有没有），但用计数法实现时就要 `COUNT(DISTINCT Cno)`。

## 九、其他等价写法

### 1. 经典版：选修了「全部课程」

把被除集合换成**课程表 Course 的全部课程**，就是教材里那道最基础的除法题：

```sql
SELECT Sno
FROM Student
WHERE NOT EXISTS (
    SELECT *
    FROM Course
    WHERE NOT EXISTS (
        SELECT *
        FROM SC
        WHERE SC.Sno = Student.Sno
          AND SC.Cno = Course.Cno
    )
);
```

区别只在中间层：**课程从 `Course` 表枚举**（被除集合固定），而本例从 `SC` 表按某个学生枚举（被除集合动态）。

### 2. 计数法（HAVING）

```sql
SELECT Sno
FROM SC
WHERE Cno IN (SELECT Cno FROM SC WHERE Sno = '20180002')
GROUP BY Sno
HAVING COUNT(DISTINCT Cno) =
       (SELECT COUNT(DISTINCT Cno) FROM SC WHERE Sno = '20180002');
```

- 必须先 `WHERE Cno IN (…)` 限定在「20180002 的课程」范围内，否则多选的学生用数量凑够也会误判。
- 可读性好，但 `DISTINCT`、重复课、NULL 都要额外注意。

### 3. 除法 vs 双重否定，怎么选

| 写法 | 优点 | 缺点 |
| --- | --- | --- |
| 双重 `NOT EXISTS` | NULL 安全、语义贴合「全部」 | 嵌套深、可读性差 |
| `NOT IN` | 写法短 | 子查询含 NULL 时结果错误 |
| `HAVING COUNT` | 直观、易调试 | 要限定范围、处理重复 |

## 十、记忆口诀

> **「全部」不是数出来的，是「找不到反例」找出来的。**
> **外层「不存在」，内层「没选它」；两层 `NOT EXISTS`，一门不缺才留下。**
> **同表用两次，别名必须不一样；常量别写成相关，`NOT IN` 怕 `NULL`。**
