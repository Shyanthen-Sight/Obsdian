# 组件注册

> [!abstract] 一句话
> 组件想被当成标签写进模板，必须先"登记"：==**全局注册**是把组件登记到整个应用（`app.component()`，到处能用），**局部注册**是把组件登记到当前组件（`components` 选项，或 `<script setup>` 里 `import` 即注册）==。没登记就写标签，Vue 会警告 `Failed to resolve component`，并把它当成一个不存在的原生元素渲染。

---

## 一、为什么必须注册

模板里的 `<MyButton />` 对浏览器来说只是一个**不认识的标签**。Vue 编译模板时必须回答"这个名字对应哪个组件"，答案只能来自注册表。

```text
<template><MyButton /></template>
          │
          ▼
  Vue 名字解析器 ──「MyButton 是谁？」
          │
   ┌──────┴───────┐
   ▼              ▼
局部注册表      全局注册表
(components)  (app.component)
   └──────┬───────┘
          ▼
  找到 → 渲染组件 ／ 没找到 → 警告 + 当作原生标签
```

> [!info] 注册必须在渲染之前
> 编译后 `<MyButton />` 会变成 `resolveComponent('MyButton')` 一类的调用，**运行时才查表**。所以全局组件要在 `app.mount()` 之前注册好。

> [!warning] "定义" ≠ "注册"
> 写好 `MyButton.vue` 只是**定义**了组件；把它塞进某个注册表才叫**注册**。<br>
> `<script setup>` 是特例：`import` 进来的组件会被编译器自动登记为**当前组件**的局部组件，可以理解成"import 即注册"。

---

## 二、全局注册：`app.component()`

在入口 `main.js` 里用 `app.component(名字, 组件)` 登记：

```js
import { createApp } from 'vue'
import App from './App.vue'
import MyButton from './components/MyButton.vue'
import MyInput from './components/MyInput.vue'

const app = createApp(App)

app.component('MyButton', MyButton)   // ① 全局登记，谁都能用
app.component('MyInput', MyInput)     // ②

app.mount('#app')                     // ③ 注册要在 mount 之前
```

`app.component()` 的返回值就是 `app` 本身，所以能**链式**写：

```js
app.component('MyButton', MyButton).component('MyInput', MyInput).component('UserCard', UserCard)
```

> [!tip] 参数顺序别写反
> 是 `app.component(组件名, 组件对象)`——**名字在前**，语义同 `components: { 名字: 组件 }`。

注册之后，**任意组件**（哪怕没 import）都能直接用：

```vue
<template>
  <MyButton>保存</MyButton>
</template>
```

### 2.1 全局注册的三个代价

| 代价                  | 说明                                                            |
| ------------------- | ------------------------------------------------------------- |
| **无法 tree-shaking** | 入口顶层的 `import` + 无条件 `app.component()` 调用，打包器**无法证明它没用**，全量进包 |
| **命名冲突且静默覆盖**       | 全局名字全应用共享，两个文件都注册 `'Card'`，**后注册的悄悄顶掉先注册的**，不报错不警告            |
| **依赖不清晰**           | 依赖关系藏进 `main.js`，组件从"自包含"变成"依赖环境"，难复用、难测试                     |

> [!danger] 组件库为什么坚持"按需引入"
> 全局注册 60 个组件而只用 2 个，60 个的代码依然全进 bundle。这正是 tree-shaking 失效的直接后果——也是各类 UI 库反对全局注册的根本原因。

## 三、局部注册：只给当前组件用

### 3.1 Options API：`components` 选项

```vue
<script>
import MyButton from './MyButton.vue'

export default {
  components: { MyButton },   // 登记为局部组件：只在本组件模板里可用
  data() {
    return { count: 0 }
  }
}
</script>

<template>
  <MyButton>只在这里能用</MyButton>
</template>
```

也可以**重命名**（键是模板里用的名字，值是组件对象）：

```js
import MyLongNameButton from './MyLongNameButton.vue'
export default { components: { ShortBtn: MyLongNameButton } }  // 模板里写 <ShortBtn />
```

### 3.2 `<script setup>`：import 即注册（重点）

用 `<script setup>` 时**根本不需要 `components` 选项**——`import` 进来的组件直接就能当标签用：

```vue
<script setup>
import MyButton from './MyButton.vue'   // ← 这一行就等于完成了注册
</script>

<template>
  <MyButton>直接用</MyButton>
</template>
```

> [!success] 机制：编译器替你登记
> `<script setup>` 编译后，顶层 `import` 的组件会被自动写进产物的局部注册信息，等价于帮你生成了 `components: { MyButton }`。所以：==**有 import → 就能用；删掉 import → 立刻报 `Failed to resolve component`。**==

| 写法 | 注册方式 | 模板里怎么用 |
| --- | --- | --- |
| Options API | `components: { MyButton }` | `<MyButton />` 或 `<my-button />` |
| `<script setup>` | `import MyButton from './MyButton.vue'` | `<MyButton />` 或 `<my-button />` |
| 全局 | `app.component('MyButton', MyButton)` | 任意组件里都能写 |

> [!note] 局部注册的组件"不外溢"
> 局部注册只对**当前组件**生效。父组件注册了 `MyButton`，**子组件并不能直接用**——子组件要用就得自己 import。这是特性不是 bug：它保证每个组件的依赖都自解释。详见 [[setup语法糖]]。

## 四、组件名的大小写规则（重点）

### 4.1 一个组件名，三种写法

假设组件文件是 `MyFirstComponent.vue`：

| 写法              | 形式        | 例子                   | 用在哪               |
| --------------- | --------- | -------------------- | ----------------- |
| camelCase（小驼峰）  | 首字母小写     | `myFirstComponent`   | JS 里常用；模板中少用      |
| PascalCase（大驼峰） | 首字母大写     | `MyFirstComponent`   | ✅ **声明 / 注册的首选**  |
| kebab-case（短横线） | 全小写 + 连字符 | `my-first-component` | ✅ **DOM 模板里必须用它** |
|                 |           |                      |                   |


**根因：HTML 是大小写不敏感的。**

```text
SFC 的 <template>（.vue 文件）         HTML / DOM 内模板
    编译器直接读源码                  浏览器先把标签"转小写"
    <MyComponent /> 原样保留          <MyComponent /> → mycomponent
    三种写法都能匹配                  只剩 kebab 能匹配 ✗
```

### 4.2 什么时候必须 kebab-case

| 模板所在的"容器" | PascalCase | kebab-case | 说明 |
| --- | --- | --- | --- |
| `.vue` 文件的 `<template>`（SFC） | ✅ | ✅ | 都由 Vue 编译器处理，两种都认 |
| `index.html` 里的内联模板 | ❌ | ✅ | DOM 会把 `<MyComponent>` 转成 `mycomponent` |
| 字符串模板 `template: '...'` | ✅ | ✅ | 不经过 HTML 解析器 |
| 动态组件 `:is="字符串"` | ✅ | ✅ | 按注册名匹配 |

```html
<div id="app"><MyComponent /></div>                  <!-- ❌ 浏览器转成 mycomponent，找不到 -->
<div id="app"><my-component></my-component></div>    <!-- ✅ kebab-case，且不能自闭合 -->
```

> [!warning] DOM 模板的两个额外坑
> 1. **不能自闭合**：`<my-component />` 在 HTML 里不合法，必须写 `<my-component></my-component>`（只有 Vue 编译的 SFC 模板才允许自闭合）。
> 2. **大小写被吞**：`<MyComponent>` 与 `<mycomponent>` 在浏览器眼里**完全相同**，都和 `my-component` 对不上。

> [!tip] 一条万能规则
> **注册 / 声明组件统一用 PascalCase；在 DOM 模板里统一写 kebab-case。** 在 SFC 里其实怎么写都行，但坚持这条规则，能让"把模板复制到 `index.html` 调试"这类场景不出意外。

## 五、命名建议

### 5.1 用多单词，避免单词名

```js
app.component('UserCard', UserCard)   // ✅ 多单词，语义清晰、几乎不冲突
app.component('Card', Card)           // ❌ 单词名，太泛、易撞车
```

HTML 现有和未来的原生标签都是**单词**形式，单词名组件极易与它们（或第三方组件）冲突。多单词名几乎能规避整类问题。

### 5.2 避免与原生元素重名

| 危险名字 | 为什么危险 |
| --- | --- |
| `Header` / `Footer` / `Main` / `Aside` | HTML5 语义化标签已有同名元素 |
| `Select` / `Option` / `Table` / `Button` | 表单元素，全局注册后 `<Select>` 产生歧义 |
| `Progress` / `Text` / `Image` / `Menu` | SVG 小写标签 `progress` / `text` 等已存在 |

> [!note] 大小写救不了你
> 在 SFC 里 `<Button>` 大写会被优先当作组件解析，看似没事；但这段模板一旦出现在 DOM 模板里，`<Button>` 被转小写就撞上原生 `<button>`，行为立刻不可预测。==别赌，直接叫 `BaseButton` / `UserSelect`。==

> [!warning] 还有一批保留名
> `component`、`slot`、`template`、`transition`、`keep-alive`、`teleport` 等是 Vue 的**内置组件 / 关键字**，注册同名组件会被内置实现抢占。

## 六、递归组件

组件可以在**自己的模板里引用自己**，这就是递归组件，常用于树形结构（目录树、楼中楼评论、多级菜单）。

### 6.1 `<script setup>` 写法：文件名即名字

```vue
<!-- TreeItem.vue -->
<script setup>
defineProps({ node: Object })
</script>

<template>
  <li>
    {{ node.label }}
    <ul v-if="node.children">
      <!-- 用"自己的文件名"递归引用自己 -->
      <TreeItem v-for="child in node.children" :key="child.id" :node="child" />
    </ul>
  </li>
</template>
```

> [!info] 为什么不用 import 自己？
> 一个 SFC 可以用**它自己的文件名**隐式引用自身，Vue 编译器据此推断出组件名（相当于内置了 `name: 'TreeItem'`）。所以直接写 `<TreeItem />` 即可，无需 `import TreeItem from './TreeItem.vue'`。

### 6.2 递归必须能"停下来"

```text
node ─┬─ node
      ├─ node
      │   └─ node (children 为空) ← v-if 为假，递归到此结束
      └─ node
```

> [!warning] 少了终止条件就是无限递归 → 爆栈
> 终止条件通常靠 `v-if` 或数据的边界（如上例的 `v-if="node.children"`）。

### 6.3 用显式 `name` 的写法

Options API 靠 `name` 选项，模板写法完全一样：

```vue
<script>
export default { name: 'TreeItem', props: { node: Object } }
</script>
```

> [!warning] 递归"名字对不上"是最常见的坑
> 递归依赖**组件名**。若注册名 / `name` 选项 / 文件名三者不一致，模板里的 `<TreeItem />` 就解析不到自己，控制台报 `Failed to resolve component: TreeItem`。<br>
> `<script setup>` 里改名（`defineOptions({ name: 'X' })`）后，**模板标签也要一起改成 `X`**。

## 七、命名空间组件

一堆同"家族"的组件（如整套表单控件），可以用 `import * as` 收进一个命名空间，模板里用**点号访问**：

```vue
<script setup>
import * as Form from './form'   // form 模块导出了 Input、Select、Label…
</script>

<template>
  <Form.Input />
  <Form.Select />
  <Form.Label>姓名</Form.Label>
</template>
```

```js
// form/index.js —— 统一出口（Label 等其余控件同理）
export { default as Input } from './Input.vue'
export { default as Select } from './Select.vue'
export { default as Label } from './Label.vue'
```

> [!warning] 点号语法只在 SFC 模板里能用
> `<Form.Input>` **不是合法的 HTML 标签名**，只在 `.vue` 的 `<template>`（或字符串模板）里有效，放进 `index.html` 的 DOM 模板一定失败。

> [!tip] 好处
> 一眼看出"这几个组件是一家的"，同时避免 `FormInput` / `FormSelect` 这类长前缀污染全局命名空间。

## 八、全局注册 vs 局部注册：怎么选

| 对比项 | 全局注册 | 局部注册 |
| --- | --- | --- |
| 注册位置 | `main.js` 的 `app.component()` | 组件内 `components` / `import` |
| 作用范围 | 整个应用 | 仅当前组件 |
| 使用处要不要 import | **不用** | **要** |
| 能否 tree-shaking | ❌ 不能，全量进包 | ✅ 能，没用到的会被摇掉 |
| 命名冲突风险 | 高（全应用共享命名空间） | 低（只在本组件内解析） |
| 依赖是否清晰 | ❌ 藏在入口文件 | ✅ 一眼可见 |
| 解析优先级 | 低 | **高**（同名时局部胜出） |
| 适合场景 | 组件库、极高频基础组件 | **绝大多数业务组件** |

> [!success] 结论：默认局部，全局慎用
> **业务组件一律局部注册**（`<script setup>` 里 import 一下的事），这是环保又安全的默认选择。只有"几乎所有页面都在用、且体量很小"的基础组件（图标、按钮、基础布局）才考虑全局。

### 8.1 大型应用：用插件集中注册

全局组件多到 `main.js` 塞不下时，别一行行堆 `app.component()`，写一个**插件**统一处理：

```js
// plugins/global-components.js
import MyButton from '@/components/base/MyButton.vue'
import MyIcon   from '@/components/base/MyIcon.vue'

export default {
  install(app) {
    app.component('MyButton', MyButton).component('MyIcon', MyIcon)
  }
}
```

```js
// main.js
import GlobalComponents from '@/plugins/global-components'
app.use(GlobalComponents)   // 一行装完，避免 main.js 里堆一长串 app.component()
```

> [!note] 自动批量注册的诱惑
> Vite 的 `import.meta.glob` 能扫目录一键注册全部组件，很爽，但它**同样会摧毁 tree-shaking**。基础组件不多时，显式列出反而更可控。

## 九、常见问题

> [!question] 组件写好了、也注册了，为什么还是渲染不出来（`Failed to resolve component`）？
> 按这个顺序查：
> 1. **大小写**：DOM 模板里是不是写了 `<MyComponent>`？改成 `<my-component>`。
> 2. **注册名对不上**：`import MyButton` 却写 `<MyBtn />`——`<script setup>` 里标签名必须和 import 的变量名（或其 kebab 形式）一致。
> 3. **`components` 选项漏了**：Options API 里写了 `import` 却忘了 `components: { MyButton }`。
> 4. **路径错 / 导入到 `undefined`**：注册了也白搭。

> [!question] 注册了同名组件，会怎样？
> **不报错，后者静默覆盖前者。** 全局 vs 全局：先注册的被顶掉；全局 vs 局部：==局部优先==（解析顺序是 `components` 选项 → 全局注册表）。

> [!question] 为什么组件库文档都让我"按需引入"而不是全局注册？
> 因为全局注册**让 tree-shaking 失效**。`app.component('Xxx', Xxx)` 一旦写进入口，打包器就删不掉那个 import，即使一个都没用，全量代码也会进 bundle。按需（局部）引入才能"用几个打几个"。

> [!question] `<script setup>` 里还要写 `components: {}` 吗？
> **不要，也没有这个选项。** `import` 进来就已经完成局部注册；再手写一遍只会产生未使用变量的 lint 告警。要声明 `name` / `inheritAttrs` 等选项，用 `defineOptions()`。详见 [[setup语法糖]]。

> [!question] 递归组件报 "Failed to resolve component: TreeItem"？
> 递归靠**组件名**解析。检查：文件是否叫 `TreeItem.vue`（`<script setup>` 靠文件名推断名字）；若用了 `defineOptions({ name: 'X' })` 或 Options API 的 `name`，模板里的标签必须换成那个名字。三者不一致就解析不到自己。

> [!question] 组件名能不能叫 `Card` / `Button` 这种单词？
> 技术上可以，但**强烈不建议**：容易和原生标签（`button`、`select`、`header`…）及第三方组件冲突。多单词命名（`UserCard`、`BaseButton`）几乎零成本地规避了整类问题。

> [!question] DOM 模板里为什么"注册了却像原生元素"？必须 kebab-case？
> 是的。DOM 内模板中浏览器先把标签名转小写（`MyComponent` → `mycomponent`）再交给 Vue，自然找不到 `MyComponent`。所以 DOM 模板**只能用 kebab-case**：`<my-component></my-component>`。
