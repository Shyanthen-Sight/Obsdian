# 其他仓库

Docker Hub 之外的选择基本跟着云环境走。CLI 用法没有变化，变的是地址格式和登录方式。

| 仓库 | 地址格式 | 认证方式 |
| --- | --- | --- |
| GHCR | `ghcr.io/<owner>/<image>` | GitHub PAT，需要 `read:packages` 或 `write:packages` |
| ECR | `<acct>.dkr.ecr.<region>.amazonaws.com/<image>` | `aws ecr get-login-password` |
| Artifact Registry | `<region>-docker.pkg.dev/<project>/<repo>/<image>` | `gcloud auth configure-docker` |
| ACR | `<name>.azurecr.io/<image>` | `az acr login` |
| Harbor | `harbor.example.com/<project>/<image>` | `docker login`，按项目授权 |

## 登录与推送

GHCR 最省事，token 直接当密码用：

```bash
echo "$GH_TOKEN" | docker login ghcr.io -u "$GITHUB_ACTOR" --password-stdin
docker tag my-app:1.0 ghcr.io/acme/my-app:1.0
docker push ghcr.io/acme/my-app:1.0
```

ECR 的 token 只有 12 小时有效期，CI 里每次构建前都要重新取，不能写死到配置里：

```bash
aws ecr get-login-password --region ap-east-1 \
  | docker login --username AWS --password-stdin 123456789012.dkr.ecr.ap-east-1.amazonaws.com
```

`--password-stdin` 比 `-p` 好，密码不会留在 shell history 和进程列表里。`gcloud auth configure-docker` 和 `az acr login` 本质上都是往 `~/.docker/config.json` 写一个 credential helper，之后 docker 命令会自动调用它取凭证。

Harbor 是自建方案里最常见的一个，项目隔离、RBAC、镜像复制、漏洞扫描都有。跨云或多集群的场景常拿它当统一入口，各云仓库只做上游。选哪个通常取决于云环境和现有权限体系，不是技术优劣。

> [!warning] 地址要写全
> `docker push my-app:1.0` 会推到 Docker Hub。推云仓库必须带完整 registry 前缀，而且 GHCR 要求 owner 和镜像名全小写，`My-App` 会被直接拒绝。

排查思路：登录成功但 push 报 `denied`，先看仓库是否存在、账号有没有写权限；报 `no basic auth credentials`，多半是 credential helper 没生效，或者登录的 registry 和推送地址不是同一个。
