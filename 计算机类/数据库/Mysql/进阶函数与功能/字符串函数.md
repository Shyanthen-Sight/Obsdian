# 字符串函数 —— 拼接、截取、查找、清洗

> [!abstract] 一句话
> 字符串函数都是"**进去一个串，出来一个串**"的表达式。真正要记住的只有四条：**位置从 1 开始**、**NULL 会传染**、**`LENGTH` 数字节而 `CHAR_LENGTH` 数字符**、**函数套在索引列上会让索引失效**。

---

> [!example] 本篇示例数据
> 下面所有例子都基于这张 `customer` 表。数据里特意埋了 **NULL、空串、大小写、前后空格、中文、`@`、`%`**，用来演示字符串函数最常见的坑。

CREATE TABLE customer (

    name     VARCHAR(50)  NOT NULL,
    nickname VARCHAR(50)  DEFAULT NULL,

## 一、先记四条总规则

### 1.1 位置从 1 开始，负数从尾部数

```sql
SELECT SUBSTRING('abcdef', 1, 3);    -- 'abc'  第 1 个字符开始
SELECT SUBSTRING('abcdef', 0, 3);    -- ''     0 不是"从头开始"，而是空串
SELECT SUBSTRING('abcdef', -2);      -- 'ef'   从倒数第 2 个字符到结尾
```

> [!warning] 不要把它当成 Java / Python 的下标
> Java 的 `substring(0, 3)` 是前 3 个字符；MySQL 的 `SUBSTRING(str, 0, 3)` 返回**空串**。
> 在 MySQL 里，**第一个字符的位置是 1**。

### 1.2 NULL 会传染

```sql
SELECT CONCAT('a', NULL);            -- NULL，不是 'a'
SELECT CONCAT('a', NULL, 'b');       -- NULL
SELECT REPLACE(NULL, 'a', 'b');      -- NULL
SELECT UPPER(NULL);                  -- NULL
```

> [!danger] `CONCAT` 里混进一个 NULL，整个结果就是 NULL
> 这跟 Java 的字符串拼接（`"a" + null` 得到 `"anull"`）完全不同。
> 要做"可空字段拼接"，必须先 `IFNULL(col, '')` 或 `COALESCE(col, '')`：

```sql
-- ❌ 李四的 nickname 是 NULL，整行拼接结果为 NULL
SELECT CONCAT(name, '-', nickname) FROM customer;

-- ✅ 先把 NULL 变成空串
SELECT CONCAT(name, '-', IFNULL(nickname, '')) FROM customer;

-- ✅ 或者用 CONCAT_WS，它会自动跳过 NULL
SELECT CONCAT_WS('-', name, nickname) FROM customer;
```

### 1.3 字符数 ≠ 字节数

| 函数 | 单位 | `'张三'` | `'abc'` | `'😀'` |
| --- | --- | --- | --- | --- |
| `CHAR_LENGTH(str)` | **字符** | 2 | 3 | 1 |
| `LENGTH(str)` | **字节** | 6 | 3 | 4 |
| `BIT_LENGTH(str)` | 位 | 48 | 24 | 32 |

```sql
SELECT name,
       CHAR_LENGTH(name) AS 字符数,
       LENGTH(name)      AS 字节数
FROM customer;
```

```
+---------+--------+--------+
| name    | 字符数 | 字节数 |
+---------+--------+--------+
| 张三    |      2 |      6 |
| 李四    |      2 |      6 |
| Wang Wu |      7 |      7 |
| 赵六    |      2 |      6 |
+---------+--------+--------+
```

> [!tip] 该用哪个？
> - 校验"用户名最多 20 个字"→ `CHAR_LENGTH`
> - 估算存储 / 网络字节数 → `LENGTH`
> - `VARCHAR(n)` 里的 `n` 是**字符数**，不是字节数
>
> `utf8mb4` 下一个汉字占 3 字节，一个 emoji 占 4 字节。用 `LENGTH` 做长度校验，中文用户会被莫名其妙地卡住。

### 1.4 大小写与比较取决于排序规则

```sql
SELECT 'ABC' = 'abc';                         -- 1（默认 _ci 排序规则，不区分大小写）
SELECT BINARY 'ABC' = 'abc';                  -- 0（按字节比较，区分大小写）
SELECT 'ABC' COLLATE utf8mb4_bin = 'abc';     -- 0
```

> [!note] `_ci` / `_cs` / `_bin`
> - `_ci` = case-insensitive，不区分大小写（MySQL 默认）
> - `_cs` = case-sensitive，区分大小写
> - `_bin` = 按二进制字节比较
>
> 所以 `WHERE name = 'wang wu'` 能查到 `'Wang Wu'`——不是 SQL 写错了，是排序规则在起作用。
> 要精确匹配，用 `BINARY name = 'Wang Wu'` 或 `COLLATE utf8mb4_bin`。

## 二、拼接：`CONCAT` / `CONCAT_WS`

### 2.1 `CONCAT`

```sql
CONCAT(str1, str2, ...)
```

```sql
SELECT CONCAT('Hello', ' ', 'World');          -- 'Hello World'
SELECT CONCAT(name, ' <', email, '>') FROM customer;
```

```
+--------------------------------------+
| CONCAT(name, ' <', email, '>')       |
+--------------------------------------+
| 张三 <zhangsan@example.com>          |
| 李四 <lisi@EXAMPLE.com>              |
| Wang Wu <wangwu@example.com>         |
| 赵六 <zhaoliu@example.com>           |
+--------------------------------------+
```

> [!warning] 数字会被自动转成字符串
> `CONCAT(1, 2)` 得到 `'12'`，不是 `3`。想算术相加请用 `+`，别用 `CONCAT`。

> [!note] `||` 默认不是拼接
> 标准 SQL 用 `||` 拼接，但 MySQL 默认把 `||` 当**逻辑或**。
> 除非开启 `PIPES_AS_CONCAT` SQL 模式，否则不要写 `'a' || 'b'`。

### 2.2 `CONCAT_WS`（带分隔符，自动跳过 NULL）

```sql
CONCAT_WS(separator, str1, str2, ...)
```

```sql
SELECT CONCAT_WS('-', name, nickname, email) AS 拼接结果
FROM customer;
```

```
+----------------------------------+
| 拼接结果                         |
+----------------------------------+
| 张三-小三-zhangsan@example.com   |
| 李四-lisi@EXAMPLE.com            |
| Wang Wu-阿五-wangwu@example.com  |
| 赵六--zhaoliu@example.com        |
+----------------------------------+
```

| 表达式 | 结果 | 说明 |
| --- | --- | --- |
| `CONCAT_WS(',', 'a', NULL, 'b')` | `'a,b'` | ==**跳过 NULL**== |
| `CONCAT_WS(',', 'a', '', 'b')` | `'a,,b'` | 空串**不**跳过 |
| `CONCAT_WS(NULL, 'a', 'b')` | `NULL` | 分隔符为 NULL 时整体为 NULL |

> [!danger] `CONCAT_WS` 跳过的是 NULL，不是空串
> 赵六的 `nickname` 是空串 `''`，所以出现了 `赵六--zhaoliu@...` 两个连续分隔符。
> 如果业务上"空串"也算没填，先 `NULLIF(nickname, '')` 再交给 `CONCAT_WS`：
> ```sql
> SELECT CONCAT_WS('-', name, NULLIF(nickname, ''), email) FROM customer;
> ```

## 三、长度、大小写与字符集

### 3.1 长度相关

| 函数 | 作用 | 示例 | 结果 |
| --- | --- | --- | --- |
| `CHAR_LENGTH(str)` | 字符数 | `CHAR_LENGTH('张三')` | `2` |
| `LENGTH(str)` | 字节数 | `LENGTH('张三')` | `6` |
| `BIT_LENGTH(str)` | 位数 | `BIT_LENGTH('abc')` | `24` |
| `CHARSET(str)` | 字符集 | `CHARSET('张三')` | `utf8mb4` |
| `COLLATION(str)` | 排序规则 | `COLLATION('张三')` | `utf8mb4_0900_ai_ci` |

```sql
SELECT CHARSET(name), COLLATION(name) FROM customer LIMIT 1;
```

> [!note] `CHAR_LENGTH` 的别名
> `CHARACTER_LENGTH(str)` 与 `CHAR_LENGTH(str)` 完全等价。

### 3.2 大小写

```sql
SELECT UPPER('abc');       -- 'ABC'
SELECT LOWER('ABC');       -- 'abc'
SELECT UCASE('abc');       -- 'ABC'，UPPER 的别名
SELECT LCASE('ABC');       -- 'abc'，LOWER 的别名
```

```sql
SELECT email, UPPER(email) AS 大写, LOWER(email) AS 小写
FROM customer;
```

```
+----------------------+----------------------+----------------------+
| email                | 大写                 | 小写                 |
+----------------------+----------------------+----------------------+
| zhangsan@example.com | ZHANGSAN@EXAMPLE.COM | zhangsan@example.com |
| lisi@EXAMPLE.com     | LISI@EXAMPLE.COM     | lisi@example.com     |
| wangwu@example.com   | WANGWU@EXAMPLE.COM   | wangwu@example.com   |
| zhaoliu@example.com  | ZHAOLIU@EXAMPLE.COM  | zhaoliu@example.com  |
+----------------------+----------------------+----------------------+
```

> [!tip] 统一大小写是数据清洗的第一步
> 导入外部数据后，常先 `UPDATE customer SET email = LOWER(email);`，再建唯一索引——否则 `A@x.com` 和 `a@x.com` 会被当成两条。

## 四、截取：`LEFT` / `RIGHT` / `SUBSTRING` / `SUBSTRING_INDEX`

### 4.1 左右截取

```sql
SELECT LEFT('abcdef', 3);      -- 'abc'
SELECT RIGHT('abcdef', 3);     -- 'def'
SELECT LEFT(phone, 3)  AS 号段,
       RIGHT(phone, 4) AS 尾号
FROM customer;
```

```
+--------+--------+
| 号段   | 尾号   |
+--------+--------+
| 138    | 5678   |
| 139    | 1111   |
| 159    | 2222   |
| 138    | 5432   |
+--------+--------+
```

> [!warning] `LEFT` / `RIGHT` 的第二个参数是**字符数**
> `LEFT('张三丰', 2)` 得到 `'张三'`，不会把汉字劈成半个字节。

### 4.2 `SUBSTRING`（别名 `SUBSTR` / `MID`）

```sql
SUBSTRING(str, pos)            -- 从 pos 到结尾
SUBSTRING(str, pos, len)       -- 从 pos 开始取 len 个字符
SUBSTRING(str FROM pos FOR len)
```

```sql
SELECT SUBSTRING('abcdef', 2, 3);       -- 'bcd'
SELECT SUBSTRING('abcdef', 2);          -- 'bcdef'
SELECT SUBSTRING('abcdef', -2);         -- 'ef'
SELECT SUBSTRING('abcdef', 0);          -- ''
SELECT SUBSTRING('abcdef', 2, 0);       -- ''
```

抽取邮箱的"@ 前面"和"@ 后面"：

```sql
SELECT email,
       SUBSTRING(email, 1, LOCATE('@', email) - 1) AS 用户名,
       SUBSTRING(email, LOCATE('@', email) + 1)     AS 域名
FROM customer;
```

```
+----------------------+----------+-------------+
| email                | 用户名   | 域名        |
+----------------------+----------+-------------+
| zhangsan@example.com | zhangsan | example.com |
| lisi@EXAMPLE.com     | lisi     | EXAMPLE.com |
| wangwu@example.com   | wangwu   | example.com |
| zhaoliu@example.com  | zhaoliu  | example.com |
+----------------------+----------+-------------+
```

### 4.3 `SUBSTRING_INDEX`（按分隔符切）

```sql
SUBSTRING_INDEX(str, delim, count)
```

| `count` | 含义 | `SUBSTRING_INDEX('a-b-c-d', '-', count)` |
| --- | --- | --- |
| 正数 `n` | 取**从左往右**第 `n` 个分隔符**之前**的内容 | `2` → `'a-b'` |
| 负数 `-n` | 取**从右往左**第 `n` 个分隔符**之后**的内容 | `-2` → `'c-d'` |
| `0` | 空串 | `0` → `''` |
| 分隔符不存在 | 返回原串 | `'a-b-c-d'` |

```sql
SELECT SUBSTRING_INDEX(email, '@', 1)  AS 用户名,
       SUBSTRING_INDEX(email, '@', -1) AS 域名
FROM customer;
```

> [!tip] 取"最后一段"最省事的写法
> `SUBSTRING_INDEX(path, '/', -1)` 直接拿路径最后一段，比 `SUBSTRING` + `LENGTH` 拼半天干净得多。
> 注意：它**按字面量分隔符**切，不支持正则；要按正则切用 `REGEXP_SUBSTR`。

## 五、查找与定位

### 5.1 `LOCATE` / `INSTR` / `POSITION`

| 写法 | 参数顺序 | 示例 | 结果 |
| --- | --- | --- | --- |
| `LOCATE(substr, str)` | 子串在前 | `LOCATE('@', 'a@b.com')` | `2` |
| `LOCATE(substr, str, pos)` | 从 `pos` 开始找 | `LOCATE('a', 'abcabc', 2)` | `4` |
| `INSTR(str, substr)` | **字符串在前** | `INSTR('a@b.com', '@')` | `2` |
| `POSITION(substr IN str)` | 标准 SQL 写法 | `POSITION('@' IN 'a@b.com')` | `2` |

```sql
SELECT email,
       LOCATE('@', email) AS at位置,
       INSTR(email, '.')  AS 点位置
FROM customer;
```

```
+----------------------+--------+--------+
| email                | at位置 | 点位置 |
+----------------------+--------+--------+
| zhangsan@example.com |      9 |     17 |
| lisi@EXAMPLE.com     |      5 |     13 |
| wangwu@example.com   |      7 |     15 |
| zhaoliu@example.com  |      8 |     16 |
+----------------------+--------+--------+
```

> [!warning] 找不到返回 `0`，不是 `NULL`
> `LOCATE('z', 'abc')` 返回 `0`。所以判断"包不包含"可以写 `LOCATE(...) > 0`，但别写 `IS NULL`。
> 参数里有 NULL 时，返回值才是 NULL。

### 5.2 `FIND_IN_SET`（在逗号列表里找）

```sql
FIND_IN_SET(str, strlist)
```

```sql
SELECT FIND_IN_SET('b', 'a,b,c');       -- 2
SELECT FIND_IN_SET('d', 'a,b,c');       -- 0
SELECT FIND_IN_SET('b', 'a, b, c');     -- 0  ← 空格是值的一部分！
SELECT FIND_IN_SET(NULL, 'a,b,c');      -- NULL
```

> [!danger] 它只认"逗号 + 无空格"的列表
> `'a, b, c'` 里的第二项是 `' b'`（前面带空格），不是 `'b'`。
> 这种"把多个值塞进一个字段"的建模本身就违反第一范式，能拆表就拆表；临时用一下可以，别当长期方案。

### 5.3 `STRCMP`（按排序规则比较）

```sql
SELECT STRCMP('a', 'b');      -- -1  （前者小于后者）
SELECT STRCMP('a', 'a');      --  0
SELECT STRCMP('b', 'a');      --  1
SELECT STRCMP(NULL, 'a');     -- NULL
```

> [!note] 返回值只有 `-1 / 0 / 1`
> 它不告诉你差多少，只告诉你大小关系。按默认 `_ci` 排序规则，`STRCMP('A', 'a')` 返回 `0`。

## 六、替换、填充与清理

### 6.1 `REPLACE`

```sql
REPLACE(str, from_str, to_str)
```

```sql
SELECT REPLACE('Hello', 'l', 'L');             -- 'HeLLo'
SELECT REPLACE('Hello', 'hello', 'x');         -- 'Hello'（大小写敏感，没匹配上）
SELECT REPLACE(NULL, 'a', 'b');                -- NULL
```

> [!warning] `REPLACE` 是**区分大小写**的字面量替换
> 想忽略大小写，先统一大小写：`REPLACE(LOWER(str), 'hello', 'x')`。
> 它也不是正则替换；按模式替换用 `REGEXP_REPLACE`。

手机号打码（保留前 3 后 4）：

```sql
SELECT phone,
       REPLACE(phone, SUBSTRING(phone, 4, 4), '****') AS 打码后
FROM customer;
```

```
+-------------+-------------+
| phone       | 打码后      |
+-------------+-------------+
| 13812345678 | 138****5678 |
| 13900001111 | 139****1111 |
| 15900002222 | 159****2222 |
| 13898765432 | 138****5432 |
+-------------+-------------+
```

### 6.2 `INSERT`（按位置替换一段）

```sql
INSERT(str, pos, len, newstr)
```

```sql
SELECT INSERT('Quadratic', 3, 4, 'What');     -- 'QuWhattic'
SELECT INSERT('Quadratic', -1, 4, 'What');    -- 'Quadratic'（负位置不处理）
SELECT INSERT('Quadratic', 3, 100, 'What');   -- 'QuWhat'（超出部分按到结尾）
```

> [!warning] `INSERT` 会**删掉** `len` 个字符再插入
> 它不是在原位置"插入"，而是"**替换**"。只想插入不删除，`len` 写 `0`：`INSERT('abc', 2, 0, 'X')` → `'aXbc'`。

### 6.3 `TRIM` / `LTRIM` / `RTRIM`

```sql
TRIM([{BOTH | LEADING | TRAILING} [remstr] FROM] str)
LTRIM(str)
RTRIM(str)
```

```sql
SELECT TRIM('  bar  ');                                  -- 'bar'
SELECT LTRIM('  bar  ');                                 -- 'bar  '
SELECT RTRIM('  bar  ');                                 -- '  bar'
SELECT TRIM(LEADING 'x' FROM 'xxxbarxxx');               -- 'barxxx'
SELECT TRIM(TRAILING 'x' FROM 'xxxbarxxx');              -- 'xxxbar'
SELECT TRIM(BOTH 'x' FROM 'xxxbarxxx');                  -- 'bar'
```

```sql
SELECT id, remark, TRIM(remark) AS 清理后
FROM customer;
```

```
+----+-------------+-------------+
| id | remark      | 清理后      |
+----+-------------+-------------+
|  1 |   VIP客户   | VIP客户     |
|  2 | NULL        | NULL        |
|  3 | 需发票50%   | 需发票50%   |
|  4 | 上门安装    | 上门安装    |
+----+-------------+-------------+
```

> [!danger] 默认只去掉**空格**
> `TRIM` 不带 `remstr` 时只删普通空格，**不删 `\t`、`\n`、全角空格**。
> 要清这些，得显式指定：`TRIM(BOTH '\t' FROM str)`，或先 `REPLACE`。

> [!note] `remstr` 是"字符集合"不是"子串"
> `TRIM(BOTH 'xy' FROM 'xyxbarxyx')` 会从两端反复删掉 `x` 或 `y`，直到遇到别的字符。
> 它不像 `REPLACE` 那样按完整子串匹配。

### 6.4 `LPAD` / `RPAD`（补到指定长度）

```sql
LPAD(str, len, padstr)    -- 左侧补
RPAD(str, len, padstr)    -- 右侧补
```

```sql
SELECT LPAD('5', 3, '0');             -- '005'
SELECT LPAD('abc', 6, 'xy');          -- 'xyxabc'
SELECT RPAD('abc', 6, 'xy');          -- 'abcxyx'
SELECT LPAD('abcdef', 3, 'x');        -- 'abc'  ← 超长会被截断
SELECT RPAD('abcdef', 3, 'x');        -- 'abc'
```

```sql
SELECT id,
       LPAD(id, 5, '0')   AS 订单号,
       RPAD(name, 6, '*') AS 定宽姓名
FROM customer;
```

```
+----+--------+------------+
| id | 订单号 | 定宽姓名   |
+----+--------+------------+
|  1 | 00001  | 张三****   |
|  2 | 00002  | 李四****   |
|  3 | 00003  | Wang W     |
|  4 | 00004  | 赵六****   |
+----+--------+------------+
```

> [!warning] 超长时 `LPAD` / `RPAD` 是**截断**，不是补
> `'Wang Wu'` 有 7 个字符，`RPAD(name, 6, '*')` 取前 6 个字符 `'Wang W'`——空格也算一个字符。
> 如果业务上"超长要报错"，别指望它，自己在应用层校验。

### 6.5 重复、空格与反转

```sql
SELECT REPEAT('ab', 3);      -- 'ababab'
SELECT REPEAT('ab', 0);      -- ''
SELECT SPACE(3);             -- '   '（3 个空格）
SELECT REVERSE('abcdef');    -- 'fedcba'
SELECT REVERSE('张三');      -- '三张'
```

> [!tip] 用 `REPEAT` + `LPAD` 造测试数据
> `SELECT REPEAT('x', 100);` 可以快速造一个 100 字符的串，测试 `VARCHAR` 边界很方便。

## 七、格式化、编码与进制转换

### 7.1 `FORMAT`（千分位）

```sql
FORMAT(number, decimals)
```

```sql
SELECT FORMAT(1234567.891, 2);     -- '1,234,567.89'
SELECT FORMAT(1234567.891, 0);     -- '1,234,568'
SELECT FORMAT(123.456, 4);         -- '123.4560'
```

> [!danger] `FORMAT` 返回的是**字符串**，不是数字
> `FORMAT(x, 2) + 1` 会发生隐式转换，`'1,234.56'` 转数字时只取到 `1`（逗号截断）。
> **只在最终展示层用它**；中间计算一律用 `ROUND` / `CAST`。

### 7.2 `QUOTE`（转义成 SQL 字面量）

```sql
SELECT QUOTE("Don't");     -- 'Don\'t'（外层单引号是结果的一部分）
SELECT QUOTE(NULL);        -- NULL
```

> [!note] 它不是防 SQL 注入的方案
> `QUOTE` 只是加引号、转义特殊字符，适合生成 SQL 文本做调试。
> 应用代码里请用**预编译参数**（`?` / `PreparedStatement`），不要自己拼字符串。

### 7.3 字符与编码

| 函数 | 作用 | 示例 | 结果 |
| --- | --- | --- | --- |
| `ASCII(str)` | 最左字符的 ASCII 码 | `ASCII('A')` | `65` |
| `ORD(str)` | 最左字符的编码（支持多字节） | `ORD('中')` | 多字节编码值 |
| `CHAR(N, ...)` | 按编码造字符 | `CHAR(77,121,83,81,76)` | `'MySQL'` |
| `HEX(str)` | 转十六进制字符串 | `HEX('abc')` | `'616263'` |
| `UNHEX(hex)` | 十六进制转回字符串 | `UNHEX('616263')` | `'abc'` |
| `BIN(N)` | 十进制转二进制字符串 | `BIN(12)` | `'1100'` |
| `OCT(N)` | 十进制转八进制字符串 | `OCT(12)` | `'14'` |
| `CONV(N, from, to)` | 任意进制转换 | `CONV('ff',16,10)` | `'255'` |

```sql
SELECT ASCII('A'), CHAR(65), HEX('abc'), UNHEX('616263'), BIN(12), CONV('ff',16,10);
```

> [!warning] `CHAR()` 的结果受字符集影响
> `CHAR(65)` 得到 `'A'`；要按指定字符集解释，写 `CHAR(65 USING utf8mb4)`。
> `HEX` / `UNHEX` 处理的是**字节**，对中文要特别注意：`HEX('张')` 得到的是 UTF-8 的 3 字节十六进制。

### 7.4 `ELT` / `FIELD`（按序号取值 / 查序号）

```sql
SELECT ELT(1, 'a', 'b', 'c');          -- 'a'
SELECT ELT(3, 'a', 'b', 'c');          -- 'c'
SELECT ELT(4, 'a', 'b', 'c');          -- NULL（越界）
SELECT FIELD('b', 'a', 'b', 'c');      -- 2
SELECT FIELD('d', 'a', 'b', 'c');      -- 0（找不到）
```

> [!tip] 它们常用于"状态码 → 文案"
> `ELT(status + 1, '待支付', '已支付', '已发货', '已完成')` 比一长串 `CASE WHEN` 短。
> 但状态码不连续、或需要多语言时，还是建一张字典表更稳。

## 八、正则表达式（MySQL 8.0+）

### 8.1 四个函数

| 函数 | 作用 | 示例 | 结果 |
| --- | --- | --- | --- |
| `REGEXP_LIKE(str, pat[, match_type])` | 是否匹配 | `REGEXP_LIKE('abc123','[0-9]+')` | `1` |
| `REGEXP_INSTR(str, pat[, ...])` | 匹配位置 | `REGEXP_INSTR('abc123','[0-9]+')` | `4` |
| `REGEXP_SUBSTR(str, pat[, ...])` | 提取匹配片段 | `REGEXP_SUBSTR('abc123','[0-9]+')` | `'123'` |
| `REGEXP_REPLACE(str, pat, repl[, ...])` | 正则替换 | `REGEXP_REPLACE('abc123','[0-9]+','#')` | `'abc#'` |

```sql
SELECT REGEXP_LIKE('abc123', '^[a-z]+[0-9]+$');        -- 1
SELECT REGEXP_SUBSTR('zhangsan@example.com', '[^@]+$');-- 'example.com'
SELECT REGEXP_REPLACE('a1b2c3', '[0-9]', '');          -- 'abc'
SELECT REGEXP_REPLACE('2026-10-17', '-', '/');          -- '2026/10/17'
```

`match_type` 常用值：

| 值 | 含义 |
| --- | --- |
| `c` | 区分大小写 |
| `i` | 不区分大小写 |
| `m` | 多行模式，`^` / `$` 匹配每行 |
| `n` | `.` 匹配换行符 |
| `u` | Unix 行尾 |

```sql
SELECT REGEXP_LIKE('ABC', 'abc');          -- 1（默认排序规则不区分大小写）
SELECT REGEXP_LIKE('ABC', 'abc', 'c');     -- 0（强制区分大小写）
```

> [!note] 8.0 之前只有 `REGEXP` / `RLIKE` 运算符
> MySQL 8.0.4 才加入上面四个函数。老版本只能写 `WHERE col REGEXP '...'` 做布尔判断，不能提取、不能替换。
> 正则语法基于 ICU，和 PCRE 高度相似但不完全一致；复杂正则建议先在 `SELECT` 里试。

> [!danger] 正则会让你彻底告别索引
> `WHERE phone REGEXP '^138'` 必然全表扫描。
> 能用 `LIKE '138%'` 就别用正则；能用等值 / 范围查询就别用模式匹配。
> 大表上的复杂文本检索，应该交给 `FULLTEXT` 或 Elasticsearch。

## 九、`GROUP_CONCAT`：把多行拼成一个串

```sql
GROUP_CONCAT([DISTINCT] expr
             [ORDER BY ...]
             [SEPARATOR str])
```

```sql
SELECT GROUP_CONCAT(name ORDER BY id SEPARATOR '、') AS 客户名单
FROM customer;
```

```
+--------------------------+
| 客户名单                 |
+--------------------------+
| 张三、李四、Wang Wu、赵六 |
+--------------------------+
```

| 要点 | 说明 |
| --- | --- |
| 默认分隔符 | `,` |
| NULL | **跳过**，不产生多余分隔符 |
| 排序 | 必须写在 `GROUP_CONCAT` **内部**：`ORDER BY id` |
| 长度上限 | `group_concat_max_len`，默认 **1024 字节** |
| 超限 | **静默截断**，只给一条 warning（1260） |

```sql
-- 查看 / 修改上限
SHOW VARIABLES LIKE 'group_concat_max_len';
SET SESSION group_concat_max_len = 1024 * 1024;
```

> [!danger] 超过 1024 字节会被悄悄截断
> 拼出来的串很长时，结果可能只保留前 1024 字节，**不报错**。
> 要么调大 `group_concat_max_len`，要么别用 `GROUP_CONCAT` 做"导出整表"这种活。

> [!warning] 默认没有顺序
> 不写 `ORDER BY` 时，拼接顺序**不确定**。要稳定输出，必须写 `GROUP_CONCAT(name ORDER BY id)`。

## 十、性能：函数为什么会让索引失效

> [!important] 核心原则：**索引列上不要套函数**
> B+ 树索引里存的是**列的原始值**。一旦写成 `LEFT(phone,3) = '138'`，MySQL 必须把每一行的 `phone` 取出来、算出 `LEFT`、再比较——索引的顺序完全用不上。

```sql
-- ❌ 全表扫描：phone 上有索引也用不了
SELECT * FROM customer WHERE LEFT(phone, 3) = '138';
SELECT * FROM customer WHERE SUBSTRING(phone, 1, 3) = '138';

-- ✅ 前缀匹配：能走索引
SELECT * FROM customer WHERE phone LIKE '138%';
```

```sql
-- ❌ UPPER 套在索引列上，索引失效
SELECT * FROM customer WHERE UPPER(email) = 'LISI@EXAMPLE.COM';

-- ✅ 改成不区分大小写的等值比较（默认排序规则本来就 _ci）
SELECT * FROM customer WHERE email = 'lisi@example.com';
```

```sql
-- ❌ 前导 % 让索引失效
SELECT * FROM customer WHERE name LIKE '%三%';

-- ✅ 前缀匹配能走索引
SELECT * FROM customer WHERE name LIKE '张%';
```

> [!tip] 三种补救方案
> 1. **改写法**：把函数挪到常量侧，例如 `created_at >= '2026-10-01'` 代替 `DATE(created_at) = '2026-10-01'`
> 2. **函数索引**（MySQL 8.0.13+）：`CREATE INDEX idx_left_phone ON customer ((LEFT(phone,3)));`
> 3. **生成列 + 普通索引**：`ALTER TABLE customer ADD COLUMN phone_prefix CHAR(3) GENERATED ALWAYS AS (LEFT(phone,3)) STORED, ADD INDEX idx_prefix (phone_prefix);`
>
> 能改 SQL 就改 SQL，函数索引是最后的补丁。

> [!note] 函数写在 `SELECT` 列表里没问题
> `SELECT UPPER(name) FROM customer` 只影响输出，不影响 `WHERE` 走索引。
> 真正要小心的是 `WHERE`、`JOIN ON`、`ORDER BY`、`GROUP BY` 里对**索引列**套函数。

## 十一、常见错误合集

> [!danger] 坑一：`CONCAT` 拼出 NULL
> `CONCAT(name, nickname)` 只要 `nickname` 为 NULL，整行就是 NULL。用 `CONCAT_WS` 或 `IFNULL`。

> [!danger] 坑二：用 `LENGTH` 做字符长度校验
> `LENGTH('张三') = 6`，不是 2。校验长度用 `CHAR_LENGTH`。

> [!danger] 坑三：`SUBSTRING(str, 0, n)` 得到空串
> MySQL 的位置从 1 开始，0 不是"从头开始"。

> [!failure] 坑四：`SUBSTRING_INDEX(str, delim, 0)` 得到空串
> 想取全部内容却写了 0。正数从左、负数从右，别写 0。

> [!failure] 坑五：`REPLACE` 大小写没匹配上
> `REPLACE('Hello','hello','x')` 结果还是 `'Hello'`。先 `LOWER` 或改用 `REGEXP_REPLACE` + `i`。

> [!failure] 坑六：`LPAD` / `RPAD` 超长直接截断
> 不是"补到更长"，而是"截到指定长度"。要校验长度请单独判断 `CHAR_LENGTH`。

> [!failure] 坑七：`GROUP_CONCAT` 被 1024 字节截断
> 结果不完整但不报错。先看 `group_concat_max_len`。

> [!failure] 坑八：`FIND_IN_SET` 的列表带空格
> `'a, b, c'` 里的值是 `' b'`，`FIND_IN_SET('b', ...)` 返回 0。要么去掉空格，要么拆表。

> [!failure] 坑九：`CHAR` 字段的尾随空格
> `CHAR(n)` 存入时会补空格，取出时默认去掉；比较时还受排序规则的 `PAD SPACE` / `NO PAD` 影响。
> 需要精确保留尾部空格，用 `VARCHAR`，或显式开 `PAD_CHAR_TO_FULL_LENGTH`。
> MySQL 8.0 默认的 `utf8mb4_0900_ai_ci` 是 **NO PAD**，尾随空格参与比较；老版本 `utf8mb4_general_ci` 是 PAD SPACE，`'a' = 'a '` 为真。跨版本迁移时要留意。

## 十二、速查表

| 需求 | 函数 | 示例 → 结果 |
| --- | --- | --- |
| 拼接 | `CONCAT` | `CONCAT('a','b')` → `ab` |
| 带分隔符拼接、跳过 NULL | `CONCAT_WS` | `CONCAT_WS('-','a',NULL,'b')` → `a-b` |
| 字符数 | `CHAR_LENGTH` | `CHAR_LENGTH('张三')` → `2` |
| 字节数 | `LENGTH` | `LENGTH('张三')` → `6` |
| 转大写 / 小写 | `UPPER` / `LOWER` | `UPPER('ab')` → `AB` |
| 左 / 右截取 | `LEFT` / `RIGHT` | `LEFT('abcdef',3)` → `abc` |
| 任意位置截取 | `SUBSTRING` | `SUBSTRING('abcdef',2,3)` → `bcd` |
| 按分隔符切 | `SUBSTRING_INDEX` | `SUBSTRING_INDEX('a-b-c','-',2)` → `a-b` |
| 查找子串位置 | `LOCATE` / `INSTR` | `LOCATE('@','a@b')` → `2` |
| 逗号列表查找 | `FIND_IN_SET` | `FIND_IN_SET('b','a,b,c')` → `2` |
| 替换 | `REPLACE` | `REPLACE('abc','b','X')` → `aXc` |
| 按位置替换 | `INSERT` | `INSERT('abc',2,1,'X')` → `aXc` |
| 去首尾空格 | `TRIM` | `TRIM('  a  ')` → `a` |
| 左 / 右填充 | `LPAD` / `RPAD` | `LPAD('5',3,'0')` → `005` |

| 正则判断 | `REGEXP_LIKE` | `REGEXP_LIKE('a1','[0-9]')` → `1` |
| 正则提取 | `REGEXP_SUBSTR` | `REGEXP_SUBSTR('a1','[0-9]')` → `1` |

> [!question] 自测三连
> 1. `CONCAT('a', NULL, 'b')` 和 `CONCAT_WS('-', 'a', NULL, 'b')` 各返回什么？为什么？
> 2. `LENGTH('张三')` 和 `CHAR_LENGTH('张三')` 各是多少？`VARCHAR(20)` 里的 20 指什么？

> [!quote] 一句话记忆
> **位置从 1 开始**（0 是空串）、**NULL 会传染**（`CONCAT` 全变 NULL，`CONCAT_WS` 跳过 NULL）、**`LENGTH` 数字节、`CHAR_LENGTH` 数字符**；**函数套在索引列上必失效**，前缀匹配用 `LIKE 'x%'`，别用 `LIKE '%x%'`。
