## 考察内容

- **ECharts dataset**：用 `dataset.source` 统一提供数据，多个 series 共用一张表。
- **行列布局**：`seriesLayoutBy: "row"` 让「一行 = 一个系列」，`"column"`（默认）让「一列 = 一个系列」。
- **encode 映射**：饼图用 `itemName` / `value` 指定维度，不写死数据。
- **折线图 + 饼图混排**：同一份 dataset，折线取全部年份，饼图只取 2022 年。
- **axios 异步请求**：`axios.get().then()` 拿到 JSON，注意 `res.data` 与 `res.data.data` 的区别。
- **数据转置**：把「年份为外层、作物为内层」的嵌套对象，转成「作物为行、年份为列」的二维数组。
- **考试约束**：只改 `index.html` 里的 TODO，不能动文件名、目录、已有代码。

## 三、解题思路

### 1. `data.json` 的结构

```json
{
  "data": {
    "2017": { "wheat": 431, "soybean": 142, "potato": 232, "corn": 642 },
    "2018": { "wheat": 417, "soybean": 156, "potato": 258, "corn": 643 },
    "2019": { "wheat": 416, "soybean": 168, "potato": 269, "corn": 650 },
    "2020": { "wheat": 436, "soybean": 174, "potato": 277, "corn": 680 },
    "2021": { "wheat": 441, "soybean": 186, "potato": 289, "corn": 692 },
    "2022": { "wheat": 445, "soybean": 201, "potato": 315, "corn": 706 }
  }
}
```

- 外层是**年份**，内层是**作物 → 产量**（单位：万吨）；
- `res.data` 是 axios 解析后的 JSON，真正的数据还要再点一层：`res.data.data`；
- JSON 对象的数字型字符串键（`"2017"`…）会按数值升序枚举，所以 `for…in` 天然是时间顺序，不用额外排序。

> [!note] 关于「五年」
> 题面写「近五年」，但 `data.json` 实际给了 `2017 ~ 2022` 六年数据，初始模板表头也是六年。**以数据为准**，不要自己截断成五年，也不要把表头写死成五年。

### 2. `dataset.source` 的行列布局

题目需要的最终形态：

```js
[
  ["全部", "2017", "2018", "2019", "2020", "2021", "2022"],
  ["小麦", 431, 417, 416, 436, 441, 445],
  ["大豆", 142, 156, 168, 174, 186, 201],
  ["马铃薯", 232, 258, 269, 277, 289, 315],
  ["玉米", 642, 643, 650, 680, 692, 706],
]
```

可以把这张表理解成 Excel：

| | 全部 | 2017 | 2018 | 2019 | 2020 | 2021 | 2022 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 小麦 | 小麦 | 431 | 417 | 416 | 436 | 441 | 445 |
| 大豆 | 大豆 | 142 | 156 | 168 | 174 | 186 | 201 |
| 马铃薯 | 马铃薯 | 232 | 258 | 269 | 277 | 289 | 315 |
| 玉米 | 玉米 | 642 | 643 | 650 | 680 | 692 | 706 |

- **第一行是表头（维度名）**，`"全部"` 这一列存作物名，年份列存产量；
- `seriesLayoutBy: "row"` 时，**表头之后每一行是一个系列**：第 1 列是系列名（作物），后面的列按表头对应到 x 轴类目（年份）；
- 也就是说，4 个 `line` series 正好对应 4 行作物，顺序就是行序：小麦、大豆、马铃薯、玉米。

对比 `seriesLayoutBy` 的两种取值：

| 取值 | 一个系列 = | 适合的表格方向 |
| --- | --- | --- |
| `"column"`（默认） | 一**列** | 表头在行、每个系列占一列 |
| `"row"` | 一**行** | 表头在列、每个系列占一行 |

本题的表是「作物为行、年份为列」，所以折线必须写 `seriesLayoutBy: "row"`。这个字段题目已经写好，不用改。

### 3. 饼图为什么只要 2022

饼图没有 x/y 轴，它靠 `encode` 指定用哪两列：

```js
encode: {
  itemName: "全部",   // 扇区名字取「全部」列（即作物中文名）
  value: "2022",      // 扇区数值取「2022」列
  tooltip: "2022",
}
```

```js
label: { formatter: "{b} {@2022} ({d}%)" }
```

- `{b}` 是数据项名（作物名）；
- `{@2022}` 是「名为 2022 的维度」的数值（`@` 前缀表示按维度名取值）；
- `{d}` 是 ECharts 自动算出的百分比。

==饼图的 `seriesLayoutBy` 是默认的 `"column"`==：每一**行**是一个数据项（一种作物），从 `"全部"` 列取名字、从 `"2022"` 列取值，于是自然只画 2022 年那一列。这就是「折线图用全部年份、饼图只用 2022」能共用一份 dataset 的原因。

> [!warning] 表头第一格必须是「全部」
> 饼图的 `itemName` 写的是 `"全部"`，`value` 写的是 `"2022"`。如果表头第一格改成别的名字、或者某年缺失，饼图就会取不到维度而变空。

### 4. 数据转置的三步

原始数据结构是「年份在外、作物在内」，目标结构是「作物在外、年份在内」，所以要转置：

```js
// ① 每种作物先建一行，第一格放中文名
const rows = {
  wheat: ["小麦"],
  soybean: ["大豆"],
  potato: ["马铃薯"],
  corn: ["玉米"],
};

// ② 表头第一格固定「全部」，后面按年份依次追加
const header = ["全部"];

// ③ 外层遍历年份，内层遍历作物，把值 push 到对应行
for (const year in data) {
  header.push(year);
  for (const crop in rows) {
    rows[crop].push(data[year][crop]);
  }
}
```

循环结束后：

```js
header              // ["全部", "2017", …, "2022"]
rows.wheat          // ["小麦", 431, 417, …, 445]
rows.soybean        // ["大豆", 142, 156, …, 201]
```

此时每个数组的长度都等于「1 + 年份数」，行与行之间天然对齐，直接拼成 `dataset.source`：

```js
option.dataset.source = [header, rows.wheat, rows.soybean, rows.potato, rows.corn];
```

> [!tip] 为什么用 `for…in` 而不是写死多年份
> `for…in` 遍历对象的可枚举键，年份是 `"2017"` 这样的数字型字符串，枚举顺序就是升序，和表头顺序一致。这样即使将来 `data.json` 增删年份，代码也不用改。写死 `data["2017"].wheat`、`data["2018"].wheat`… 虽然也能过，但既啰嗦又容易错位。

### 5. 异步与第二次 `setOption`

页面加载时序：

1. `initCharts()` 先用**占位数据** `myChart.setOption(option)`，画出一张演示图；
2. `axios.get("./data.json")` 发请求，它返回 `Promise`；
3. `.then` 回调里拿到真实数据，改写 `option.dataset.source`；
4. 再调一次 `myChart.setOption(option)`，用新数据覆盖旧图。

两个要点：

- ==`option` 是同一个对象==，`initCharts` 里 `option = {...}` 赋值后，`.then` 里仍然能访问到它，所以直接改属性再 `setOption` 即可；
- 请求是**异步**的，不能在 `axios.get` 外面直接读 `res`；所有用到数据的逻辑都必须写在 `.then` 里。

## 五、关键点与易错点

### 1. 只改 TODO，别动 `option`

题目提供的 `title`、`dataset` 占位数据、`seriesLayoutBy`、`encode`、`label.formatter` 全部是正确的「画法」，缺的只是「数据」。==动它们很容易把判分点改坏==。正确做法是保留 `option` 结构，只在 `.then` 里替换 `source`。

### 2. `res.data` 和 `res.data.data` 别混

```js
axios.get("./data.json").then((res) => {
  // res.data        → { data: { "2017": {...}, ... } }
  // res.data.data   → { "2017": {...}, ... }
  const data = res.data.data;
});
```

写成 `res.data` 后直接 `for (const year in data)`，遍历到的是 `data` 这个字段本身，数据全错位。

### 3. 行名必须是中文

```js
// ✅ 行首放中文
const rows = { wheat: ["小麦"], soybean: ["大豆"], potato: ["马铃薯"], corn: ["玉米"] };

// ❌ 行首放英文，图例和饼图标签会显示 wheat / soybean…
option.dataset.source = [["全部", …], ["wheat", …], …];
```

中文映射的另一个作用是：饼图 `encode.itemName: "全部"` 取到的就是这些中文名。

### 4. 表头与数据必须对齐

- 表头 = `["全部", ...年份]`，每个作物行 = `["作物名", ...对应年份的产量]`；
- 两者长度必须一致，年份顺序必须一致；
- 表头第一格固定 `"全部"`，因为饼图 `itemName` 写的就是它；
- 饼图 `value: "2022"` 要求表头里确实有 `"2022"` 这一列。

### 5. 折线用 `row`，饼图用默认 `column`

| series | `seriesLayoutBy` | 取数方式 |
| --- | --- | --- |
| 4 个 `line` | `"row"` | 每行一个系列，行内按年份展开 |
| `pie` | 默认 `"column"` | 每行一个数据项，按 `encode` 取列 |

不要给饼图加 `seriesLayoutBy: "row"`，否则它会把整行当成一个系列，取不到「2022」列。

### 6. 两次 `setOption` 是正常的

`initCharts()` 先画占位图，请求回来再画真实图。看到页面**闪一下**占位数据不是 bug。不要为了「只画一次」去删掉 `initCharts()`。

### 7. 不要改文件与结构

- 只改 `index.html` 里的 TODO；
- `data.json`、`js/echarts.min.js`、`js/axios.min.js` 一律不动；
- 不改文件名、目录层级、`container` 的 id；
- 保持 Live Server / Web 服务可访问，再点「提交检测」。
