# 属性继承

> [!abstract] 一句话
> 写在组件标签上、但**没有被 `props` / `emits` 声明**的属性（`class`、`style`、`id`、`@click` 等），会 ==自动“掉”到组件的根元素上==。这个行为叫**透传属性**（Fallthrough Attributes），也叫**属性继承**——父组件写在标签上的东西，子组件没伸手接，它就自己往下渗。

---

## 一、什么叫“透传”（fallthrough）

“透传”这个词很形象：父组件写在组件标签上的属性像水，组件这截管道本身不拦它，水就一路渗到最底下那个真实的 DOM 元素上。

```text
父组件里写：
   <MyButton class="btn" id="submit" @click="onClick" />
        │
        │  MyButton 内部既没 props 声明 class/id，
        │  @click 也没写进 emits
        ▼
   MyButton 组件（这截“管道”什么都不拦）
        │
        │  自动向下渗
        ▼
   <button class="btn" id="submit">    ← 真正的 DOM 元素，属性落在它头上
```

> [!info] 关键条件是「未声明」
> `props` 和 `emits` 就是管道上的两道**闸门**：
> - `class` / `id` 没被声明成 prop → 拦不住 → 透传；
> - `@click` 没被写进 `emits` → 拦不住 → 透传；
> - 一旦声明了，就被“截胡”，不再往下流，而是当成正经的 prop / 自定义事件处理。

对应的官方概念叫 **Fallthrough Attributes**（直译“掉落/透传的属性”），中文文档译作“透传 Attributes”或“透传属性”。本笔记的标题“属性继承”说的是同一件事：**根元素“继承”了写在组件上的属性**。

| 写在组件标签上的东西 | 子组件有没有声明 | 结果 |
| --- | --- | --- |
| `class` / `style` / `id` | 无（天生不是 prop） | ✅ 透传到根元素，且与根元素已有的**合并** |
| `data-*` / `aria-*` / 自定义属性 | 无 | ✅ 原样透传 |
| `title`、`disabled` 等普通属性 | 未声明为 prop | ✅ 透传 |
| `title`、`disabled` 等普通属性 | 已声明为 prop | ❌ 被 props 截住，不透传 |
| `@click`、`@input` 等监听器 | 未写进 `emits` | ✅ 透传（相当于给根元素绑原生监听） |
| `@click`、`@input` 等监听器 | 已写进 `emits` | ❌ 被 emits 截住，只当自定义事件 |

## 二、单一根节点：默认全自动

组件模板只有一个根元素时，**不需要写任何代码**，透传是默认开启的。

```vue
<!-- MyButton.vue：根元素是一个 <button> -->
<template>
  <button class="btn" type="button">
    <slot />
  </button>
</template>
```

```vue
<!-- 父组件：在组件标签上写 class / id / @click -->
<script setup>
function onClick() {
  console.log('被点了')
}
</script>

<template>
  <MyButton class="large" id="submit" @click="onClick">提交</MyButton>
</template>
```

渲染出来的 DOM：

```html
<!-- class 被合并了（不是覆盖），id 和 click 监听都落到了 button 上 -->
<button class="btn large" type="button" id="submit">提交</button>
```

> [!tip] `class` / `style` 是**合并**，其余属性是**覆盖**
> - `class`：根元素自己的 `btn` + 传来的 `large` → `"btn large"`，**两边都保留**。
> - `style`：合并成一个样式对象，**同名属性**由后传入的（父组件那份）覆盖。
> - 其它属性（`id`、`type`、`title`…）：同名就是**后来的覆盖前面的**，根元素上写什么就是什么。

> [!quote] 拼接顺序 ≠ 优先级
> `class` 合并结果一般是「内部 class 在前、传入 class 在后」，但字符串里的先后**不影响 CSS 优先级**——谁生效仍取决于样式表中规则的书写先后与选择器权重。

## 三、多个根节点（多根组件）：重点坑

组件模板有**多个根元素**时，Vue 不知道该把属性给谁，于是**自动继承直接失效**。

```vue
<!-- MyInput.vue：注意是两个并列根元素，属于多根（fragment） -->
<template>
  <label>用户名</label>
  <input type="text" />
</template>
```

```vue
<!-- 父组件 -->
<template>
  <MyInput class="big" placeholder="请输入" />
</template>
```

结果：**不会报错崩溃，但控制台会出现运行时警告**，并且 `class` / `placeholder` 哪儿都没落上：

```text
[Vue warn]: Extraneous non-props attributes (class, placeholder) were passed
to component but could not be automatically inherited because component
renders fragment or text root nodes.
```

> [!warning] 多根节点必须**手动指定**落点
> 警告的意思是：“你传了属性，但我不知道该放哪（我渲染的是 fragment / 文本根节点）。”
> 解决办法：在**你希望接收属性的那个根元素**上写 `v-bind="$attrs"`。

```vue
<!-- MyInput.vue：手动绑定到 <input> 上 -->
<script setup>
// 多根时如果想“关掉警告”，也常配合 inheritAttrs: false（见第四节）
</script>

<template>
  <label>用户名</label>
  <input type="text" v-bind="$attrs" />
</template>
```

这样父组件传的 `class="big"`、`placeholder="请输入"` 就都会落到 `<input>` 上，警告也随之消失。

> [!danger] 一个组件里只能绑一次吗？
> 技术上 `v-bind="$attrs"` 可以写在多个元素上（属性会被复制到每一处），但这几乎总是错的——同一个 `id` 出现两次就是无效 HTML。**只绑在语义上正确的那个元素上。**

## 四、关掉自动继承：`inheritAttrs: false`

有时你不希望属性落到根元素上（例如根元素是个包裹用的 `<div>`，你只想让属性落到内部真正的 `<input>` 上）。这时关掉自动继承。

Options API 写法：

```vue
<script>
export default {
  inheritAttrs: false   // 不再把 $attrs 自动铺到根元素上
}
</script>
```

`<script setup>` 写法：用 `defineOptions`（见 [[setup语法糖]] 的 3.4 节）：

```vue
<script setup>
defineOptions({
  inheritAttrs: false   // 单根场景下也用这个关掉自动铺开
})
</script>

<template>
  <div class="wrapper">
    <!-- 属性只落到 input 上，wrapper 保持干净 -->
    <input v-bind="$attrs" />
  </div>
</template>
```

> [!note] `inheritAttrs: false` ≠ 拿不到属性
> 它**只影响“是否自动铺到根元素”**，不影响 `$attrs` 的内容。
> 关掉之后，这些属性依然完整地躺在 `$attrs` 里，你可以自由决定绑到哪里。
> 换句话说：==它关的是“自动”，不是“属性本身”==。

| 配置 | 根元素是否自动得到属性 | `$attrs` 里是否还有这些属性 |
| --- | --- | --- |
| 默认（`inheritAttrs: true`） | ✅ 自动铺上 | ✅ 有 |
| `inheritAttrs: false` | ❌ 不铺 | ✅ 仍然有 |

## 五、拿到透传属性：`$attrs` 与 `useAttrs()`

透传属性都收集在一个对象里，`$attrs`（模板里）或 `useAttrs()`（`<script setup>` 里）都能取到。

### 5.1 模板里：`$attrs`

```vue
<template>
  <div class="wrapper">
    <!-- 把收集到的所有透传属性，一次性绑到包裹层上 -->
    <div v-bind="$attrs" class="inner-card">
      <slot />
    </div>
  </div>
</template>
```

> [!tip] `v-bind` 不带参数 = 展开整个对象
> `v-bind="$attrs"` 等价于把对象里每个键值对逐个写成 `:key="value"`。这是透传最常用的招式。

### 5.2 脚本里：`useAttrs()`

```vue
<script setup>
import { useAttrs } from 'vue'

const attrs = useAttrs()          // 注意：要 import，它是真正的函数

console.log(attrs.id)             // 读单个属性
console.log(attrs.class)          // class 也在里面
console.log(attrs.onClick)        // 监听器的键名是 on + 事件名（驼峰）
</script>
```

> [!info] 监听器在 `$attrs` 里长什么样
> `@click` 在 `$attrs` 里是 `onClick`，`@my-event` 是 `onMyEvent`——**`on` 前缀 + 事件名驼峰化**。
> 这也解释了为什么透传的监听器能直接铺到 DOM 元素上：`onClick` 正是原生事件绑定属性的写法。

> [!warning] `$attrs` 里**永远没有** props
> 它在设计上只装“没被 props / emits 接住的**剩余**属性”。
> 想读 props 请直接用 `props.xxx`；想在模板里同时用两者，各自取各自的。

> [!note] 关于响应式
> `$attrs` 对象总是反映**最新**传入的属性（不会漏掉后来新增的键），但**不要指望用它做精细的响应式派生**——真要响应式变化，用 props 是更清晰的做法。

## 六、嵌套透传：一层层往下传

组件套组件时，属性会**沿着组件树逐层下渗**，直到某一层接住它（声明成 prop）或落到 DOM 上。

经典例子：给 `<BaseInput>` 包一层 `<MyInput>`：

```vue
<!-- BaseInput.vue：只负责最底层的真实 input -->
<script setup>
defineOptions({ inheritAttrs: false })   // 不让属性乱铺，明确绑给 input
</script>

<template>
  <input class="base-input" v-bind="$attrs" />
</template>
```

```vue
<!-- MyInput.vue：中间层，什么都不声明，只是把属性继续往下传 -->
<template>
  <label>
    用户名
    <!-- 关键一行：把收到的透传属性原样交给 BaseInput -->
    <BaseInput v-bind="$attrs" />
  </label>
</template>
```

```vue
<!-- 父组件：属性跨越两层，最终落到最底层的 <input> 上 -->
<template>
  <MyInput type="email" placeholder="邮箱" @focus="onFocus" />
</template>
```

```text
父组件  <MyInput type="email" placeholder="邮箱" @focus="onFocus" />
   │
   ▼  MyInput   （无 props / emits，$attrs = { type, placeholder, onFocus }）
   │  v-bind="$attrs" 原样下传
   ▼  BaseInput （inheritAttrs: false，$attrs 仍是那三样）
   │  v-bind="$attrs"
   ▼  <input type="email" placeholder="邮箱" onFocus={...} class="base-input" />
```

> [!success] 一句话记住“中转站”写法
> **中间组件不参与业务，只做搬运工：`v-bind="$attrs"` 从上一跳取，再 `v-bind="$attrs"` 往下一跳送。**

## 七、`class` / `style` 与监听器：合并还是覆盖

`$attrs` 里其实混着三类东西，规则各不相同，必须分清：

| `$attrs` 里的内容 | 例子 | 与根元素已有内容的合并规则 |
| --- | --- | --- |
| `class`（特殊：字符串/数组/对象） | `class="large"` | **合并**成 `"btn large"` |
| `style`（特殊：对象/数组） | `:style="{ color: 'red' }"` | **合并**成对象，同名属性以传入的为准 |
| 普通属性 | `id`、`title`、`data-*` | 同名**覆盖** |
| 事件监听器 | `onClick`、`onInput` | **合并成一个数组**，全部都会执行 |

```text
class  传入「large」 + 根元素「btn」      ──合并──▶ class="btn large"
style  传入「color:red」 + 根元素「margin:0」──合并──▶ { color:'red', margin:0 }（同名键传入的胜出）
onClick 传入的 + 根元素自己的 @click      ──合并──▶ [传入的, 自己的]  两个都跑
```

> [!quote] 为什么 `class` / `style` 要特殊对待？
> 因为它们是**组合式**的：一个元素有多个类名、多条样式是常态，合并比覆盖更符合直觉。
> 其它属性是**单值**的：`id` 只能有一个，覆盖才合理。

## 八、与 `emits` 的关系：声明了就“截胡”

这是理解透传的**最后一块拼图**，也是最容易踩坑的地方：**事件一旦写进 `emits`，就不再透传。**

```vue
<!-- ChildA.vue：没有声明 emits -->
<template>
  <button>点我</button>
</template>
```

```vue
<!-- ChildB.vue：声明了 click 这个自定义事件 -->
<script setup>
defineEmits(['click'])
</script>

<template>
  <button>点我</button>
</template>
```

父组件对两者都写 `@click="onClick"`，结果完全不同：

| 子组件 | `@click` 的去向 | 点击后 `onClick` 会跑吗 |
| --- | --- | --- |
| `ChildA`（未声明 emits） | **透传**到根元素 `<button>`，成为原生监听 | ✅ 会（浏览器原生点击触发） |
| `ChildB`（声明了 `emits: ['click']`） | 被 emits 拦截，**不再透传** | ❌ 不会——除非组件内部 `emit('click')` |

```vue
<!-- ChildB 要想真的通知父组件，必须自己 emit -->
<script setup>
const emit = defineEmits(['click'])
</script>

<template>
  <!-- 用户点按钮 → 触发自定义 click → 父组件的 @click 才被调用 -->
  <button @click="emit('click')">点我</button>
</template>
```

> [!warning] 这就是“为什么要显式声明 emits”的原因之一
> 1. **语义清晰**：一眼看出组件会主动抛出哪些事件（对外接口）。
> 2. **避免误透传**：声明后该事件不再落到根元素上，防止“自定义事件”和“原生事件”混在一起。
> 3. **可校验参数**（对象 / TS 写法），还能改善 `v-on` 的类型推导。
> 细节见 [[Events 自定义事件]]。

> [!danger] 声明 emits 后原生监听也一起没了
> 因为 `@click` 被 emits 拿走了，它**不会**再绑到根 `<button>` 上。
> 如果你既想要原生 DOM 的点击、又想要自定义事件，两者会打架——正确做法是**只留一个语义**，由组件内部决定何时 `emit`。

## 九、常见坑与问答

> [!question] 控制台报 “could not be automatically inherited because component renders fragment or text root nodes”？
> 组件有**多个根节点**（fragment），Vue 找不到唯一落点。在你要接收属性的元素上写 `v-bind="$attrs"` 即可。
> 如果确实**不想接收**这些属性，用 `defineOptions({ inheritAttrs: false })` 显式关掉，警告也会消失。

> [!question] 设了 `inheritAttrs: false`，怎么 `class` 反而不生效了？
> 因为它只负责“**不要自动铺**”。关掉之后你必须**自己**用 `v-bind="$attrs"`（或手动写 `:class="attrs.class"`）把它绑上去。
> 只关不绑 = 属性被彻底丢弃，这不是 bug，是预期行为。

> [!question] 为什么 `$attrs` 里找不到我写的 props？
> 设计如此。`$attrs` 只装**没有被 props / emits 接住的剩余属性**。
> 需要 props 就直接用 `props.xxx`，两套数据各有各的入口。

> [!question] 父组件传的 `@click` 好像被“触发两次”？
> 如果子组件**根元素自己也写了 `@click`**，Vue 会把你传的和它自己的**合并成数组、两个都执行**。
> 看起来像“两次”，实际是“两个不同的处理函数各跑一次”。此时在父组件传 `@click` 本来就是给原生元素用的。
> 另一种“错乱”来源是：组件声明了 `emits: ['click']`，父组件的 `@click` 被当成自定义事件，而组件内部又用原生点击去触发它——检查一下是不是同一次点击被两个语义各处理了一遍。

> [!quote] 一句话记牢
> **`inheritAttrs` 管“铺不铺”，`emits` 管“拦不拦”，`$attrs` 管“有没有”。**
