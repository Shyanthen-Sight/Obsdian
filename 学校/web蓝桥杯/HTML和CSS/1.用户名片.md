# 用户名片案例：5 行 CSS 实现绝对居中

> [!info] 原题
> 蓝桥云课 · 用户名片（题目 2321）
> [题目链接](https://www.lanqiao.cn/problems/2321/learning/?page=1&first_category_id=2&tags=HTML5&tag_relation=union)

> [!summary] 速记版
> ```css
> .center {
>   position: absolute;
>   top: 50%;
>   left: 50%;
>   transform: translate(-50%, -50%);
> }
> ```
> - `top/left: 50%`：把元素**左上角**放到父容器中心，百分比参照**父级**宽高。
> - `translate(-50%, -50%)`：按元素**自身**宽高的 50% 往回退，百分比参照**自己**。
> - 两次 `50%` 参照物不同，所以不需要知道元素尺寸就能居中。
> - 同一个 `.center` 被复用到 4 个元素：外层参照视口，`.level` / `.points` / 头像参照最近的定位祖先 `.user-card`。
> - 前提：`.card` 和 `.user-card` 必须是 `position: relative`，否则绝对定位会一路向上、参照视口。

## 二、结论先行

题目要补的只有 `TODO` 下面这一段：

```css
.center {
  position: absolute;
  top: 50%;
  left: 50%;
  transform: translate(-50%, -50%);
}
```

**原理一句话：`top/left: 50%` 先把元素左上角挪到父容器中心；`translate(-50%, -50%)` 再按元素自身的宽高往回退一半，于是元素中心与父容器中心重合。**

```
① top:50% + left:50%
父容器
┌────────────────────┐
│                    │
│           ┌────┐   │   ← 左上角落在了
│           │元素│   │     父容器的中心点
│           └────┘   │
│                    │
└────────────────────┘

② transform: translate(-50%,-50%)
┌────────────────────┐
│                    │
│         ┌────┐     │
│         │元素│     │   ← 整体向左上回退
│         └────┘     │     自身宽高的一半
│                    │
└────────────────────┘
→ 元素中心 = 父容器中心
```

## 三、这 5 行为什么有效（逐行拆）

| 行                                  | 作用                        | 为什么不能少                                                                                         |
| ---------------------------------- | ------------------------- | ---------------------------------------------------------------------------------------------- |
| `position: absolute`               | 让元素脱离文档流，并让 `top/left` 生效 | `static` 元素上的 `top/left` 完全无效                                                                  |
| `top: 50%`                         | 把元素**上边缘**放到包含块高度的 50% 处  | 百分比参照的是**包含块**，不是自身                                                                            |
| `left: 50%`                        | 把元素**左边缘**放到包含块宽度的 50% 处  | 同上                                                                                             |
| `transform: translate(-50%, -50%)` | 按**元素自身**宽高的 50% 向左上平移    | <font color="#c00000">关键！`tr<font color="#c00000">anslate` 的百分比参照自身，正好抵消多出来的半个身位</font></font> |

### 最容易混淆的一点：两个 `50%` 参照物不同

- `top: 50%` / `left: 50%` → 参照**父级（包含块）**的宽高。
- `translate(-50%, -50%)` → 参照**元素自己**的宽高。

正因为参照物不同，才能实现"不知道元素尺寸也能居中"。

### 和其他写法的对比

```css
/* ❌ margin 的百分比参照父容器宽度，不是自身 */
margin-left: -50%;

/* ❌ 必须提前知道尺寸，尺寸一变就失效 */
position: absolute;
left: calc(50% - 225px);  /* 450 / 2 */
top: calc(50% - 125px);   /* 250 / 2 */

/* ✅ 不需要知道尺寸，宽高变化仍然居中 */
position: absolute;
left: 50%;
top: 50%;
transform: translate(-50%, -50%);
```

### 为什么用 `transform` 而不是负 margin / `calc`

1. **不需要写死尺寸**，元素宽高变化后依然居中。
2. `transform` 不参与布局计算，**不会触发重排**，通常由合成层处理，动画更顺滑。
3. `margin` 的百分比参照父宽度，`calc` 要手写一半尺寸，都不通用。

## 四、为什么一个 `.center` 能管四个地方

HTML 里 `center` 这个类出现了 **4 次**：外层容器、`Level 13`、`5312 Points`、头像 `<img>`。

绝对定位的参照物是**最近的、`position` 不为 `static` 的祖先**，所以同一个 `.center` 规则在不同位置会得到不同结果：

| 元素 | 最近的定位祖先 | 实际效果 |
| --- | --- | --- |
| `.center`（最外层 div） | 没有 → 初始包含块（视口） | 整个卡片在视口中居中 |
| `img.avatar.center` | `.user-card`（`position: relative`） | 头像在 150×250 的用户卡区域内居中 |
| `.level.center` | `.user-card` | 横向居中；纵向被 `top: 15% !important` 覆盖 |
| `.points.center` | `.user-card` | 横向居中；纵向被 `.user-card .points { top: 85% }` 覆盖 |

### 覆盖关系细节

```css
.level {
  top: 15% !important;   /* !important 优先级最高，压过 .center 的 top: 50% */
}

.user-card .points {
  top: 85%;              /* 特异性 (0,2,0) > .center 的 (0,1,0)，也压过 top: 50% */
}
```

但 `.level` 和 `.points` 都没有重新声明 `left` 和 `transform`，所以：

- `left: 50%` + `translateX(-50%)` 生效 → **横向居中**；
- `translateY(-50%)` 同样生效 → 实际定位的是元素**中心**，而不是顶边（作者接受了这个纵向偏移）。

> [!tip] 复用类名的双刃剑
> 这段 CSS 能"几行搞定全部"，靠的就是 `.center` 被复用到多个元素上。
> 但它也有副作用：`.level` / `.points` 被额外施加了 `translateY(-50%)`，定位基准从"顶边"变成了"中心"。
> 真实项目里更推荐拆成两个类，例如 `.center`（居中定位）和 `.center-x`（仅横向居中），可读性更好。

## 五、其他 CSS 不是"没用"，而是必要铺垫

### 1. `.card` 必须是定位祖先

```css
.card {
  width: 450px;
  height: 250px;
  position: relative;   /* 关键 */
}
```

- 给 `.additional`、`.general` 提供定位参照。
- 如果去掉，两者会跑到视口上，整个卡片布局散架。
- 固定宽高让居中结果稳定、可预期。

### 2. `html, body { height: 100% }`

- 让背景色铺满视口。
- 外层 `.center` 参照初始包含块其实不依赖它，但页面没有内容撑高时，`height:100%` 是让背景铺满的常规手段。
- `overflow: hidden` 隐藏固定尺寸卡片在边缘可能产生的滚动条。

### 3. `.additional` 没写宽度，为什么正好 150px？

```css
.additional {
  position: absolute;
  height: 100%;
  /* 没有 width */
}
```

- 绝对定位且 `left/right` 都是 `auto`、`width: auto` 时，宽度按 **shrink-to-fit** 收缩包裹内容。
- 里面唯一参与流布局的是 `float: left` 的 `.user-card`（`width: 150px`），其余（level、points、avatar）都是绝对定位，不占空间。
- 另外，绝对定位元素会建立 **BFC**，所以能包住浮动子元素（否则浮动会溢出）。
- 最终宽度 = 150px，绿色区域正好是左半边。

### 4. `.general` 占据右半边

```css
.general {
  width: 300px;      /* 450 - 150 */
  height: 100%;
  position: absolute;
  top: 0;
  right: 0;
}
```

- 固定 300px 宽、贴右，与左侧 150px 正好拼满 450px。
- `display: flex; flex-flow: column; justify-content: space-around;` 让标题、正文、署名在竖直方向均匀分布。

### 5. `.more` 为什么要 `display: block`

```css
.more {
  display: block;        /* span 默认 inline，无法独占一行 */
  text-align: right;     /* 文字右对齐 */
}
```

### 6. `* { margin: 0; padding: 0 }`

清除浏览器默认间距，避免 `h1`、`p` 的默认外边距把布局撑歪。

## 六、和其他居中方案的对比

### Flexbox（现代首选）

```css
body {
  display: flex;
  justify-content: center;
  align-items: center;
  min-height: 100vh;
}
```

### Grid（代码最短）

```css
body {
  display: grid;
  place-items: center;
  min-height: 100vh;
}
```

### 绝对定位 + transform（本例）

- 优点：元素浮在某个定位容器内时非常方便（比如头像在 `.user-card` 内居中）。
- 缺点：脱离文档流，父容器不会被它撑开；页面有多个内容时容易叠在一起。
- 现代补充写法：定宽高元素也可以用 `inset: 0; margin: auto;` 居中。

| 方案 | 是否脱离文档流 | 是否需知道尺寸 | 适用场景 |
| --- | --- | --- | --- |
| absolute + transform | 是 | 否 | 浮层、装饰元素、定位容器内部 |
| flex | 否 | 否 | 常规页面布局 |
| grid | 否 | 否 | 单个/多个元素居中 |
| margin: auto + inset: 0 | 是 | 需要定宽高 | 弹窗、固定尺寸卡片 |

## 七、常见坑

1. **父级没有 `position`**：`absolute` 会一路向上找定位祖先，最后参照视口，位置"跑偏"。本例依赖 `.user-card { position: relative }`。
2. **把 `.center` 写成 `position: relative`**：`relative` 的 `top/left` 是相对自身原位置的偏移，不会以父容器中心为基准，居中失效。
3. **只写 `top/left: 50%` 忘了 `transform`**：元素左上角对齐中心，整体偏右下半个身位。
4. **混用两种百分比参照**：以为 `translate` 的 `50%` 也参照父级，结果算错。记住：`top/left` 看父级，`translate` 看自己。
5. **`transform` 会创建包含块**：元素内部的 `fixed` / `absolute` 后代可能因此改变参照物。
6. **固定 450px 卡片在窄屏溢出**：加上 `overflow: hidden` 后会被直接裁掉，移动端需要媒体查询或改成流式布局。
7. **类名复用导致意外覆盖**：`.level` / `.points` 被 `.center` 的 `translateY(-50%)` 影响，定位基准变成中心。

---

## 八、记忆口诀

> **绝对定位先脱流，`top/left: 50%` 到中心；**
> **`translate` 反推自身一半，不知尺寸也居中。**

> **父级不设 `relative`，绝对定位满天飞。**
