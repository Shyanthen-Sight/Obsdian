# Java 继承

## 1. 什么是继承

继承（Inheritance）是面向对象三大特性之一，它允许==一个类获取另一个类的字段与方法==，并==在其基础上扩展自身功能==。

在 Java 中，==被继承的类称为**父类 / 超类 / 基类==（Superclass）**，==继承父类的类称为**子类==（Subclass）**。子类通过 ==`extends` 关键字==与父类建立"是一个（is-a）"的关系。
 
```java
public class Manager extends Employee {
    // Manager 是一个 Employee
}
```

## 2. 为什么要用继承

- **代码复用**：避免在多个类中==重复编写相同属性与方==法。
- **逻辑分层**：将通用行为上提至父类，特有行为下沉到子类。
- **多态基础**：父类引用可以指向子类对象，为==后续多态、接口设计铺路==。

## 3. 核心案例：员工管理系统

贯穿整篇笔记的案例：一家公司有多种员工，所有员工都有姓名、工号、基本工资，但薪资计算方式不同。

- 父类：`Employee`（所有员工的共性）
- 子类：`SalariedEmployee`（固定月薪员工）
- 子类：`HourlyEmployee`（按小时计薪员工）
- 子类：`Manager`（经理，有额外奖金）

### 3.1 父类定义

```java
public class Employee {
    protected String name;
    protected String id;
    protected double baseSalary;//基本薪资

    public Employee(String name, String id, double baseSalary) {//员工薪资对象
        this.name = name;
        this.id = id;
        this.baseSalary = baseSalary;
    }

    public double calculateSalary() {
        return baseSalary;
    }

    public String getDetails() {
        return "ID: " + id + ", 姓名: " + name + ", 基本工资: " + baseSalary;
    }
}
```

说明：字段使用 `protected` 修饰，==允许子类直接访问==，==同时避免被包外无关类随意修改==。

### 3.2 子类定义

```java
public class SalariedEmployee extends Employee {
    public SalariedEmployee(String name, String id, double baseSalary) {
        super(name, id, baseSalary);
    }

    @Override
    public double calculateSalary() {
        return baseSalary;
    }
}
---------------------------------------------------------------------------
public class HourlyEmployee extends Employee {
    private double hoursWorked;
    private double hourlyRate;

    public HourlyEmployee(String name, String id, double hourlyRate) {
        super(name, id, 0);
        this.hourlyRate = hourlyRate;
    }

    public void setHoursWorked(double hours) {
        this.hoursWorked = hours;
    }

    @Override
    public double calculateSalary() {
        return hoursWorked * hourlyRate;
    }
}
---------------------------------------------------------------------------
public class Manager extends Employee {
    private double bonus;

    public Manager(String name, String id, double baseSalary, double bonus) {
        super(name, id, baseSalary);
        this.bonus = bonus;
    }

    @Override
    public double calculateSalary() {
        return baseSalary + bonus;
    }
}
```

每个子类都根据自身业务规则重写了 `calculateSalary()`，但共用父类的 `getDetails()` 与字段。

## 4. 继承的语法规则

### 4.1 extends 关键字

```java
class 子类 extends 父类 {
    // 子类体
}
```

Java 只支持**单继承**：一个子类只能直接继承一个父类。若需==模拟多继承，可通过接口（`implements`）实现==。

### 4.2 子类能继承什么

| 父类成员        | 子类是否可继承                    |
| ----------- | -------------------------- |
| `public`    | 是                          |
| `protected` | 是                          |
| 默认（包私有）     | 同包可继承，跨包不可                 |
| `private`   | ==否，但可通过父类提供的公共/保护方法间接访问== |
| 构造方法        | ==否，但可通过 `super()` 调用==    |

## 5. super 关键字

`super` 用于==在子类中访问父类成员==，主要有两种用法。(详细解释[[super关键字]])

### 5.1 调用父类构造方法

子类构造方法默认第一行隐式调用 `super()`（父类无参构造）。若父类只有带参构造，必须显式使用 `super(...)`，否则编译报错。

```java
public Manager(String name, String id, double baseSalary, double bonus) {
    super(name, id, baseSalary);  // 必须写在第一行
    this.bonus = bonus;
}
```

### 5.2 调用父类普通方法或字段

当==子类与父类出现同名成员时，可用 `super` 明确指定父类版本。==

```java
@Override
public String getDetails() {
    return super.getDetails() + ", 奖金: " + bonus;
}
```

## 6. 方法重写（Override）

子类对父类中==已有方法重新实现，称为方法重写==。重写需满足以下条件：

1. 方法名、参数列表、返回值类型（或协变返回）必须相同。
2. 访问权限不能比父类更严格。
3. 抛出的异常不能比父类更宽泛（非检查异常除外）。
4. ==父类方法不能是 `final` 或 `static`==。

以案例中的 `Manager` 为例：

```java
@Override
public double calculateSalary() {
    return baseSalary + bonus;
}
```

## 7. @Override 注解

### 7.1 基本用法

`@Override` 用于==显式标记某个方法是重写父类（或实现接口）的方法==。

```java
@Override
public double calculateSalary() {
    return baseSalary + bonus;
}
```

### 7.2 为什么要加 @Override

- **编译期校验**：若==方法签名与父类不匹配，编译器立即报错==，避免"以为重写了，实际写成了重载或新方法"的隐藏 Bug。
- **可读性提升**：==阅读代码时==一眼可知该方法是父类行为的覆盖。
- **维护友好**：后续==重构父类方法签名==时，==子类会同步产生编译错误==，提醒开发者检查。

### 7.3 错误示例

以下代码意图重写 `calculateSalary`，但把参数类型写错了。没有 `@Override` 时，==它会被当作子类的新方法==，==导致多态调用时仍走父类逻辑==。

```java
// 错误：参数写错，变成重载而非重写
public double calculateSalary(int month) {
    return baseSalary + bonus;
}
```

加上 `@Override` 后：

```java
@Override
public double calculateSalary(int month) {  // 编译报错：方法不存在于父类
    return baseSalary + bonus;
}
```

### 7.4 使用建议

==只要方法意图是重写父类或实现接口方法==，就应当加上 `@Override`。IDE 通常会自动生成，手动编写时也不要省略。

## 8. 构造方法与继承

创建子类对象时，构造方法的执行顺序是：**先父类，后子类**。

```java
public class Demo {
    public static void main(String[] args) {
        Manager manager = new Manager("张三", "M001", 8000, 2000);
        System.out.println(manager.calculateSalary());  // 10000.0
        System.out.println(manager.getDetails());
    }
}
```

执行流程：

>1. 为 `Manager` 对象分配内存。
>2. 调用 `Employee` 构造方法初始化 `name`、`id`、`baseSalary`。
>3. 调用 `Manager` 构造方法初始化 `bonus`。

若父类没有无参构造，子类所有构造方法都必须显式调用父类构造方法。

## 9. 访问权限与继承

| 修饰符         | 父类中 | 子类中（同包） | 子类中（跨包） |
| ----------- | --- | ------- | ------- |
| `public`    | 可访问 | 可访问     | 可访问     |
| `protected` | 可访问 | 可访问     | 可访问     |
| 默认          | 可访问 | 可访问     | 不可访问    |
| `private`   | 可访问 | 不可直接访问  | 不可直接访问  |


设计建议：

- ==希望子类访问且不希望外部访问：用 `protected`。==
- ==纯属父类内部状态：用 `private`，通过 `getter/setter` 暴露==。
- 避免为了继承方便而将字段设为 `public`，破坏封装。

## 10. Object 类：所有类的根

任何未显式继承其他类的类，都默认继承自 `java.lang.Object`。因此所有对象都拥有以下常用方法：

- `toString()`
- `equals(Object obj)`
- `hashCode()`
- `getClass()`

```java
Employee e = new Manager("李四", "M002", 9000, 1000);
System.out.println(e.toString());  // 默认输出类全名 + 哈希值
```

通常需要重写 `toString()`、`equals()`、`hashCode()` 以满足业务需求。

## 11. 常见误区

### 11.1 重写 vs 重载

| 维度   | 重写（Override） | 重载（Overload） |
| ---- | ------------ | ------------ |
| 位置   | 父子类之间        | 同一类中         |
| 方法名  | 相同           | 相同           |
| 参数列表 | 相同           | 不同           |
| 返回值  | 相同或协变        | 可不同          |
| 多态   | 运行时绑定        | 编译时绑定        |

### 11.2 private 方法不能被重写

==父类中的 `private` 方法对子类不可见==，==子类若写同名方法，只是子类自己的新方法，不算重写==。

### 11.3 static 方法不参与重写

`static` 方法属于类，子类可以写同名静态方法，但这称为**隐藏（hide）**，不是重写，也不会有多态效果。

## 12. 最佳实践

- **优先组合，必要时继承**：若子类只是为了复用代码而与父类没有"is-a"关系，考虑使用组合。
- **父类设计为抽象或具体类视场景而定**：若父类不应被直接实例化，可声明为 `abstract`。
- **重写方法尽量加 `@Override`**：养成习惯，减少隐藏 Bug。
- **避免在构造方法中调用可重写方法**：可能引发子类未初始化完成就被调用的问题。

## 13. 总结

继承通过 `extends` 建立类之间的层次关系，使子类复用父类成员并扩展自身行为。方法重写配合 `@Override` 注解，可以在保持接口统一的前提下实现不同的业务逻辑。合理使用继承能够降低重复代码、增强系统可扩展性，但需注意访问权限、构造方法执行顺序以及重写与重载的区别。
