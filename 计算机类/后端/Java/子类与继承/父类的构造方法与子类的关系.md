# 父类的构造方法与子类的关系

## 1. 核心规则

在 Java 中，**子类对象实例化时，父类的构造方法一定会被调用**。这是由 JVM 保证的，目的是为了确保父类中的成员变量能够得到正确初始化。

### 1.1 隐式调用 `super()`

如果子类的构造方法**没有显式地调用** `super(...)` 或 `this(...)`，那么编译器会在子类构造方法的第一行**自动插入**一行 `super()`，即调用父类的**无参构造方法**。

```java
class Parent {
    Parent() {
        System.out.println("Parent 无参构造");
    }
}

class Child extends Parent {
    Child() {
        // 编译器自动插入：super();
        System.out.println("Child 无参构造");
    }
}

public class Test {
    public static void main(String[] args) {
        Child c = new Child();
    }
}
```

输出：

```text
Parent 无参构造
Child 无参构造
```

## 2. 父类没有无参构造时怎么办

如果父类**只定义了带参构造方法**，而没有显式定义无参构造方法，那么编译器**不会**为父类自动生成默认无参构造方法。此时子类构造方法如果仍然隐式调用 `super()`，就会编译报错。

```java
class Parent {
    String name;

    // 只有带参构造，没有无参构造
    Parent(String name) {
        this.name = name;
    }
}

class Child extends Parent {
    Child() {
        // 错误：Implicit super constructor Parent() is undefined
        // 必须显式调用父类带参构造
    }
}
```

正确做法：

```java
class Child extends Parent {
    Child() {
        super("default"); // 显式调用父类带参构造
    }
}
```

## 3. `super(...)` 与 `this(...)` 的约束

- `super(...)` 和 `this(...)` 都必须是构造方法中的**第一条语句**。
- 同一个构造方法中，`super(...)` 和 `this(...)` **不能同时出现**。
- 如果构造方法中显式使用了 `this(...)`，则该构造方法不会再隐式调用 `super()`，但 `this(...)` 指向的另一个构造方法最终必须能够调用到 `super(...)`。

```java
class Child extends Parent {
    Child() {
        this(10); // 调用本类其他构造方法
    }

    Child(int age) {
        super(); // 最终仍要调用父类构造
    }
}
```

## 4. 构造方法的执行顺序

创建一个子类对象时，构造方法的执行顺序是：

1. **父类静态代码块 / 静态变量初始化**（只执行一次）
2. **子类静态代码块 / 静态变量初始化**（只执行一次）
3. **父类构造代码块 / 实例变量初始化**
4. **父类构造方法**
5. **子类构造代码块 / 实例变量初始化**
6. **子类构造方法**

```java
class Parent {
    static { System.out.println("Parent 静态代码块"); }
    { System.out.println("Parent 构造代码块"); }
    Parent() { System.out.println("Parent 构造方法"); }
}

class Child extends Parent {
    static { System.out.println("Child 静态代码块"); }
    { System.out.println("Child 构造代码块"); }
    Child() { System.out.println("Child 构造方法"); }
}

// 输出：
// Parent 静态代码块
// Child 静态代码块
// Parent 构造代码块
// Parent 构造方法
// Child 构造代码块
// Child 构造方法
```

## 5. 父类构造方法中调用被子类重写的方法

**危险操作**：如果在父类构造方法中调用了被子类重写的方法，而子类重写方法中访问了子类自己的实例变量，这些变量可能还没有初始化（因为父类构造先于子类构造执行），从而导致异常或不符合预期的结果。

```java
class Parent {
    Parent() {
        init(); // 调用的是子类重写后的 init()
    }

    void init() {
        System.out.println("Parent.init");
    }
}

class Child extends Parent {
    int value = 10;

    @Override
    void init() {
        System.out.println("Child.init, value=" + value); // value 可能还是 0
    }
}
```

因此，**一般不建议在构造方法中调用非 final / 非 private 的方法**。

## 6. 常见面试题总结

| 问题 | 答案 |
|------|------|
| 子类构造方法会先调用父类构造方法吗？ | 会，编译器默认在第一行插入 `super()` |
| 父类没有无参构造时子类怎么办？ | 必须显式调用父类的带参构造 `super(...)` |
| `super()` 和 `this()` 能同时出现吗？ | 不能，且都必须是第一条语句 |
| 构造方法可以继承吗？ | 不能，构造方法不属于成员方法，不能被继承，但可以通过 `super()` 调用 |
| 抽象类有构造方法吗？ | 有，抽象类虽然不能直接实例化，但其构造方法会供子类调用 |

## 7. 小结

- 子类构造方法执行前，必须先完成父类构造方法的执行。
- 默认调用 `super()`，父类没有无参构造时必须显式 `super(...)`。
- `super(...)` / `this(...)` 必须是构造方法第一条语句，且不能共存。
- 注意构造方法中调用可重写方法可能带来的初始化问题。
