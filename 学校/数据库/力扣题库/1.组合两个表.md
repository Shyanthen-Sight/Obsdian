# 组合两个表：LEFT JOIN 保留左表全部行

> [!info] 原题
> LeetCode · 175. 组合两个表
> [题目链接](https://leetcode.cn/problems/combine-two-tables/)

> [!summary] 速记版
> ```sql
> SELECT
>     p.firstName,
>     p.lastName,
>     a.city,
>     a.state
> FROM Person AS p
> LEFT JOIN Address AS a
>     ON p.personId = a.personId;
> ```
> - 题目要「`Person` 表里的**每个人**」→ 左表必须是 `Person`，且必须用 **`LEFT JOIN`**。
> - `ON p.personId = a.personId`：两表靠 `personId` 对应，一个 `personId` 至多一条地址。
> - 右表匹配不到时由数据库**自动补 `NULL`**，不用 `IFNULL` / `COALESCE`。
> - 列顺序必须是 `firstName, lastName, city, state`，写错判错。
> - 用 `INNER JOIN` 会丢掉没有地址的人；左右表写反也会丢。

## 考察内容

- **外连接**：`LEFT JOIN` / `RIGHT JOIN` / `INNER JOIN` 的行保留规则。
- **连接条件**：`ON` 与 `WHERE` 的区别，尤其是外连接里不能把右表条件写进 `WHERE`。
- **`NULL` 语义**：左连接未匹配行填 `NULL`，以及 `NULL` 参与比较、计数时的行为。
- **主键与唯一性**：`personId` 是 `Person` 主键、`addressId` 是 `Address` 主键，保证连接后不产生重复行。
- **结果集列顺序**：`SELECT` 的列顺序即输出列顺序，必须与题目一致。

## 一、题目要求

`Person` 表：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| personId    | int     |
| lastName    | varchar |
| firstName   | varchar |
+-------------+---------+
personId 是该表的主键（唯一值）。
```

`Address` 表：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| addressId   | int     |
| personId    | int     |
| city        | varchar |
| state       | varchar |
+-------------+---------+
addressId 是该表的主键（唯一值）。
```

要求：报告 `Person` 表中**每个人**的姓、名、城市、州；若某人的 `personId` 在 `Address` 中不存在，城市和州报告 `null`。结果顺序任意。

**示例输入：**

`Person`：

```
+----------+----------+-----------+
| personId | lastName | firstName |
+----------+----------+-----------+
| 1        | Wang     | Allen     |
| 2        | Alice    | Bob       |
+----------+----------+-----------+
```

`Address`：

```
+-----------+----------+---------------+------------+
| addressId | personId | city          | state      |
+-----------+----------+---------------+------------+
| 1         | 2        | New York City | New York   |
| 2         | 3        | Leetcode      | California |
+-----------+----------+---------------+------------+
```

**示例输出：**

```
+-----------+----------+---------------+----------+
| firstName | lastName | city          | state    |
+-----------+----------+---------------+----------+
| Allen     | Wang     | NULL          | NULL     |
| Bob       | Alice    | New York City | New York |
+-----------+----------+---------------+----------+
```

- `personId = 1`（Allen）在 `Address` 里没有记录 → 城市、州为 `NULL`。
- `Address` 里 `personId = 3` 在 `Person` 里没有对应的人 → 不出现在结果中。

## 二、结论先行

```sql
SELECT
    p.firstName,
    p.lastName,
    a.city,
    a.state
FROM Person AS p
LEFT JOIN Address AS a
    ON p.personId = a.personId;
```

**一句话原理：`LEFT JOIN` 保留左表（`Person`）的全部行，右表按 `personId` 去匹配；匹配不到就把右表列填成 `NULL`。** 这正好同时满足「报告每个人」和「没有地址则报 `null`」两个要求。

## 三、为什么必须是 `LEFT JOIN`

| 连接方式 | 保留哪些行 | 本题结果 |
| --- | --- | --- |
| `INNER JOIN` | 两表都能匹配上的行 | ❌ Allen 被丢掉，只剩 Bob |
| `LEFT JOIN`（`Person` 在左） | 左表全部 + 能匹配的右表 | ✅ 正确答案 |
| `RIGHT JOIN`（`Address` 在左） | 右表全部 | ❌ Allen 丢失，还多出 `personId=3` |
| `FULL OUTER JOIN` | 两边全部 | ❌ 多出 `personId=3`，且 MySQL 不支持 |

关键判断：**谁是「必须全部出现」的表，谁就放在 `LEFT JOIN` 的左边。** 本题是 `Person`。

## 四、逐行拆解

| 片段 | 作用 | 为什么不能少 / 不能改 |
| --- | --- | --- |
| `FROM Person AS p` | 左表（驱动表） | 必须让 `Person` 当左表，否则会丢人 |
| `LEFT JOIN Address AS a` | 左外连接右表 | 换成 `INNER JOIN` 会丢无地址的人 |
| `ON p.personId = a.personId` | 连接条件 | 两表唯一对应的键，写错会笛卡尔积或匹配不上 |
| `SELECT p.firstName, ...` | 指定输出列 | 顺序必须是 姓/名/城市/州，且用表别名前缀避免歧义 |

### `ON` 和 `WHERE` 的区别

```sql
-- ✅ 正确：右表的匹配条件写在 ON 里，左表行照样保留
FROM Person AS p
LEFT JOIN Address AS a ON p.personId = a.personId

-- ❌ 错误：把右表过滤写进 WHERE，左连接会被"退化成"内连接
FROM Person AS p
LEFT JOIN Address AS a ON p.personId = a.personId
WHERE a.city IS NOT NULL;   -- Allen 会被过滤掉
```

`WHERE` 是在连接**之后**过滤整行结果；把右表条件放进 `WHERE`（除了 `IS NULL` 这类专门做反连接的写法），等于要求右表必须存在，`LEFT JOIN` 就白写了。

### 为什么会自动出 `NULL`

- 左连接对左表每一行做一个匹配尝试。
- 匹配成功 → 输出右表对应列。
- 匹配失败 → 右表所有列在该行输出 `NULL`。
- 这是连接语义的一部分，**不需要也不应该**手动 `IFNULL(a.city, NULL)`。

## 五、常见坑

1. **用成 `INNER JOIN`**：无地址的人整行消失，输出少行，最典型的丢分点。
2. **左右表写反**：`Address LEFT JOIN Person` 会保留右侧多出来的地址记录，同时丢掉没地址的人，方向和内容全错。
3. **列顺序写错**：`SELECT` 的列顺序就是结果列顺序，必须是 `firstName, lastName, city, state`。
4. **右表条件写进 `WHERE`**：会让 `LEFT JOIN` 退化成 `INNER JOIN`（见上一节）。
5. **画蛇添足加 `IFNULL`**：`NULL` 本来就由左连接产生，再包一层不影响正确性，但没必要；若题目要求输出空字符串才需要。
6. **以为会重复**：本题 `Person.personId` 是主键、`Address.addressId` 是主键，一个 `personId` 至多一条地址，连接后不会重复。若 `Address` 的 `personId` 可能重复，结果才会膨胀，届时需要 `DISTINCT` 或先去重。
7. **`NULL` 不能用 `=` 比较**：`a.city = NULL` 永远不成立，判断空值要用 `IS NULL` / `IS NOT NULL`。

### 复盘：`JOIN` 默认就是 `INNER JOIN`（本题最典型错法）

```sql
-- ❌ 常见错解：JOIN 等于 INNER JOIN
SELECT p.firstName, p.lastName, a.city, a.state
FROM Person p
JOIN Address a ON p.personId = a.personId;
```

这版**只有一处错**，其余全部正确：

| 检查项 | 结论 |
| --- | --- |
| 列顺序 `firstName, lastName, city, state` | ✅ 正确 |
| 表别名 `Person p`（省略 `AS`） | ✅ MySQL 合法 |
| 连接键 `p.personId = a.personId` | ✅ 正确 |
| 列前缀 `p.` / `a.` | ✅ 防歧义，好习惯 |
| 连接类型 `JOIN` | ❌ 等于 `INNER JOIN`，会丢行 |

**走一遍示例数据：**

- `Person` 里 `personId = 1`（Allen）→ `Address` 查不到 → **整行被丢掉**
- `personId = 2`（Bob）→ 能匹配 → 保留
- `Address` 里 `personId = 3` → `Person` 没有 → 也不保留

最终只输出 Bob 一行，而题目要求 2 行（Allen 的 `city/state` 应为 `NULL`）→ **Wrong Answer**。

**修正：只改连接类型，其它一行都不用动。**

```sql
-- ✅ 正确
SELECT p.firstName, p.lastName, a.city, a.state
FROM Person p
LEFT JOIN Address a ON p.personId = a.personId;
```

> [!warning] 「侥幸通过」的陷阱
> 如果测试数据里**每个人恰好都有地址**，`INNER JOIN` 的结果和正确答案完全一样，会让人误以为写对了。
> 而力扣的隐藏用例**故意**放了没有地址的人（示例里的 Allen 就是提示），所以必然判错。
> 判断口诀：题目只要出现「**所有 / 每个 / 即使……也要保留**」，就优先考虑 `LEFT JOIN`。

## 六、其他等价写法

```sql
-- 1) 用 USING，连接键同名时可简写（结果列里 personId 只出现一次）
SELECT firstName, lastName, city, state
FROM Person
LEFT JOIN Address USING (personId);

-- 2) 不加别名，直接用表名限定（列名不冲突时其实可省略前缀）
SELECT Person.firstName, Person.lastName, Address.city, Address.state
FROM Person
LEFT JOIN Address ON Person.personId = Address.personId;
```

三种写法结果完全一致；生产代码推荐别名 + 显式列名，可读性和可维护性最好。

## 七、记忆口诀

> **要「全部的人」就 `LEFT JOIN`，左表放人、右表放地址。**
> **匹配不到自动 `NULL`，右表条件别进 `WHERE`。**
> **列顺序照题目，姓、名、city、state 不能乱。**
