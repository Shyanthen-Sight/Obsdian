# 条件函数 —— IF、CASE、IFNULL 与 NULL 处理

> [!abstract] 一句话
> SQL 里的"条件"不是 `if` 语句，而是**表达式**：`IF(条件, 值1, 值2)`、`CASE WHEN ... THEN ... END`、`IFNULL`、`COALESCE`、`NULLIF`。它们只做三件事：**分支**（满足条件走哪条路）、**兜底**（NULL 换成什么）、**判定**（是不是 NULL）。

---

## 一、五种条件表达式总览

| 表达式 | 参数 | 作用 | 典型场景 |
| --- | --- | --- | --- |
| `IF(cond, a, b)` | 3 个 | 条件为真取 `a`，否则取 `b` | 简单二选一 |
| `IFNULL(a, b)` | 2 个 | `a` 是 NULL 就取 `b`，否则取 `a` | 单列兜底 |
| `COALESCE(a, b, ...)` | 2 个以上 | 取**第一个非 NULL** | 多列兜底 |
| `NULLIF(a, b)` | 2 个 | `a = b` 时返回 NULL，否则返回 `a` | 防除零、哨兵值转 NULL |
| `CASE ... END` | 多分支 | 简单分支 / 搜索分支 | 多条件、行转列 |
| `ISNULL(a)` | 1 个 | 是 NULL 返回 1，否则 0 | 布尔判断 |

> [!tip] 选型口诀
> **二选一用 `IF`，单列兜底用 `IFNULL`，多列兜底用 `COALESCE`，相等变 NULL 用 `NULLIF`，多分支用 `CASE`。**
> 超过两个分支就别嵌套 `IF` 了，`CASE` 可读性高一个量级。

## 二、`IF`：最简单的二选一

```sql
IF(expr1, expr2, expr3)
```

| 参数 | 含义 |
| --- | --- |
| `expr1` | 条件。**非 0 且非 NULL** 视为真 |
| `expr2` | 条件为真时返回的值 |
| `expr3` | 条件为假或为 NULL 时返回的值 |

```sql
SELECT IF(1 = 1, '真', '假');        -- '真'
SELECT IF(1 = 2, '真', '假');        -- '假'
SELECT IF(NULL, '真', '假');         -- '假'（NULL 走 else 分支）
SELECT IF(1, '真', '假');            -- '真'
SELECT IF(0, '真', '假');            -- '假'
```

```sql
SELECT name, salary,
       IF(salary >= 10000, '高薪', '普通') AS 薪资档位
FROM emp;
```

```
+--------+----------+----------+
| name   | salary   | 薪资档位 |
+--------+----------+----------+
| 张伟   | 12000.00 | 高薪     |
| 李娜   |  9000.00 | 普通     |
| 王强   | 15000.00 | 高薪     |
| 赵敏   |  8000.00 | 普通     |
| 陈晨   |  6500.00 | 普通     |
| 刘洋   |  7500.00 | 普通     |
| 孙悦   |  7000.00 | 普通     |
| 周杰   |  9500.00 | 普通     |
+--------+----------+----------+
```

> [!danger] `IF` 的条件是"非 0 且非 NULL"
> 不是"非空字符串"，也不是"非 FALSE 关键字"。
> ```sql
> SELECT IF('0', '真', '假');      -- '假'（字符串 '0' 转数字是 0）
> SELECT IF('abc', '真', '假');    -- '假'（'abc' 转数字是 0，附 warning）
> SELECT IF(' ', '真', '假');      -- '假'（空格转数字是 0）
> ```
> 条件尽量写成明确的比较：`IF(score > 60, ...)`，不要写 `IF(score, ...)` 依赖隐式转换。

### 2.1 嵌套 `IF`

```sql
SELECT name, salary,
       IF(salary >= 15000, 'A',
          IF(salary >= 10000, 'B',
             IF(salary >= 8000, 'C', 'D'))) AS 等级
FROM emp;
```

> [!warning] 嵌套超过两层就该换 `CASE`
> 嵌套 `IF` 的括号和缩进很容易看错，尤其是条件有交叉时。
> 上面的逻辑用 `CASE` 写出来更直白（见第五节）。

### 2.2 `IF` 不是 `IF ... THEN` 语句

```sql
-- ❌ 语法错误：IF 语句只能在存储过程 / 函数 / 触发器里用
IF (salary > 10000) THEN
    ...
END IF;

-- ✅ 在普通 SQL 里，IF 是函数，返回一个值
SELECT IF(salary > 10000, '高薪', '普通') FROM emp;
```

> [!note] 两种 `IF` 别混淆
> - `IF()`：**函数**，写在表达式里，任何 SQL 都能用
> - `IF ... THEN ... END IF`：**语句**，只能出现在 `CREATE PROCEDURE` / `CREATE FUNCTION` / 触发器 / 事件里
>
> 日常查询用的是前者。

## 三、`IFNULL` 与 `COALESCE`：NULL 兜底

### 3.1 `IFNULL(a, b)`

```sql
IFNULL(expr1, expr2)
```

规则：`expr1` 不是 NULL → 返回 `expr1`；`expr1` 是 NULL → 返回 `expr2`。

```sql
SELECT IFNULL(NULL, '兜底');        -- '兜底'
SELECT IFNULL('有值', '兜底');      -- '有值'
SELECT IFNULL(NULL, NULL);          -- NULL
SELECT IFNULL(0, '兜底');           -- 0（0 不是 NULL）
SELECT IFNULL('', '兜底');          -- ''（空串不是 NULL）
```

```sql
SELECT name, bonus,
       IFNULL(bonus, 0) AS 奖金
FROM emp;
```

```
+--------+---------+---------+
| name   | bonus   | 奖金    |
+--------+---------+---------+
| 张伟   | 5000.00 | 5000.00 |
| 李娜   | NULL    |    0.00 |
| 王强   | 8000.00 | 8000.00 |
| 赵敏   | 3000.00 | 3000.00 |
| 陈晨   | NULL    |    0.00 |
| 刘洋   | 3000.00 | 3000.00 |
| 孙悦   | NULL    |    0.00 |
| 周杰   | 4000.00 | 4000.00 |
+--------+---------+---------+
```

> [!warning] `0` 和 `''` 都不是 NULL
> `IFNULL(0, 100)` 返回 `0`，`IFNULL('', '无')` 返回 `''`。
> 如果业务上"0 也算没填"，要先 `NULLIF(col, 0)` 再 `IFNULL`：
> ```sql
> SELECT IFNULL(NULLIF(bonus, 0), 0) FROM emp;
> ```

### 3.2 `COALESCE(a, b, ...)`

```sql
COALESCE(value1, value2, ...)
```

规则：从左到右，返回**第一个非 NULL** 的值；全是 NULL 才返回 NULL。

```sql
SELECT COALESCE(NULL, NULL, 'x');       -- 'x'
SELECT COALESCE(NULL, 'y', 'x');        -- 'y'
SELECT COALESCE('z', 'y', 'x');         -- 'z'
SELECT COALESCE(NULL, NULL, NULL);      -- NULL
```

```sql
-- 奖金没有就用工资兜底，再没有就 0
SELECT name,
       COALESCE(bonus, salary, 0) AS 兜底金额
FROM emp;
```

```
+--------+----------+
| name   | 兜底金额 |
+--------+----------+
| 张伟   |  5000.00 |
| 李娜   |  9000.00 |
| 王强   |  8000.00 |
| 赵敏   |  3000.00 |
| 陈晨   |  6500.00 |
| 刘洋   |  3000.00 |
| 孙悦   |  7000.00 |
| 周杰   |  4000.00 |
+--------+----------+
```

### 3.3 `IFNULL` vs `COALESCE`

| 对比项 | `IFNULL` | `COALESCE` |
| --- | --- | --- |
| 参数个数 | **恰好 2 个** | 2 个及以上 |
| 标准 SQL | ❌ MySQL 方言 | ✅ 标准 SQL |
| 可移植性 | 差（Oracle 用 `NVL`，SQL Server 用 `ISNULL`） | 好 |
| 语义 | 两选一 | 取第一个非 NULL |
| 推荐场景 | 简单单列兜底 | 多列兜底、跨库代码 |

```sql
-- 两者等价
SELECT IFNULL(a, b);
SELECT COALESCE(a, b);
```

> [!tip] 写跨库代码时优先 `COALESCE`
> PostgreSQL、Oracle、SQL Server 都支持 `COALESCE`；`IFNULL` 只有 MySQL / SQLite 有。
> 但 `COALESCE` 参数多，表达式会稍微长一点，单列兜底用 `IFNULL` 也无妨。

> [!danger] 在索引列上用 `IFNULL` 会让索引失效
> ```sql
> -- ❌ 索引失效
> SELECT * FROM emp WHERE IFNULL(bonus, 0) > 0;
>
> -- ✅ 语义相同，能走索引（NULL > 0 本来就是 UNKNOWN，不会命中）
> SELECT * FROM emp WHERE bonus > 0;
> ```
> `COALESCE` 同理。能改写成直接比较就改。

## 四、`NULLIF`：相等就变 NULL

```sql
NULLIF(expr1, expr2)
```

规则：`expr1 = expr2` 为真 → 返回 `NULL`；否则返回 `expr1`。
等价于：

```sql
CASE WHEN expr1 = expr2 THEN NULL ELSE expr1 END
```

```sql
SELECT NULLIF(1, 1);          -- NULL
SELECT NULLIF(1, 2);          -- 1
SELECT NULLIF('a', 'a');      -- NULL
SELECT NULLIF('a', 'b');      -- 'a'
SELECT NULLIF(NULL, 1);       -- NULL
```

### 4.1 防除零（最常用的场景）

```sql
-- ❌ 除数为 0 时得到 NULL，但表达式本身没有"防"的语义
SELECT total / count FROM t;

-- ✅ 除数为 0 时明确变 NULL，再交给 IFNULL 兜底
SELECT total / NULLIF(count, 0) AS 平均值 FROM t;
SELECT IFNULL(total / NULLIF(count, 0), 0) AS 平均值 FROM t;
```

```sql
SELECT 100 / NULLIF(0, 0);              -- NULL
SELECT IFNULL(100 / NULLIF(0, 0), 0);   -- 0
SELECT 100 / NULLIF(5, 0);              -- 20
```

> [!tip] 为什么用 `NULLIF(b, 0)` 而不是 `IF(b=0, NULL, b)`
> 两者语义一样，但 `NULLIF` 更短，而且标准 SQL 支持。
> 它在"聚合函数的分母可能是 0"时特别有用：
> ```sql
> SELECT SUM(bonus) / NULLIF(COUNT(bonus), 0) FROM emp;
> ```

### 4.2 把哨兵值转成 NULL

```sql
-- 把 0 当成"未填写"
SELECT name, NULLIF(bonus, 0) AS 有效奖金 FROM emp;

-- 把空串当成"未填写"
SELECT name, NULLIF(nickname, '') AS 有效昵称 FROM customer;
```

> [!note] `NULLIF` 返回的是第一个参数的类型
> `NULLIF(1, 1)` 返回 NULL，但类型仍是数值；`NULLIF('a','a')` 返回 NULL，类型是字符串。
> 后续参与运算时，注意 NULL 的传染性。

## 五、`CASE`：多分支的主力

### 5.1 两种写法

**简单 `CASE`**（等值判断）：

```sql
CASE 表达式
    WHEN 值1 THEN 结果1
    WHEN 值2 THEN 结果2
    ELSE 默认结果
END
```

**搜索 `CASE`**（任意条件判断）：

```sql
CASE
    WHEN 条件1 THEN 结果1
    WHEN 条件2 THEN 结果2
    ELSE 默认结果
END
```

| 写法 | 适合 | 示例 |
| --- | --- | --- |
| 简单 `CASE` | 一个字段等于几个固定值 | `CASE dept WHEN '研发部' THEN ...` |
| 搜索 `CASE` | 范围、组合条件、NULL 判断 | `CASE WHEN salary >= 10000 THEN ...` |

### 5.2 简单 `CASE`：状态码映射

```sql
SELECT name, dept,
       CASE dept
           WHEN '研发部' THEN '技术'
           WHEN '销售部' THEN '业务'
           ELSE '职能'
       END AS 部门类型
FROM emp;
```

```
+--------+--------+----------+
| name   | dept   | 部门类型 |
+--------+--------+----------+
| 张伟   | 研发部 | 技术     |
| 李娜   | 研发部 | 技术     |
| 王强   | 研发部 | 技术     |
| 赵敏   | 销售部 | 业务     |
| 陈晨   | 销售部 | 业务     |
| 刘洋   | 销售部 | 业务     |
| 孙悦   | 财务部 | 职能     |
| 周杰   | 财务部 | 职能     |
+--------+--------+----------+
```

> [!danger] 简单 `CASE` 遇 NULL 不会匹配
> ```sql
> SELECT CASE NULL WHEN NULL THEN '相等' ELSE '不相等' END;
> -- 结果：'不相等'
> ```
> 因为简单 `CASE` 内部用的是 `=`，而 `NULL = NULL` 是 UNKNOWN，不是 TRUE。
> 要判断 NULL，必须用搜索 `CASE`：
> ```sql
> SELECT CASE WHEN col IS NULL THEN '空' ELSE col END FROM t;
> ```

### 5.3 搜索 `CASE`：范围分级

```sql
SELECT name, salary,
       CASE
           WHEN salary >= 15000 THEN 'A'
           WHEN salary >= 10000 THEN 'B'
           WHEN salary >= 8000  THEN 'C'
           ELSE 'D'
       END AS 等级
FROM emp
ORDER BY salary DESC;
```

```
+--------+----------+------+
| name   | salary   | 等级 |
+--------+----------+------+
| 王强   | 15000.00 | A    |
| 张伟   | 12000.00 | B    |
| 周杰   |  9500.00 | C    |
| 李娜   |  9000.00 | C    |
| 赵敏   |  8000.00 | C    |
| 刘洋   |  7500.00 | D    |
| 孙悦   |  7000.00 | D    |
| 陈晨   |  6500.00 | D    |
+--------+----------+------+
```

> [!important] `CASE` 是**从上到下短路匹配**
> 第一个为真的 `WHEN` 命中后，后面的分支不再判断。
> 所以范围条件要**从大到小**写：先 `>= 15000`，再 `>= 10000`，最后 `>= 8000`。
> 如果顺序反过来，所有人都会先命中 `>= 8000`，后面的分支永远走不到。

### 5.4 没有 `ELSE` 会返回 `NULL`

```sql
SELECT CASE WHEN 1 = 2 THEN '命中' END;   -- NULL
```

> [!warning] 省略 `ELSE` 不是"返回空字符串"
> 是返回 `NULL`。后续拼接、计算都会被 NULL 传染。
> 除非你确实想用 NULL 表示"不匹配"，否则把 `ELSE` 写全。

### 5.5 `CASE` 的返回类型

```sql
CASE
    WHEN cond1 THEN 1
    WHEN cond2 THEN 'a'
END
```

> [!note] 所有分支的类型会被统一推断
> 数字和字符串混用可能触发隐式转换，结果类型不一定是你想要的。
> 养成习惯：**同一条 `CASE` 里所有 `THEN` / `ELSE` 返回同一类型**（全是数字或全是字符串）。

## 六、条件聚合与行转列（重点）

把 `CASE` 塞进聚合函数，可以在**一次扫描**里算出多个维度的指标，这是报表 SQL 的核心技巧。

### 6.1 按部门统计男女与空奖金人数

```sql
SELECT dept,
       COUNT(*) AS 人数,
       SUM(CASE WHEN gender = 'M' THEN 1 ELSE 0 END) AS 男,
       SUM(CASE WHEN gender = 'F' THEN 1 ELSE 0 END) AS 女,
       COUNT(CASE WHEN gender = 'M' THEN 1 END)      AS 男_另一种写法,
       SUM(CASE WHEN bonus IS NULL THEN 1 ELSE 0 END) AS 无奖金人数,
       IFNULL(SUM(bonus), 0) AS 奖金总额
FROM emp
GROUP BY dept;
```

```
+--------+------+------+------+----------------+------------+----------+
| dept   | 人数 | 男   | 女   | 男_另一种写法  | 无奖金人数 | 奖金总额 |
+--------+------+------+------+----------------+------------+----------+
| 研发部 |    3 |    2 |    1 |              2 |          1 | 13000.00 |
| 销售部 |    3 |    1 |    2 |              1 |          1 |  6000.00 |
| 财务部 |    2 |    1 |    1 |              1 |          1 |  4000.00 |
+--------+------+------+------+----------------+------------+----------+
```

验算：
- 研发部：张伟（M）、李娜（F）、王强（M）→ 男 2、女 1；李娜无奖金 → 1；奖金 5000 + 8000 = 13000。
- 销售部：赵敏（F）、陈晨（M）、刘洋（F）→ 男 1、女 2；陈晨无奖金 → 1；奖金 3000 + 3000 = 6000。
- 财务部：孙悦（F）、周杰（M）→ 男 1、女 1；孙悦无奖金 → 1；奖金 4000。

### 6.2 `SUM(CASE ... ELSE 0)` vs `COUNT(CASE ...)`

| 写法 | 匹配行数 | 空集 / 全不匹配时 |
| --- | --- | --- |
| `SUM(CASE WHEN cond THEN 1 ELSE 0 END)` | 匹配行数 | **`NULL`**（没有行可 SUM） |
| `COUNT(CASE WHEN cond THEN 1 END)` | 匹配行数 | `0` |
| `COUNT(CASE WHEN cond THEN 1 ELSE 0 END)` | **总行数** | 总行数（0 不是 NULL，全被数进去） |
| `COUNT(*)` | 总行数 | `0` |

> [!danger] `COUNT(CASE WHEN ... THEN 1 ELSE 0 END)` 是最经典的错误
> 你以为在数"满足条件的行"，其实 `ELSE 0` 让**每一行都返回了非 NULL 值**，`COUNT` 把全部行都数进去。
> 只数匹配行：**要么不写 `ELSE`，要么用 `SUM(... ELSE 0)`**。
> ```sql
> -- ❌ 返回总行数 8
> SELECT COUNT(CASE WHEN gender = 'M' THEN 1 ELSE 0 END) FROM emp;
>
> -- ✅ 返回 4
> SELECT COUNT(CASE WHEN gender = 'M' THEN 1 END) FROM emp;
> -- ✅ 也返回 4
> SELECT SUM(CASE WHEN gender = 'M' THEN 1 ELSE 0 END) FROM emp;
> ```

> [!warning] `SUM(... ELSE 0)` 在空集上返回 NULL
> ```sql
> SELECT SUM(CASE WHEN 1 = 0 THEN 1 ELSE 0 END) FROM emp WHERE 1 = 0;
> -- NULL，不是 0
> ```
> 报表里套一层 `IFNULL(SUM(...), 0)`，否则前端会显示 `null`。

### 6.3 条件平均

```sql
SELECT dept,
       ROUND(AVG(salary), 2) AS 全员平均,
       ROUND(AVG(CASE WHEN gender = 'M' THEN salary END), 2) AS 男平均,
       ROUND(AVG(CASE WHEN gender = 'F' THEN salary END), 2) AS 女平均
FROM emp
GROUP BY dept;
```

```
+--------+----------+----------+----------+
| dept   | 全员平均 | 男平均   | 女平均   |
+--------+----------+----------+----------+
| 研发部 | 12000.00 | 13500.00 |  9000.00 |
| 销售部 |  7333.33 |  6500.00 |  7750.00 |
| 财务部 |  8250.00 |  9500.00 |  7000.00 |
+--------+----------+----------+----------+
```

验算：研发部男 `(12000+15000)/2 = 13500`；销售部女 `(8000+7500)/2 = 7750`；财务部男 `9500`、女 `7000`。

> [!danger] 条件平均的 `CASE` **绝对不要加 `ELSE 0`**
> `AVG(CASE WHEN gender='M' THEN salary ELSE 0 END)` 会把女员工的 0 也算进分母，男性平均被稀释。
> 不写 `ELSE` 时，不匹配的行返回 NULL，`AVG` 自动忽略 NULL，分母才是正确的"男性人数"。
> 详见 [[AVG]]。

### 6.4 行转列（Pivot）

```sql
SELECT
    SUM(CASE WHEN dept = '研发部' THEN salary ELSE 0 END) AS 研发部,
    SUM(CASE WHEN dept = '销售部' THEN salary ELSE 0 END) AS 销售部,
    SUM(CASE WHEN dept = '财务部' THEN salary ELSE 0 END) AS 财务部
FROM emp;
```

```
+----------+----------+----------+
| 研发部   | 销售部   | 财务部   |
+----------+----------+----------+
| 36000.00 | 22000.00 | 16500.00 |
+----------+----------+----------+
```

验算：研发 12000+9000+15000=36000；销售 8000+6500+7500=22000；财务 7000+9500=16500。

> [!tip] 行转列的前提是"列名固定"
> `CASE` 里写了几个部门，结果就只有几列。部门会动态增加时，SQL 得动态拼，或者干脆在应用层透视。
> MySQL 没有 `PIVOT` 关键字，靠的就是 `SUM(CASE ...)`。

## 七、`CASE` 的其他实用场景

### 7.1 自定义排序

```sql
SELECT name, dept, salary
FROM emp
ORDER BY CASE dept
             WHEN '研发部' THEN 1
             WHEN '销售部' THEN 2
             ELSE 3
         END,
         salary DESC;
```

结果顺序：研发部（王强、张伟、李娜）→ 销售部（赵敏、刘洋、陈晨）→ 财务部（周杰、孙悦）。

> [!note] `CASE` 排序会产生 `filesort`
> 它按计算出来的序号排序，索引帮不上忙。数据量大时，更稳的做法是建一张部门排序字典表，然后 `JOIN` 排序。
> 小结果集、后台报表里用 `CASE` 完全够。

### 7.2 按条件更新

```sql
UPDATE emp
SET salary = salary * CASE
    WHEN dept = '研发部' THEN 1.10
    WHEN dept = '销售部' THEN 1.05
    ELSE 1.03
END;
```

> [!danger] 这条 `UPDATE` 没有 `WHERE`，会改全表
> 生产环境执行前先 `SELECT` 验证、开事务、做好备份。
> 想只改部分人，补 `WHERE`；改完用 `SELECT` 核对。

### 7.3 在 `WHERE` 里用 `CASE`（不推荐）

```sql
-- ❌ 能跑，但索引失效，可读性也差
SELECT * FROM emp
WHERE CASE WHEN dept = '研发部' THEN salary ELSE 0 END > 10000;

-- ✅ 改写成普通条件
SELECT * FROM emp
WHERE dept = '研发部' AND salary > 10000;
```

> [!warning] `CASE` / `IF` / `IFNULL` 套在索引列上，索引一律失效
> `WHERE` 的目标是**让优化器用上索引**，能写成 `AND` / `OR` / `IN` / 范围，就别写函数。

### 7.4 在 `HAVING` 里用条件聚合

```sql
SELECT dept
FROM emp
GROUP BY dept
HAVING SUM(CASE WHEN gender = 'M' THEN 1 ELSE 0 END) >= 2;
```

结果：只有研发部（男 2 人）。

> [!note] `HAVING` 能引用聚合结果
> `SUM(CASE ...)` 是聚合表达式，放在 `HAVING` 里合法；放在 `WHERE` 里会报 `ERROR 1111`。
> 详见 [[Where]] 和 [[计算机类/数据库/Mysql/Data Query Language/聚合查询/HAVING]]。

### 7.5 在 `SELECT` 里做展示层转换

```sql
SELECT name,
       CASE gender
           WHEN 'M' THEN '男'
           WHEN 'F' THEN '女'
           ELSE '未知'
       END AS 性别,
       CASE WHEN bonus IS NULL THEN '未发放' ELSE '已发放' END AS 奖金状态
FROM emp;
```

> [!tip] 展示转换放 SQL 还是应用层？
> 单表查询、报表导出放 SQL 方便；多语言、复杂文案放应用层。
> 状态码映射最好建字典表，别在十几条 SQL 里各写一份 `CASE`。

## 八、三值逻辑：`CASE` 与 NULL 的关系

SQL 的条件只有三种结果：**TRUE / FALSE / UNKNOWN**。`NULL` 参与比较得到的是 UNKNOWN。

| 表达式 | 结果 |
| --- | --- |
| `NULL = NULL` | `UNKNOWN` |
| `NULL <> 1` | `UNKNOWN` |
| `NULL IS NULL` | `TRUE` |
| `NULL IS NOT NULL` | `FALSE` |

> [!important] UNKNOWN 在 `WHEN` / `IF` 里等同于"不成立"
> ```sql
> SELECT IF(NULL = NULL, '相等', '不相等');   -- '不相等'
> ```
> 所以判断 NULL 只能用 `IS NULL` / `IS NOT NULL`，不能写 `= NULL`。

区分"不匹配"和"值是 NULL"：

```sql
SELECT name,
       CASE
           WHEN gender = 'M' THEN '男'
           WHEN gender = 'F' THEN '女'
           ELSE '未知/NULL'
       END AS 性别
FROM emp;
```

> [!tip] 想分别处理 NULL
> ```sql
> CASE
>     WHEN gender IS NULL THEN '空值'
>     WHEN gender = 'M'   THEN '男'
>     WHEN gender = 'F'   THEN '女'
>     ELSE '其他'
> END
> ```
> `IS NULL` 必须放在最前面，否则 `gender = 'M'` 对 NULL 行返回 UNKNOWN，会落到 `ELSE`。

### 8.1 `ISNULL()` 函数

```sql
SELECT ISNULL(NULL);      -- 1
SELECT ISNULL(0);         -- 0
SELECT ISNULL('');        -- 0
SELECT ISNULL('abc');     -- 0
```

> [!note] `ISNULL()` 与 `IS NULL`
> `ISNULL(expr)` 返回 `1/0`，可以当布尔值用；`expr IS NULL` 是标准 SQL 谓词。
> 写跨库代码用 `IS NULL`；MySQL 内部短表达式用 `ISNULL()` 也行。
> 注意 SQL Server 的 `ISNULL(a,b)` 是"两参数兜底"，和 MySQL 的同名函数**语义完全不同**，别混淆。

## 九、性能与索引

> [!important] 核心原则：**条件表达式不要包住索引列**
> 索引里存的是列的原始值。`IFNULL(col, 0)`、`CASE WHEN col ...`、`IF(col ...)` 都会让优化器放弃索引。

```sql
-- ❌ 索引失效
SELECT * FROM emp WHERE IFNULL(bonus, 0) > 0;
SELECT * FROM emp WHERE IF(dept = '研发部', 1, 0) = 1;
SELECT * FROM emp WHERE CASE WHEN salary > 10000 THEN 1 ELSE 0 END = 1;

-- ✅ 改写成普通条件
SELECT * FROM emp WHERE bonus > 0;
SELECT * FROM emp WHERE dept = '研发部';
SELECT * FROM emp WHERE salary > 10000;
```

`IFNULL` 在 `WHERE` 里的正确改写：

```sql
-- 原意：status 为 NULL 时当作 0，取 status = 0 的行
-- ❌
WHERE IFNULL(status, 0) = 0
-- ✅
WHERE status = 0 OR status IS NULL
```

> [!tip] 条件表达式放在 `SELECT` 列表里没问题
> `SELECT IF(...)`、`SELECT CASE ... END` 只影响输出，不会让 `WHERE` 的索引失效。
> 真正要避免的是 `WHERE`、`JOIN ON`、`ORDER BY`、`GROUP BY` 里对索引列做运算。

### 9.1 条件聚合 vs 多次查询

```sql
-- ✅ 一次扫描算出男女
SELECT dept,
       SUM(gender = 'M') AS 男,
       SUM(gender = 'F') AS 女
FROM emp
GROUP BY dept;
```

> [!note] MySQL 里布尔表达式就是 0/1
> `gender = 'M'` 返回 `1/0`，`SUM` 一下就是人数。这比 `CASE` 更短。
> 但可读性和跨库兼容性不如 `CASE`；团队里统一一种写法即可。

```sql
-- 与上面等价，更标准
SELECT dept,
       SUM(CASE WHEN gender = 'M' THEN 1 ELSE 0 END) AS 男,
       SUM(CASE WHEN gender = 'F' THEN 1 ELSE 0 END) AS 女
FROM emp
GROUP BY dept;
```

## 十、常见错误合集

> [!danger] 坑一：`CASE` 简单写法判断 NULL
> `CASE NULL WHEN NULL THEN ...` 不会命中，因为 `NULL = NULL` 是 UNKNOWN。用搜索 `CASE` + `IS NULL`。

> [!danger] 坑二：`CASE` 范围顺序写反
> 先写 `WHEN salary >= 8000`，后面 `WHEN salary >= 15000` 永远不执行。范围条件从大到小（或从小到大）按你的分级逻辑排好。

> [!danger] 坑三：`COUNT(CASE ... ELSE 0 END)` 数了全表
> `ELSE 0` 让每行都非 NULL，`COUNT` 全数。只数匹配行就别写 `ELSE`，或用 `SUM(... ELSE 0)`。

> [!danger] 坑四：条件平均加了 `ELSE 0`
> `AVG(CASE WHEN cond THEN x ELSE 0 END)` 分母被撑大，结果偏小。不写 `ELSE`。

> [!danger] 坑五：`IF` 依赖隐式转换
> `IF('0', ...)` 走假分支，`IF('abc', ...)` 也是假。条件写成显式比较。

> [!failure] 坑六：`SUM(CASE ... ELSE 0)` 在空集返回 NULL
> 没有行时 `SUM` 返回 NULL，不是 0。外层套 `IFNULL`。

> [!failure] 坑七：`IFNULL` 在 `WHERE` 里让索引失效
> `WHERE IFNULL(col,0)=...` 改成 `col=... OR col IS NULL`。

> [!failure] 坑八：`IFNULL` 和 `COALESCE` 参数个数搞错
> `IFNULL(1,2,3)` 直接语法错误；多列兜底必须用 `COALESCE`。

> [!failure] 坑九：`NULLIF` 防除零后忘了兜底
> `100 / NULLIF(0,0)` 得到 NULL，前端可能直接崩。需要数值就 `IFNULL(..., 0)`。

> [!failure] 坑十：把 `IF` 当语句
> 普通 SQL 里没有 `IF ... THEN`，只有 `IF()` 函数；语句形式只能在存储程序里用。

> [!failure] 坑十一：`CASE` 分支类型混用
> 数字和字符串混在一起会触发隐式转换，结果可能出乎意料。所有 `THEN` / `ELSE` 保持同一类型。

> [!failure] 坑十二：`CASE` 没写 `ELSE`
> 不匹配时返回 NULL，不是空串。需要默认值就写全。

## 十一、速查表

| 需求 | 写法 | `emp` 表结果 |
| --- | --- | --- |
| 二选一 | `IF(cond, a, b)` | `IF(salary>=10000,'高薪','普通')` |
| 单列 NULL 兜底 | `IFNULL(a, b)` | `IFNULL(bonus, 0)` |
| 多列 NULL 兜底 | `COALESCE(a, b, ...)` | `COALESCE(bonus, salary, 0)` |
| 相等变 NULL | `NULLIF(a, b)` | `NULLIF(bonus, 0)` |
| 防除零 | `a / NULLIF(b, 0)` | `100 / NULLIF(0,0)` → NULL |
| 是否 NULL | `ISNULL(a)` / `a IS NULL` | `ISNULL(NULL)` → 1 |
| 等值分支 | `CASE col WHEN v THEN ... END` | 部门映射 |
| 范围分支 | `CASE WHEN cond THEN ... END` | 薪资分级 |
| 条件计数（匹配行） | `SUM(CASE WHEN cond THEN 1 ELSE 0 END)` | 男 2 / 女 1 |
| 条件计数（不写 ELSE） | `COUNT(CASE WHEN cond THEN 1 END)` | 男 2 / 女 1 |
| 条件求和 | `SUM(CASE WHEN cond THEN x ELSE 0 END)` | 部门工资合计 |
| 条件平均 | `AVG(CASE WHEN cond THEN x END)` | 男平均 13500 |
| 行转列 | `SUM(CASE WHEN dept='X' THEN x ELSE 0 END)` | 研发 36000 |
| 自定义排序 | `ORDER BY CASE ... END` | 研发→销售→财务 |
| 条件更新 | `SET col = CASE ... END` | 按部门调薪 |

> [!question] 自测三连
> 1. `IF(NULL, '真', '假')` 返回什么？`IF('0', '真', '假')` 呢？为什么？
> 2. `COUNT(CASE WHEN gender='M' THEN 1 ELSE 0 END)` 和 `COUNT(CASE WHEN gender='M' THEN 1 END)` 有什么区别？
> 3. `CASE NULL WHEN NULL THEN '相等' ELSE '不相等' END` 返回什么？怎么改才能正确判断 NULL？

---

> [!quote] 一句话记忆
> **`IF` 二选一、`IFNULL` 单列兜底、`COALESCE` 多列兜底、`NULLIF` 相等变 NULL、`CASE` 多分支**；`CASE` 判断 NULL 必须用 `IS NULL`（`= NULL` 永远不成立）；**条件计数只数匹配行就别写 `ELSE 0`**；**条件表达式别包住索引列**。
