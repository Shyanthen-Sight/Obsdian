# enum

> [!abstract] 一句话定义
> `enum`（枚举）把**一组具名常量**收拢在一个名字下——==它既声明类型，又在运行时生成真实对象==，是少数"编译后仍在产物里留痕"的类型。

---

## 一、基本用法

```ts
// 数字枚举：自动从 0 递增，且有反向映射
enum Direction { Up, Down, Left, Right }
Direction.Up        // 0
Direction[0]        // 'Up'（反向映射）

// 指定初值 / 手动赋值
enum Status { Ok = 200, NotFound = 404, Error = 500 }

// 字符串枚举：无反向映射，但可读性更好
enum Role { Admin = 'ADMIN', User = 'USER' }

// 常量枚举：编译期内联，不生成运行时对象
const enum Level { Low, High }
const l = Level.High      // 产物里直接变成 1
```

---

## 二、常见场景与注意事项

- 一组**相关的具名常量**：状态码、方向、角色、模式。
- 需要**反向映射**（数值 → 名字）或独立运行时对象时。

> [!tip] 用字面量联合替代 enum
> 若只是"固定的几个字符串"，==优先用 `type X = 'a' | 'b'`==：零运行时产物、写法更贴近普通 JS、无需导入。
> ```ts
> type Role = 'ADMIN' | 'USER'          // 多数场景的首选
> ```
> enum 的优势主要在数值反向映射与"命名空间式"组织。

> [!warning] `const enum` 有坑
> 它在编译期被**内联替换**，跨文件、跨编译配置（如 `isolatedModules`）时容易出问题，实践中越来越不推荐。

> [!note] enum 是"真实存在"的
> 不同于 interface/type 编译后被擦除，**枚举会生成运行时代码**（一个对象/IIFE），见 [[解析产物说明]]。

> [!warning] 数字枚举不够严格
> 数字枚举**接受任意数字**：`let d: Direction = 99` 居然合法。需要严格取值时用字符串枚举或字面量联合。

---

## 三、与其他类型的关系

| 关系 | 说明 |
| --- | --- |
| 枚举成员 → 枚举类型 | ✅ |
| 任意 `number` → 数字枚举 | ⚠️ 居然允许（不够严格） |
| 字符串枚举 | 只接受自身成员，更严格 |
| `enum` 与字面量联合 | 语义相近，联合更轻、无产物 |
| `enum` 与 `number` | 数字枚举成员可当数字用 |
| 编译产物 | 有（`const enum` 除外，被内联） |

---

## 四、小结

| 项目 | 内容 |
| --- | --- |
| 所属层级 | 对象类型（Object） |
| 关键字 | `enum` / `const enum` |
| 种类 | 数字枚举、字符串枚举、常量枚举、异构枚举（不推荐） |
| 运行时产物 | 有（常量枚举除外） |
| 反向映射 | 数字枚举有，字符串枚举无 |
| 常见陷阱 | 数字枚举接受任意数字、`const enum` 跨模块问题 |
| 替代方案 | 字面量联合 `type X = 'a' \| 'b'` |
