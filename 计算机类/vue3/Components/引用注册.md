

> [!abstract] 一句话
> 模板引用（Template Refs）是声明式模板的**逃生舱**：==在元素或组件标签上写 `ref="名字"`，Vue 就会在该组件**挂载之后**，把对应的 **DOM 元素**或**子组件实例**"登记"进一个同名变量里==。它是唯一一种"从模板反向拿到真实节点"的正规途径——平时你只描述"长什么样"，只有这里才允许你伸手去碰那个节点。

> [!info] 标题里的"引用"= ref
> 本笔记讲的是 **Template Refs**（模板引用），即 `ref` 这个**特殊 attribute**；不要和响应式里的 `ref()` 函数混为一谈——虽然它们常常成对出现。注册用的是 **attribute + 变量的名字匹配**，不是 `ref()` 本身。

---

## 一、为什么需要它：声明式也需要"手动挡"

Vue 的默认姿势是**声明式**：你改数据，Vue 去改 DOM，你从不亲自碰节点。但有些事**天生只能对着真实 DOM 做**——这时就需要一个"手动挡"。

```text
声明式（默认姿势）                    模板引用（手动挡）
  data 变了 → 模板自动重渲染           拿到真实 DOM / 组件实例 → 直接调
  <input :value="text">               inputEl.value.focus()
  只描述"长什么样"                     像 jQuery 那样亲手操作
  优点：可预测、好维护                  优点：能触达声明式表达不了的能力
```

需要真实节点的经典场景：

| 场景 | 为什么非它不可 |
| --- | --- |
| 让输入框**自动聚焦** | `focus()` 是 DOM 方法，模板里没有对应语法 |
| 播放 / 暂停 `<video>`、`<audio>` | 媒体控制是命令式 API |
| 测量元素**宽高、位置** | 要读 `getBoundingClientRect()` |
| 初始化**第三方库**（图表、地图、富文本、拖拽） | 库要求你递给它一个真实 DOM 容器 |
| 手动**滚动**到某处 | `scrollIntoView()` |
| 从外部调用**子组件的方法** | 要拿到子组件实例 |

> [!warning] 先别急着用它
> 模板引用是"逃生舱"，不是常用通道。**能用 props / emits / 计算属性表达的，就不要用 ref 去手搓 DOM**——那等于把 Vue 的声明式好处又还了回去。只在上述"声明式确实做不到"的场合才用。

## 二、DOM 元素的引用：两步注册

`<script setup>` 里，写法就两步，且**必须同名**：

```vue
<script setup>
import { ref, onMounted } from 'vue'

const inputEl = ref(null)          // ① 先声明一个 ref 变量

onMounted(() => {
  inputEl.value?.focus()           // ③ 挂载后才拿得到，才谈得上调用
})
</script>

<template>
  <!-- ② 标签上写 ref="inputEl"，名字和上面变量一模一样 -->
  <input ref="inputEl" />
</template>
```

```text
       <input ref="inputEl" />        ← 模板里的 ref attribute
                    │
                    │  编译器按"名字"连线
                    ▼
const inputEl = ref(null)             ← 脚本里的同名变量
                    │
                    │  组件挂载后
                    ▼
   inputEl.value === <input> 真实 DOM 元素
```

> [!success] 核心规则：`ref="X"` ↔ 脚本里的 `X`
> 在 `<script setup>` 中，模板上的 `ref="inputEl"` 会**自动**绑定到同名的顶层变量上。名字不一致，就绑不上，`inputEl.value` 永远是 `null`。

> [!tip] 初值为什么写 `null`
> 因为**挂载之前它根本没有值**。先声明成 `ref(null)`，等 Vue 挂载时再去"填充"它。写 `ref()` 也行，但显式 `null` 更能提醒你"这里可能是空的"。类型上写成 `ref<HTMLInputElement | null>(null)`，调用时才敢用 `?.` 或先判空。

## 三、`useTemplateRef()`：3.5+ 的新写法

Vue 3.5 起多了个组合式函数，把"名字匹配"从**隐式**改成**显式**：

```vue
<script setup>
import { useTemplateRef, onMounted } from 'vue'

// 直接传模板里那个名字的字符串
const inputEl = useTemplateRef('my-input')

onMounted(() => {
  inputEl.value?.focus()
})
</script>

<template>
  <!-- 名字可以和变量名完全不同 -->
  <input ref="my-input" />
</template>
```

它返回的是一个**只读的浅层 ref**，`value` 就是元素 / 组件实例。

| 写法 | 绑定方式 | 变量名和 ref 名 | 适用版本 |
| --- | --- | --- | --- |
| `const el = ref(null)` | **隐式**按同名自动连线 | 必须**相同** | 3.2+（`<script setup>`） |
| `const el = useTemplateRef('x')` | **显式**传入名字 | 可以**不同** | **3.5+** |

> [!note] 什么时候值得换成 `useTemplateRef`
> 1. **名字冲突**：`v-for` 里你想给"装着引用的数组"和"`ref` 名字"用同一个词时，隐式绑定会打架，显式写法一刀两断。
> 2. **类型推导更好**：`useTemplateRef<HTMLInputElement>('x')` 的 `value` 类型更干净。
> 3. **语义更直白**：一眼看出"这个变量的值来自模板里的哪一处"。

> [!warning] 它**只是**帮你拿到引用
> `useTemplateRef` 不改变时机——**挂载前 `value` 依然是 `null`**，`onMounted` / `watch` 这些规矩一条不少。别把它当成"立刻可用"的魔法。

## 四、`v-for` 里的引用：收集成数组

同一个 `ref` 名字出现在 `v-for` 的多个元素上时，Vue 会**收集成一个数组**（顺序见下方警告）：

```vue
<script setup>
import { ref, onMounted } from 'vue'

const list = ref([1, 2, 3])
const itemRefs = ref([])                 // 容器：数组

onMounted(() => {
  console.log(itemRefs.value)            // [<li>, <li>, <li>]
  console.log(itemRefs.value[0])         // 第一个真实 <li>
})
</script>

<template>
  <ul>
    <li v-for="item in list" ref="itemRefs">{{ item }}</li>
  </ul>
</template>
```

```text
v-for 渲染出多个同 ref 的元素
   <li ref="itemRefs">1</li>  ┐
   <li ref="itemRefs">2</li>  ├─▶  Vue 逐个塞进同一个数组
   <li ref="itemRefs">3</li>  ┘        itemRefs.value = [li, li, li]
```

> [!danger] 数组**不保证**和源数据顺序一致
> 官方明确说明：`ref` 数组**不能保证**与源数组的索引一一对应。**别用下标去对应数据**（`itemRefs.value[index]` 可能对错人）。如果业务上必须知道"这个引用属于哪条数据"，改用**函数式 ref**（见下一节），在回调里把它明确存到你自己的 Map / 对象里。

> [!note] `useTemplateRef` + `v-for`
> 3.5+ 里同样可以用 `useTemplateRef('itemRefs')` 配合 `v-for`，拿到的也是数组，顺序问题依旧存在。

## 五、函数式 ref：自己决定存到哪

`:ref`（注意带冒号）可以接一个**函数**，Vue 每次绑定 / 解绑时都会调用它，参数是**元素或组件实例**（解绑时为 `null`）：

```vue
<script setup>
import { ref } from 'vue'

const itemRefs = new Map()          // 想怎么存就怎么存

function setItemRef(el, item) {
  if (el) itemRefs.set(item.id, el) // 绑定：登记进 Map
  else itemRefs.delete(item.id)     // 解绑：清理掉
}
</script>

<template>
  <li v-for="item in list" :ref="(el) => setItemRef(el, item)">
    {{ item.name }}
  </li>
</template>
```

> [!tip] 函数式 ref 的杀手锏
> 它把"引用 → 数据"的对应关系**交还给你**，彻底绕开 `v-for` 数组顺序不可靠的问题。需要"按 id 找回某个元素"时，这是最稳的做法。回调的参数也可能是 `null`（元素被卸载），**必须判空**。

## 六、引用组件实例（本目录的重点）

`ref` 不只给 DOM，写在**组件标签**上拿到的是**子组件实例**：

```vue
<script setup>
import { ref, onMounted } from 'vue'
import ChildForm from './ChildForm.vue'

const formRef = ref(null)

onMounted(() => {
  formRef.value?.reset()            // 调用子组件暴露出来的方法
})
</script>

<template>
  <ChildForm ref="formRef" />
</template>
```

### 6.1 关键：`<script setup>` 的组件默认是"封闭"的

这是最容易踩的坑：`<script setup>` 组件**不会**把内部所有东西都暴露给父组件，父组件默认只能拿到一个"空壳子"。想让父组件用得上，子组件必须显式 **`defineExpose`**：

```vue
<!-- ChildForm.vue -->
<script setup>
import { ref } from 'vue'

const username = ref('')
function reset() {
  username.value = ''
}

// ✅ 显式挑选：只有列出来的，父组件才通过 ref 拿得到
defineExpose({ username, reset })
</script>

<template>
  <input v-model="username" />
</template>
```

| 子组件写法 | 父组件 `formRef.value` 能拿到什么 |
| --- | --- |
| `<script setup>` + **没有** `defineExpose` | ❌ 拿不到内部变量 / 方法（封闭实例） |
| `<script setup>` + `defineExpose({ reset })` | ✅ 只有 `reset`（及挂载后变的 `username`） |
| Options API，无 `expose` | ✅ 整个实例（`this` 上的东西基本都能访问） |

> [!warning] 声明 `defineExpose` 后，`$el` 之类也会被挡住
> 用 `<script setup>` 且调用 `defineExpose` 后，除了你列出的东西，父级**不能再**随意访问实例内部（包括 `$el` 这种"顺带"的路子）。这是刻意的封装，逼你把组件的**对外接口**写清楚。

> [!danger] `expose` 会"砍掉"默认暴露
> Options API 里若写了 `expose: ['reset']`，效果类似：**只暴露白名单**，其余一律不可见。需要"暴露全部 + 额外补充"就换成 `expose` 用函数形式或在 `<script setup>` 里用 `defineExpose` 明确列全。

### 6.2 该暴露什么？——像设计 API 一样克制

```text
✅ 值得暴露：init() / reset() / validate() / focus() /
            open() / close() 等"动作"
❌ 别暴露：内部 state、私有方法、实现细节
           —— 否则子组件的重构会变成"破坏性变更"
```

> [!tip] 能靠 props / emits 解决的，就别开 ref 这道口子
> 用 ref 主动调子组件方法，会让**父组件和子组件强耦合**。默认优先数据流：父传 props 进去，子 emit 事件出来。只有"父组件需要**命令式触发**子组件动作"（如"提交表单""重新加载"）时，才用 ref + `defineExpose`。它与 [[Props 组件属性]]、[[Events 自定义事件]] 是**互为补充**的三条通道。

## 七、时机：引用什么时候才"有值"

**挂载之前一律是 `null`。** 官方原话是"refs 只有在组件挂载后才会被填充"。所以：

```text
组件生命周期            inputEl.value
   setup 执行              null          ← 声明了，但还没填
   render / 创建 DOM       null
   onMounted              <input>       ← 从这一刻起才有值 ✅
   更新 / 卸载              元素 或 null（v-if 关闭时会变回 null）
```

| 你想访问 ref 的地方 | 能不能拿到值 | 说明 |
| --- | --- | --- |
| `setup` 顶层直接写 `inputEl.value.focus()` | ❌ | 此刻还没挂载，`null` |
| `onMounted` 里 | ✅ | 最常用、最稳的触发点 |
| `watch` / `watchEffect` 里 | ✅ | 配合 `v-if` 时用，能响应"变空 / 变有" |
| 事件回调、`nextTick` 之后 | ✅ | 数据刚改完、想读**更新后的** DOM 时 |

```js
// 元素会被 v-if 反复挂载 / 卸载时：用 watch 盯着它
watch(inputEl, (el) => {
  if (el) el.focus()
})
```

> [!warning] 它不是响应式数据，别拿它当状态源
> 模板引用是个"容器"，只在挂载 / 卸载时被赋值。**不要**试图用它驱动视图（"el 变了就重新渲染"）——那是 props / data 的活儿。反过来，**数据变了想读新 DOM，要等 `nextTick`**，因为 DOM 更新是异步的。
> 另外：Options API 里的 `this.$refs` **不是响应式的**，模板更新它不一定立刻跟着更新。

> [!question] 为什么我 `onMounted` 里还是 `null`？
> 常见原因：① `ref` 名字和变量名不一致（见第二节）；② 元素被 `v-if` 关着，压根没渲染；③ 元素在**还没挂载的子组件**内部，父组件的 `onMounted` 早于子组件的挂载。检查优先级：先对名字，再看 `v-if`。

## 八、Options API：`this.$refs`

不用 `<script setup>` 时，引用统一收进 `$refs`：

```vue
<script>
export default {
  mounted() {
    this.$refs.inputEl.focus()      // 按 ref 的名字取
  }
}
</script>

<template>
  <input ref="inputEl" />
</template>
```

| 对比项 | `<script setup>` | Options API |
| --- | --- | --- |
| 取得方式 | 同名变量 / `useTemplateRef` | `this.$refs.名字` |
| 是否响应式 | 变量是 ref，可 `watch` | `$refs` **不是**响应式对象 |
| 组件实例暴露 | 需 `defineExpose` | 默认暴露整个实例 |
| `v-for` 场景 | 数组 | `$refs.名字` 也是数组 |

> [!note] `$refs` 只在挂载后才可用
> 和组合式一样的时机规矩：`created` 阶段拿不到，`mounted` 之后才有。别在模板里指望 `$refs` 参与渲染。

## 九、常见坑与问答

> [!question] `ref="input"` 写了，`input.value` 却是 `null`？
> 九成是**名字没对上**：`<script setup>` 靠"模板 ref 名 = 顶层变量名"自动连线。检查大小写、连字符（`ref="my-input"` 对应的是 `useTemplateRef('my-input')`，不是变量 `myInput`）。
> 其次是**时机**：访问写在了 `setup` 顶层或 `onMounted` 之前。最后查 `v-if`：元素没渲染，自然没有引用。

> [!question] `v-for` 里 `ref` 数组的顺序和我的数据对不上？
> 官方明确**不保证顺序**。需要精确对应就改用**函数式 ref**（`:ref="(el) => dict.set(id, el)"`），把引用存进自己的 Map / 对象。

> [!question] 拿到了子组件实例，却调不到它的方法（报 undefined）？
> 因为 `<script setup>` 的子组件默认**封闭**。让子组件 `defineExpose({ 方法名 })`，父组件才访问得到。这也是为什么很多组件库会在文档里写"通过 ref 可调用 `validate()`、`resetFields()`"——那都是它们 `defineExpose` 出来的。

> [!question] 给组件写 `ref`，拿到的是 DOM 还是实例？
> 标签是**普通元素** → 真实 DOM 元素；标签是**组件** → 组件实例（受 `defineExpose` 约束）。想从组件 ref 拿根 DOM，用实例上的 `$el`（但在 `<script setup>` 里可能已被 `defineExpose` 挡掉）。

> [!question] `useTemplateRef` 和 `ref(null)` 该用哪个？
> 3.5+ 项目里，**需要显式名字 / 更好类型 / 避免命名冲突时用 `useTemplateRef`**；只是在简单场景里"同名变量"够用，`ref(null)` 也没问题。两者行为一致，`useTemplateRef` 只是把隐式规则摆到了明面上。

> [!question] 用 `ref` 操作 DOM，是不是和"不要直接操作 DOM"的原则矛盾？
> 不矛盾。原则反对的是**用 DOM 当数据源**（手动改 `textContent`、拼 `innerHTML`）。模板引用只用来调用那些**模板语法表达不了**的 DOM API（`focus`、播放、测量、初始化第三方库），不参与"渲染逻辑"。

> [!quote] 一句话记牢
> **`ref="名字"` 负责"登记"，`ref(null)` / `useTemplateRef` 负责"接收"，`onMounted` 负责"时机"，`defineExpose` 负责"组件要不要交出内部"。**
