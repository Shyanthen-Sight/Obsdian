# 删除分支 —— git branch -d / -D

> [!abstract] 一句话
> ==删除分支只是删掉那个指针文件==。如果该分支的提交**已经合并**进别的分支，删了不丢任何东西；如果**没合并**，删掉会让那些提交变成"没有名字的孤儿"（短期内还能从 `reflog` 捞回来）。所以 Git 用 `-d` / `-D` 把"安全删"和"强删"分开。

---

## 一、安全删除：`-d`

```bash
git branch -d <分支名>       # 只删"已合并"的分支，否则拒绝
```

有未合并提交时会报错：

```text
error: The branch 'feature/x' is not fully merged.
If you are sure you want to delete it, run 'git branch -D feature/x'.
```

> [!info] 为什么 Git 要拦你
> `-d` 相当于一道保险：它检查该分支的独有提交**是否都已并入其他分支**。
> 只要还有"独一份、没进主线"的提交，它就拒绝删——这是在保护你==**没丢工作**==。
> 顺带一提：`git branch -d` 也常用来删除**已合并的远程跟踪分支**（`git branch -dr origin/x`）。

---

## 二、强制删除：`-D`

```bash
git branch -D <分支名>       # 无视合并状态，直接删
```

> [!danger] `-D` 可能删掉尚未合并的工作
> 那些提交立刻变成"游离对象"，**不在任何分支上**。
> 短期内（`reflog` 默认保留 30/90 天）还能救：
> ```bash
> git reflog                    # 找到被删前的分支顶端提交哈希
> git branch 救回来 <哈希>       # 重新给它一个名字
> ```
> 但一旦对象被 `gc` 回收，就**永久消失**了。所以 `-D` 之前，先确认这些提交真的不要了。

---

## 三、两道硬限制

> [!failure] 不能删除"当前所在"的分支
> ```text
> error: Cannot delete branch 'main' checked out at '...'
> ```
> 先切到别的分支：`git switch main`（或 `git switch -`）再删。
> 另外，正被其他 **worktree** 检出的分支同样不能删。

---

## 四、删除远程分支

本地删了，远程还在。要删远程分支：

```bash
git push origin --delete <分支名>     # ★ 推荐，语义清晰
git push origin :<分支名>             # 老写法，等价的"空推送"
```

> [!warning] 这是一次影响所有人的操作
> 远程分支是全体协作者共享的成果。删之前确认：==**PR 是否已合并、是否还有人在用**==。
> 好在很多平台（如 GitHub）会在 PR 合并后由按钮自动删，通常轮不到你手删。

---

## 五、清理"远程已消失"的本地跟踪引用

远程分支被别人删了，你本地的 `origin/xxx` 缓存还在：

```bash
git fetch --prune                   # fetch 时顺带清理已消失的远程引用
git remote prune origin             # 只做清理，不拉取
git branch -dr origin/<分支名>       # 只手删某一条远程跟踪引用
```

> [!tip] 常挂一个别名，一劳永逸
> ```bash
> git config --global fetch.prune true   # 以后每次 fetch 自动 prune
> ```

---

## 六、批量清理已合并分支

```bash
git branch --merged | grep -v '\*' | xargs git branch -d
```

> [!warning] 先看清清单再动手
> 上面这条会删掉**所有已合并的非当前分支**。执行前先只跑 `git branch --merged` 确认清单，
> 尤其小心 `main` / `develop` 这类长期分支——它们常常显示为"已合并"，但**绝不该删**。

---

## 七、完整示例：干完一条 feature 分支

```bash
git switch main                  # 1. 回到主线
git pull                         # 2. 确保主线是最新的

git branch --merged              # 3. 确认 feature/login 已在"可删"清单里
git branch -d feature/login      # 4. 本地安全删除

git push origin --delete feature/login   # 5. 需要的话删远程
git fetch --prune                # 6. 清掉本地过期的远程引用
```

> [!success] 成功标志
> `git branch` 里不再有 `feature/login`；`git branch -vv` 不再报 `[gone]`。

---

## 八、常见困惑

> [!question] 删分支会不会把这些提交从历史上抹掉？
> 只有当那些提交**没有别的地方引用**时，它们才会随 `gc` 消失。
> 已合并的分支，其提交早已并入主线——你删的是"多余的名字"，不是内容。

> [!question] 删错了怎么救？
> 尽快 `git reflog` 找到被删前的分支顶端提交，`git branch <名字> <哈希>` 重建。
> 前提是对象还没被 `gc` 回收。==**发现删错立刻救，别拖。**==

> [!question] `-d` 说没合并，可我明明合并过了？
> 常见于合并时用了 **squash**（`--squash`）或 **rebase**：Git 看到的是"内容相同、但哈希不同的新提交"，
> 于是认为原分支"没被合并"。
> 这种情况要么用 `-D` 强删，要么改用普通 `merge` 保持可识别性（见 [[合并基础]]）。

> [!question] 删了远程分支，别的同事会怎样？
> 他们下次 `git fetch --prune` 后，本地的 `origin/旧名` 会变成 `[gone]`，再往楼上 `push` 会失败。
> 删除前最好在群里知会一声。

> [!question] 分支删了，它对应的 tag 还在吗？
> 在。tag 和分支是**各自独立**的引用。删分支不影响 tag；反之亦然。

---

> [!quote] 一句话记忆
> **`-d` 是"安全拔线"**（没合并就拒绝）、**`-D` 是"直接拔"**（后果自负）；远程分支要用手删，且==**删之前一定先商量**==。
