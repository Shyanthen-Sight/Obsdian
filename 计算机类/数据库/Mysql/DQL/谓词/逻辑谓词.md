# 逻辑谓词 —— `AND` / `OR` / `NOT` / `XOR`

> [!abstract] 一句话
> 逻辑谓词把多个条件组合成一个更大的谓词，结果是 `TRUE` / `FALSE` / `UNKNOWN`。
> 三条铁律：==**`NOT` 优先级最高，`AND` 高于 `OR`，`AND`/`OR` 混用必须加括号**==；以及==**`UNKNOWN` 不是 `FALSE`**==。

> [!info] 与其它笔记的分工
> 完整真值表和运算符细节见 [[计算机类/数据库/Mysql/sql运算符/逻辑运算符|逻辑运算符]]。
> 本篇从"谓词组合"的角度讲：优先级、否定形式、德摩根、短路与 NULL。
> `WHERE` 的整体用法见 [[Where]]。

---

## 一、四个逻辑运算符

| 运算符 | 名称 | 别名 | 结果 |
| --- | --- | --- | --- |
| `AND` | 与 | `&&` | 两边都 TRUE 才 TRUE |
| `OR` | 或 | `\|\|` | 一边 TRUE 就 TRUE |
| `NOT` | 非 | `!` | 一元，取反 |
| `XOR` | 异或 | 无 | 恰好一边 TRUE 才 TRUE（MySQL 扩展） |

```sql
SELECT TRUE AND FALSE,   -- 0
       TRUE OR FALSE,    -- 1
       NOT TRUE,         -- 0
       TRUE XOR TRUE,    -- 0
       TRUE XOR FALSE;   -- 1
```

> [!warning] 别名不推荐在生产代码里用
> `&&`、`||`、`!` 虽然能用，但：
> - `||` 在标准 SQL 里是字符串拼接，在 MySQL 里是 `OR`（除非启用 `PIPES_AS_CONCAT`）；
> - 可读性差，跨库容易出问题。
> **一律写 `AND` / `OR` / `NOT`。**

## 二、三值逻辑真值表

### 2.1 `AND`

| `AND` | TRUE | FALSE | UNKNOWN |
| --- | --- | --- | --- |
| **TRUE** | TRUE | FALSE | UNKNOWN |
| **FALSE** | FALSE | FALSE | **FALSE** |
| **UNKNOWN** | UNKNOWN | **FALSE** | UNKNOWN |

### 2.2 `OR`

| `OR` | TRUE | FALSE | UNKNOWN |
| --- | --- | --- | --- |
| **TRUE** | TRUE | **TRUE** | **TRUE** |
| **FALSE** | TRUE | FALSE | UNKNOWN |
| **UNKNOWN** | **TRUE** | UNKNOWN | UNKNOWN |

### 2.3 `NOT` / `XOR`

| 表达式 | 结果 |
| --- | --- |
| `NOT TRUE` | FALSE |
| `NOT FALSE` | TRUE |
| `NOT UNKNOWN` | **UNKNOWN** |
| `TRUE XOR TRUE` | FALSE |
| `TRUE XOR FALSE` | TRUE |
| `TRUE XOR UNKNOWN` | **UNKNOWN** |
| `UNKNOWN XOR UNKNOWN` | **UNKNOWN** |

> [!tip] 两条口诀
> **`AND` 遇假即为假，`OR` 遇真即为真。**
> 只有这两种情况能"吞掉" UNKNOWN，其余组合多半还是 UNKNOWN。
> 这也是短路求值的逻辑基础。

## 三、优先级：`NOT` > `AND` > `XOR` > `OR`

```text
NOT
 ↓
AND
 ↓
XOR
 ↓
OR
```

```sql
-- 本意：成年人，且性别为男或女
WHERE age > 18 AND gender = 'M' OR gender = 'F'
-- 实际解析：(age > 18 AND gender = 'M') OR (gender = 'F')
-- 结果：未成年女生也会被查出来
```

```sql
-- ✅ 加括号，让意图和解析一致
WHERE age > 18 AND (gender = 'M' OR gender = 'F')
```

> [!danger] 这是"不报错但结果错"的典型
> 优先级记错不会给你任何提示，只会让查询结果悄悄多几行或少几行。
> **规则：只要一条条件里同时出现 `AND` 和 `OR`，就给每个 `OR` 分组加括号。**

### 3.1 `NOT` 的作用范围

`NOT` 只作用于**紧挨着它的那个谓词**：

```sql
NOT age > 18 AND gender = 'M'
-- 解析为 (NOT (age > 18)) AND gender = 'M'
```

虽然优先级上 `NOT` 高于 `AND`，但 `NOT age > 18` 读起来仍然费劲。
建议显式写括号：

```sql
NOT (age > 18) AND gender = 'M'
```

## 四、否定谓词：`NOT` 与各类谓词的组合

`NOT` 可以直接否定一个谓词，形成新的谓词：

| 否定形式 | 含义 | 注意 |
| --- | --- | --- |
| `NOT (a = b)` | 不等于 | 等价 `a <> b` |
| `a NOT IN (...)` | 不属于 | NULL 陷阱 |
| `a NOT BETWEEN x AND y` | 不在区间 | NULL 得 UNKNOWN |
| `a NOT LIKE '...'` | 不匹配模式 | NULL 得 UNKNOWN |
| `a NOT REGEXP '...'` | 不匹配正则 | NULL 得 UNKNOWN |
| `NOT EXISTS (...)` | 不存在 | NULL 安全 |
| `NOT (a <=> b)` | NULL 安全不等 | 无 UNKNOWN |

> [!warning] `NOT` + NULL 仍然是 UNKNOWN
> ```sql
> SELECT NOT (NULL = 1);   -- NULL
> SELECT NOT (NULL <> 1);  -- NULL
> ```
> `NOT UNKNOWN` 还是 `UNKNOWN`，不会变成 TRUE。
> 所以"否定一个含 NULL 的条件"并不会把 NULL 行捞回来。

### 4.1 德摩根定律

```sql
NOT (A AND B)  ≡  (NOT A) OR  (NOT B)
NOT (A OR  B)  ≡  (NOT A) AND (NOT B)
```

```sql
-- 这两条等价
WHERE NOT (age > 18 AND gender = 'M')
WHERE age <= 18 OR gender <> 'M'
```

> [!tip] 用德摩根化简复杂否定
> 看到 `NOT (... AND ...)` 就拆成 `OR`，看到 `NOT (... OR ...)` 就拆成 `AND`。
> 但拆完后要重新检查 NULL 语义——`NOT (a = b)` 和 `a <> b` 在 NULL 上都会得 UNKNOWN，这一点是一致的。

## 五、短路求值：不要依赖它

从真值表看：

- `FALSE AND x` 一定是 FALSE，不必算 `x`；
- `TRUE OR x` 一定是 TRUE，不必算 `x`。

这叫**短路求值**。但 MySQL **不保证**逻辑表达式的求值顺序：

```sql
-- 不要依赖"b 不为 0 才除"
WHERE b <> 0 AND a / b > 1
```

优化器可能先算 `a / b`，导致除零错误或 warning。

> [!danger] 不要用 `AND` / `OR` 的短路来"保护"运算
> 需要条件求值时，用 `CASE` / `IF`：
> ```sql
> WHERE CASE WHEN b <> 0 THEN a / b > 1 ELSE FALSE END
> ```
> 同样，不要依赖短路来避免函数副作用——SQL 里也不该有副作用。

## 六、NULL 与逻辑组合的实用推论

### 6.1 `AND` 的"假吞噬"

```sql
SELECT NULL AND FALSE;   -- 0（FALSE）
SELECT NULL AND TRUE;    -- NULL（UNKNOWN）
```

### 6.2 `OR` 的"真吞噬"

```sql
SELECT NULL OR TRUE;     -- 1（TRUE）
SELECT NULL OR FALSE;    -- NULL（UNKNOWN）
```

### 6.3 为什么 `NOT IN` 会全空

```sql
x NOT IN (1, 2, NULL)
= x <> 1 AND x <> 2 AND x <> NULL
```

最后一项是 UNKNOWN；如果前两项都是 TRUE，整个 `AND` 就是 UNKNOWN；`WHERE` 丢弃。
详见 [[IN谓词]]。

### 6.4 保留 NULL 行的写法

```sql
-- 需要"不满足条件"或"值未知"的行
WHERE NOT (col = 1) OR col IS NULL
-- 或
WHERE col <> 1 OR col IS NULL
```

> [!important] 先问清楚业务语义
> "不是 1"到底包不包括"不知道是不是 1"？SQL 默认不包括（UNKNOWN 被丢弃）。
> 如果业务要包括，必须显式加 `OR col IS NULL`。

## 七、`XOR`：MySQL 的异或

```sql
expr1 XOR expr2
```

| 左 | 右 | 结果 |
| --- | --- | --- |
| TRUE | TRUE | FALSE |
| TRUE | FALSE | TRUE |
| FALSE | TRUE | TRUE |
| FALSE | FALSE | FALSE |
| 任一 UNKNOWN | — | UNKNOWN |

```sql
SELECT (age >= 18) XOR (gender = 'M');
-- 恰好一个条件成立时为 TRUE
```

> [!note] `XOR` 很少用
> 它不是 SQL 标准运算符（MySQL 扩展），可读性差。
> 需要"恰好一个成立"时，用 `AND` / `OR` 显式写更清楚：
> ```sql
> WHERE (a AND NOT b) OR (NOT a AND b)
> ```

## 八、常见错误合集

> [!failure] `AND` / `OR` 不加括号
> 优先级导致结果静默跑偏。混用就加括号。

> [!failure] 以为 `NOT` 会作用于整个表达式
> `NOT a = 1 AND b = 2` 解析为 `(NOT (a = 1)) AND (b = 2)`。
> 要否定整体，写 `NOT (a = 1 AND b = 2)`。

> [!failure] 以为 `NOT UNKNOWN` 是 TRUE
> 它还是 UNKNOWN，行仍会被 `WHERE` 丢弃。

> [!failure] 依赖短路避免除零
> MySQL 不保证求值顺序。用 `CASE` / `IF`。

> [!failure] 用 `||` 当字符串拼接
> MySQL 默认 `||` 是 `OR`。字符串拼接用 `CONCAT()`。

> [!failure] 在 `OR` 两边用不同列却期待走索引
> 不同列的 `OR` 可能退化成全表扫描，必要时拆成 `UNION ALL` 或 `UNION`。

## 九、速查表

| 需求 | 写法 |
| --- | --- |
| 同时满足 | `A AND B` |
| 满足任一 | `A OR B` |
| 取反 | `NOT A` |
| 恰好一个 | `(A AND NOT B) OR (NOT A AND B)` |
| 混用 `AND`/`OR` | 给每个 `OR` 分组加括号 |
| 否定整体 | `NOT (A AND B)` |
| 保留 NULL 行 | `条件 OR col IS NULL` |
| 条件求值 | `CASE WHEN ... THEN ... END` |
| 字符串拼接 | `CONCAT(a, b)`（不是 `||`） |

> [!quote] 一句话记忆
> **`NOT` > `AND` > `XOR` > `OR`；`AND` 遇假即为假，`OR` 遇真即为真；`NOT UNKNOWN` 仍是 UNKNOWN；`AND`/`OR` 混用必加括号；短路求值不可依赖。**
