# AVG —— 平均值

> [!abstract] 一句话
> `AVG(列)` = `SUM(列) / COUNT(列)`，**分母是"非 NULL 的行数"，不是总行数**——这一条让 `AVG` 成为聚合函数里==**最容易算错**==的一个：8 个人里 3 个人没填奖金，`AVG` 算的是除以 5，不是除以 8。

---

> [!example] 本篇示例数据
> 与同目录的 `COUNT` / `SUM` / `MAX` / `MIN` / `GROUP BY` / `HAVING` 各篇**共用同一张 `emp` 表**。
> **`bonus` 有 3 行是 `NULL`** —— 整个 `AVG` 的分母问题就是靠它演示的。**3 个部门人数不等**（研发 3 人、销售 3 人、财务 2 人）——用来演示"平均值不能再平均"。

```sql
CREATE TABLE emp (
    id        INT AUTO_INCREMENT PRIMARY KEY,

    dept      VARCHAR(20),      -- 部门

INSERT INTO emp (name, dept, gender, salary, hire_date, bonus) VALUES

('李娜', '研发部', 'F',  9000.00, '2020-07-01',    NULL),

('陈晨', '销售部', 'M',  6500.00, '2022-02-08',    NULL),

('周杰', '财务部', 'M',  9500.00, '2020-08-22', 4000.00);
```

## 一、语法

```sql
AVG([DISTINCT] 表达式)
```

| 要点 | 说明 |
| --- | --- |
| 参数 | 列名、常量、或表达式 |
| `DISTINCT` | 可选，先**去重**再平均 |
| 忽略 NULL | ✅ 是，NULL 不进分子、**也不进分母** |
| 等价形式 | `AVG(x)` == `SUM(x) / COUNT(x)` |
| 空集结果 | ==**`NULL`**==（不是 `0`） |
| `GROUP BY` | 可选；不写则全表当一个组 |

```sql
SELECT
    AVG(salary)   AS 平均工资,      -- 9312.500000
    AVG(bonus)    AS 平均奖金       -- 4600.000000
FROM emp;
```

```
+--------------+--------------+
| 平均工资     | 平均奖金     |
+--------------+--------------+
|  9312.500000 |  4600.000000 |
+--------------+--------------+
```

> [!note] 返回值的小数位
> `AVG` 返回的是**浮点/精确小数**，上面表里显示了 6 位小数。
> 展示时通常套 `ROUND(AVG(salary), 2)` 变成 `9312.50`。
> `AVG(salary)` 的分子 `74500`、分母 `8`（salary 没有 NULL），`74500 / 8 = 9312.5` ✅。

## 二、`AVG` 的分母：忽略 NULL（本文最重要）

```sql
SELECT
    SUM(bonus)             AS 奖金分子,        -- 23000.00
    COUNT(bonus)           AS 非NULL分母,      -- 5
    COUNT(*)               AS 总行数,          -- 8
    AVG(bonus)             AS AVG结果,         -- 4600.00  = 23000 / 5
    SUM(bonus) / COUNT(*)  AS 人均口径         -- 2875.00  = 23000 / 8
FROM emp;
```

```
+----------+-------------+--------+----------+----------+
| 奖金分子 | 非NULL分母  | 总行数 | AVG结果  | 人均口径 |
+----------+-------------+--------+----------+----------+
| 23000.00 |           5 |      8 |  4600.00 |  2875.00 |
+----------+-------------+--------+----------+----------+
```

> [!danger] 这是本文最要命的坑
> `AVG(bonus)` = `23000 / 5` = **`4600.00`**（只除以"填了奖金的人"）
> `SUM(bonus) / COUNT(*)` = `23000 / 8` = **`2875.00`**（除以"所有人"，没填的当 0）
> **两者差 60%**。业务方看到的"平均奖金 4600"其实远高于真实的"人均 2875"。

演算对照：

| 项 | 值 | 说明 |
| --- | --- | --- |
| `SUM(bonus)` | `23000.00` | `5000 + 8000 + 3000 + 3000 + 4000` |
| 非 NULL 行数 | `5` | `COUNT(bonus)` |
| 总行数 | `8` | `COUNT(*)` |
| `AVG(bonus)` | `23000 / 5` = **`4600.00`** | 只除以有值的人 |
| `SUM(bonus) / COUNT(*)` | `23000 / 8` = **`2875.00`** | 除以所有人，把没奖金的算作 0 |

> [!question] 那到底该用哪个？
> **取决于业务口径，代码层面没有对错**：
> - "**填报单位的平均奖金**是多少" → `AVG(bonus)`（只看填报了的）
> - "**每个员工平均拿到多少奖金**" → `SUM(bonus) / COUNT(*)`（没拿到就是 0）
>
> 这类口径问题**必须问清楚需求方**，不能自己拍脑袋。

> [!tip] 想按总行数算平均，三种写法
> ```sql
> SELECT SUM(bonus) / COUNT(*) FROM emp;          -- 最直白
> SELECT AVG(IFNULL(bonus, 0)) FROM emp;          -- 把 NULL 当 0 再平均
> SELECT AVG(COALESCE(bonus, 0)) FROM emp;        -- 同义，标准 SQL 函数
> ```
> 三者结果都是 `2875.00`。

> [!warning] 分母是 0 时返回 NULL
> ```sql
> SELECT AVG(bonus) FROM emp WHERE bonus IS NULL;   -- 结果：NULL
> ```
> 一个可平均的值都没有 → 分母为 0 → `AVG` 返回 `NULL`（MySQL 不报"除零"错）。
> 前端展示通常要套 `IFNULL(AVG(x), 0)`。

## 三、`AVG` 与 `GROUP BY`：分组平均

```sql
SELECT dept,
       COUNT(*)              AS 人数,
       ROUND(AVG(salary), 2) AS 平均工资
FROM emp
GROUP BY dept;
```

```
+--------+--------+--------------+
| dept   | 人数   | 平均工资     |
+--------+--------+--------------+
| 研发部 |      3 |     12000.00 |
| 财务部 |      2 |      8250.00 |
| 销售部 |      3 |      7333.33 |
+--------+--------+--------------+
```

验算：研发部 `(12000+9000+15000)/3 = 12000.00`；财务部 `(7000+9500)/2 = 8250.00`；销售部 `(8000+6500+7500)/3 = 7333.33`。

> [!tip] 分组求平均也要警惕 NULL
> 如果按 `dept` 分组求 `AVG(bonus)`，**每个部门各自的分母都不一样**（研发部 2 个、销售部 2 个、财务部 1 个有奖金）。
> 部门之间的"平均奖金"不可比——研发部除的是 2，财务部除的是 1。

## 四、平均值不能再平均（加权平均陷阱）

> [!danger] 这是统计报表里最经典的错误
> **"各部门平均工资"的简单平均 ≠ "全公司平均工资"。**

```sql
-- ❌ 错误：把三个部门的平均工资再平均一次
SELECT ROUND(AVG(avg_sal), 2) FROM (
    SELECT AVG(salary) AS avg_sal FROM emp GROUP BY dept
) AS t;
-- 结果：(12000 + 8250 + 7333.33) / 3 = 9194.44   ← 错的！
```

```
+--------------------+
| AVG(avg_sal)       |
+--------------------+
|            9194.44 |   ← 三个部门各占 1/3，无视了人数差异
+--------------------+
```

```sql
-- ✅ 正确：全公司平均工资 = 总工资 / 总人数
SELECT ROUND(AVG(salary), 2) FROM emp;
-- 74500 / 8 = 9312.50
```

```
+--------------------+
| AVG(salary)        |
+--------------------+
|            9312.50 |   ← 每个"人"各占 1/8，正确
+--------------------+
```

差额 `9312.50 - 9194.44 = 118.06` 从哪来？因为三个部门**人数不等**（3 / 2 / 3），简单平均让每个部门都占 `1/3` 的权重，而正确算法里每个**人**占 `1/8`。

| 算法 | 各项权重 | 结果 |
| --- | --- | --- |
| 部门平均再平均（错） | 每部门 `1/3` | `9194.44` |
| 总工资 / 总人数（对） | 每人 `1/8` | `9312.50` |

> [!success] 正确姿势
> 要对"整体"求平均，**永远从明细算**：`SUM(x) / COUNT(*)`，或直接 `AVG(x)` 打在全表上。
> 只有**各组人数完全相等**时，"平均的平均"才恰好等于整体平均——这是巧合，不是规律。

> [!info] 真要加权时用加权平均
> 若只有"各组均值 + 各组人数"两张数据（拿不到明细），加权平均公式：
> `SUM(组均值 × 组人数) / SUM(组人数)`
> ```sql
> SELECT SUM(avg_sal * cnt) / SUM(cnt) FROM (
>     SELECT AVG(salary) AS avg_sal, COUNT(*) AS cnt FROM emp GROUP BY dept
> ) AS t;   -- = 9312.50 ✅
> ```

## 五、`AVG(DISTINCT ...)`：去重再平均

```sql
SELECT
    AVG(bonus)           AS 全部平均,     -- 4600.00（含两个 3000）
    AVG(DISTINCT bonus)  AS 去重平均      -- 5000.00（5000+8000+3000+4000）/4
FROM emp;
```

```
+----------+----------+
| 全部平均 | 去重平均 |
+----------+----------+
|  4600.00 |  5000.00 |
+----------+----------+
```

`AVG(DISTINCT bonus)` = `(5000 + 8000 + 3000 + 4000) / 4 = 5000.00`。

> [!warning] 用错场景会得出荒谬结论
> "员工平均奖金"用 `AVG(DISTINCT bonus)`，会把"有两个人都拿 3000"这种情况**压缩成一个人**，结果虚高。
> `DISTINCT` 只在"每种取值各算一次"时才有意义，日常统计极少用。

## 六、条件平均：`AVG(CASE WHEN ...)`

想在**不分组**的情况下，一次算出多个维度的平均，用条件表达式：

```sql
SELECT
    ROUND(AVG(salary), 2)                                  AS 全员平均,   -- 9312.50
    ROUND(AVG(CASE WHEN gender = 'M' THEN salary END), 2)  AS 男平均,     -- 10750.00
    ROUND(AVG(CASE WHEN gender = 'F' THEN salary END), 2)  AS 女平均      -- 7875.00
FROM emp;
```

```
+----------+----------+----------+
| 全员平均 | 男平均   | 女平均   |
+----------+----------+----------+
|  9312.50 | 10750.00 |  7875.00 |
+----------+----------+----------+
```

验算：男性 `(12000+15000+6500+9500)/4 = 10750.00`；女性 `(9000+8000+7500+7000)/4 = 7875.00`。

> [!note] 为什么 `CASE WHEN` 不写 `ELSE 0`（关键细节）
> `AVG(CASE WHEN gender='M' THEN salary END)` —— 不匹配的行返回 **`NULL`**，`AVG` **忽略 NULL**，于是分子只是男员工工资、**分母也只是男员工人数**（4）。
> 如果写成 `ELSE 0`，分母会变成 8，男性平均被"稀释"成 `43000 / 8 = 5375` —— **错得离谱**。
> ==**做条件平均，`CASE WHEN` 千万不要加 `ELSE 0`。**==

| 写法 | 男平均 | 说明 |
| --- | --- | --- |
| `AVG(CASE WHEN gender='M' THEN salary END)` | `10750.00` | ✅ 分母 = 男员工数 4 |
| `AVG(CASE WHEN gender='M' THEN salary ELSE 0 END)` | `5375.00` | ❌ 分母被撑成 8 |

> [!tip] `COUNT` 版"行转列"对照
> 同一个技巧配合 `COUNT` 就能做"男女各几人"：
> `COUNT(CASE WHEN gender='M' THEN 1 END)` —— 同样**别加 `ELSE 0`**，否则每行都有值、全部算进去。

## 七、窗口函数：移动平均

`AVG(...) OVER (...)` 保留明细行，同时附上组内/移动平均：

```sql
SELECT name, dept, salary,
       ROUND(AVG(salary) OVER (PARTITION BY dept), 2)                    AS 部门平均,
       ROUND(AVG(salary) OVER (ORDER BY hire_date ROWS BETWEEN 2 PRECEDING AND CURRENT ROW), 2) AS 近三人平均
FROM emp
ORDER BY hire_date;
```

```
+--------+--------+----------+----------+------------+
| name   | dept   | salary   | 部门平均 | 近三人平均 |
+--------+--------+----------+----------+------------+
| 张伟   | 研发部 | 12000.00 | 12000.00 |   12000.00 |
| 王强   | 研发部 | 15000.00 | 12000.00 |   13500.00 |
| 李娜   | 研发部 |  9000.00 | 12000.00 |   12000.00 |
| 周杰   | 财务部 |  9500.00 |  8250.00 |   11666.67 |
| 刘洋   | 销售部 |  7500.00 |  7333.33 |   10500.00 |
| 赵敏   | 销售部 |  8000.00 |  7333.33 |    8333.33 |
| 陈晨   | 销售部 |  6500.00 |  7333.33 |    7333.33 |
| 孙悦   | 财务部 |  7000.00 |  8250.00 |   10000.00 |
+--------+--------+----------+----------+------------+
```

| 窗口写法 | 效果 |
| --- | --- |
| `AVG(salary) OVER ()` | 每行都显示全表平均 `9312.50` |
| `AVG(salary) OVER (PARTITION BY dept)` | 每行显示**本部门**平均 |
| `AVG(salary) OVER (ORDER BY hire_date)` | **累计**平均（从第一行到当前行） |
| `... ROWS BETWEEN 2 PRECEDING AND CURRENT ROW` | **滑动窗口**平均（近 3 行），做移动平均线用 |

> [!important] 对比 `GROUP BY`
> `GROUP BY dept` + `AVG` 会**折叠**成 3 行；`AVG(...) OVER (PARTITION BY dept)` **保留 8 行明细**，每行带上部门均值。
> "既要明细、又要对比组均值"（比如算"某员工比部门均值高多少"）必须用窗口函数。

## 八、常见错误合集

> [!danger] 坑一：以为 `AVG` 除以总行数
> `AVG(bonus)` 得 `4600`，以为"人均奖金 4600"——其实分母是 5 不是 8。
> **`AVG` 的分母永远是"非 NULL 行数"**，要按总行数算就写 `SUM(x) / COUNT(*)`。

> [!danger] 坑二：平均值再平均
> `AVG(AVG(salary))` 或"对各部门均值求均值"——各组人数不等时必然算错（第四节）。

> [!danger] 坑三：条件平均加了 `ELSE 0`
> 分母被撑大，结果偏小（第六节）。

> [!failure] 坑四：空集返回 `NULL`
> ```sql
> SELECT AVG(salary) FROM emp WHERE 1 = 0;    -- NULL
> ```
> 展示前套 `IFNULL(AVG(...), 0)` 或 `ROUND(AVG(...), 2)`（后者对 NULL 仍是 NULL，还是得兜底）。

> [!failure] 坑五：ERROR 1111 —— 把 `AVG` 写进 `WHERE`
> ```sql
> SELECT dept, AVG(salary) FROM emp WHERE AVG(salary) > 8000 GROUP BY dept;
> -- ERROR 1111 (HY000): Invalid use of group function
> ```
> 改到 `HAVING`：
> ```sql
> SELECT dept, AVG(salary) FROM emp GROUP BY dept HAVING AVG(salary) > 8000;
> ```

> [!failure] 坑六：ERROR 1055 —— `AVG` 和裸列一起 SELECT
> ```sql
> SELECT dept, name, AVG(salary) FROM emp GROUP BY dept;   -- ERROR 1055
> ```
> 详见 [[计算机类/数据库/Mysql/聚合查询/GROUP BY]]。

## 九、速查表

| 需求 | 写法 | `emp` 表结果 |
| --- | --- | --- |
| 全表平均 | `AVG(salary)` | `9312.50` |
| 忽略 NULL 的平均 | `AVG(bonus)` | `4600.00` |
| 按总行数平均 | `SUM(bonus) / COUNT(*)` | `2875.00` |
| 去重平均 | `AVG(DISTINCT bonus)` | `5000.00` |
| 分组平均 | `GROUP BY dept` + `AVG(salary)` | 每部门均值 |
| 条件平均 | `AVG(CASE WHEN 条件 THEN x END)` | 分子分母都只含匹配行 |
| 移动平均 | `AVG(x) OVER (ORDER BY ... ROWS BETWEEN ...)` | 滑动窗口均值 |
| 空集兜底 | `IFNULL(AVG(x), 0)` | `0` |

> [!question] 自测三连
> 1. 8 人中 3 人 `bonus` 为 NULL，`AVG(bonus)` 和 `SUM(bonus)/COUNT(*)` 各是多少？差在哪？
> 2. 三个部门的平均工资是 `12000 / 8250 / 7333.33`，它们的平均 `9194.44` 为什么 ≠ 全公司平均 `9312.50`？
> 3. `AVG(CASE WHEN gender='M' THEN salary ELSE 0 END)` 为什么是错的？

---

> [!quote] 一句话记忆
> **`AVG(x) = SUM(x) / COUNT(x)`，分母是"非 NULL 行数"**；要按总人数平均就写 `SUM(x)/COUNT(*)`；**平均值不能再平均**（各组人数不等会算错）；条件平均的 `CASE WHEN` **绝不加 `ELSE 0`**。
