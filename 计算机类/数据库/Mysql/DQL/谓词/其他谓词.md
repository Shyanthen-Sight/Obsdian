# 其他谓词 —— 标准 SQL 有、MySQL 未必支持的那些

> [!abstract] 一句话
> 除了比较、`BETWEEN`、`IN`、`LIKE`、`EXISTS` 这些常用谓词，SQL 标准里还有 `UNIQUE`、`IS DISTINCT FROM`、`OVERLAPS`、`SIMILAR TO` 等谓词。
> 它们==**在 MySQL 里大多不支持**==，但知道它们的存在，能帮你在读标准文档、跨库迁移时不至于一脸茫然。

> [!info] 本篇定位
> 这是 `谓词/` 的"补遗篇"，收录**低频、标准 SQL 或 MySQL 方言**的谓词。
> 常用谓词请直接看 [[谓词总览]] 的分类表。

---

## 一、MySQL 支持的方言谓词

### 1.1 `SOUNDS LIKE`

```sql
expr1 SOUNDS LIKE expr2
```

等价于：

```sql
SOUNDEX(expr1) = SOUNDEX(expr2)
```

按**发音**比较两个字符串（主要用于英文）：

```sql
SELECT 'Smith' SOUNDS LIKE 'Smyth';   -- 1
SELECT 'Robert' SOUNDS LIKE 'Rupert'; -- 1（取决于 SOUNDEX 结果）
-- 中文不要用：SOUNDEX 对非 ASCII 字符的结果不可靠
SELECT '张三' SOUNDS LIKE '李四';
```

> [!warning] `SOUNDS LIKE` 很鸡肋
> - 只对英文发音有效，对中文无效；
> - `SOUNDEX` 算法粗糙，误判率高；
> - 无法使用索引。
> 现代系统做"拼写纠错/模糊姓名匹配"通常用编辑距离、拼音库或搜索引擎，而不是 `SOUNDS LIKE`。

### 1.2 `XOR`

```sql
expr1 XOR expr2
```

逻辑异或，MySQL 扩展。详见 [[逻辑谓词]]。

```sql
SELECT TRUE XOR FALSE;   -- 1
SELECT TRUE XOR TRUE;    -- 0
```

### 1.3 `<=>`

NULL 安全等于，MySQL 方言。详见 [[安全等于]]。

```sql
SELECT NULL <=> NULL;    -- 1
```

## 二、标准 SQL 谓词：MySQL 不支持

### 2.1 `IS DISTINCT FROM` / `IS NOT DISTINCT FROM`

标准 SQL 的"NULL 安全不等 / 相等"：

```sql
-- 标准 SQL
a IS DISTINCT FROM b        -- a 与 b 不同（NULL 也参与判断）
a IS NOT DISTINCT FROM b    -- a 与 b 相同（NULL 也参与判断）
```

语义：

| `a` | `b` | `a IS DISTINCT FROM b` | `a IS NOT DISTINCT FROM b` |
| --- | --- | --- | --- |
| `1` | `1` | FALSE | TRUE |
| `1` | `2` | TRUE | FALSE |
| `1` | `NULL` | TRUE | FALSE |
| `NULL` | `NULL` | FALSE | TRUE |

MySQL **不支持**这个语法，用 `<=>` 改写：

```sql
-- 相等（NULL 安全）
a <=> b
-- 不等（NULL 安全）
NOT (a <=> b)
```

> [!tip] 跨库迁移时注意
> PostgreSQL、Oracle、SQL Server 等对 `IS DISTINCT FROM` 的支持情况不同。
> 写可移植 SQL 时，可以用 `(a = b) OR (a IS NULL AND b IS NULL)` 这类展开，但可读性较差。

### 2.2 `UNIQUE` 谓词

标准 SQL 的 `UNIQUE` 谓词判断**子查询结果是否有重复行**：

```sql
UNIQUE (subquery)
```

语义：如果子查询返回的行**没有重复**，返回 TRUE；有重复返回 FALSE；含 NULL 时可能返回 UNKNOWN。

```sql
-- 标准 SQL（MySQL 不支持）
SELECT * FROM t
WHERE UNIQUE (SELECT a FROM u WHERE u.b = t.b);
```

MySQL 没有这个谓词，等价写法是 `GROUP BY ... HAVING COUNT(*) = 1` 或 `NOT EXISTS` 自连接。

> [!note] 别和 `UNIQUE` 约束混淆
> `UNIQUE` 作为**约束**（`CREATE TABLE ... UNIQUE`）MySQL 支持；
> `UNIQUE` 作为**谓词**（判断子查询是否无重复）MySQL 不支持。
> 同名不同物。

### 2.3 `OVERLAPS` 谓词

标准 SQL 用于判断两个**时间区间**是否重叠：

```sql
-- 标准 SQL（MySQL 不支持）
(start1, end1) OVERLAPS (start2, end2)
```

语义：两个左闭右开区间 `[start, end)` 有交集时返回 TRUE。

MySQL 的等价写法：

```sql
WHERE start1 < end2 AND start2 < end1
```

```sql
-- 例：判断两个会议时间段是否冲突
SELECT * FROM meeting m1
JOIN meeting m2 ON m1.id < m2.id
WHERE m1.start_time < m2.end_time
  AND m2.start_time < m1.end_time;
```

> [!warning] 区间开闭要统一
> 上面的等价写法假设区间是**左闭右开** `[start, end)`。
> 如果业务把结束时间也包含在内（闭区间），条件要改成 `<=`。
> 先定义清楚，再写 SQL。

### 2.4 标准 `MATCH` 谓词

标准 SQL 的 `MATCH` 用于"部分匹配 / 完全匹配"：

```sql
-- 标准 SQL（MySQL 不支持这种语义）
expr MATCH [UNIQUE] [PARTIAL|FULL] (subquery)
```

MySQL 的 `MATCH ... AGAINST` 是**全文检索**，名字相同但语义完全不同，见 [[全文检索谓词]]。

> [!danger] 同名不同物
> 看到 `MATCH` 不要条件反射以为是全文检索。
> 标准 SQL 的 `MATCH` 是"行值匹配"，MySQL 不支持；MySQL 的 `MATCH` 是全文检索谓词。

### 2.5 `SIMILAR TO`

标准 SQL 的正则匹配谓词：

```sql
-- 标准 SQL（MySQL 不支持）
expr SIMILAR TO pattern
```

MySQL 用 `REGEXP` / `RLIKE` 代替，见 [[REGEXP谓词]]。

```sql
-- MySQL
WHERE col REGEXP '^[0-9]+$'
```

> [!note] `SIMILAR TO` 与 `LIKE`、`REGEXP` 的区别
> - `LIKE`：只有 `%`、`_` 两个通配符；
> - `SIMILAR TO`：标准 SQL 的正则子集；
> - `REGEXP`：MySQL 的完整正则（8.0 用 ICU）。
> 三者语法不完全兼容，跨库时不要直接复制。

## 三、MySQL 支持情况总表

| 谓词 | 标准 SQL | MySQL | MySQL 替代写法 |
| --- | --- | --- | --- |
| `=` / `<>` / `>` 等 | ✅ | ✅ | — |
| `BETWEEN` | ✅ | ✅ | — |
| `IN` | ✅ | ✅ | — |
| `LIKE` | ✅ | ✅ | — |
| `IS NULL` | ✅ | ✅ | — |
| `EXISTS` | ✅ | ✅ | — |
| `ANY` / `SOME` / `ALL` | ✅ | ✅（限子查询） | `IN` / 聚合 |
| `IS TRUE/FALSE/UNKNOWN` | ✅ | ✅ | — |
| `IS JSON` | 部分标准 | ✅（5.7.8+） | — |
| `MEMBER OF` | ❌（MySQL 扩展） | ✅（8.0.17+） | `JSON_CONTAINS` |
| `<=>` | ❌（MySQL 扩展） | ✅ | — |
| `REGEXP` / `RLIKE` | 部分标准 | ✅ | — |
| `MATCH ... AGAINST` | ❌（全文语义） | ✅ | — |
| `SOUNDS LIKE` | ❌（MySQL 扩展） | ✅ | — |
| `IS DISTINCT FROM` | ✅ | ❌ | `NOT (a <=> b)` |
| `IS NOT DISTINCT FROM` | ✅ | ❌ | `a <=> b` |
| `UNIQUE (subquery)` | ✅ | ❌ | `GROUP BY ... HAVING COUNT(*)` |
| `OVERLAPS` | ✅ | ❌ | `a_start < b_end AND b_start < a_end` |
| `SIMILAR TO` | ✅ | ❌ | `REGEXP` |
| 标准 `MATCH` | ✅ | ❌ | 用 `EXISTS` / `JOIN` 改写 |

## 四、遇到不支持的谓词怎么办

> [!tip] 四步走
> 1. **查 MySQL 版本**：`SELECT VERSION();`，确认是否真的不支持；
> 2. **找等价写法**：优先用标准 SQL 的 `EXISTS` / `JOIN` / 聚合改写；
> 3. **保持语义一致**：特别注意 NULL 语义，别用 `=` 代替 `IS NOT DISTINCT FROM`；
> 4. **写测试**：跨库迁移时，用同样的数据跑一遍，对比结果集。

```sql
-- IS DISTINCT FROM 的等价改写（NULL 安全）
NOT (a <=> b)

-- 或者更通用的写法（不依赖 MySQL 方言）
(a <> b) OR (a IS NULL AND b IS NULL)   -- 这是"相同"的写法，注意取反
```

> [!warning] `(a <> b) OR (a IS NULL AND b IS NULL)` 是"相同"还是"不同"？
> 它是 **NULL 安全相等**：两边都非 NULL 且相等，或两边都为 NULL。
> 要"不同"，整体取反：
> ```sql
> NOT ((a <> b) OR (a IS NULL AND b IS NULL))
> ```
> 这类布尔代数很容易写反，建议直接用 `<=>`（MySQL）或 `IS NOT DISTINCT FROM`（标准库）。

## 五、速查表

| 需求 | 标准 SQL | MySQL |
| --- | --- | --- |
| NULL 安全相等 | `a IS NOT DISTINCT FROM b` | `a <=> b` |
| NULL 安全不等 | `a IS DISTINCT FROM b` | `NOT (a <=> b)` |
| 子查询无重复 | `UNIQUE (subquery)` | `GROUP BY ... HAVING COUNT(*) = 1` |
| 时间区间重叠 | `(s1, e1) OVERLAPS (s2, e2)` | `s1 < e2 AND s2 < e1` |
| 正则匹配 | `SIMILAR TO` | `REGEXP` / `RLIKE` |
| 发音相似 | — | `SOUNDS LIKE` |
| 全文检索 | 标准 `MATCH`（语义不同） | `MATCH ... AGAINST` |

> [!quote] 一句话记忆
> **MySQL 的方言谓词有 `<=>`、`REGEXP`、`MATCH ... AGAINST`、`SOUNDS LIKE`、`MEMBER OF`；标准 SQL 的 `IS DISTINCT FROM`、`UNIQUE`、`OVERLAPS`、`SIMILAR TO` 它大多不支持，分别用 `<=>`、`GROUP BY`、区间比较、`REGEXP` 改写。**
