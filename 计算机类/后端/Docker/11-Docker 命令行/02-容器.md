# 容器

容器命令是日常用得最多的一组。真正高频的其实就十来个，剩下的靠 `--help` 和 `inspect` 现查。

## 从启动到清理

```bash
docker run -d --name web -p 8080:80 --restart unless-stopped nginx:1.27
docker ps
docker ps -a
docker logs --tail 100 -f web
docker exec -it web sh
docker stop web
docker rm web
```

`-d` 后台运行，`--name` 给一个稳定名字，`--restart unless-stopped` 让宿主机重启后自动拉起，`-p 8080:80` 是宿主端口在前。`docker run` 每次都新建容器；已有容器用 `start`，想改参数只能删掉重建。`docker exec` 是在运行中的容器里再开一个进程，容器停了就用不了。

`ps` 默认只显示运行中的容器，忘了 `-a` 是“容器消失了”的常见误会。格式化输出加批量操作：

```bash
docker ps -a --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}'
docker ps -q --filter status=exited | xargs -r docker rm
```

`-q` 只输出 ID，接 `xargs` 处理一批容器很顺手。

## inspect 是排障入口

`docker inspect` 返回一大段 JSON，用 `-f` 取关键字段：

```bash
docker inspect -f '{{.State.Status}} exit={{.State.ExitCode}} oom={{.State.OOMKilled}}' web
docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' web
docker inspect -f '{{json .Mounts}}' web
docker inspect -f '{{.RestartCount}}' web
docker inspect -f '{{json .Config.Healthcheck}}' web
```

容器反复重启，先看 `RestartCount` 和 `OOMKilled`；服务访问不到，先确认 IP 和端口；数据没落盘，先看 `Mounts` 里到底挂没挂上。这些字段往往比日志更早给出方向。

## 日志、资源和现场

```bash
docker logs --since 10m -t web
docker stats --no-stream --format 'table {{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}'
docker top web
docker port web
docker cp web:/etc/nginx/nginx.conf ./nginx.conf
docker diff web
```

`--since` 和 `--tail` 能避免几万行日志一次刷屏；`stats --no-stream` 取一次快照，适合写进巡检脚本。容器没有 shell（distroless）时，`docker cp` 和日志就是主要手段，`docker diff` 能看出可写层改了哪些文件。

## 退出码

- `0`：正常结束
- `1`：应用自己报错，看日志
- `126`：命令不可执行，常见于权限或 shebang 错误
- `127`：命令不存在，镜像里没装
- `137`：收到 SIGKILL，多半是 OOM 或 `docker stop` 超时
- `143`：收到 SIGTERM，正常停止流程

137 不要只翻日志，先 `inspect` 确认 `OOMKilled`。为 `true` 就调内存限制或查内存泄漏；为 `false` 则检查停止超时，以及应用是不是忽略了 SIGTERM。

> [!tip] 容器起不来看什么
> `ps -a` 看状态和退出码，`logs` 看应用报错，`inspect` 看配置、挂载和 OOM，最后才 `exec` 进去。顺序反了容易在错误的方向上耗时间。
