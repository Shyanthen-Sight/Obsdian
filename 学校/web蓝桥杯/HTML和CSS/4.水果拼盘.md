# 水果拼盘案例：两行 Flex 让 15 个水果自动落盘

> [!info] 原题
> 蓝桥云课 · 水果拼盘（题目 2448）· 第十三届蓝桥杯 Web 应用开发省赛第 1 题（5 分）
> [题目链接](https://www.lanqiao.cn/problems/2448/learning/?page=1&first_category_id=2&tags=HTML5&tag_relation=union)

> [!summary] 速记版
> ```css
> /* TODO：待补充代码 */
> #pond {
>   flex-direction: column;
>   flex-wrap: wrap;
> }
>
> /* 等价简写 */
> #pond { flex-flow: column wrap; }
> ```
> - 页面是**两层叠在一起的相同结构**：`#fruit-background` 放盘子，`#pond` 放水果，各有 15 个。
> - 盘子层在 HTML 里已经内联写了 `style="flex-flow: column wrap"`——**答案直接藏在 `index.html` 里**。
> - `column`：主轴改成纵向，5 个水果先竖着排满一列（每个 `height: 20%`，`5 × 20% = 100%`）。
> - `wrap`：第 6 个放不下就换到下一列；15 个正好 3 列，顺序是苹果 → 梨 → 香蕉。
> - 两层盒模型、尺寸、内边距、排列规则完全一致，所以水果天然落在同色盘子正中间，**不需要任何定位**。
> - 判分是**全对才给分**：布局差一点就是 0 分。

## 考察内容

- **Flex 主轴方向**：`flex-direction: column` 把主轴从水平改为垂直。
- **Flex 换行**：`flex-wrap: wrap` 在主轴排满后换到新的一行 / 一列。
- **简写属性**：`flex-flow: <direction> || <wrap>`。
- **多行 Flex 容器**：`align-content` 控制各 flex line 在交叉轴上的分布，`align-items` 控制单行内项目的对齐。
- **百分比尺寸的参照物**：flex 项目的 `width/height` 百分比参照**容器内容盒**。
- **可换行需要确定的主轴尺寸**：`column + wrap` 依赖容器有确定高度，否则永远不会换列。
- **层叠与定位**：两个 `position: absolute` 的满屏容器叠加，`z-index` 决定谁在上面。
- **读源码的能力**：题目把参考写法留在了另一层的内联样式里。

## 三、为什么两行就够了

### 1. 屏幕上是两层完全重叠的容器

```css
#pond,
#fruit-background {
  display: flex;
  position: absolute;
  top: 0;
  left: 0;
  width: 100%;
  height: 100%;
  padding: 1em;
}
```

两层都是满屏、同样的 `padding`、同样的 `display: flex`，并且 `#pond` 用 `z-index: 20` 盖在盘子层上面：

```
同一块屏幕上叠着两层：

#fruit-background（底层）  →  红盘列 │ 蓝盘列 │ 黄盘列
#pond（上层，z-index:20）  →  苹果列 │ 梨列   │ 香蕉列

两层的列位置、每格尺寸完全一致
        ↓
每个水果正好落在同色盘子的正中间
```

所以本题不需要算坐标、不需要 `position`、不需要 `transform`，只要让**水果层的排列方式和盘子层一样**。

### 2. `column` 先把水果竖着排

flex 容器默认 `flex-direction: row`，15 个水果会挤在一行里。改成 `column` 后主轴变成纵向：

```
#pond { flex-direction: column; }   ← 只有这一条时

┌──────────┐
│  🍎 20%  │
│  🍎 20%  │
│  🍎 20%  │
│  🍎 20%  │
│  🍎 20%  │
│  🍎 20%  │   ← 15 个全塞进一列
│   …      │      放不下就压缩（flex-shrink: 1）
└──────────┘
```

每个 `.fruit` 都是 `height: 20%`，15 个需要 300% 的高度。因为默认 `flex-wrap: nowrap`，浏览器不会换列，而是把 15 个一起压扁，水果变得又细又小。

### 3. `wrap` 再让第 6 个换到下一列

```css
#pond { flex-wrap: wrap; }   /* 配合 column */
```

- 容器内容高度 = `100% - 2em`（`box-sizing: border-box` + `padding: 1em`）。
- 每个水果高度 = 内容高度的 `20%`。
- **5 × 20% = 100%**，正好排满一列。
- 第 6 个水果放不下，于是新开一列；15 个正好 3 列。

```
#pond { flex-direction: column; flex-wrap: wrap; }

第 1 列        第 2 列        第 3 列
┌────────┐   ┌────────┐   ┌────────┐
│ 🍎 苹果 │   │ 🍐 梨   │   │ 🍌 香蕉 │   ← 每列 5 个
│ 🍎 苹果 │   │ 🍐 梨   │   │ 🍌 香蕉 │
│ 🍎 苹果 │   │ 🍐 梨   │   │ 🍌 香蕉 │
│ 🍎 苹果 │   │ 🍐 梨   │   │ 🍌 香蕉 │
│ 🍎 苹果 │   │ 🍐 梨   │   │ 🍌 香蕉 │
└────────┘   └────────┘   └────────┘
```

而盘子层的内联样式本来就是 `flex-flow: column wrap`，所以盘子也是同样的三列：

| 列 | 水果层 | 盘子层 | 盘子图片 |
| --- | --- | --- | --- |
| 第 1 列 | `.fruit.apple` ×5 | `.lilypad.apple` ×5 | `redplate.svg` |
| 第 2 列 | `.fruit.pear` ×5 | `.lilypad.pear` ×5 | `blueplate.svg` |
| 第 3 列 | `.fruit.banana` ×5 | `.lilypad.banana` ×5 | `yellowplate.svg` |

### 4. 为什么是"正中间"

```css
.lilypad, .fruit { width: 20%; height: 20%; }

.lilypad .bg, .fruit .bg {
  width: 100%;
  height: 100%;
  background-position: center center;   /* 图片在格子里居中 */
}

.lilypad .bg { background-size: 80% 80%; }   /* 盘子占格子的 80% */
.fruit   .bg { background-size: 30% 30%; }   /* 水果占格子的 30% */
```

- 水果格子和盘子格子尺寸相同、位置相同（两层布局一致）。
- 两个 `.bg` 都铺满各自格子，背景图都 `center center` 居中。
- 所以水果的中心 = 格子中心 = 盘子中心，天然"正中间"。

> [!note] 关于"三列为什么是散开的"
> 多行 flex 容器的 `align-content` 默认是 `stretch`，会把 3 条 flex line 拉伸铺满整个宽度，所以视觉上三列之间有明显空隙。盘子层和水果层的规则完全一致，拉伸方式也一致，因此仍然逐格对齐。**不要额外加 `justify-content` / `align-content`**，只改一层会把两层错开。

## 四、逐条拆解

| 声明 | 作用 | 本题为什么需要 / 容易错 |
| --- | --- | --- |
| `flex-direction: column` | 主轴改为纵向 | 让水果竖着排队；默认 `row` 会全挤成一行 |
| `flex-wrap: wrap` | 主轴排满后换行 / 换列 | 15 个水果不能压在一列里；换列后才是 3 列 |
| `flex-flow: column wrap` | 上面两条的简写 | 等价写法，顺序无所谓 |

### 换行的两个前提

1. **主轴尺寸必须确定**。`column` 方向的主轴是高度，`#pond` 是绝对定位元素，`height: 100%` 相对初始包含块（视口）解析，高度确定，浏览器才知道"一列排到哪里算满"。
2. **项目尺寸必须确定**。`.fruit { height: 20% }` 相对容器内容盒解析，5 个刚好 100%。

如果容器高度是 `auto`，`column + wrap` 就没有"满"的概念，所有项目会一直排在同一个无限长的列里。

### 百分比参照谁

```css
#pond { width: 100%; height: 100%; padding: 1em; }   /* border-box */
.fruit { width: 20%; height: 20%; }
```

- 容器的 `100%`：绝对定位、`top: 0`、无定位祖先 → 参照视口。
- 项目的 `20%`：参照**容器内容盒**（已扣掉左右 / 上下各 `1em` 的 padding）。
- 因为两层容器的 padding 相同，扣掉的量相同，所以格子仍然逐像素重合。

### `flex-shrink` 为什么没捣乱

- 5 个项目正好占满 100%，没有溢出，`flex-shrink: 1` 不会触发收缩。
- 第 6 个项目在换行计算时已经放到下一列，不会参与这一列的收缩。

## 五、错误写法对照

| 写法 | 实际效果 | 为什么错 |
| --- | --- | --- |
| 只写 `display: flex` | 15 个水果挤在一行，被压得很小 | 默认 `row nowrap`；盘子层却是 3 列 |
| 只写 `flex-direction: column` | 15 个水果挤在一列，被压得很扁 | 没有 `wrap`，不会换列 |
| 只写 `flex-wrap: wrap` | 5 个一行，共 3 行 | 主轴仍是横向，行与盘子列对不上 |
| `flex-direction: column-reverse` | 香蕉跑到第一列 | 顺序反转，落到错误颜色的盘子 |
| `flex-wrap: wrap-reverse` | 列从右往左排 | 列顺序反转，颜色全错位 |
| 额外加 `justify-content: center` | 本题每列正好占满，看不出效果；一旦每列个数变化就会整体偏移 | 只改水果层，剩余空间一出现就与盘子错位 |
| 额外加 `align-content: center` | 水果三列居中，盘子仍在原位 | 交叉轴分布只作用于 `#pond` |
| 给 `.fruit` 加 `margin` / 改宽高 | 水果偏离格子 | 违反"禁止修改图片大小"，且两层错位 |
| 给 `#pond` 加 `position` / `transform` 挪位置 | 可能碰巧对齐，但极脆弱 | 题目禁止改圆盘位置，且不同分辨率会崩 |
| 改 HTML 结构或类名 | 直接 0 分 | 判分按原结构取元素 |

> [!warning] 别把"颜色"理解成取色
> 盘子颜色是 **class 决定的**：`.lilypad.apple` → 红盘，`.lilypad.pear` → 蓝盘，`.lilypad.banana` → 黄盘。水果也按同名 class 分组。只要两层的**顺序和列数一致**，同名 class 自然重合，不需要写任何颜色判断。

## 七、Flex 属性详解

> [!info] 阅读顺序
> 先看 7.0 的三个前置概念，再看 7.1 总表；之后按"容器属性 → 项目属性 → 本题推演"展开。每个属性都标了**作用在哪条轴**、**本题用没用、为什么**。

### 7.0 三个前置概念

#### ① 主轴与交叉轴

flex 布局里没有绝对的"横竖"，只有"主轴 / 交叉轴"。`flex-direction` 决定主轴，交叉轴永远与主轴垂直。

```
flex-direction: row（默认）           flex-direction: column
┌───────────────────────────┐        ┌──────────────────┐
│ main-start → 主轴（水平）  │        │ main-start        │
│                           │        │   ↓               │
│ 交叉轴（垂直）↓            │        │ 主轴（垂直）       │
│                    main-end│        │   ↓               │
└───────────────────────────┘        │ 交叉轴（水平）→    │
                                     └──────────────────┘
```

- 主轴两端叫 **main-start / main-end**，交叉轴两端叫 **cross-start / cross-end**。
- `justify-content` 管**主轴**；`align-items`、`align-content`、`align-self` 管**交叉轴**。
- 一旦 `flex-direction` 改变，同一条属性管的物理方向就变了：`justify-content` 在 row 里管左右，在 column 里管上下。

#### ② 主轴尺寸与交叉轴尺寸

| `flex-direction` | 主轴尺寸 | 交叉轴尺寸 |
| --- | --- | --- |
| `row` / `row-reverse` | `width` | `height` |
| `column` / `column-reverse` | `height` | `width` |

这直接解释了本题：`flex-direction: column` 后，**`height: 20%` 决定"一列放几个"**，`width: 20%` 只决定列有多宽。

#### ③ flex line（弹性行 / 列）

- 一条横排叫一行（row），一条竖排叫一列（column），统称 **flex line**。
- 单行容器只有 1 条 line；开了 `wrap` 才可能有多条。
- "换行 / 换列"的本质是**新开一条 line**，不是给元素加换行符。
- 本题 15 个水果 = 3 条 line，每条 5 个。

### 7.1 属性总览

**容器属性**（写在 `display: flex` 的元素上）

| 属性 | 作用轴 | 一句话 | 本题 |
| --- | --- | --- | --- |
| `display` | — | 开启 flex 格式化上下文 | 题目已给 |
| `flex-direction` | 主轴 | 主轴朝哪 | ✅ `column` |
| `flex-wrap` | 主轴 | 排满后换不换 | ✅ `wrap` |
| `flex-flow` | 主轴 | 上面两条的简写 | 等价写法 |
| `justify-content` | 主轴 | 剩余空间怎么分 | ❌ 未用 |
| `align-items` | 交叉轴（单行内） | 一条 line 里怎么对齐 | ❌ 默认值 |
| `align-content` | 交叉轴（多行间） | 多条 line 怎么排 | ❌ 默认 `stretch` |
| `gap` / `row-gap` / `column-gap` | 主轴 / 交叉轴 | item 间距 | ❌ 会破坏 20% |

**项目属性**（写在 flex item 上）

| 属性 | 作用轴 | 一句话 | 本题 |
| --- | --- | --- | --- |
| `order` | 主轴 | 视觉顺序 | ❌ 默认 0 |
| `flex-grow` | 主轴 | 有剩余空间时放大 | ❌ 默认 0 |
| `flex-shrink` | 主轴 | 空间不足时压缩 | ❌ 默认 1，但没触发 |
| `flex-basis` | 主轴 | 主轴基准尺寸 | ❌ `auto` 取 `height` |
| `flex` | 主轴 | 上面三条的简写 | ❌ 未用 |
| `align-self` | 交叉轴 | 单独覆盖 `align-items` | ❌ 未用 |

### 7.2 `display: flex` / `inline-flex`（容器）

```css
#pond { display: flex; }
```

- `display: flex`：容器**对外是块级**元素，**对内**开启 flex 格式化上下文。
- `display: inline-flex`：容器对外表现为行内级，内部仍是 flex。
- 直接子元素自动成为 **flex item**，并且：
  - 子元素的 `display` 被"块化"（`inline` 会表现得像 `block`）。
  - `float`、`clear`、`vertical-align` 对 flex item **失效**。
  - 连续的文本节点会被包成匿名 flex item。
  - `::before` / `::after` 也会成为 item。
- 本题：`#pond, #fruit-background { display: flex; }` 已经在"不需要修改"的区域给出，所以 15 个 `.fruit` 自动成为 15 个 item，不需要额外设置。

### 7.3 `flex-direction`（容器，定义主轴）

| 值 | 主轴 | main-start | 项目排列 |
| --- | --- | --- | --- |
| `row`（默认） | 水平 | 左 | 左 → 右 |
| `row-reverse` | 水平 | 右 | 右 → 左 |
| `column` | 垂直 | 上 | 上 → 下 |
| `column-reverse` | 垂直 | 下 | 下 → 上 |

- 它只改**主轴方向**；交叉轴始终与主轴垂直，其起点由书写模式决定（LTR 下 column 的交叉轴从左边开始）。
- `-reverse` 改变的是 main-start 的位置，不只是"倒着画"，`justify-content: flex-start` 也会跟着换边。
- 本题必须 `column`：盘子是三列纵向排列，水果也要先纵向排队。
- 用 `row` 会把 15 个水果排成横排，与盘子的列完全错位。

### 7.4 `flex-wrap`（容器，是否换 line）

| 值 | 行为 |
| --- | --- |
| `nowrap`（默认） | 全部挤在一条 line 里，必要时压缩 |
| `wrap` | 排满后新开一条 line |
| `wrap-reverse` | 新 line 出现在反方向 |

**换行判断规则**：把 item 的"外层假想主轴尺寸"依次相加，超过容器主轴尺寸就换 line。

**关键前提：主轴尺寸必须确定。**

- `row + wrap`：宽度通常由块级容器自动撑满，天然确定，所以容器高度 `auto` 也能正常换行。
- `column + wrap`：主轴是**高度**。如果高度是 `auto`，容器会跟着内容一起长高，永远"没排满"，**永远不会换列**。
- 本题 `#pond` 是绝对定位元素，`height: 100%` 相对视口解析，高度确定，所以 `wrap` 有效。

本题 `wrap` 的作用：5 个 `20%` 正好 100%，第 6 个必须新开一列。

### 7.5 `flex-flow`（容器，简写）

```css
flex-flow: <flex-direction> || <flex-wrap>;
```

- 两个值顺序任意：`column wrap` 与 `wrap column` 等价。
- 没写的部分取初始值（`row` / `nowrap`）。
- 本题：`flex-flow: column wrap;`。
- 题目里 `#fruit-background` 的内联样式正是这一条，所以它天生就是三列盘子。

### 7.6 `justify-content`（容器，主轴）

| 值 | 效果 |
| --- | --- |
| `flex-start`（默认） | 全部靠 main-start |
| `flex-end` | 全部靠 main-end |
| `center` | 整体居中 |
| `space-between` | 两端贴边，中间均分 |
| `space-around` | 每个 item 两侧等距 |
| `space-evenly` | 所有间隙完全相等 |

- 它分配的是**主轴方向的剩余空间**；没有剩余空间时，各值看不出差别。
- 在 column 容器里它管**上下**，不是左右。
- 本题每列 `5 × 20% = 100%`，主轴正好占满，写 `justify-content` 当前看不出效果；但只要每列个数变化（比如 4 个），剩余空间一出现，水果就会整体偏移，与盘子错位。
- 想让整组内容居中，正确做法不是加 `justify-content`，而是保证两层规则一致。

### 7.7 `align-items`（容器，单条 line 的交叉轴）

| 值 | 效果 |
| --- | --- |
| `stretch`（默认） | item 交叉轴尺寸为 `auto` 时拉满整条 line |
| `flex-start` | 靠 cross-start |
| `flex-end` | 靠 cross-end |
| `center` | 交叉轴居中 |
| `baseline` | 按文字基线对齐（横向排列时常用） |

- 只作用于**一条 line 内部**，管不到 line 与 line 之间。
- `stretch` 有前提：item 在交叉轴上的尺寸必须是 `auto`。本题 `.fruit` 明确写了 `width: 20%`（column 下交叉轴是宽度），尺寸确定，所以 `stretch` 退化成 `flex-start`，不会把格子拉宽。
- 本题不写：默认值已经让每个 item 贴着自己那条 line 的 cross-start。

### 7.8 `align-content`（容器，多条 line 之间，交叉轴）

| 值 | 效果 |
| --- | --- |
| `normal`（默认，等同 `stretch`） | 把各 line 拉伸填满交叉轴 |
| `stretch` | 剩余交叉轴空间平均分给各 line |
| `flex-start` / `flex-end` | 所有 line 靠 cross-start / cross-end |
| `center` | 所有 line 整体居中 |
| `space-between` / `space-around` / `space-evenly` | 各 line 之间均分 |

- **只在多行（`wrap`）时生效**；单行容器写了也没用。
- 管的是 **line 与 line 之间**，不是 item 与 item 之间。
- 本题 3 条 line，每条交叉尺寸 `233.6px`，总和 `700.8px`；容器内容宽 `1168px`，剩余 `467.2px` 被平均分给 3 条 line，每条变成约 `389.3px`。所以三列看起来是均匀散开的。
- 盘子层和水果层吃的是同一个默认值，散开方式一模一样，因此仍然逐格对齐。
- **只给 `#pond` 加 `align-content: center` 会立刻错位**，因为盘子层还在 `stretch`。

### 7.9 `gap` / `row-gap` / `column-gap`（容器，间距）

```css
#pond {
  gap: 10px;          /* row-gap 与 column-gap 同时设置 */
  column-gap: 10px;   /* 只设列间距 */
}
```

- `gap` 是 `row-gap` + `column-gap` 的简写。
- flex 容器里表示 item 之间的间距：只加在 item 与 item 之间，**不加在容器边缘**。
- 间距会**计入换行计算**。
- 本题不能用：`5 × 20%` 已经是 100%，再加 4 个 gap 必然超过 100%，每列只能放 4 个，列数变成 4 列，和盘子对不上。
- 本题的"间距"其实是 `padding: 1em` 和 `align-content: stretch` 共同造成的，不是 `gap`。

### 7.10 `order`（项目，主轴顺序）

- 整数，默认 `0`；数值小的排前面，相同则按 DOM 顺序。
- 只改**视觉顺序**：DOM 顺序、Tab 焦点顺序、读屏顺序都不变。
- 本题不用：HTML 里已经是苹果 → 梨 → 香蕉，与盘子顺序一致。
- 变体题"水果摆盘"用 `order: 1` 把某个水果挪到最后。

### 7.11 `flex-grow`（项目，主轴放大）

- 默认 `0`：不参与分配剩余空间。
- 主轴有**正剩余空间**时，按各 item 的 grow 比例分配。
- 只在主轴方向生效：row 里加宽，column 里加高。
- 所有 grow 之和小于 1 时，只分配相应比例，剩下留空。
- 本题不用：每列正好占满，没有剩余空间；乱加会改变列内高度分配。

### 7.12 `flex-shrink`（项目，主轴压缩）

- 默认 `1`：主轴空间不足时允许压缩。
- 负剩余空间按 `flex-shrink × flex-basis` 加权分配。
- 设为 `0` 可以禁止压缩。
- flex item 还有"自动最小尺寸"（`min-width` / `min-height` 的 `auto`），内容撑住时可能压不下去；必要时显式写 `min-width: 0`。
- 本题：
  - 5 个正好 100%，没有负剩余空间，**不触发压缩**。
  - 如果只写 `column` 不写 `wrap`，15 个总高 300%，会被压成各 `1/15`，水果变得又扁又小——这就是"只写 column 为什么错"的底层原因。
  - 同理，只写 `row` 时 15 个水果会被压成各 `1/15` 宽。

### 7.13 `flex-basis`（项目，主轴基准尺寸）

| 值 | 含义 |
| --- | --- |
| `auto`（默认） | 取主轴方向上的 `width` / `height`；两者也为 `auto` 时看内容 |
| `content` | 按内容尺寸 |
| 长度 / 百分比 | 直接指定主轴基准；百分比参照容器**内容盒**的主轴尺寸 |
| `0` | 基准为 0，内容不参与基准计算 |

- `flex-basis` 优先于主轴方向的 `width` / `height`：
  - row：basis 覆盖 `width`。
  - column：basis 覆盖 `height`。
- 但另一条轴的尺寸仍由 `width` / `height` 决定。
- 本题 `.fruit { height: 20% }`，没有写 basis，于是 `flex-basis: auto` 取 `height = 20%`，这就是"一列正好 5 个"的来源。
- 写成 `flex-basis: 20%` 效果相同；写成 `flex: 0 0 20%` 则同时锁死"不放大、不压缩、固定 20%"。

### 7.14 `flex`（项目，简写）

```css
flex: <flex-grow> <flex-shrink>? <flex-basis>?;
```

| 写法 | 展开为 | 常见用途 |
| --- | --- | --- |
| `flex: initial` | `0 1 auto` | 初始值 |
| `flex: 1` | `1 1 0%` | 平分剩余空间 |
| `flex: auto` | `1 1 auto` | 先按内容大小，再分剩余 |
| `flex: none` | `0 0 auto` | 不伸不缩 |
| `flex: 0 0 20%` | `0 0 20%` | 固定占 20% |

- 单值写数字时是 `flex-grow`；`flex-shrink` 自动为 `1`，`flex-basis` 为 `0%`。
- `flex: 1` 与 `flex: auto` 的差别在 basis：`0%` 忽略内容，`auto` 先看内容。
- 本题不用简写；但 `flex: 0 0 20%` 可以替代 column 下的 `height: 20%`，语义更明确。

### 7.15 `align-self`（项目，交叉轴）

- 默认 `auto`，表示继承容器的 `align-items`。
- 取值与 `align-items` 相同：`stretch` / `flex-start` / `flex-end` / `center` / `baseline`。
- 只影响当前 item，用来做"个别元素单独对齐"。
- 变体题"水果摆盘"：`.yellow { align-self: flex-end; order: 1; }`。

### 7.16 auto margin（项目，两条轴都能吸空间）

- flex item 的 `margin: auto` 会**先吸走该方向的所有剩余空间**，再谈 `justify-content`。
- `margin-left: auto` 把 item 推到最右；`margin: auto` 在两条轴上都居中。
- 本题不用：给某个水果加 auto margin，它就离开格子，和盘子错位。
- 区分：块级元素的 `margin: 0 auto` 是"左右 auto 平分剩余宽度"；flex item 的 auto margin 优先级更高、语义更强，`margin-top: auto` 也能吸走纵向剩余空间。

### 7.17 属性作用轴速查

| 属性 | 作用轴 | 作用对象 | 本题状态 |
| --- | --- | --- | --- |
| `flex-direction` | 主轴（定义） | 容器 | `column` |
| `flex-wrap` | 主轴（换 line） | 容器 | `wrap` |
| `justify-content` | 主轴 | 容器内 item | 默认 `flex-start` |
| `align-items` | 交叉轴（line 内） | 容器内 item | 默认 `stretch`，因定宽退化 |
| `align-content` | 交叉轴（line 间） | 多条 line | 默认 `stretch`，三列散开 |
| `gap` | 主轴 / 交叉轴 | item 之间 | 未用 |
| `order` | 主轴 | 单个 item | 默认 0 |
| `flex-grow` | 主轴 | 单个 item | 默认 0 |
| `flex-shrink` | 主轴 | 单个 item | 默认 1，未触发 |
| `flex-basis` | 主轴 | 单个 item | `auto` → `height:20%` |
| `align-self` | 交叉轴 | 单个 item | 默认 `auto` |

### 7.18 本题完整推演（1200 × 800，1em = 16px）

1. `#pond` 是绝对定位，`width/height: 100%` → 参照视口，盒子 `1200 × 800`。
2. `padding: 1em` + `box-sizing: border-box` → **内容盒 `1168 × 768`**。
3. `.fruit` 的 `width/height: 20%` 相对内容盒解析 → 每格 **`233.6 × 153.6`**。
4. `flex-direction: column` → 主轴是高度，每格主轴尺寸 `153.6`。
5. `5 × 153.6 = 768`，正好等于内容盒高度 → **一列 5 个**。
6. 第 6 个放不下 → `flex-wrap: wrap` 新开一列；15 个 → **3 列**。
7. 每条 line 的交叉尺寸 = 最大的 item 交叉尺寸 = `233.6`；3 条共 `700.8`。
8. `align-content` 默认 `stretch`：剩余 `1168 - 700.8 = 467.2` 平均分给 3 条 line，每条变成约 `389.3`。
9. `align-items: stretch` 因 item 宽度确定而不拉伸，item 贴在每条 line 的 cross-start。
10. 盘子层尺寸、`padding`、规则完全相同 → 每个格子**逐像素重合**。
11. 两个 `.bg` 都在格子里 `center center` 居中（水果 30%、盘子 80%）→ 水果落在盘子正中心。
12. `#pond { z-index: 20 }` 且两层都是绝对定位 → 水果层盖在盘子层上面。

### 7.19 最容易混的六组

| 对比 | 区别 |
| --- | --- |
| `justify-content` vs `align-items` | 主轴 vs 交叉轴（单条 line 内） |
| `align-items` vs `align-content` | 一条 line 内的 item vs 多条 line 之间 |
| `flex-grow` vs `justify-content` | 把剩余空间变成 item 的尺寸 vs 调整 item 之间的位置 |
| `flex-basis` vs `width/height` | 主轴基准优先；另一条轴仍看 `width/height` |
| `order` vs DOM 顺序 | 只改视觉顺序，焦点 / 读屏顺序不变 |
| `flex-wrap: wrap` vs `overflow` | 换 line 重新排版 vs 裁切 / 滚动 |

## 八、举一反三

### 1. 同一考点的模拟赛题：水果摆盘

省模拟赛里有一道"水果摆盘"，答案用到 `order` 和 `align-self`：

```css
.yellow {
  align-self: flex-end;   /* 单独覆盖父级 align-items，在交叉轴末端对齐 */
  order: 1;               /* 改变主轴排列顺序，默认所有项目 order: 0 */
}
```

- `order` 只改**视觉顺序**，不改 DOM 顺序；值越小越靠前。
- `align-self` 只作用于**单个项目**，优先级高于容器的 `align-items`。
- 和本题一样：先判断主轴，再决定用容器属性还是项目属性。

### 2. 如果题目改成"每行 5 个"

```css
#pond {
  flex-direction: row;   /* 或省略，默认就是 row */
  flex-wrap: wrap;
}
```

15 个项目、每个宽 20%，正好 5 个一行、3 行。

### 3. 如果每列个数不是 5

- 列数固定、每列个数变化：改项目的主轴尺寸（`height`）或容器高度。
- 每列个数固定、列数变化：保持 `20%`，由项目总数决定列数。
- 想精确控制网格，`display: grid` + `grid-template-columns: repeat(3, 1fr)` 也可以，但本题明确考 flex。

### 4. 一眼判断该用 row 还是 column

看参考图里**同类元素是横着重复还是竖着重复**：

- 一排排横着放 → `row`。
- 一列列竖着放 → `column`。
- 放不下要折行 → 加 `wrap`。
