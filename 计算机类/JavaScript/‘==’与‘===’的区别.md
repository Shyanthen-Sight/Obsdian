# == 与 === 的区别

> 一句话：`===` 先比类型再比值，类型不同直接 `false`；`==` 类型不同时先隐式转换再比。**默认用 `===`，只有判空时用 `x == null`。**

## 对比

| | `===` 严格相等 | `==` 宽松相等 |
| --- | --- | --- |
| 类型不同 | 直接 `false` | 先转换，再比较 |
| 性能 | 无转换，更快 | 有转换开销 |
| 可预测性 | 高 | 低，规则绕 |
| 默认选择 | ✅ | 尽量避免 |

```js
1 === '1'   // false
1 ==  '1'   // true（字符串转数字）
0 === false // false
0 ==  false // true（布尔转数字）
```

## `==` 的转换规则

1. **同类型**：等价于 `===`（除 `NaN`）。
2. **`null` / `undefined`**：`null == undefined` 为 `true`，且两者**只和彼此相等**。
3. **数字 vs 字符串**：字符串转数字。
4. **布尔参与**：布尔先转数字（`true→1`、`false→0`）。
5. **对象 vs 原始值**：对象先转原始值（`valueOf` → `toString`）。
6. **对象 vs 对象**：比较引用地址。

## 常见坑

```js
null == undefined   // true
null == 0           // false
undefined == 0      // false
'' == 0             // true
'0' == false        // true
[] == false         // true   （[] → '' → 0）
[] == ![]           // true   （两边都变 0）
NaN == NaN          // false  （=== 也是 false）
0 === -0            // true
```

## 实践建议

- 一律用 `===` / `!==`，避免隐式转换带来的意外。
- 判空可写 `x == null`，一次性覆盖 `null` 和 `undefined`。
- 判断 `NaN` 用 `Number.isNaN(x)`，不要用 `x === NaN`。
- 需要区分 `+0` / `-0`，或让 `NaN` 等于自身，用 `Object.is(a, b)`。
