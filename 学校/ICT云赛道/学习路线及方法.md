## 0. 先看结论

1. **云赛道不等于“云计算”**。本届考的是 **云服务 + 云原生 + AI/大模型/AI Agent**，其中云服务是底座，AI 是拉分项。
2. **省资格赛 = 实验 50 题 + 理论 60 题**。实验决定你有没有“有效成绩”，理论决定你排第几。
3. **新手性价比最高的三件事**：实验题全部做完 → 真题刷三遍 → 拿 HCCDA 认证加分（团队最多 +600 分）。
4. **学到精髓的标志**：给你一个需求能画架构，给你一个故障能按层排查，给你两个相似服务能说出取舍。
5. **拿奖路径**：先保“有效成绩”，再争省三/省二，最后冲省一；省一等奖才有资格进中国总决赛。

> [!warning] 如果你是零基础，先接受一个现实
> 20 天不可能变成云架构师。但云赛道是**考试型赛道**：考纲有限、题型固定、实验题带指导。用对方法，20 天拿到省级奖项是现实的；想冲省一，需要把理论排名做上去。

## 1. 先把规则吃透（比看 10 小时视频重要）

| 省资格赛·理论 | 2026-11-14 — 11-15 | 客户端答题，60 分钟 | 60 题，判断/单选/多选 |
| 省赛 | 2026-12（部分赛区 12/5—6） | 线下集中，理论 + 实验 | 理论 150 题/90 分钟；实验 3—5 题/90 分钟（参考往届） |

> [!note] 省资格赛不发省级证书
> 它只作为晋级省赛的依据。**省级奖项在省赛评**。所以省资格赛的目标不是“拿证”，而是“进省赛 + 拿个好名次”。

### 1.2 分值结构（以本校通知为准）

| 环节 | 题量 | 时长 | 团队满分 | 说明 |
|---|---|---|---|---|
| 实验 | 50 道综合实验题 | 9/18—11/8 开放 | 3000 | 每题独立，通常有 3 次作答机会 |
| 理论 | 60 题 | 60 分钟 | 3000 | 判断 + 单选 + 多选 |
| 总成绩 | — | — | — | 常见写法：**实验 40% + 理论 60%**；也有赛区写实验 60% + 理论 40% |
| 认证加分 | — | — | 上限 600 | 计入省资格赛 |

> [!warning] 两种权重都出现过
> 多数学校通知写“实验 40% + 理论 60%”，也有赛区写“实验 60% + 理论 40%”。**不要猜，去看本校文件**。无论哪种，结论都一样：实验必须全做完，理论必须刷真题。

### 1.3 到底考什么

| 模块 | 本届重点 | 高频服务/概念 |
|---|---|---|
| 云服务 | 计算、存储、网络、数据库、安全、运维 | ECS、IMS、AS、EVS、SFS、OBS、CBR、VPC、EIP、ELB、NAT、RDS、DCS、CCE、CCI、SWR、FunctionGraph、IAM、CES、CTS、LTS、WAF、HSS、SMS |
| 云原生 | 容器与编排 | Docker、镜像、K8s 架构、Pod/Deployment/Service/Ingress、HPA、Helm、CCE |
| AI | 机器学习到大模型 | ML 流程、CNN/RNN/Transformer、CV/NLP、LLM、RAG、Agent、ModelArts、盘古 |
| 大数据（往届常考） | 组件原理 | HDFS、YARN、Hive、HBase、Spark、Flink、Kafka |

> [!tip] 权重怎么理解
> 往届省赛常见比例是 **云 40% / 大数据 20% / AI 40%**；本届官方强调“云服务、云原生、AI、大模型、AI Agent”，具体占比以本届考纲为准。新手策略：**云服务必须拿满基础分，AI 拿概念分，大数据只背高频**。

### 1.4 加分机制（新手最大的杠杆）

- 本届云赛道：考取 **HCCDA-AI** 或 **HCCDA-Tech Essentials**，任一 **+100 分/人**。
- 个人上限 **200 分**，团队上限 **600 分**。
- **报名账号必须和认证考试账号一致**，否则加分无效。
- 600 分相当于团队满分的 **20%**，比多刷对几道题更划算。

> [!warning] 别照搬旧帖
> 往届云赛道按 HCIA/HCIP/HCIE 加分（+50/+100/+200），本届改成了 HCCDA 两个认证。看到“考两个 HCIP 加 200”的旧攻略，先确认是否还适用。

### 1.5 必须知道的规则细节

- 团队赛：**3 名学生 + 1 名指导教师**，全部同校，报名截止后不得换人。
- 实践赛、创新赛、编程赛**互斥**，只能选一个。
- 云赛道要求**全体队员完成实验**，否则团队无有效成绩。
- 省赛是线下集中赛会制，按团队总分排名评奖。
- 报名免费；认证考试、云资源可能产生费用，提前看预算。

## 2. 云赛道的“精髓”到底是什么

> 不是记住 30 个产品名，而是建立**三张图**：流量图、数据图、生存图。
> 能做到“给我需求能画架构，给我故障能按层排查”，理论和实验都会变得可解释。

### 2.1 三条主线（所有知识点都挂在这三条线上）

| 主线 | 要回答的问题 | 对应服务 |
|---|---|---|
| **流量线** | 用户请求怎么进来、怎么出去、怎么隔离？ | DNS、EIP、ELB、VPC、子网、路由、安全组、ACL、NAT |
| **数据线** | 数据放哪、怎么备份、怎么迁移？ | EVS、SFS、OBS、CBR、RDS、DCS、DRS、SMS |
| **生存线** | 应用怎么部署、扩容、监控、排错？ | ECS、CCE、FunctionGraph、CES、LTS、CTS、IAM、WAF、HSS |

### 2.2 三层能力模型

| 层次 | 标准 | 怎么练 |
|---|---|---|
| **会用** | 能在控制台/API 把服务开起来 | 跟做实验，记录每一步 |
| **会讲** | 能解释每个参数为什么这么填 | 服务卡片 + 讲给队友听 |
| **会设计** | 能给场景画架构、做取舍、定位故障 | 综合实验 + 故障注入 |

**自测：你是否学到精髓？**

1. 给你“一个 Web 应用上云”，能否 10 分钟画出架构并说明每层作用？
2. 给你“网站打不开”，能否按层在 5 分钟内定位？
3. 给你 ECS 和 CCE、EVS 和 OBS，能否说出选择依据和成本差异？

### 2.3 一条项目主线：把同一个应用做 5 版（强烈建议）

不要按产品目录从头学到尾。选一个最简单的应用（博客、待办、静态站都行），迭代 5 版：

| 版本 | 架构 | 新增服务 | 你会学到 |
|---|---|---|---|
| V1 | 单台 ECS + 公网 | ECS、EIP、安全组、VPC | 最小闭环：网站能访问 |
| V2 | 静态资源分离 | OBS、IAM/桶策略 | 对象存储、权限、403 排查 |
| V3 | 两台 ECS + 负载均衡 | ELB、多可用区 | 健康检查、四层/七层、高可用 |
| V4 | 接入数据库 | RDS、DCS | 主备、白名单、备份恢复、缓存 |
| V5 | 容器化 | CCE、SWR、CES | 镜像、Pod、Service、Ingress、HPA、监控 |
| V6（加分） | 加安全和备份 | WAF、HSS、CBR、LTS | 防护、日志、备份、成本 |

每做完一版，**画一张架构图 + 记一次故障**。这比刷 100 道孤立的选择题更接近比赛。

### 2.4 一个请求的完整路径（必须背下来）

```text
用户浏览器
   │  DNS 解析
   ▼
EIP / ELB（四层或七层）
   │  VPC 路由表
   ▼
安全组（有状态，默认拒绝入站）
   ▼
ECS / CCE Pod
   │  应用进程
   ├── RDS（结构化数据）
   ├── DCS Redis（缓存）
   └── OBS（图片、附件、备份）
```

**排错顺序（从外到内）：**

1. DNS 能否解析？
2. EIP 是否绑定、带宽是否足够？
3. ELB 监听器、后端组、健康检查是否正常？
4. 安全组 / 网络 ACL 是否放行？
5. 子网、路由表、NAT 是否正确？
6. 服务器进程和端口是否在监听？
7. 看 LTS 日志、CES 指标、CTS 审计。

### 2.5 高频易混服务对比（理论题最爱考）

| 容易混 | 一句话区别 | 选择依据 |
|---|---|---|
| ECS / BMS / CCI / CCE | 虚拟机 / 物理机 / 免服务器容器 / 容器集群 | 要不要管操作系统、要不要编排 |
| EVS / SFS / OBS | 块存储 / 文件共享 / 对象存储 | 数据库盘 / 多机共享 / 图片备份 |
| ELB / NAT / EIP | 负载均衡 / 出口共享 / 公网地址 | 分摊流量 / 私网访问公网 / 单机公网 |
| 安全组 / ACL / WAF | 实例级有状态 / 子网级无状态 / 应用层防护 | 放行端口 / 子网隔离 / 防 Web 攻击 |
| RDS / GaussDB / DDS / DCS | 托管关系型 / 分布式关系型 / 文档型 / 缓存 | 一般业务 / 高并发金融 / JSON / 加速 |
| IMS / CBR | 镜像 / 备份 | 批量装系统 / 数据恢复 |
| CES / LTS / CTS | 指标监控 / 日志 / 审计 | 告警 / 查日志 / 查谁改了配置 |
| CCE / CCI | 容器集群 / 免运维容器实例 | 长期业务 / 突发任务 |

### 2.6 服务卡片法（每个服务一张）

不要抄书。每学一个服务，填一张卡：

```markdown
### 服务卡片：ECS
- 一句话：可弹性伸缩的云服务器。
- 解决什么问题：不用买硬件，按需开通，分钟级交付。
- 核心概念：规格族、镜像、系统盘/数据盘、安全组、可用区、密钥对。
- 关键参数：vCPU/内存、带宽、磁盘类型与大小、计费模式。
- 计费方式：按需、包年包月、竞价。
- 约束与限制：配额、规格可选范围、区域/AZ 限制。
- 三个高频故障：安全组没放行、密钥错误、磁盘满。
- 与谁搭配：VPC、EIP、EVS、ELB、CES。
- 一个实验：创建 ECS 并部署 Nginx。
- 我讲不清的点：______
```

> [!tip] 卡片的标准
> 合上文档，能用 60 秒讲清楚这张卡，才算过关。讲不清的条目，就是下一轮复习重点。

### 2.7 实验三遍法（比“跟着点一遍”有效 5 倍）

| 遍数 | 做法 | 目的 |
|---|---|---|
| 第一遍·跟做 | 照文档/视频做通，记录每一步和参数 | 建立正确路径 |
| 第二遍·脱稿 | 关掉文档重做，卡住就标记 | 暴露盲点 |
| 第三遍·破坏 | 故意改错一个参数，观察报错并修复 | 接近国赛排错 |

**故障注入清单：**

| 故障 | 怎么制造 | 预期现象 | 考察点 |
|---|---|---|---|
| 网站打不开 | 安全组删除 80 端口 | 连接超时 | 安全组方向、优先级 |
| 跨子网不通 | 删除自定义路由 | ping 不通 | 路由表 |
| 静态资源 403 | OBS 桶策略设为私有 | 403 | 桶策略 vs IAM |
| 后端 unhealthy | ELB 健康检查路径写错 | 502/503 | 健康检查 |
| 数据库连不上 | RDS 白名单没加 ECS IP | 连接超时 | 白名单、安全组 |
| Pod 起不来 | 镜像地址写错 | ImagePullBackOff | 镜像仓库、拉取密钥 |

### 2.8 错题归因法（理论提分核心）

不要只记“正确答案”，要记“为什么错”：

| 日期 | 题目关键词 | 我的答案 | 正确答案 | 错因 | 关联服务 | 重做 |
|---|---|---|---|---|---|---|
| 11/09 | ELB 健康检查 | 四层 | 七层 | 概念混淆 | ELB | ☐ |

错因只分四类：**概念不清 / 参数记错 / 审题错误 / 完全没见过**。
每周统计一次，错得最多的那一类，就是下周的主攻方向。

### 2.9 费曼输出法

- 每周日花 10 分钟，在白板上给队友讲“一个请求怎么走”。
- 讲不下去的地方，就是你没懂的地方。
- 讲完让队友提 3 个“为什么”，答不上就回去查文档。

### 2.10 每周复盘 4 问

1. 这周我能**脱稿**做出哪个实验？
2. 哪个服务我还讲不清？
3. 错题最多的知识点是什么？
4. 下周要砍掉什么低效动作？

## 5. 理论怎么学（不是死背）

### 5.1 先算分，再决定投入

- 实验 40%：50 题，带指导，**必须全做**。
- 理论 60%：60 题，决定排名，**必须刷真题**。
- 加分 600：两个 HCCDA，**能拿就拿**。

结论：**实验保底、理论拉分、加分兜底**。三者顺序不要反。

### 5.2 高频考点清单

**云服务（必拿）**

- 云计算 5 特征、3 种服务模式（IaaS/PaaS/SaaS）、4 种部署模式。
- 虚拟化 vs 容器；区域（Region）vs 可用区（AZ）。
- ECS：规格族、镜像、计费、登录方式、安全组。
- VPC：子网、路由表、安全组、ACL、对等连接。
- ELB：四层 vs 七层、监听器、后端服务器组、健康检查、算法。
- OBS：桶、存储类别、权限、生命周期、静态网站。
- EVS：磁盘类型、快照、扩容。
- RDS：主备、只读、备份、白名单。
- IAM：用户、用户组、策略、委托。
- CES / LTS / CTS：指标、日志、审计的区别。
- 迁移：SMS（主机）、DRS（数据库）、OBS 工具。

**云原生**

- Docker：镜像、容器、仓库、Dockerfile。
- K8s：Master/Node、Pod、Deployment、Service、Ingress、ConfigMap、HPA。
- CCE：节点池、工作负载、弹性伸缩、网络模型。
- Helm、CI/CD、DevOps 基本概念。

**AI**

- ML 流程：数据 → 特征 → 训练 → 评估 → 推理。
- 监督/无监督/强化学习；过拟合与正则化；交叉验证。
- CNN / RNN / Transformer 的适用场景。
- CV/NLP 常见任务。
- LLM、Prompt、RAG、Agent、微调。
- ModelArts 全流程；盘古大模型的基本定位。

**大数据（只背高频）**

- HDFS、YARN、Hive、HBase、Spark、Flink、Kafka。
- 批处理 vs 流处理；数据仓库 vs 数据湖。

### 5.3 真题三遍法

| 遍数 | 做法 | 目标 |
|---|---|---|
| 第一遍 | 按知识点分类刷，不限时 | 暴露盲区 |
| 第二遍 | 只刷错题 + 高频题 | 正确率 ≥ 80% |
| 第三遍 | 整套计时，60 题/60 分钟 | 速度 + 稳定 |

> [!tip] 真题来源
> 优先用赛事“学习空间”里的官方真题和考纲解读；社区题库只作补充，遇到答案矛盾以官方文档为准。

### 5.4 记忆锚点（考前反复看）

1. 安全组**有状态**，网络 ACL **无状态**。
2. 安全组默认**拒绝入站、允许出站**。
3. ELB 四层看 IP+端口，七层看域名/URL。
4. OBS 桶名**全局唯一**。
5. RDS 连不上，先看**白名单**和**安全组**。
6. 块存储给系统/数据库，文件存储给多机共享，对象存储给图片/备份。
7. 云计算三模式：IaaS / PaaS / SaaS。
8. 备份 3-2-1：3 份数据、2 种介质、1 份异地。
9. RPO 是“能丢多少数据”，RTO 是“多久能恢复”。
10. 负载均衡算法：轮询、加权轮询、最少连接、IP Hash。
11. AI 三要素：数据、算法、算力。
12. RAG = 检索 + 生成，解决“模型不知道最新/私有知识”。
13. Agent = 规划 + 工具 + 记忆。
14. 迁移五步：评估 → 设计 → 迁移 → 验证 → 切换。
15. 高可用三件事：冗余、健康检查、故障转移。

## 8. 新手最容易踩的 12 个坑

1. **只刷题不做实验**：省赛实验一上机就崩。
2. **实验拖到 11/8**：系统拥堵、次数用完、提交失败。

5. **跨校组队或报名后换人**：违规，成绩无效。
6. **忽略“全员完成实验”**：团队没有有效成绩。
7. **用个人账号做实验不释放资源**：欠费、配额不足。
8. **只学云服务不看 AI**：直接丢掉一大块分。
9. **只背控制台界面**：题目一变形就不会。
10. **不做限时训练**：省赛 150 题做不完。
11. **不画架构图**：综合实验串不起来。
12. **不看本校通知**：错过校内选拔、考场和权重说明。
