# 概念

==`package` 是 Java 用来「给类分组、避免重名」的机制==，它声明了当前这个 `.java` 文件里的类**属于哪个命名空间**。

```java
package com.example.demo;   // 声明：本文件里的类都归属于 com.example.demo 这个包

public class Demo {
    // ...
}
```

一句话理解：==包 = 类的「姓氏」==。同一个姓氏下可以有 `张三`、`李四`，不同姓氏下也能各有一个 `张三`——它们靠「姓氏 + 名字」（即**全限定名**）来区分，不会冲突。

---

# 为什么需要包

Java 项目里成千上万个类，如果都堆在一起，两个问题会立刻爆炸：

1. **重名**：你写了个 `Date`，别人也写了个 `Date`，编译器该认谁？
2. **管理**：上千个类文件平铺在一个目录里，根本没法找、没法维护。

包就是解法：

| 问题 | 包如何解决 |
|------|-----------|
| 类名冲突 | 用「包名 + 类名」唯一标识一个类 |
| 组织混乱 | 按功能/层级分目录存放，一眼看清结构 |
| 权限控制 | 默认（包）权限让「同包可见」成为可能，见 [[java中的权限修饰符]] |

> 包名本质上是「类的身份证前缀」。全限定名 = `包名 + 类名`，JVM 靠它唯一定位一个类。
>
> ```
> java.util.ArrayList   // java.util 是包名，ArrayList 是类名
> ```

---

# 包名与目录的对应关系

==包名和文件夹目录是一一对应的，点号 `.` 就是目录分隔符==。

```java
package com.example.demo;
```

对应的磁盘结构就是：

```
com/
  └── example/
        └── demo/
              └── Demo.java
```

> ✅ 只要声明了 `package com.example.demo;`，这个文件就**必须**放在 `com/example/demo/` 目录下，否则编译/运行会出问题。
>
> ✅ 一个 `.java` 文件里==最多只能有一条 `package` 语句==，且必须写在**所有代码的最前面**（注释除外）。

# 命名规范

包名不是随便起的，业界有约定俗成的规则：

| 规则 | 说明 | 示例 |
|------|------|------|
| 全部小写 | 用 `.` 分隔，**不要**用大写 | `com.example.demo` ✅ |
| 域名倒写 | 用公司域名倒着写，保证全球唯一 | `com.google.guava` |
| 见名知意 | 按业务/职责分层 | `com.shop.order.service` |

```java
package com.example.demo;      // ✅ 规范
package com.example.demo.util; // ✅ 按职责再分层
package com.Example.Demo;      // ❌ 一整个词里不该出现大写
```

> ⚠️ 常用分层习惯：根包 → `com.公司.项目` → 再按 `controller / service / dao / util / entity` 分包。

# 包的作用域

包不只是「目录」，它还是一个**权限边界**：

- 同一个包里的类，==默认可以互相访问==（不需要 `import`，也不需要 `public`）。
- 跨包使用别的类，就==必须 `import` 或写全限定名==，且目标类本身要足够「开放」（`public`）。

```java
package com.example.a;

class Helper {   // 没有 public，默认（包）权限
    void sayHi() {
        System.out.println("hi");
    }
}
```

```java
package com.example.b;

import com.example.a.Helper;   // ❌ 编译错误：Helper 不是 public，出不了自己的包

public class Demo {
    // ...
}
```

> 这也解释了为什么「默认权限」又叫「**包权限**」——它把可见范围正好卡在一个包之内。

# 包的两层含义

这是初学者最容易混淆的点，一定要分清：

| 说法 | 指的是什么 | 例子 |
|------|-----------|------|
| **声明包** | `package` 关键字，写在文件顶部，声明「我属于谁」 | `package com.example.demo;` |
| **使用包** | 引用别的包里的类，用 `import` 或全限定名 | `import java.util.List;` |

一个常用的比喻：

> ==`package` 是「写自己的门牌号」，`import` 是「存别人的门牌号」。==
>
> 自己家门牌号一个文件只能写一次；别人的门牌号可以记很多个。具体用法见 [[import]]。

# 常见问题

1. **忘了写 `package` 会怎样？**
   类就归到「**默认包 / 无名包（unnamed package）**」。默认包无法被其他包 `import`，只适合写一次性小 demo，==正式项目里绝不要用==。

2. **`package` 写错位置会怎样？**
   `package` 必须是最前面的语句（注释之外）。写在 `import` 之后、或写在类里，都会**直接编译报错**。

3. **包名能包含大写字母吗？**
   语法上允许，但==约定上禁止==（会导致类和包的命名看起来一样，难区分）。

4. **`java.util` 和 `java.util.concurrent` 是同一个包吗？**
   不是。前者是后者**父包**，==子包不会自动被父包导入，父包也不会自动被子包导入==，两者相互独立，都要单独处理。

5. **包能改变类的访问权限吗？**
   不能直接改变，但「默认权限」的判定以包为单位，所以==包是权限规则里绕不开的一环==。

# 小结

| 要点 | 结论 |
|------|------|
| 作用 | 给类分组、避免重名、作为权限边界 |
| 位置 | 每个 `.java` 文件最前面，**最多一条** |
| 格式 | `package 包名;`，全小写，点号分隔，对应目录结构 |
| 命名 | 域名倒写，如 `com.example.demo` |
| 不写 | 落入默认包，无法被其他包引用（不推荐） |
| 与 import | `package` 声明自己，`import` 引用别人 |

> **一句话记忆**：
> ==`package` 就是给类「起个姓、编个门牌号」——姓相同的是同包，写全了才叫全限定名。==
